## 判準（不是新訂的，沿用 `../倖存清單_2026-09-13.md`）

只有一條:**這個量測有沒有經過「GT 影像 ↔ 姿態」的配對？**

```
沒經過  => ✅ 倖存，可直接引用
          資源與時間／程式行為（讀碼、位元級比對）／資料事實／評測協定／量測方法論
經過    => ⛔ 作廢，要重測才能引用
          所有 PSNR/SSIM/LPIPS/紋理比，以及由它們推出的殼層、失敗區、init、成本感知結論
中間    => ⚠ 機制倖存、數字要重量
          binning 浪費、cap 只交付 90%、trim 佔比、糊掉判準 …
```

★ 為什麼這條判準夠用：2026-09-13 查明 `input/NNNN.png` 裝的是「該塊第 N 個**檔案**」，
而相機 N 的姿態是「block_1..10 串接後第 N 幀」——**86.64% 的影像對到別的姿態**。
所以任何「把渲染結果與 GT 影像相比」得到的數字都不成立；而不碰這個配對的量測不受影響。

## ⚠ 2026-09-13 自我修正：三個被刪的檔案裡，兩個判錯

使用者問「檔名自述作廢，會不會也是因為 GT 問題？」—— 逐一回查後：
```
S11_成本模型_bug下量測_作廢   作廢理由＝zfill GT 錯位 => **是** GT 問題，刪得對（且雙重作廢）
block_taus/block_caps         作廢理由＝量於 EXACT_SUPPORT 之前、用 gsplat 前向估（非 trim）
                              => **不是** GT 問題。tau 是渲染幾何統計量，**量本身倖存**，
                                 只是要用現行 renderer 重量 => 已列進 v2 §0「待重測」
裁切coarse_已刪除_2026-08-06  它本身就是一份**刪除紀錄**，而專案慣例是保留那種紀錄
                              => 已還原成 紀錄/已刪除_裁切coarse_2026-08-06.md
```
⇒ 教訓：**「作廢」標籤是過去的自己貼的，也要重驗。**
  看到它要先問「是因為 GT 配對，還是別的理由」—— 後者常常是「量本身還在，只是要重量」。
