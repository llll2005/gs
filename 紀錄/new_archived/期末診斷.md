**目前最好的結果（24.06 dB）來自「最簡單的版本」——depth-init + immune eta，其他所有加上去的東西

## 2. 批判一：核心貢獻（GAT-ADMM）目前不只是「還沒 work」，是機制本身有三個疑慮

### 2.1 強度差了 1000 倍，而補強的代價剛好打到專案命脈

- 量級事實：`||y|| ~ 0.006-0.016`，AL penalty = `(rho/2)||x-z||^2 ≈ (0.1/2)(0.05)^2 ≈ 1.3e-4`，
  render loss 梯度 `~1e-1`。**consensus 訊號比主訊號弱約 3 個數量級。**
- 你自己的記錄三次都寫「需要 n_outer=20+ 才會有效」。但 y 是線性累積的：要把 `||y||` 從 0.01 拉到 0.05，
  需要約 4-5 倍的 outer iteration，即 `20+ outer × 500 inner = 10000+ 額外步`，疊在現有 30000 上。
- **這直接砍掉專案的賣點。** 賣點是「6GB 消費級硬體、24-48 小時」。為了讓核心機制產生效果，
  訓練時間要 +33%~+50%，而這還是在「假設它真的會收斂到有用」的前提下——這個前提從未被驗證。

### 2.2 「feature-space 平均」可能是錯的算子

z-update 做的是 `z_v = sigma(sum alpha_vu * W * h_u)`，把鄰居的 12 維特徵（含 SH_dc 顏色、normal）
做注意力加權平均。問題：

- 當 block A 和 block B 在邊界對同一塊表面有**不同但各自合理**的估計時，正確答案通常**不是平均**，
  而是「採用視角覆蓋較好的那一方」。平均顏色 → 邊界色調糊化；平均 normal → 幾何被拉平。
- 證據已經出現：S9 裡 `block_12 Phase C 比 Phase B 退 -0.37 dB`，這正是 consensus 把該 block 的
  Gaussian 拉離自己最優點的典型症狀。
- DOGS 之所以能用硬 ADMM，是因為它在**重疊區**做共識（兩個 block 都渲染同一塊區域，逼它們一致）。
  我們是 depth-init、各 block 幾何獨立、且 **10/25 是孤島（完全沒有 boundary）**。我們的「邊界」
  比 DOGS 稀疏得多，consensus 能著力的點本來就少。

### 2.3 「優雅處理 dynamic topology」是一個敘事優勢，不是一個量測優勢

- clone→y、split→y/2、prune→discard 這套在機制上跑得起來（已驗證），Lyapunov 也能寫。
  但**它解決的是「DOGS 用啟發式」這個美學問題，不是任何一個 PSNR 數字。**
- 換句話說：就算 dynamic topology 處理得比 DOGS 漂亮，只要最終 consensus 本身不產生品質增益，
  這個優勢就無法兌現成審稿人認可的結果。你是在優化一個「正確但不影響結果」的環節。

> **小結**：GAT-ADMM 不是「再多跑幾輪就好」。它有強度問題（修了會殺賣點）、算子問題
> （平均可能有害）、和落地問題（邊界太稀疏）。在投入更多算力前，必須先用**一個決定性實驗**
> 回答「它到底能不能贏過 no-ADMM 超過雜訊」——而這個實驗到現在還沒做。

## 3. 批判二：真正的 4.64 dB 缺口來自「拿掉 coarse pretrain」，而 ADMM 補不回來

這是整個架構最深的邏輯漏洞，值得單獨講清楚：

```
CityGSV2 的全域一致性 ← 來自 global coarse pretrain（訓練過一遍整個場景）
我們主動拿掉 coarse pretrain ← 用 depth-init 取代（理由：省 OOM）
            ↓
失去全域一致性（你自己在 pipeline doc 5.5 寫了「全域一致性：無」）
            ↓
押注 DT-ADMM-GAT 的 consensus 把它補回來
            ↓
但實驗證明 consensus 補回來的量 = 雜訊（+0.06 dB）
```

**這個鏈條中間斷了。** 我們移除了提供全域一致性的元件，賭一個機制去補，而那個機制（用我們自己的數據）
補回來的是零。結果就是 -4.64 dB 卡在那裡。

而且有個尷尬事實：**coarse 模型其實存在且訓得起來**
（`outputs/RTG_mc_aerial_coarse_sh2/checkpoints/epoch=6-step=30000.ckpt`，177MB，已在 6GB 上跑完）。
也就是說「coarse pretrain 在 6GB 上不可行」這個 depth-init 的前提，**本身就不完全成立**——
你已經有一個能跑的 coarse。那 depth-init 省下的到底是什麼？值不值 4.64 dB？這需要直接做 A/B。

## 4. 批判三：實驗投入的方向錯置

把 5/15 之後的實驗攤開看：

| 投入 | 內容 | 產出 |
|------|------|------|
| **大量**（6 組訓練，多為全 25 block 或多 block） | RTG-SLAM B1/B3/B4/B5 各種開關組合 | **全部負結果**，結論是「都別開」 |
| **極少**（5 outer × 3 次，從未跑 20+） | ADMM consensus（= 論文核心貢獻） | 三次都收尾成「需要更多 iteration」，從未驗證 |

問題不在於「做 ablation 不對」——negative result 也是 result。問題在於**精力分配跟論文重心相反**：

- 花最多力氣打磨的是 density controller（引擎），而引擎的最佳狀態恰好是「什麼都不加」。
- 花最少力氣驗證的是 thesis 本身（ADMM consensus），而它至今處於薛丁格狀態——
  既沒被證明有效，也沒被證明無效，只是一直「下次跑更多」。

**一個健康的研究週期應該先用最便宜的實驗去 kill or confirm 核心假設，再去打磨周邊。
我們做反了。**

## 5. 批判四：評估地基不可信（這個要最優先修，否則上面所有結論都飄）

反覆出現在記錄裡的句子：「全域 merged PSNR 不可信，Gaussian drift 導致 AABB filter 只留 13-15%」。

這是**地基級的問題**：

- per-block PSNR（同分布 test）和 global merged PSNR（跨 block）天生差 3-5 dB，
  而我們唯一能跟 CityGSV2「28.70」公平比的是 **global** 數字——但 global 數字因為 drift 失真。
- 換句話說：**我們現在沒有一個可信的尺，去回答「有沒有追平 CityGSV2」這個專案的核心問題。**
- 在這把尺修好之前，所有「+0.06」「-0.834」的解讀都建立在浮沙上。drift 一修，相對排序可能整個變。

**這應該是第一順位，先於任何新演算法。** 修法見 §7 的 step 0。

## 7. 重新定位：三條路，附誠實風險評估

### Step 0（無論走哪條都要先做）：修好評估尺
1. 解決 Gaussian drift：訓練時對 depth-init Gaussian 加 AABB position penalty，
   或 merge 時改用 visibility-based（誰看得到用誰的），讓 merged 保留率從 13% 拉回合理值。
2. 固定一組 held-out global test view，建立**可信、可重現**的 global PSNR/SSIM/LPIPS。
3. 沒有這把尺，下面三條路都沒法判斷成敗。

---

### Path A — 誠實重定位（低風險，建議的保底）
**論點改成：「Consumer-GPU City-Scale 3DGS：什麼能搬、什麼不能搬。」**

- 主貢獻 = 工程整合（depth-init + GS-Scale offloading + GaussianSpa）把 city-scale 壓進 6GB，
  + 一份**嚴謹的負結果 ablation**：RTG-SLAM 的 indoor SLAM lifecycle（B1-B5）為何在 aerial
  city-scale 不 transfer。你手上這 6 組數據**就是論文的一個 section**，不是浪費。
- ADMM 降級成「輕量 boundary regularizer」的 minor component，不當頭牌。
- 風險：新穎性偏工程，投稿要挑對 venue（systems / 應用導向 workshop 比 top-tier vision 合適）。
- 為什麼建議當保底：它**只依賴已驗證有效的東西**，不賭任何未證實的機制。

---

### Path B — 把 ADMM-GAT 救活（高風險高報酬，要設停損）
若堅持 thesis 當頭牌，**先做這一個決定性實驗，再決定要不要繼續**：

1. 固定 2 個有真實 boundary 的相鄰 block（如 6+7），從乾淨 step=30000 出發。
2. 跑 `n_outer = 30, k_inner = 500`，並讓 `rho` 自適應上調（殘差不降就 ×1.5），
   目標把 `||y||` 推到 `~0.05-0.1` 量級。
3. 判準（**事先講死，不准事後找理由**）：
   - 若 ADMM-active block 的 global PSNR 比 no-ADMM 同 block **穩定 > +0.3 dB**（超過雜訊）→ thesis 活，繼續。
   - 若還是 < +0.1 dB 或退步 → **承認 consensus-on-raw-features 不 work，轉 Path A 或 C。**
4. 額外要查：z-update 改成「選擇」而非「平均」（gating 而非 soft attention 平均）會不會更好——
   呼應 §2.2 的疑慮。

**這條路最大的價值是：它很便宜（2 block）就能 kill or confirm 整個 thesis。早該做了。**

---

### Path C — 更聰明的論文組合（中風險，可能是真正的好故事）
把參考文獻重新洗牌，針對「depth-init 沒有全域先驗」這個根問題下手，而不是硬補：

**C-1：用 Scaffold-GS anchor 取代 raw-Gaussian consensus（推薦深入評估）**
- 痛點：dynamic topology（Gaussian 一直 split/clone）是 GAT 要處理的麻煩，也是 §2.2 平均算子失效的來源。
- Scaffold-GS 的 anchor 是**稀疏、結構化、不隨 densification 暴增**的。讓**跨 block 共享一層 anchor grid**，
  consensus 在 anchor 上做——anchor 拓撲穩定，根本繞過「dynamic topology」這個原本要 GAT 解的問題。
- 諷刺但務實：dynamic topology 本來是「GAT 優於 DOGS」的賣點，但如果 anchor 方案真的比較好，
  那就誠實換掉。**研究要的是 work，不是守住一個漂亮但無效的賣點。**

**C-2：輕量全域先驗（cheap global anchor，直接補 §3 的洞）**
- 你做 depth-init 時已經把**每個 block 的點雲反投影出來了**。把它們 merge 成一個全域稀疏雲，
  訓一個很小的全域 2DGS（幾 K iter、低解析度、host-offload），當作**一致性錨點**，再 per-block refine。
- 這比完整 coarse pretrain 便宜一個數量級，但把「全域一致性 = 無」改成「弱但存在」。
  很可能用很小的成本吃回 4.64 dB 的一大塊。**這是性價比最高的單一改動，值得先試。**

**C-3：GaussianSpa 的時機點當成貢獻**
- 你的 open question 4/5 問的就是「sparsify 該在 init 後還是訓練中」。把它做成一個受控研究
  （在 6GB 預算下，sparsify 排程對 quality/memory 的 Pareto front），本身就有 systems 貢獻。

## 9. 對「結合是否合理」的直接回答

你問的是「我們做的結合或方向是否真的合理、參考文獻能不能整合成有用 pipeline」。誠實版：

- **RTG-SLAM depth-init**：合理，但被誤用為「coarse pretrain 的完全替代」。它適合當**加速初始化**，
  不適合當**全域先驗的替代**——這兩個角色不一樣，混為一談是 4.64 dB 的根源。
- **GAT-ADMM consensus**：理論漂亮，但目前是 net-zero，且有結構性疑慮（§2）。**值得用 step 2
  做最後一次決定性驗證，但不該無條件繼續加碼。**
- **GS-Scale + GaussianSpa**：最務實、最可能真正達標的兩塊，**卻是唯二還沒動工的**。優先級被排反了。
- **最被低估的整合**：C-2（depth-init 點雲 → 輕量全域 2DGS 錨點）幾乎免費，直接補架構的洞，
  我認為這是目前 ROI 最高、最該先試的一招，甚至優先於救 ADMM。

一句話：**方向不是「錯」，是「重心放錯 + 缺一個可信的尺 + 一個沒被驗證的核心假設」。
先修尺、先用便宜實驗逼問核心假設、把輕量全域先驗補上，再決定 ADMM 要不要當頭牌。**

## 戰略釐清：RTG-init ⟷ consensus 的因果關係（2026-06-06）

來源：對抗推演中使用者提問「consensus 做好了，還需要 RTG-SLAM 嗎？感覺一個省成本、一個拼質量，方向不同。」

### 核心洞察：不是兩個對立方向，是一條因果鏈的兩端
- **不同軸**：RTG depth-init 在「**初始化成本**」軸；consensus 在「**一致性**」軸。
- **耦合**：DOGS/CityGS 的 block 全從**同一個全域 coarse** 出發 → 邊界天生大致一致，consensus 只是微調。我們**拿掉全域 coarse**（換 per-block 各自獨立的 depth-init）→ blocks **無共享基底** → 這才**逼出**對 consensus 的需求。
- **因果方向（關鍵）**：不是「consensus 取代 RTG」，而是「**RTG 挖洞、consensus 補洞**」。使用者的直覺把依賴方向搞反了。

### 一致性收支表
```
需要的一致性 = f(init 多差)      ← RTG-init 各 block 全獨立 → 需求「最高」
供給的一致性 = g(consensus 多強)  ← 目前「最弱」（單一-rho 餓死）
品質缺口 ≈ 需求 - 供給 ≈ 4.64 dB
  DOGS：昂貴全域預訓練壓低「需求」 + 輕量 consensus
  我們：最便宜 RTG 把「需求」拉到最高 + 全押 consensus ← 最高風險組合
```
關洞兩條路：(a) 拉高供給＝修 consensus（per-property / normalized-space rho）；(b) 拉低需求＝C-2 廉價全域先驗當 init，本來就少挖洞。

### 三種組合
| 組合 | init | consensus | 成本/風險 |
|---|---|---|---|
| 1 DOGS/CityGS | 全域預訓練 | 輕 | 高成本、高質量 |
| 2 我們現況 | RTG-init（需求最高） | 重（扛全部一致性） | 低 init 成本、**風險最高** |
| 3 路線 D/混合 | C-2 廉價全域先驗 | 輕 | 中成本、需求低、**風險低** |

### 結論
- **consensus 做好不會讓 RTG 多餘**：RTG 省的是「預訓練成本」，consensus 不負責這塊。兩者疊加＝「低 init 成本 **且** 高一致性」＝ **thesis 夢想型態**。它們服務同一個 6GB 目標，是砍在不同成本中心的兩刀，不是對立。
- **修正使用者的框架**：consensus 不是「拼質量不計成本」——那是 DOGS 的 24GB consensus。**我們的 GAT-consensus 本身就是把 24GB 共識壓進 6GB 的降成本動作。**
- **但若 consensus 始終邊緣**：該被換掉的是 **RTG（→ 改用 C-2）**，不是 consensus——因為 RTG 為省一點 init 成本破壞了大量一致性，C-2 只多花一點卻少挖很多洞。
- **consensus 唯一無可取代之處**：並行時可觸發 Split/Prune **改拓撲修掉邊界 floater**，靜態 init 一致性永遠做不到（呼應 Gemini Q4）。這是 consensus 配 RTG（而非被 C-2 取代）的唯一鐵桿理由。
- **真正的活問題**：「RTG 是否砍太兇、該不該換 C-2？」← 由 **task1（量化 init 缺口）+ 修好的 task2（量化 consensus 上限）** 合起來回答。
