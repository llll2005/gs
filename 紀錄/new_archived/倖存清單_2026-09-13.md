### 量測方法論（代價昂貴換來的）
```
判準要跑正控制              沒有正控制的判準不能下結論 —— 我用未驗證的 16x16 顏色簽名
                           得出「配對壞掉」，方向對但證據撐不起，後來又用三個**不足**的
                           測試撤回（循環/不敏感/循環）=> 三個不足的測試不會相加成一個足夠的
驗「A 對應 B」不能用 A 或 B 推導出來的判準
                           今天唯一有效的兩個：第三份 metadata（transforms_origin.json）、
                           SfM 自己的 2D 對應（獨立於姿態）
「模型重建得好」不能驗配對    val ⊂ train，模型可以把錯的影像背下來
不要把診斷資訊靜音          `>/dev/null 2>&1` 讓 git pull 失敗看起來像成功，追了一輪
相對門檻擋不住低對比        `GT std > quantile(sg, 0.40)` 在空拍圖上仍近乎平坦 =>
                           兩張平坦圖的 corr 是噪音 => 任何「糊掉 %」都要附**絕對**門檻
極端尾巴不是母體            從 corr<0.25 的 32 個 tile 看出的「規律」在代表性抽樣下消失
基建一定要乾跑              set -u 對空關聯陣列取長度、平行化要先認領、
                           drop_task 要連註解移除 —— 三個都不報錯
```

## ⚠ 機制倖存、數字要重量

```
binning 外接盒浪費          **機制是程式事實**：forward.cu:281 的 tile 數是較長軸撐出的
                           正方形外接盒 => tiles ∝ s_max² 而真覆蓋 ∝ s_max·s_min
                           ⛔ 數字（p50 長寬比 3.17、浪費 76.5%、>20 佔 15.3%）是
                             **錯配對資料訓練出來的模型**的分布 => 要重量
cap 只交付 90%              機制（densify 停但 opacity_reg 續壓 => 收割期掉 10%）合理，
                           但 90.00% 這個值來自 4 個作廢的跑次 => 要重新標定
週期性 trim 的成本          **結構倖存**（掃全部相機、每 contribution_prune_interval 步、
                           until_iter=-1 所以整個 60k 都做）
                           ⛔ 「占 20.8%」是 284 台相機時的值；新資料 548~667 台 =>
                             同一項漲 1.9~2.35 倍（單次 pass 從約 51 秒漲到約 156 秒）
步驟時間分解                backward 37% / forward 24% / trim 21% / optimizer 10.5% /
                           搬運 3.8% —— 除 trim 外的比例應該接近，但都在 N=1.787M 上量的
糊掉判準被汙染（§16.10）    **方法論結論倖存**（相對門檻 + corr 在平坦區是噪音）
                           ⛔ 所有百分比（46% / 28% / 紋理比 0.330 vs 0.933）作廢
```
