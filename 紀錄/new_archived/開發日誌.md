**歸因**：本實驗同時改了 B3=OFF 和 B5=50→10。N_Gauss 腰斬是決定性線索：

`freeze=True` 時 opacity pruning 關閉，B5 是唯一剪枝機制。B5=10（5000 steps）太激進，大量仍在訓練前期的 Gaussian 被過早清除。這一效應完全掩蓋了 B3=OFF 的潛在影響。

**B3 獨立效果**：未能隔離（被 B5 confound 掩蓋）。若要完整隔離，需要 freeze=True, B3=OFF, B5=50 的對照組。

#### 2. 隔離實驗結論

五組實驗的因果鏈已大致釐清：

| 變數 | freeze=False | freeze=True |
|------|-------------|-------------|
| B5 interval 敏感度 | 無敏感（opacity pruning 主導） | 高度敏感（B5 是唯一剪枝） |
| B5=10 影響 | ≈0 dB | -0.20 dB（過剪，N_Gauss -53%） |
| 最佳 B5 設定 | 任意 | 50（25000 steps）或更長 |
| B3 效果 | -0.834 dB（推測，未完全隔離） | 未知（被 B5=10 confound 掩蓋） |

**最終實驗建議**：
- DT-ADMM-GAT baseline 使用 `no_freeze`（freeze=False, B3=ON, B5=50）
- 若要確認 B3 是否有害：run freeze=True, B3=OFF, B5=50（僅需 2 blocks，~2hr）

修復三個問題：

**問題一：已完成 block 的 AssertionError 導致腳本看似提前停止**

`cli.py` 中若 block 已有 checkpoint 且 `ckpt_path is None` 則 assert fail → subprocess 立即退出。主迴圈在失敗的 block 後有 60s sleep（無輸出），用戶誤以為腳本卡死而 Ctrl+C。

**問題二：GPU wait 訊息一直刷屏**

每 2 分鐘印一次 "No free GPUs available"，90 分鐘訓練刷 45 次。

Fix：只在第一次 wait 和每 5 次（10 分鐘）才印一次，並顯示 elapsed 時間。

**問題三：sleep 用 subprocess 實作**

`subprocess.run(["sleep", "120"])` 每次 spawn 一個 shell process 只是為了等待。

Fix：改為 `time.sleep(120/60)`，初始等待從 60s 改為 90s（給 subprocess 更多時間佔用 GPU 再做下次檢查）。

per-block PSNR ~23-27 → merged 全域 20.5 的落差是 divide-and-conquer 架構固有限制：

- 基線也有相同落差（24.06 → 19.12，-4.9 dB）；no_freeze 僅 -2.7 dB，相對更好

完整重寫 density controller，新增以下功能（所有新參數預設關閉，不影響現有訓練）：

**B1（freeze_opacity）**：
- `freeze_opacity: bool = False`
- `setup()` 首次呼叫 `_maybe_freeze_opacity_lr()` 凍結 opacities optimizer param group lr=0
- `_densify_and_prune()`：`freeze_opacity=True` 時跳過 opacity-based pruning

**B3（M_c transparent Gaussian adding）**：
- 新增 config 參數：`mc_enabled`, `mc_color_threshold`（δ_c=0.1）, `mc_sample_ratio`（5%）, `mc_transparent_alpha`（0.1）, `mc_scale_factor`（0.01）
- `_add_mc_gaussians()` 在每個 densification interval 執行：
  1. 計算 per-pixel L1 color error vs GT → M_c mask（error > δ_c 且 depth > 0）
  2. 用 surf_depth 反投影到世界座標（`R_c2w @ pts_cam + camera_center`）
  3. 隨機採樣 5% M_c 點
  4. 建立 transparent Gaussian 屬性：logit(0.1) opacity、depth-adaptive scale（depth/focal * scale_factor）、法向量四元數（camera-facing）、GT color 轉 SH DC
  5. 呼叫 `_densification_postfix()` 加入模型
- `_normal_to_quats()` static method：[0,0,1] → normal 的四元數旋轉

**B4（e_i error count → stable→unstable reversion）**：
- 新增 config 參數：`stable_revert_enabled`, `stable_revert_threshold`（δ_c=0.1）, `stable_revert_count`（δ_e=5）
- 新增 buffer：`stable_error_count (N,)` torch.long
- `_update_stable_error_count()` 在每個 densification interval 執行：
  1. 將 stable Gaussian centers 投影到當前相機 image plane
  2. 取對應 pixel 的 color error
  3. error > threshold → e_i += 1；否則 e_i = max(0, e_i - 1)
  4. e_i >= δ_e → eta 歸零（stable→unstable），e_i 重置

**B5（long-term unstable pruning）**：
- 新增 config 參數：`max_unstable_intervals`（δ_t，0=停用）
- 新增 buffer：`birth_step (N,)` torch.long（記錄 Gaussian 建立時的 global step）
- `_densify_and_prune()` 中追加：`(current_step - birth_step) > max_unstable_intervals * densification_interval AND eta < threshold` → prune

**Topology 維護（三個新 buffer 全部同步）**：

| 操作 | eta | birth_step | stable_error_count |
|------|-----|------------|--------------------|
| Clone | 繼承父 | 繼承父 | 0 |
| Split | 0 | current_step | 0 |
| M_c add | 0 | current_step | 0 |
| Prune | 移除 | 移除 | 移除 |

`on_load_checkpoint()` 與 `after_density_changed()` 均對三個 buffer 做向後相容處理（舊 checkpoint 無對應 key → 初始化為 0）。

#### 4. 討論：時間窗口取樣變體作為全局一致性手段

使用者提議：把 RTG-SLAM 時間窗口取樣改為「訓練時偶爾使用相鄰 block 相機」以提升 block 間一致性。

分析結論：
- 原始時間窗口 = 解決線上 SLAM 的遺忘問題，離線訓練已看全部 frame，無此需求
- 跨 block 相機取樣不等於空間一致性；block B 的相機對 block A 的內容幾乎不可見 → 巨大 render loss → Gaussian drift 加速
- 可行變體：只加入「位於兩 block AABB 重疊區的邊界相機」作為共享監督，但這是弱約束（各自找到不同解釋方式），無法替代 ADMM 的直接屬性值約束（||x_A - x_B|| ≈ 0）

**根因：** `pl_module.optimizers()` 在多 optimizer（means + params）設定下回傳 `list`，而非單一 optimizer 物件。原本的程式碼假設回傳值有 `.param_groups`，對 list 直接操作導致崩潰。

**修正（`_maybe_freeze_opacity_lr`）：**
```python
# 修正前
opt = pl_module.optimizers()
optimizer = opt.optimizer if hasattr(opt, "optimizer") else opt
for pg in optimizer.param_groups:  # ← 若 opt 是 list 就崩潰

# 修正後
opts = pl_module.optimizers()
if not isinstance(opts, list):
    opts = [opts]
for opt in opts:
    actual = opt.optimizer if hasattr(opt, "optimizer") else opt
    for pg in actual.param_groups:
        if pg.get("name") == "opacities":
            pg["lr"] = 0.0
            ...
            return
```

# 修正前

#### 4. RTGStableDensityController（RTG-SLAM Sec. 3.2，S3 核心實作）

**動機**：block_6 depth S3 PLY（484K → 65K）實驗的「幾何崩塌」根因並非 Gaussian 數量下降（RTG-SLAM 設計本就傾向緊湊表達），而是 `opacity_reset_interval=2000` 在 30k 步中共重置 15 次，每次都把尚未穩定的 Gaussian 透明度清零然後被 prune 掉。

**解方**：追蹤每個 Gaussian 的信心計數器 `eta`，只對未穩定（eta < stable_threshold）的 Gaussian 執行 opacity_reset 和 opacity-based pruning。

**新增檔案**：`internal/density_controllers/rtg_stable_density_controller.py`

```python
@dataclass
class RTGStableDensityController(CityGSV2DensityController):
    stable_threshold: int = 10  # 10 × 500 = 5000 steps to become stable
```

核心機制：
- `eta` buffer（`torch.long`，per-Gaussian）：每次 densification_interval 觸發時 +1
- `_stable_mask`：`eta >= stable_threshold`（boolean mask）
- `_reset_opacities()`：穩定 Gaussian 跳過 opacity reset（保留原 logit-opacity）
- `_densify_and_prune()`：`prune_mask &= ~_stable_mask`（穩定 Gaussian 免疫 opacity-based 剔除）
- `_prune_points()`：`self.eta = self.eta[~mask]`（同步移除被剃除 Gaussian 的 eta）
- `_densification_postfix()`：既有 Gaussian 保留 eta，新增 Gaussian 歸零
- `_densify_and_clone()`：複製子女**繼承**父 eta（RTG-SLAM 能量守恆）；split 子女保持 eta=0（重新積累）
- `on_load_checkpoint()`：舊 checkpoint（無 eta 欄位）一律設為 stable_threshold（視為已穩定）

**拓撲規則**（符合 ADMM 對偶變量規範）：
| 操作 | eta 繼承 |
|------|---------|
| Clone | 子女繼承父 eta（能量保留） |
| Split | 子女 eta=0（重新累積） |
| Prune | eta 條目移除 |

**更新 configs**：

兩個 config 的 `density.class_path` 由 `CityGSV2DensityController` 改為 `RTGStableDensityController`，並加入 `stable_threshold: 10`：
- `configs/RTG_mc_aerial_sh2_trim24.yaml`（depth-init 專用）
- `configs/RTG_mc_aerial_sh2_trim24_coarse.yaml`（coarse-init 專用）
