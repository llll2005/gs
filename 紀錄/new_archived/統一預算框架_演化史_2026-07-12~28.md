## ★★封閉預算公式（2026-07-13，取代反應式 λ，已實測驗證）
反應式 VRAM-λ 會抖/滯後 OOM（Path b smoke K=1 在 1.70M OOM,λ 全程 0 沒反應）。改成**預測式封閉解**:
```
N_max = (V_target − V_os) / (M·F·4 + γ·τ/K)
```
- V_target=硬體目標(6GB→安全 5.4×0.9=4.86,吸收碎片化)、V_os=OS+CUDA context、F=每點 floats(sh3=59)、
  M=狀態倍數(params+grad+2Adam=4)、γ=每相交 bytes、τ=最壞視角每點 tile(用 MAX 非 EMA,防怪物突襲)、K=tiling。
- **b12 校準（calibrate_budget.py,2026-07-13）**：V_os=0.718G、V_model@1.21M=1.065G、**γ=23B/相交、τ_mean=30.5/τ_MAX=73**(b12 overdraw 量化)。
- **★公式驗證**：預測 **K=1 N_max=1.70M**——Path(b) smoke 實際就死在 1.70M。零校準純算命中=公式對。
- **N_max 表**：K=1→1.70M / K=2→2.50M / K=4→3.26M / **K=8→3.86M(≈b7 的 4M)**。→ **K 把 b12 天花板從 1.70M 抬到 3.86M,病理塊追平乖塊。**
- **高 K 時模型狀態主導**(K=8:render 210B/pt vs model 944B/pt)→ **Adam-offload(M:4→2)** 代入 K=8 → N_max≈6.5M(超 b7)。
- **三桿統一在分母**：K↑(render 項)、M↓ offload(模型項)、F↓ sh0(模型項)。budget 不猜不伺服,直接算。
- **λ 降級**：只清 value≈0 真廢點(免費 floor,KKT: 約束不緊時 λ=0),不當預算執法者。
- **Gemini 三工程 caveat(皆採納)**：(1)碎片化→V_target×0.9;(2)τ 用 MAX 非 EMA(怪物一步暴增);(3)densify 暫態峰值→add gate 留 buffer。
  ⚠我方 nuance:別為偶發怪物把 N_max 設超保守(永久壓顆數),用 K 綁尖峰+condemn 清怪物讓 τ 穩,再算 N_max。
- **★凍結測試揭露漏洞（2026-07-13,freeze_b12_K2）**：K=2 cap2.5M 在 **~1.8M 就 OOM**（isect_tiles,allocated 5.19G,沒到 cap）。
  死因=**τ 在訓練中長大**:init 校準 τ_MAX=73(depth-init 小高斯),訓練後高斯攤開 τ 漲到 ~120→render 緩衝 γτN/K 爆。
  +radix sort 暫存(~2×相交陣列)沒完全進 γ。→ **static 公式用 init-τ 偏樂觀,K=2 只撐 1.70M→~1.8M 沒到 2.5M**。
  **驗證 Gemini caveat #2 + 需要動態 τ 追蹤(calibration step2)**。**修法**:(a)訓練中週期量 τ_current 重算 N_max 凍結在動態值;
  (b)直接用更高 K(4/8)留 render 餘裕吸收 τ 成長。**公式框架對(K=1 預測 1.70M 命中),但 τ 必須 live 追蹤非 init。**
- **★★★關鍵負結果:b12 更多點無益(2026-07-13~17,K8 v2-v5 迭代)**：K=8 tiling **技術成功**(馴服 OOM、衝 1.94M 顆、吃 97.9M 相交怪物 peak 僅 3.35G→供給側 K 綁 render 在最難塊驗證)。
  **但品質沒兌現**:b12 單塊同尺規 beta 500k=21.83 vs **K8 1.37M/60k/+depth+normal reg=21.52、v4 1.94M→920k=21.59**。**4 倍顆數+60k 步+幾何正則→PSNR 反降**。
  → **翻掉核心前提「b12 落後=顆數餓死,給更多點就追上 b7」**。b12 ~4.8dB 缺口**不是 count 問題**=b12 內容天花板(近相機怪物視角/高 overdraw/難幾何)。
  **動態天花板+ω=2.0 風險溢價+ceiling 強制賣=淨負**:做成 churn 相反效果(v4 1.94M 被賣到 920k,λ 全程 0=maxcost ceiling 毀滅性拋售非市場機制),點一直賣→長→賣 settle 不下來。
  Gemini「幾何正則突破 25」也沒兌現(開了還是 21.5)。**含意:tiling 只關 count 缺口未關 quality 缺口;需(a)換 count 真受限的塊驗證 或(b)改攻 b12 為何 quality-capped(怪物視角本身)。**
  **⚠2026-07-17 使用者抓出 confound,結論修正**:上面「更多點無益」是**跨 kernel 比較**(21.83=beta@500k vs 21.5=gsplat@1.9M vs 22.45=trim@1.0M),不乾淨。
  乾淨的說法只有:(1)**在 gsplat 線上**加點無益;(2)**kernel 品質主導 b12**(trim 半數顆數贏 gsplat)。**同 kernel count ablation 在 b12 從未做過**
  (trim/beta 推高 count 會 OOM,當時無 K 護體)→「b12 更多點有沒有用」=**開放問題**。驗證路線=trim+SB color(最強 kernel+F 槓桿)推高 cap 對照 22.45@1.0M。

## 核心不等式（一條主判別式）

記號：
- `c_iv` = 高斯 i 在視角 v 覆蓋的螢幕 tile 數（渲染成本 = tiles_per_gauss = 共同貨幣）
- `v_i`  = 高斯 i 的價值（目前實作用 opacity）
- `c_i = sum_v c_iv`（跨視角總成本），實作用 EMA `ĉ_i`（見下）
- `B`    = rasterizer 記憶體預算（≈ 6GB − 固定 params）
- `K`    = tiling 條帶數（1 = 不分塊）
- `lambda` = 預算的影子價格（拉格朗日對偶變數）

```
可行(不 OOM)  <=>  對所有視角 v：  (1/K) * sum_i [ c_iv * 1(v_i/c_i >= lambda) ]  <=  B
                                            └─ tiling 加供給 ─┘  └─ cost-aware 減需求 ─┘
```

兩個對偶旋鈕作用在同一個量 `sum c_iv`（相交負載）上：
- **lambda（演算法貢獻）**：丟掉 v/c < λ 的點 → 減需求
- **K（系統 enabler）**：相交量分攤到 K 條帶 → 加供給（route 2 用 camera-crop 偽造子視窗）

## 影子價格更新（cost-aware 引擎）

```
lambda <- max(0, lambda + eta * ( sum_i ĉ_i / B  -  1 ))
```
超預算 λ 升→門檻高→丟更多；有餘裕 λ 降→允許長更多。取代硬 cap_max。

## ★三層 λ 決策階層（我方修正 Gemini 的「λ vs K 二選一」）

Gemini 把 prune 一律當「不可逆品質損失」→ 錯。**實測**：importance-prune 砍 50% 零 PSNR 損失
→ **冗餘 floor 以下的 prune 是免費的**。正確階層：

```
1. λ_floor：無損丟廢點/怪物（免費，永遠先做）        [cost-aware 的免費區間]
2. K：把「真需要但擠不下」的殘餘攤開（時間成本）      [tiling]
3. λ_budget：K 撞到 K_max 才動（唯一有品質成本，最後手段）
```

## ★K 逐步 / λ 週期（理論⇄b12 實驗收斂）

- **K = per-iteration 即時防禦**（每次 render 都 tiled）——擋單幀怪物 OOM
- **lambda = 週期性調節**（densify 事件）——清理累積的廢點
- 這正是 b12 慘案教訓：事件層回收（週期）攔不住單幀怪物 → 需 render-time（逐步）防禦。
  理論與踩坑收斂到同一句話。

## Novelty（★2026-07-12 我方聯網 G2 查證,讀原文,取代 Gemini 空真空宣稱）

**不是「絕對真空」——Pocket-SLAM 是真正最接近前作,必須引用+差異化。** Gemini 論文引用是真的(Pocket-SLAM/HiGS 已驗證存在),但它低估了 Pocket-SLAM。

- **Pocket-SLAM（arXiv 2606.24796,2026-06,3DGS-SLAM）= 最近鄰**（讀了方法章 III-B/C）：
  - Rendering-area 度量 `C_i=Σ_p α_i(p)`(opacity 加權像素覆蓋)、`S_i=C_i/ΣC_j`,按 S_i **保留** top-B_k。
  - Tile-Level Budget:按梯度 G_k 分配每 tile **保留顆數**上限(固定配額 N_tar)。
  - **我方差異化 4-5 軸**：(1)area=**價值(覆蓋大=保留)** vs 我們 c_iv=**成本(相交多=審查)**——方向相反;
    (2)opacity 加權覆蓋 vs tile 相交數(VRAM 代理);(3)固定顆數**配額** vs 影子價格 **λ 市場**;
    (4)他們 tile=空間配額分箱 vs 我們 K=光柵化**記憶體分塊(供給旋鈕)**;(5)SLAM post-hoc vs 訓練期即時防禦。
  - **★殺手級反例=近相機怪物**：怪物覆蓋大→Pocket-SLAM C_i 大→S_i 高→**它保留怪物(判重要)**;

- **HiGS（arXiv 2606.00352）**=推論期 tiling 加速(macro/render-tile 解耦,15.8×)=非 budget 耦合,差異化成立(推論速度 vs 訓練記憶體)。

## 對論文的定位

- **一條預算不等式 + 兩個對偶旋鈕**壓縮整個 6GB 故事：λ 花預算（省無用顆數）、K 擴預算（攤有用的）。
- cost-aware = 演算法貢獻（定 λ、留哪些點）；tiling = 系統 enabler（定 K）；`c_iv`(螢幕成本)=縫合兩者的共同貨幣，也正是 MCMC 三層約束(cap/opacity/scale L1)從來沒有的量。
- 把過去 densify 的「玄學調參」變成可證明的資源分配問題。

關聯 [[cost-aware-theory]]、[[project_direction]]、[[dev_cycles]]。

## ★K 的文獻定位 + VRAM 槓桿候選（2026-07-22，論文 related work + 下一步）
NeRF/3DGS 文獻裡與 K 的關係（related work 必答「有沒有先例」）：
- **NeRF ray/pixel chunking = K 的靜態祖先**：NeRF 天生 ray-parallel，chunk 是手設超參且切開無損（ray 獨立）。
  我方進步 = **動態（每步反解預算公式定 K）+ 在 splat-coupled 2DGS 上做無損（per-strip backward+h/H 加權處理條帶邊界梯度）**。
- **Instant-NGP hash / occupancy** = 打預算公式的 F（每點 floats）和 N（跳空區），與 K 正交、可疊加；對怪物無效（怪物不在空區）。
- **稀疏體素/八叉樹（Plenoxels/NSVF/PlenOctree）** = 打 N，=空間分塊同類，防不了投影層怪物。
- **Deferred per-tile backward** = 更細粒度的 K（2D tile vs 我方 1D strip），負載均衡更好，**更強但要改 CUDA**（我方 K 是純 Python route-2）。→ 使用者要試（1D→2D）。
- **★Gradient checkpointing** = 打我方實測的 OOM 主因「backward activation ∝ N」，機制不同（換時間重算 vs K 切空間），**與 K 正交可同時開**。可能讓 2M 不靠 K 也活/讓 K 需要條數更少。→ 正交先實作。
三個實驗軸：(a) K 單獨、(b) checkpointing 單獨、(c) 兩者協同。先 CPU 標定峰值再上 GPU。

## ★★動態 K 估計器：完整理論（2026-07-24 定稿，理論部分已驗證；b12@2M 訓練驗證進行中）

動態 K 的核心 = 每步用當前幾何**預測峰值 VRAM**，反解出「剛好不 OOM 的最小 K」。成敗全繫於這個
峰值預測準不準。以下是完整推導與兩次修正。

### 1. 峰值 VRAM 模型（標定得出）
單步 forward+backward 的峰值 VRAM 拆成「K 砍不到」與「K 能砍」兩塊：
```
peak(N, load, K) = [ model_state + A·N ]          ← fixed, K 砍不到
                 + [ B·N + γ·load ] / K            ← splittable, per-strip backward 分攤
```
- `model_state = N·F·4·M`：params+grad+2 Adam（M=4）。SB F=25 → 1.45M 才 0.54G（小頭）。
- `A·N`：per-N 的不可分攤 render 成本。
- `B·N`：**backward activation，∝N**——這是漸進 OOM 的主因，per-strip backward 釋放它故 K 能砍。
- `γ·load`：binning buffer，∝相交數，γ≈24 B/相交（含 CUB radix double-buffer）。
- **標定值（b12 SB，calib_peak.py）**：A≈500、B≈1550 B/pt。驗證 K=1→2.63G / K=4→1.14G（實測吻合）。

### 2. K 決策（預算不等式反解）
```
budget = safety · (V_target − V_os)          safety=0.6, V_target=5.4G, V_os=0.8G
room   = budget − (model_state + A·N)         ← fixed 之外的可用空間
K      = clip( ceil( (B·N + γ·load) / room ), 1, K_max )
若 room ≤ 0 → K_max（fixed 已逼近預算，全力分攤）   ← 邊界守衛，已在碼中
```
這就是封閉預算公式 `N_max=(V−V_os)/(4MF+γτ/K)` 對 K（而非 N）求解。**N_max 與 K 是同一條 VRAM
約束的對偶變數**——傳統 3DGS 把 N_max 當靜態約束，我們證明它有個對偶供給桿 K 可即時求解。

### 3. load 估計的兩次修正（關鍵）
`load` = 全幀 tile 相交數，用純投影估（不渲染，O(N) GPU）。歷經兩次修正才對：
- **v1 錯（量錯維度）**：只預測 binning load（∝相交），漏掉 B·N（backward activation ∝N）→ 全程判 K=1
  撞死。**教訓：OOM 主因是 activation 不是 binning**。→ 修成 §1 的完整峰值模型。
- **v2 錯（近軸近似）**：`r=3fx·s_max/z` 是**近軸近似**，漏掉**離軸透視 Jacobian 拉伸**。離軸點的 2D
  bbox 被投影矩陣放大 `×sqrt(1+(x/z)²+(y/z)²)`。日常低估 1.35×、離軸極端怪物低估達 10×（那顆被
  AABB frame-clip 誤判成畫面外小圓 → 0 tiles，實際是掃進畫面的長條）。
- **v3 對（Jacobian 拉伸修正）**：
  ```
  stretch = sqrt(1 + (x_cam/z)² + (y_cam/z)²)
  r = 3·fx·s_max/z · stretch
  ```
  這是**物理光學項不是魔術常數**：同時修好日常偏差與尾部突波。**驗證（est-vs-real, b12 死點 ckpt）**：
  加拉伸後 16 視角比值從「低估 1.35×」翻成「保守過估 1.5×（0.26-0.90×，全部 est≥real）」→ 估計器
  成為**安全上界**，K 只偏大不偏小，OOM 風險消除。代價：偏保守可能拖慢（過估視角多切條帶）。

### 4. 現狀與定位
- **理論部分已驗證**：峰值模型（K 砍 render 有效，VRAM 三桿表）、Jacobian 拉伸（est-vs-real 保守上界）。
- **🟡 進行中**：stretch 版 dynamic-K 能否讓 b12@2M 活到 60k（前兩版估計器低估→死於怪物區）。
- **論文貢獻定位**：這不是「偵測怪物」，是「把 render 峰值估準（含透視拉伸物理項），讓對偶供給桿 K
  每步自適應」。b12 = scenario S（瀰漫 overdraw 無單一巨獸），證明**基於半徑的怪物偵測是死路**（詳廢案），
  正解是**準確的峰值預測 + 對偶 K**。工具 predict_monster_defense / measure_vram_levers / calib_peak / verify_stretch。

## ★★主判別式的價值訊號升級：v_i 從 opacity → 多視角渲染貢獻（2026-07-25，理論定案待驗）

### 1. 問題：我們的命題原本是不對稱的
主判別式 `v_i/c_i ≥ λ` 兩個量的性質不對等：
```
c_iv = tile 覆蓋數       ← 我方補的成本訊號，render-grounded ✓
v_i  = opacity           ← 價值仍是「內在屬性」，跟被我們批評的現有方法同級 ✗
```
我方命題是「現有密度控制盲於渲染成本」，但我們只補了成本、**價值仍停在 opacity**。
這是理論上的不對稱：**批評別人用內在屬性定價，自己的價值項也是內在屬性。**

### 2. 正解：v_i = 多視角 alpha-blending 貢獻（render-grounded）
trim rasterizer 的 `record_transmittance` 路徑（forward.cu:405）在 CUDA 內累積：
```
transmittance[i] += T · α_i     (每個覆蓋像素)
num_covered_pixels[i] += 1
→ renderer 端正規化: contribution_i = Σ(T·α_i) / num_covered_pixels
```
`T·α_i` **正是渲染方程裡該高斯對該像素的實際貢獻權重**（T=累積穿透率、α=該點不透明度）。
跨全視角累積（`SepDepthTrim2DGSRenderer.after_training_step` 的 `top_list` 已在做）即得
**每高斯的多視角實際渲染貢獻**。→ **訊號現成，免改 CUDA。**

升級後的判別式：
```
v_i / c_i = [多視角 Σ(T·α)/覆蓋像素]  /  [tile 覆蓋數]
            └── render-grounded 價值 ──┘   └─ render-grounded 成本 ─┘
          = 「實際渲染貢獻 / VRAM 成本」= 真正的經濟量（類比 營收/成本）
```

### 3. 為何這能抓到 opacity 抓不到的病理（關鍵論證）
| 點類型 | opacity 判準 | v/c（貢獻/成本）判準 |
|---|---|---|
| 霧（o~0.02，占 binning 82%）| 低 → 殺 ✓ | 貢獻低、覆蓋大 → v/c 極低 → 殺 ✓ |
| **近相機怪物（o=0.028）** | **逃過**（0.028 不算低）✗ | **c 爆大（蓋滿全幀）→ v/c 極低 → 殺** ✓✓ |
| 真表面（o>0.9，占 binning 0.3%）| 高 → 留 ✓ | 貢獻高、覆蓋小 → v/c 高 → 留 ✓ |

**這正好補上我們一直抓不到怪物的根因**：怪物的病理不在 opacity（它不低），而在「成本爆大而貢獻有限」
——只有 v/c 這個比值抓得到。同時它也殺霧（binning 82% 的來源）→ **一個判準同時解怪物與霧**。

### 4. 與 FastGS 的關係（CVPR 2026, arXiv 2511.04283）
FastGS 用「多視角一致性」算 pruning/importance score 控制高斯數，宣稱 2-6× 訓練加速——
**它的洞察正是「價值要 render-grounded（實際被多少視角用到），不是內在屬性」**，與本升級同源。
差異：FastGS 只有價值側（用它剪冗餘加速），**我方是價值×成本的比值**（v/c，且成本是 VRAM-grounded）。
FastGS 需其自訂 CUDA（`accum_metric_counts`）+ 3DGS 底座；**我方用現成 `record_transmittance` 即可，
免 CUDA、留在 2DGS/trim 底座**。→ 可引用為「價值 render-grounded」的旁證，我方切割點=成本側與比值。

### 5. 狀態
- 🟡 **理論定案、實作待做**：判準改 v=多視角貢獻（訊號現成）。
- 實作要點：貢獻需跨視角累積（沿用 trim 的 `top_list` K-worst 機制或 EMA），成本 c 用現有 tile 估計。
- 驗證設計：b12 上比較 (a) opacity 判準 vs (b) v/c 貢獻判準——看能否自動殺掉怪物與霧
  （→ binning buffer 降、b12@2M 可行）且 PSNR 不掉。

# ★★★ 統一框架：VRAM 預算的拉格朗日對偶 × DAR 解耦（2026-07-28 定稿，論文方法章骨架）

> 這一節把整個專案的機制（cost-aware / 動態 K / 清塵 / 閥門 / 凝結）收斂成**一個約束最佳化問題**，
> 並把前人工作寫成本框架的特例。理論已推導完，🟡 尚未實驗驗證。
> 促成：使用者要求「參考 AdamW-GS 的精神統一我們的公式」（讀 `參考論文/adamW.pdf`, ICLR 2026, arXiv 2601.16736）。

## 1. 問題重寫：帶資源預算的約束最佳化
```
min_θ   ℓ(θ)                                光度損失
s.t.    Σ_i c_i · 1[點 i 存在]  ≤  B          VRAM / render 預算
```
指示函數不可微 → **用 opacity 當「軟存在指示」**（o_i ∈ (0,1)）鬆弛：
```
min_θ  ℓ(θ)    s.t.   Σ_i c_i · o_i  ≤  B
```
拉格朗日與其對 opacity 的梯度：
```
L = ℓ(θ) + λ ( Σ_i c_i o_i − B )
∂L/∂o_i = ∂ℓ/∂o_i + λ · c_i          ← 正則梯度 = 影子價格 × 該點成本
```

## 2. 統一：現有方法都是此式的特例
```
MCMC 標準 opacity L1:   R = λ_o Σ_i o_i       ⇔  c_i ≡ 1    （成本盲：每顆點計價相同）
本框架 cost-aware:      R = λ   Σ_i c_i o_i   ⇔  c_i = 渲染成本
```
**「顆數是錯的計價單位」從口號變成數學上的特例關係**（c_i≡1）。這是本專案主命題的形式化。

## 3. 加上 DAR 的解耦 → 最終統一更新式
AdamW-GS 教的兩件事：(a) 別讓 ∇R 進 Adam 動量（否則係數被 m/√v 吃掉）、(b) 用 1/√v̂ 預條件。
把 c_i 代入其 Eq.8：
```
θ_{t+1} = θ_t − η [  m̂'_i /(√v̂'_i + ε)                          ← 動量只吃 ∇ℓ（DAR 解耦）
                   + min( λ · ĉ_i /(N_I·√(v̂'_i+ε)) , C_t ) ]      ← cost-aware 正則
                            └成本┘ └1/邊際效用┘        └clip┘
λ ← max(0, λ + η_λ (V_pred/V_target − 1))                        ← 對偶上升，V_pred 用我方峰值預測器
```
**運籌學讀法**：`c_i`=資源價格、`1/√v̂'_i`=邊際效用倒數、`λ`=約束的影子價格；
**KKT 互補鬆弛 ⇒ VRAM 未撞頂時 λ=0（零懲罰），只有預算緊了才收費**。
壓力 = 價格 × 數量 / 效用 = 完整的市場定價。

## 4. 兩個可測預測（同時解掉我方兩個病理）
| 點型 | c_i | √v̂'_i | 壓力 | 預測 |
|---|---|---|---|---|
| 次像素塵埃 | 極小 | 小 | **變小** | **不再每 64 步被推過死亡線 → 63% 跑步機萎縮** |
| 近相機怪物 | 爆大 | 中 | **爆大** | **快速死亡**（DAR 做不到：它 c_i≡1 且怪物有光度梯度受保護）|
| 真表面 | 小 | 大 | 極小 | 受保護 |
且此式**每步連續作用**（走 optimizer），解掉「怪物在 150 步事件間隙內長成」的時序問題。

## 5. 實務修正（Gemini 三點，全採納）
1. **c_i 尺度壓縮防 NaN**：radii² 在怪物上可達正常點 1e4~1e5 倍 → 直接代入會爆。
   用 **`ĉ_i = c_storage + log1p(r_i² / median(r²))`**：對數壓縮保單調、中位數自正規化。
   ★`c_storage`（常數項）**有物理意義**＝每點的 model-state 人頭稅（F·4·M bytes，與螢幕足跡無關）
   → 塵埃仍有緩慢衰減壓力（不會像 reg=0 那樣無限膨脹），與我方早先「storage_cost」洞見一致。
2. **λ 先靜態、後動態**：對偶上升在 SGD 上易震盪（PID 式）。第一版固定 λ 驗證機制（兩個預測），
   確立後才接 `V_pred` 自動化（那時它就是「自動預算控制」）。
3. **二階項 detach**：`∂c_i/∂o_i ≠ 0`（trim 的 TIGHTBBOX 讓半徑含 log(o)）但小 → `c_i.detach()`，
   論文 Implementation Details 註明「將資源成本視為當前步外部給定常數」（運籌學常規做法）。

## 6. 成本項的兩層壓縮 + 一個被否決的借用（2026-07-28，CPU 實測）

Gemini 提了兩個修正，**一個採納一個否決，都用實測（b12@30k, 1M 點）判定，不用論證判定**。

### ✅ 採納：物理上限截斷（Rasterizer 的成本天花板）
學理：一顆 splat 再大，光柵化成本**不可能超過整張畫面**（tile/pixel 數有限）。所以 `r²` 夾在
螢幕對角線² = `H²+W²`（1600×900 → 3.37e6）。

必要性比預期嚴重得多——**投影 Jacobian 在 z→0 是奇異點**，z~0.02 的 surfel 會報 `r²~1e16`，
那是數學假象不是成本：

| | 原始 | log1p only | **截斷+log1p** |
|---|---|---|---|
| r² 動態範圍 | **5.8e11×** | — | **52×** |

### ❌ 否決：2DGS 扁平率折扣 `min(s)/max(s)`
提案動機（借 2DGS 的「真表面會演化成扁盤」先驗）合理，但**對我們的模型不成立**：
我們的 surfel `scales` 是 `[N,2]`，**第三軸恆等於 0 → 扁平度不是自由度**，取 min/max 只是
量「面內長寬比」。實測四個族群完全不分離，而且**方向是反的**：

| 族群 | min(s)/max(s) 中位 |
|---|---|
| 大足跡 r>2000px（要罰的）| **0.852** ← 最圓 |
| 正常 10–300px | 0.835 |
| 塵埃 o<0.01 | 0.841 |
| **高不透明 o>0.7（要保的）**| **0.786** ← 最扁 |

→ 那個乘數會**罰真表面比罰怪物更重**。這是「3DGS 的直覺不能無腦搬到 2DGS」的具體案例，
值得寫進論文的 discussion（我們的表示法選擇改變了哪些先驗可用）。

### ⚠ 真表面保護的真正來源＝`C_t`，不是成本項
Gemini 正確指出：純色平坦區（白牆）光度梯度→0 ⇒ `√v̂`→0 ⇒ `1/√v̂` 爆掉 ⇒ 真表面被撕洞。
`ĉ` **無法**保護它（真表面的 ĉ 實測 2.70 > 1，比 c≡1 還重）。唯一的防線是 clip：

```
t_death >= Δlogit / (lr_o · C_t)          Δlogit = 5.29  (o: 0.5 → 0.005)
  C_t=1.0  →  106 步   ← 與死亡跑步機同速, 白牆會被殺穿
  C_t=0.1  → 1058 步   ← 7 個 densify 週期, 有梯度防守就活得下來  ← 採用
```
所以 `C_t` 在我們的框架裡是**速率上限＝保證最短存活時間**，有封閉的選法，
不是 AdamW-GS 原文那樣的「數值安全常數」。這是我方對 DAR 的一個小補強。
