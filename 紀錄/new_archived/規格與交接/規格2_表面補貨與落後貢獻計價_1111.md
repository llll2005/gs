## 0. 為什麼做這個（概念）
- 地下那幾層是在**替路面層補貨**：路面層有縫，顏色從縫漏下去由地下層接住。
- 深度上限＝對地下顆粒課稅；「搬走地下顆粒」＝直接砍供給方。兩者都讓路面**缺貨** => 畫質跟著劑量掉（`37` §3.1；`31` §4.7）。
  規格 1 §5 已排除「顆粒被推過頭浮在路面上方」（0.19 → 0.30 層）。「缺貨」目前是排除法得到的，逐像素誤差拆解（lab `logs/cap_error_split_1111_b1.log`）出來要補進 `37`。
- **順序反過來：先在表面補供給，再對地下的課稅。** 兩個機制：
  - **A 需求地圖補貨**：某像素有多少顏色靠「表面後面的顆粒」在撐＝那個像素的表面缺多少 => 增生時把新顆粒直接放在這些像素的正確表面上。
  - **B 落後貢獻計價**：每顆的貢獻拆成「落在表面上的」與「落在表面後面的」，後者不算價值 => 併進 V/C 剪枝與 MCMC 抽母點。
    這取代規格 1 的 behind 票（用顆粒中心投票，16 種變體沒有一種兩塊都過：往下看時深度差太小、斜看牆面被放大，`37` §6）。
    用的是每顆**實際混合出的力**：被擋住的沒出力就沒有帳，斜看牆面用交點深度不會被放大。
- 經驗依據：成本的概念用在**剪枝端**有效、用在梯度與取樣端沒效（`研究總覽` §1）；「改變集合」有效、「打壞集合」無效。

## 1. 光柵器（一次重編做完；`submodules/diff-surfel-rasterization-trim-pp`）
現況（commit b615d6f）：完整路徑（forward MODE 0／backward GEOM）在設了上限圖 `depth_cap`（icap＝1／((1+margin)·z_先驗)，0＝不設）時，
`out_others[CAP_OFFSET=8]`＝B(p)＝Σ T·α·max(z·icap − 1, 0)。lean 路徑沒有動。
要加的（都只在「完整路徑且設了上限圖」時作用；**沒設上限圖時所有既有輸出要逐位元不變，lean 路徑一個字都不要改**）：
1. **逐像素落後權重** `out_others[9]`：W(p)＝Σ_i T_i·α_i·[z_i·icap(p) > 1]（落在上限後面的混合權重總和；不乘超出量）。不需要梯度（backward 忽略這個通道即可，Python 端 detach）。
2. **逐顆兩筆帳**（不可微、forward 內 atomicAdd；P 顆各一個 float）：
   - `Vc_i` ＋＝ T_i·α_i，只在 icap(p) > 0 的像素（＝這顆在「有可靠表面深度的像素」上的總貢獻）
   - `Vb_i` ＋＝ T_i·α_i·[z_i·icap(p) > 1]（其中落在表面後面的部分）
   累加位置與現有混合同一處（alpha >= 1/255、未飽和之後），和 B 的 `depth*icap` 判斷共用。回傳方式由實作者決定（重用 `transmittance`／`num_covered_pixels` 那兩個逐顆輸出或另開兩個），Python 端要拿得到本步的 `Vc`、`Vb`。
3. Python 包裝：有 `depth_cap` 時多回傳／可取得這兩個逐顆張量（標 non-differentiable）；`DEPTH_CAP_SUPPORTED` 旁加 `DEPTH_CAP_ACCOUNT_SUPPORTED = True`，呼叫端沒重編要當場報錯。
4. **檢查**（擴充 `tools/check_depth_cap.py`，本機 4050 與 lab 都要過，重編前先 `base`）：
   - `cmp`：沒設上限圖 => 渲染、前 8 個通道逐位元相同，梯度差在重跑雜訊內（現在約 1e-9）。
   - 設了上限圖 => 前 9 個通道（含 B）與 b615d6f 逐位元相同；Σ_p W(p)·[icap>0] ≈ Σ_i Vb_i；Σ_i Vc_i ≈ Σ_{icap>0} (1 − T_final)（差在 1e-4 相對內）；上限放很寬時 W、Vb 全 0。
   - 計時：完整路徑步有上限圖時 forward 增加多少（印出來；目標每步平均 < +1%，因為完整路徑只佔 1/8 的步）。

## 2. 機制 A：需求地圖補貨（改 `_hole_fill`，`internal/density_controllers/mcmc_2dgs_density_controller.py`）
- 現有補洞放點（`hole_fill_frac`）用「α < 0.5 或渲染中位深度比先驗深 margin」找像素 => 地下層躲在中位深度已對的貼地層後面，幾乎找不到（`trihf` 持平）。
- 新開關 `hole_fill_demand: bool = False`。開的時候，補洞事件那一步：
  - 候選像素＝塊外遮罩 A、先驗深度有效（可靠度過濾後 > 0）的像素；**依 W(p) 當機率抽**（缺越多抽越多；W 全 0 就不放）；另保留原本的「α < 0.5 的洞」。
  - 放的位置、朝向、大小、顏色、不透明度沿用現有程式（沿視線放在先驗深度、朝先驗表面法向、顏色取 GT）。數量上限沿用 `hole_fill_frac`。
  - 名額來源沿用現有規則（死顆粒優先，不夠用 opacity < 0.05 的），**不動 cap、不刪活的不透明顆粒**。
- 補洞事件步要有 W：`metric.depth_cap_map()` 在「補洞事件步」也要回傳上限圖（即使那一步不算 loss——loss 仍照 `depth_cap_interval`）；`depth_cap_reg = 0` 但 `hole_fill_demand` 開時也要能單獨運作（只出地圖、不加 loss）。
- 可觀測性：首次與每 2000 步印——有上限的像素比例、W 平均、W > 0.05 的像素比例、這次放了幾顆。拿不到 W 印一次 ⚠⚠。
- 測試：W 全 0 不放；抽樣集中在 W 大的像素；關閉時行為與現在相同。

## 3. 機制 B：落後貢獻計價
逐顆累加器（density controller 或 renderer 擇一處持有；顆數增減、搬家、合併時要跟著維護——搬家／新生的顆粒歸零）：`Vc_acc`、`Vb_acc`，每個完整路徑步累加本步的 `Vc`、`Vb`。
落後比例 ρ_i＝Vb_acc_i ÷ Vc_acc_i；**證據不足的一律 ρ＝0**（Vc_acc_i 小於「全體 Vc_acc 中位數的某個比例」，預設 0.1；這是相對量，不是場景單位）。
- **B1 併進 V/C 剪枝**（renderer `trim_running_vc` 的打分處）：開關 `trim_behind_price: float = 0.0`（λ）。分數＝(V/C)·max(1 − λ·ρ, 0)；λ＝1 即「落在表面後面的貢獻不算價值」。
  每次 trim 用完**不要**把 `Vc_acc／Vb_acc` 歸零（V/C 的累加器照舊歸零）；改成指數衰減（每次 trim 事件乘 0.5）讓它跟得上顆粒移動。
- **B2 併進 MCMC 抽母點**（`add_new_gs`／`relocate_gs` 的機率）：開關 `sample_behind_price: float = 0.0`；機率再乘 max(1 − λ·ρ, 0.01)。
- 不做的事：不因為 ρ 高就刪或搬（規格 1 與 `31` §4.7 的教訓）；不關二元熵。
- 可觀測性：每次 trim 印——有證據的顆粒比例、ρ 的中位／p90、ρ > 0.5 的比例、這次被剪的裡面 ρ > 0.5 佔多少（對照沒計價時會剪的）。
- 測試：ρ 的計算與證據門檻；λ＝0 時 trim 與抽樣結果與現在逐位元相同；顆數增減後累加器對得上。
