## §3 理論：成本感知密度控制

### 3.1 統一形式（背包問題）

密度控制 ＝ `max Q(θ_S) s.t. (1/K)Σ c_i ≤ B`。
既有方法差別只在**價值訊號 `v_i`**（梯度／貢獻／opacity），**`c_i` 幾乎都是 1**。

**⛔ 但「所有既有方法都是 `c_i ≡ 1`」這句話不成立，必須改寫**——RAIN-GS 的
`s = HW/(9πN)` 就是「每顆的螢幕預算」。精確的區別：

| | RAIN-GS | 我方 |
|---|---|---|
| `c_i` 角色 | 由粗到細的**優化排程下界** | 逐顆的**實際成本** |
| 逐顆差異 | **無**，每顆同一個 `s` | 有 |
| 綁在什麼上 | 顆數 `N`（自我調節） | **硬體 VRAM 預算 `B`** |
| 解的問題 | 學習頻率順序 | 資源約束最佳化 |

⇒ 貢獻表述為「**把螢幕足跡從優化排程提升為資源約束，並逐顆計價**」。

**三個誠實邊界**：背包涵蓋不了「長」（成長需要不存在之點的邊際價值）／價值不可加
（alpha-blending 次模）／預算非靜態。

### 3.1.1 ★修正（2026-08-06）：這不是背包，是**帶預算的覆蓋問題**

上面那個式子把品質當目標、成本當約束，然後自然導出「按 value-per-cost 排序再切」。
**五條剪枝曲線的實測說那個導出是錯的**（見 §5.2.5）：贏的 `count` 幾乎就是 `c_i` 本身，
按它遞減保留 ＝ **保留最貴的**，與 v/c 完全相反。

正確的結構是**覆蓋為硬下限**：

```
max Q(θ_S)   s.t.   (1/K)·Σ_{i∈S} c_i ≤ B        （預算）
                    coverage(S) 完整               （下限，不可交易）
```

「在所有能蓋滿場景的子集裡，挑成本最低／品質最高的」——
**便宜與覆蓋完整不衝突，覆蓋是底線，成本是在底線之上才開始比的東西。**

**為什麼這個表述更強**

| 觀察 | 舊表述（純背包） | 新表述（覆蓋為約束） |
|---|---|---|
| `count`（≈ `c_i`）贏 | 矛盾：怎麼會保留最貴的？ | 它意外地在最佳化覆蓋 ✓ |
| v/c 剪枝「訓練側淨負」 | 只能記成負結果 | 它踩破了覆蓋下限 ✓ |
| `max` 居中 | 無解釋 | 保護「唯一蓋到某處」的粒子，部分維持覆蓋 ✓ |
| `sum` PSNR 高但紋理崩 | 無解釋 | 用少數大顆蓋滿＝覆蓋達標但解析度不足 ✓ |

**且它接上早已量到卻沒用起來的次模性**：`dim_returns_b12_reg000_FULL` 實測
「二階差分 contribution 8/8、random 7/8 全為正 ⇒ 邊際遞減」。
**集合覆蓋是次模最佳化的典型問題**，所以那個量測現在有了歸宿——
次模函數在背包約束下的貪婪／CELF 有近似保證，而「價值可加」的 LP 論證沒有。

⚠ **待改寫**：`archive/現行方案與公式.md` §8「v/c 門檻是 LP 最優解，不是啟發式」
建立在**價值可加**上。覆蓋顯然不可加（第二顆蓋同一塊的邊際價值近零，第一顆蓋空白的極高）
⇒ **那一節的論證不成立，需重寫為次模＋覆蓋約束。**

⚠ 全部證據來自**事後剪枝**（單一模型、兩種判官、五個工作點）。
訓練中的密度控制是否適用同一結構，未驗。

```

```

|---|---|---|---|
| v1 (24k) | 350 | 衰減 | ✓ 1.21M → 77.6k |
| reg000_exact | 150 | 成長 | ✓ 撞 cap 2M |
| oreg_0p002 | 150 | 成長 | ✓ 撞 cap 1M |

### 5.2.5 ★貢獻度判準的定案（2026-08-06，兩種判官、五個工作點）

事後剪枝 `oreg_0p002_b12`（900k），建築區紋理比：

```
             ── 訓練視角 ──          ── 官方 held-out ──
保留顆數    max   topk  frustum      max   topk  frustum
640,000    .368  .367   .367        .255  .254   .254
480,000    .357  .351   .351        .248  .245   .245
320,000    .339  .328   .329        .234  .228   .228
160,000    .303  .279   .284        .211  .197   .200
 80,000    .266  .236   .243        .188  .169   .176
```

**`max` 在兩種判官、五個工作點上全勝。** ⇒ `contribution_accumulator` 預設 `reduce="max"`。

**解釋**：max 保護的是**覆蓋**。一顆粒子在單一視角關鍵，是因為那裡沒有別人蓋到那塊；
刪掉就是一個洞，而那個洞在鄰近的 held-out 視角**一樣是洞**。
⇒ 「不要製造洞」勝過「偏好多視角一致的粒子」。

**兩個被否證的假說（都是我方自己提的）**：
- ❌「固定 top-K 輸是因為分塊邊緣被 0 稀釋」→ frustum-aware K 只回收 **20%** 的落差
  （合成案例上分離 3.6× 完美，真實資料上不是主因）
- ❌「max 適合重建、top-K 適合泛化，我們只量重建」→ **held-out 上排序完全不變**

⚠ held-out 樣本小（30 幀落在 b12 內、取 8 張），但五個等級兩種判官一致。
⚠ 全部量在**已完成模型的事後剪枝**上；訓練中 trim 反覆觸發，動力學未分離。

### ★★ 第四、五種判準：MVGSR 的尺寸感知（2026-08-06 晚間實測）

MVGSR §4.2 Eq.5 `C_MV = Σ_視角 Σ_像素 [T·alpha > δ]` 需要逐像素值，我方 CUDA 只回傳
平均與像素數 ⇒ 用兩個可算的極限代替：
`count` = Σ 覆蓋像素數（δ→0）　`sum` = Σ(每像素平均 × 覆蓋像素數)（總 T·alpha）

```
保留 80,000 顆（8.9%）的建築紋理比
                訓練視角      held-out
count            0.316         0.222     ← ★兩種判官都壓倒性最好
max              0.266         0.188
frustum_topk     0.243         0.176
topk_mean        0.236         0.169
sum              0.218         0.154

交叉點約在 320k：640k 時 max 略勝（.368/.255 vs .362/.250）
```

**`count` ＝ 尺寸 × 被幾個視角看到 ＝「總螢幕存在感」**，不看貢獻強度。
**為什麼贏**：紋理比是渲染梯度 ÷ GT 梯度，**空白區梯度為零會把比值拉下來**。
`count` 保證畫面被蓋滿；`max` 保留「某處峰值高」的粒子，那些可能擠在同一區。

**⚠ 與本命題的張力（必須處理）**：`count` 幾乎就是我方的 `c_i`（螢幕足跡）。
按 `count` 遞減保留 ＝ **保留最貴的粒子** ⇒「按 value-per-cost 剪枝（保留便宜的）」方向相反。
這給了 `v/c 判準「訓練側淨負」`（早已記錄）一個機制解釋：**便宜的粒子小，剪掉會讓畫面出洞，
而洞比什麼都傷**。命題本身（用成本當**預算約束**）不受影響，但
**§3.1 的「v/c 門檻是 LP 最優解」需要重新檢視——LP 假設價值可加，而覆蓋顯然不可加。**

⚠ 全部量在事後剪枝上，單一模型。`sum` 的 PSNR 反而最高（80k：16.65 vs max 15.47）
＝面積加權保留少數大顆粒，平均顏色對但細節全無 ⇒ **反過來驗證紋理比是對的尺**。

🧪 **原始 Eq.5 仍未測**：MVGSR（arXiv 2503.08093）§4.2 Eq.5
`C_MV(p) = Σ_視角 Σ_像素 [T·alpha > δ]`——**計數**而非平均或最大，且**逐像素**（隱含尺寸，
與我方的「每像素平均」相反）。

### 6.2 depth-init 的真實 input（2026-08-06 追碼）

```
utils/depth_init_blocks.py
  :79   read_model(sparse_dir)            ← COLMAP 姿態
  :82   estimated_depth_scales.json       ← 每張影像的 (scale, offset)
  :312  estimated_depths/*.npy            ← Depth Anything V2 逆深度
  ⇒ 直接幾何構造，【完全沒有訓練】
```

而 `utils/get_depth_scales.py` 是**用該影像可見的 COLMAP 點**擬合 scale/offset：
```
scale = s_colmap / s_mono ,  offset = t_colmap − t_mono·scale     （每張影像 2 個自由度）
```

⇒ **depth-init 不是「不用 SfM」，是「用 SfM 校準單目深度」。**
⇒ **8.6% 的誤差是 DA2 的形狀誤差，2 個自由度改不掉** ⇒ 這條線上沒有便宜的改進空間。
⇒ 也解釋了為什麼體素質心融合完全沒改善：形狀誤差是同一個網路的**系統性偏差**，
不同影像犯**相關**的錯，平均不會消掉。

**對照 coarse**：`points_from: sfm` ⇒ SfM 點**直接當粒子位置** + 30k 步光度訓練。
差的那一步是「用影像訓練」，不是密度。

#### ★ 缺陷 1 的含意：它動搖了一個反覆引用的結論

`sep_depth_trim_2dgs_renderer` 的版本把 `top_list[0] = trans` 寫在**位移迴圈裡面**：

```
[a, b, c] + 破紀錄的 r
  i=0: top[2]=top[1]→b ; top[0]=r   → [r, b, b]
  i=1: top[1]=top[0]→r ; top[0]=r   → [r, r, b]
```

舊的最大值被丟掉、新紀錄佔 K−1 個槽 ⇒ 穩態 `(2·max + prev)/K` ≈ **執行中的最大值**，
而且**與相機順序有關**，第一台相機的值被複製 K 份。

本檔 §5.3 與 `measure_view_consistency.py` 反覆主張：
> floater 不是貢獻度低，是貢獻度**集中**——它被放去解釋少數視角，而它確實解釋了那些視角。

**那個推理的前提是「trim 用的是跨視角統計量」。實作實際上按「最佳單一視角」排序**
——最寬容的判準，**只在單一視角尖峰的 floater 剛好拿高分而存活**。
⇒ **「剪枝盲於幾何」有一部分可能不是判準的哲學問題，是這個實作缺陷；
真正的 top-K 平均從來沒被測試過。**

⚠ **這是機制變更不是純 bugfix**：剪枝行為改變 ⇒ **修正後的跑次與既有結果不可直接比**。
⚠ `tools/prune_curve.py` 先前那兩條曲線用的排序也是壞的（**第三種錯法**：單一值填滿所有 K 槽），
數字要重跑。

## 12.6 depth loss 與 lambda_dssim 買的是同一樣東西，而 depth loss 便宜 3 倍（2026-08-16）

三組**獨立**對照，各自只差 depth loss 開關，其餘同組態（cap 2.6M / prune 300 / oreg 0.002）：

| | 對照 | floater% 開→關 | Δ建築PSNR | Δ水面PSNR | Δ建築紋理比 | Δfloater不透明 |
|---|---|---|---|---|---|---|
| A | dssim 0.5：`dssim05` vs `npd` | 0.958 ← 1.370 | −0.123 | **+0.140** | −0.0125 | 0.520→0.565 |
| B | dssim 0.2：`sh3_nonormal` vs `noprior` | 1.193 ← 1.726 | −0.408 | −0.145 | −0.0196 | 0.493→0.530 |
| C | normal 開：`sh3_viewdep_refix` vs `sh3_nodepth` | 0.942 ← 1.450 | −0.261 | −0.077 | −0.0077 | 0.560→0.587 |

（分區域數字來自 `scratchpad/region_split.py`：讀已存的 test 並排圖 GT|渲染，用 GT 梯度把 36 張
測試視角排序、兩端各取 12 張，**純 CPU 不重渲染**。）

**⛔ 已否證：「紋理閘門式深度監督」（只在低紋理區給深度監督）。** 提出它的前提是「depth loss
在水面有益、在建築有害」——**Δ水面只有 A 是正的，B/C 都是負的**，A 是離群值。depth loss 沒有
任何區域是光度上划算的，它是**到處都在拿光度＋銳利度換 floater**。這個前提驗證是 CPU 兩分鐘，
擋掉一次實作。（另注：即使成立也不算我方貢獻，閘門用在 densify 就是 EAS，見 [[degeneracy_and_blur_split]]。）

**✅ 成立且三組一致：** floater −30~35%、建築 PSNR 與建築紋理比同時下降、**存活的 floater 更不
透明**（弱的被清掉、強的留下）。

**★ 可行動的結論——同一天平上比效率：**

| 槓桿 | floater 降幅 | PSNR 代價 | 每 dB 換到 |
|---|---|---|---|
| depth loss 開（dssim 0.2） | 30.9% | 0.254 | **122%** |
| depth loss 開（normal 開） | 35.0% | 0.239 | **147%** |
| dssim 0.2→0.5（depth 關） | 20.6% | 0.505 | 41% |

⇒ **要壓 floater 就用 depth loss，不要用 lambda_dssim，差 3 倍以上。**
⇒ **dssim 軸關閉**：0.5 被支配；0.5→0.8 再付 0.493 dB 而 SSIM/LPIPS 增益只剩 1/3，已過拐點。

**衝 27.23 的主線仍是 `noprior`（depth 關、dssim 0.2、26.083）**，因為建築區三組一致顯示
depth loss 是淨負的；floater 是**部署側／視覺側**的選項，不是分數側的。差距 1.147 dB 不會由
這條軸補上——它整條軸的動態範圍只有 ±0.5 dB。

⚠ 讀 `tools/geometry_health.py` 輸出時注意：後兩欄是 **floater 平均不透明度**與**鄰距中位**，
**不是紋理比**（它沒算紋理比）。我 2026-08-16 讀錯過一次並差點據此宣稱兩把尺矛盾。

## 12.8 ★ cap_max 不是操作點：每個跑次都停在 cap 的 90.00%（2026-08-16）

`noprior` 2,339,999 / 2.6M、`sb4` 3,150,000 / 3.5M、`sb_refix` 3,240,000 / 3.6M、
`dssim05` 2,340,000 / 2.6M —— **四個不同 cap、不同 F，全部剛好 90.00%。** 逐 ckpt 追蹤：

```

step 29,999  N=2,600,000        已達 cap
step 41,999  N=2,600,000        densify_until=42,000
step 60,000  N=2,339,999        收割期掉 10.00%
```

**⛔ 2026-08-17 更正：原本的歸因是錯的。** 我原寫「densify 停掉後 relocation 關閉，

`freeze_opacity_after_densify` 實驗 —— **那個實驗在測一個被推翻的假說，已撤換**（見 §12.12）。

要 N 顆就設 cap = N/0.9。

- **floater%（`geometry_health.py`）不可再當結構判準**。它數的是粒子位置，和螢幕上的大團塊

  **currency 是錯的**，結論要重讀：真正的結果是 **dssim 往上調在結構上是淨傷害**。
- **紋理比可以分辨「舊 kernel vs 新 kernel」那種真實品質差（r 有效），但和結構誤差無關

**★ b7 的 1708（最糟 0.01783）與 1579（最好 0.00083）：高度 5.000 vs 5.000、距離 4.970 vs 5.002、

⇒ **失效不是視角的性質，是「看向場景哪個位置」的性質。**

**★★ 關鍵矛盾**：訓練損失（L1+SSIM）**本來就對誤差最大的視角給最大梯度**，
這些視角的誤差是別人的 171 倍，梯度一直在喊，**而它們就是修不好**。
⇒ **不是分配問題**（不需要再加取樣權重／重分配點，那條線本來就被 net-zero 否決過）。
⇒ 是**表徵或最佳化的障礙**——最符合的是初始化局部極小
