## 1. 論文命題（重定調）

**「消費級 6GB 筆電上的 city-scale 高斯重建：以『每顆 primitive / 每 byte VRAM 的品質』
為中心的擬合機制改良」**

一句話版本：CityGaussian 系列靠「堆顆數 + 堆 VRAM」買品質（27.23 要 8×A100）；
我們證明在 6GB 上，透過 **更好的密度控制（MCMC-2DGS）、explore-then-prune、
表徵選擇（sh0 發現）、預算控制（cap）**，可以用少一個數量級的資源逼近同品質——
並用兩個探針決定 headline novelty（kernel 表達力 or diffusion 修復欠觀測）。

這個命題同時涵蓋使用者三個目標：更低顆數更好結果（效率前緣）、更低系統負載（6GB+offload）、
提升品質（修 merge 掉分 + 打欠觀測殘差）。

## 2. CityGS/CityGSV2 缺陷清單（證據皆來自我們實測 + 文獻對照）

### D1. 記憶體暴食：全域 coarse init + 無上限 densify
- **機制**：官方流程每個 block 都要載入完整全域 coarse（4.39M 顆）做 step-1 forward+backward
  才 trim；densify 無 cap_max，VRAM 峰值 = f(場景內容)，不可預算。
- **我們的證據**：6GB 上 step-1 直接 OOM（`citygsv2-baseline-repro`）；block_16 densify 期 OOM；
  sh2 4M 必 OOM（epoch131 5.16GB 爆）。
- **文獻對照**：CLM (ASPLOS 2026) / GS-Scale (arXiv 2509.15645) 整篇論文就是在解這個。
- **我們的解**：visibility-crop（已做）、MCMC cap / RTG hybrid soft-cap（已做）、
  host offloading（探針 P3）。

### D2. Grad-densify（DGD）脆弱：對 init 品質/解析度極敏感，暴衝或長不動
- **機制**：densify 靠 SSIM viewspace 梯度觸發；梯度大小由 init 擬合程度決定 →
  低解析度 coarse = 欠擬合 = 暴衝出垃圾球；depth-init = 擬合好 = 梯度低 = 長不動。
- **我們的證據**：ds3 coarse → 4.96M 顆只有 24.16（floater 海）；depth-init + grad-densify
  卡 280k（E2-B）；忠實重跑 CityGSV2 6GB = 21.78 / SSIM 0.560（floater 多）。
  grad-densify 對 MCMC 三連敗（21.78 / ~21 / 19.93）。
- **我們的解（已驗證資產）**：MCMC-2DGS 密度控制，同設定 +1.46dB；不看梯度、強制長到 cap、
  reset-free、預算顯式。
- **文獻對照**：Deformable Beta Splatting (SIGGRAPH 2025) 的 densification 也選了 MCMC
  且證明 kernel-agnostic → 我們的 MCMC 底座跟 kernel 賽道天然相容。

### D3. Per-primitive 表達力低：品質 ∝ ln(N) 的暴力 scaling
- **機制**：圓盤 Gaussian/surfel 邊緣軟、單顆表達力弱 → 銳利邊緣要堆很多顆；
  品質 scaling law ≈ a + 0.8·ln(N)，截距 a 由機制決定、要分數只能堆 N。
- **我們的證據**：sh0 發現（aerial 下 view-dependence 沒用，sh0-4M 被硬體鎖死且最優）→
  在 SH 軸加表達力此場景無效 → **幾何 kernel 軸是剩下唯一的 per-primitive 表達力槓桿**。
- **文獻對照（2025-2026 熱賽道）**：Triangle Splatting (3DV 2026)、Triangle Splatting+
  （**opaque** 三角形，與我們 alpha=0.99 opaque surfel 同哲學）、3D Convex Splatting
  (CVPR 2025)、Deformable Beta Splatting（bounded support + 自適應頻率，主張更少顆更高品質）。
- **我們的解**：探針 P1（Beta）/ P2（Triangle），先量 headroom 再決定移植。

### D4. 分塊-合併一致性斷裂：merge 後掉分
- **機制**：block 獨立 fine-tune → 邊界高斯漂移/重複/外觀（曝光、顏色）分歧 →
  merge 裁切丟點 + 接縫 artifact → merged < per-block 平均。
- **我們的證據**：S8 merged 19.51（drift + AABB filter 只留 13-15%，量尺壞掉）；
  ADMM 共識實測 net-zero（depth-init 下邊界幾何本就一致、外觀共識拉不動）→
  問題不在幾何共識，在 **merge 流程本身 + 外觀接縫**。
- **文獻對照**：Momentum-GS（momentum self-distillation 拉塊間一致）、CityGS-X
  （放棄 partition-merge 改 hybrid hierarchical）、Consistency-preserving GS
  (C&G 2025，overlap 一致性優化)。
- **我們的解**：先走官方 merge 工具鏈 + 子集實測掉分幅度（P5），再對症下藥
  （overlap 一致性 loss / 接縫短 fine-tune / offload 全域 consolidation pass）。

### D5. 欠觀測視角品質崩壞（coverage bias）——當前殘差主病灶
- **機制**：aerial 軌跡對斜視/低空/高樓立面/塊邊緣採樣稀疏；CityGS 沒有任何機制處理
  觀測不均，這些區域糊+拉絲+半透明疊影。
- **我們的證據**：24.30 模型 test 圖目視 = 高空正俯視完美、低空斜視爛；per-image PSNR
  方差大；distortion reg 救不動反而全面變糊（v1 22.63，dense aerial 判死）；
  ~3.7dB 殘差歸因欠觀測/全域一致性。
- **文獻對照（2025 熱賽道）**：Difix3D+ (CVPR 2025)、GSFix3D、FixingGS、3DGS-Enhancer ——
  全是「render 壞視角 → 單步 diffusion 修圖 → 蒸餾回 3DGS」。
- **我們的解**：探針 P4（diffusion 修復 headroom）+ P6（coverage 偏差量化，給論文診斷章節）。
- **誠實風險**：diffusion 主要贏 LPIPS/感知，PSNR 對 GT 可能不加分（幻覺 ≠ GT）。

### D6. 超參森林 + 消費級不可複現
- **機制**：coarse→partition→per-block ft→merge 每階段超參耦合
  （densify schedule × init 解析度 × trim × reset），官方數字要 8×A100。
- **我們的證據**：ds3/ds1.2 coarse 一個參數差 = 24.16 vs（推測）28 級；我們整個
  `_REFERENCE_annotated.yaml` 就是被迫做出來的產物。
- **我們的解**：這本身就是論文動機章節的材料（democratization 故事）；
  cap + MCMC 讓 VRAM/顆數可預算化 = 對此缺陷的部分回答。

### 缺陷 → 方向對應表

| 缺陷 | 已有資產（可寫進論文） | 探針/待做 |
|---|---|---|
| D1 記憶體暴食 | visibility-crop、cap/soft-cap | P3 offloading |
| D2 densify 脆弱 | **MCMC-2DGS (+1.46)**、explore-then-prune (+0.28~0.46) | Phase 0 的 sh0-4M 對決 |
| D3 表達力低 | **sh0 發現**（負結果轉正資產） | P1 Beta / P2 Triangle |
| D4 merge 掉分 | ADMM net-zero 的診斷價值、boundary 工具 | P5 子集 merge |
| D5 欠觀測 | 病灶診斷（test 圖 + distortion 否證） | P4 diffusion、P6 coverage 量化 |
| D6 不可複現 | 全 6GB pipeline、參數手冊 | 論文寫作素材 |

2. **sh0 為 aerial 主線**（sh2/sh3 只在效率前緣章節做對照）；hybrid-SH 留街景線。
3. **只用當前資料的 coarse**（舊 `aerial_train_block_all_3x` 禁用；舊 28.9 不直接比）。

  移植成本前置 = 高風險；probe-first = fail-cheap）。

## 5. 決策樹

```
Phase 0: MCMC-sh0-4M vs 官方24k
├─ MCMC 贏/平 → 引擎=MCMC（資產全用上）
└─ MCMC 輸    → 引擎=官方DGD；MCMC+prune 降為「小預算 regime 效率章節」

探針:
├─ P1/P2 有一個在同顆數贏 → headline = 「kernel 表達力 > 顆數」(月3-4 移植整合)
│    （移植對象優先 Beta：MCMC 底座相容、改動集中在 kernel eval + 梯度）
├─ P4 PSNR 也贏 → headline = 「diffusion 修欠觀測」(蒸餾迴圈整合)
├─ 兩者都只小贏/不贏 → headline = 「6GB 效率前緣 + offload 破牆 + merge 修復」
│    （= 保底故事，Phase 0-2 數字本身就撐得起）
└─ P3 跑通與否獨立決定「4M 牆」上限與全域 consolidation 可行性
```

衝突規則：GPU 時間優先序 = Phase 0 長 run > 子集 merge run > 探針（探針塞空檔）。

## 6.（2026-07-03 追加，使用者提案）候選 headline：自研 densify 演算法 SF-MCMC

**提案**：與其只移植別人的 kernel/diffusion，不如自己設計 densify 演算法。
**評估：與資產最對齊的 headline 候選**——我們唯一的真贏（+1.46）就在密度控制層；
不用改 rasterizer（kernel 線要）、不用外部模型（diffusion 線要）、sh0 下照樣有效、
直攻 D2。且與 kernel 線**可組合**：DBS 已證 MCMC densification 是 kernel-agnostic →
本演算法若成，之後換 Beta kernel 可以直接帶著走。

### 設計：Split-Funded MCMC（SF-MCMC，工作名）
骨幹 = 我們的 MCMC-2DGS（cap 預算 / opacity+scale L1 / dead-relocation / 切平面 noise），
新增一個操作：**預算制梯度分裂（budgeted split）**。

每個 densify interval：
1. 累積 DGD 訊號（SSIM viewspace 梯度，gg-MCMC 的 buffer 管線現成）。
2. 候選 = grad × scale（螢幕面積）**top-q 分位數**的「大而結構錯」高斯。
3. 經費 = dead 高斯（低 opacity）+ 到 cap 的餘裕：把一部分 dead 的 relocation 目的地
   從「按 opacity 抽樣的現存點」改成「top-q 候選的分裂子點」。
4. 分裂數學直接用 gsplat `compute_relocation` 的 1→N opacity/scale 重整化
   （= 3dgs-mcmc 保渲染不變的那套）→ **分裂 = 帶空間先驗的 relocation**，
   分佈保持、理論乾淨、與 MCMC 框架同語言。
5. 超 cap 時線上 importance-prune 回收（把 explore-then-prune 線上化 = DBP 想法
   搬回能長的骨幹上）。

### 三個設計決策，各對應一條我們自己的失敗教訓
| 設計 | 教訓來源 |
|---|---|
| **相對 top-q 預算制**，非絕對閾值觸發 | E2-B：DGD 絕對閾值 0.0002 在 depth-init 下永遠不觸發 → 卡 280k。top-q 永遠有候選、不會 stall |
| **改變操作（split）**，非改抽樣權重 | gg-MCMC/edge-MCMC net-zero：同機制下重加權 = 無效；紀錄明載「MCMC + SPLIT 是唯一未測的機制缺口」 |
| **分佈保持的 1→N 重整化** | MCMC 數學已驗證（CUDA 源碼對拍 diff=0），不引入新的收斂風險 |

### 兩個 gate（不過就不做，止損點明確）
- **G1（對不對症）**：Phase 0 引擎對決。若官方 24k（DGD）在當前資料 4M sh0 regime
  顯著 > MCMC-sh0-4M → DGD 截距優勢為真 → split 訊號值錢 → 綠燈。
  若 MCMC ≥ 官方 → 「SSIM-split 缺口」動機崩 → 不建，headline 回到效率前緣。
- **G2（novelty）**：先精讀 SteepGS（CVPR 2025，split 何時/往哪分裂的理論——
  child 放置可以直接借它的）與 AdpSplit（2026，error-driven split），確認
  「MCMC 骨幹 + dead-funded split + 2D surfel + city-scale」組合未被佔。
  鄰近 prior art：Taming 3DGS（budget+多訊號分數，但 grad-densify 家族）、
  Improving Densification 2508（edge score+長軸分裂，不能配 MCMC，記憶已載）。

### 消融設計（最小三臂，block_7，同 recipe）
- arm0 = MCMC-sh0-cap4M（就是 P0.3，免費）
- arm1 = + budgeted split（top-q grad×scale）
- arm2 = + budgeted split 但候選隨機（隔離「訊號」vs「分裂操作本身」）
- 成功判準：arm1 − arm0 > +0.3dB 且 arm1 > arm2；兩者缺一 = 負結果照實寫。

### 成本與排程
實作 2-4 天（梯度 buffer / relocation 數學 / importance-prune 全現成）；
sh0 4M 一發 ~5-8h。**排位：決策樹升為第一 headline 候選**（kernel/diffusion 探針
照跑當保險；kernel 若贏可與本演算法組合非競爭）。誠實 base rate：演算法層點子
已三振（ADMM/gg/edge），所以 G1/G2 兩道 gate 先過才動工。
