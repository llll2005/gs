# 新紀錄大綱（草案）

## 一、為什麼要重寫，而不是修補

`研究總覽.md` 有 **4,159 行**，佔全部紀錄的 67%。它的章節是按「發現的時間順序」長出來的
（§11.x 節號甚至亂序），而其中大部分章節的**結論已經作廢**。
問題不在於有錯的內容 —— 那可以標記；問題在於**目錄本身是按錯的結論組織的**，
所以找東西要靠 grep，而 grep 找不到「這個結論依賴什麼」。

⇒ 新結構按**問題**組織，不按時間；每個章節自帶表頭，狀態與依賴寫在最前面。

## 二、每個章節的表頭（固定格式）

```
---
id: <穩定錨點，不用行號>          # 行號會漂，id 不會
狀態: 有效 | 待重測 | 作廢
年代: 修正後(2026-09-13~) | GT錯位期 | 舊資料集
摘要: 一段話：結論是什麼、憑什麼。
資料: <ckpt / log / csv 的確切路徑>
組態: <config 檔 + 關鍵旗標>
量測: <工具、樣本數、重複次數>
依賴: [<其他章節的 id>]           # ★ 前提倒了就能反查誰跟著倒
來源論文: [<論文代號>]             # ★ 這個機制是從哪篇來的（沒有就寫「我方原創」）
取代: <archive 裡的哪一份>
時間: YYYY-MM-DD
---
```

`依賴` 是為我加的，你可以略過。它的用途：2026-09-13 發現配對錯位時，判斷「哪些結論跟著倒」
花掉整份倖存清單；同一天又發生兩次（破平衡公式的前提垮了、退化定理的前提被推翻），
而兩次都是**碰巧**查到。有 `依賴:` 就能反查。

## 四、搬遷規則

```
✅ 倖存        搬進上面的章節，補表頭，數字照舊
⚠ 機制倖存     搬進來但**數字欄留空**，標「待重測」，並在 0 節列進待辦
⛔ 作廢        留在 new_archived/，只在相關章節留一行「這條曾經是 X，見 new_archived/Y」
```

★ **合併**：同一件事散在多份文件的（例如成本感知橫跨 4 份、init 橫跨 3 份），合併成一節。
初步估計可從 6,178 行壓到 **2,000 行以內**，因為大量內容是「我推翻我自己」的中間過程 ——
那些留在 archive 就好，新紀錄只留**結論與它憑什麼**。

## 七、格式：維持 Markdown

使用者問 md 還是 html。**md** ——
```
token   HTML 的標籤開銷是實打實的浪費，而這份紀錄會被反覆讀
grep    搜內容不搜標籤；HTML 會讓關鍵字被標記切斷
結構    `##`／表格／程式碼區塊對我直接有意義，不需要穿過標記雜訊
diff    git 上看得懂
```
要好看的閱讀體驗就**從 md 生成 html**，不要改用 html 當來源 —— 否則違反單一來源原則。
