## A 表示法與渲染底座

### NeRF（ECCV 2020）`2003.08934v2.pdf`　📖
- 原文：以 MLP 表示體積密度與視角相依顏色，沿光線體積渲染。
- 我方：背景引用；ray/pixel chunking 是 K-strip 的靜態祖先（K-strip 已知在 K>1 有損，記憶 dynamic_strips_confound）。

### 3D Gaussian Splatting（SIGGRAPH 2023）`3dgs.pdf`　📖✅
- 原文：各向異性 3D 高斯＋可微 tile 光柵化（排序後 alpha 混合）＋自適應密度控制（clone/split/prune、opacity 重置）。
  §5.2 自己命名「靠近相機的 floater」並有三道解藥（opacity 重置、world 尺寸剪、viewspace 足跡剪）。
- 我方：底座。MCMC 把那三道解藥當啟發式刪掉了，`screen_size_prune_px` 是第三道的重新引入（論文核對表 §4.2）。

### EWA Splatting（TVCG 2002）`EWASplatting-TVCG02.pdf`　📖
- 原文：橢圓加權平均重採樣、透視投影 Jacobian 的原始出處。
- 我方：成本模型的拉伸項 `sqrt(1+(x/z)^2+(y/z)^2)` ＝投影 Jacobian 最大特徵值的平方根（已證，論文核對表 §4.1）。

### 2D Gaussian Splatting（SIGGRAPH 2024）`2dgs.pdf`　✅
- 原文：把高斯壓成 2D 表面元（surfel），以射線與 splat 平面的交點求值；加法線一致性 loss 與深度 distortion loss 換幾何精度。
- 我方：`Gaussian2D` 就是它。**法線一致性與 distortion 權重目前都是 0** => 光柵器算的幾何通道沒有消費者（lean_render 正在去掉，
  `運算速度_問答與待驗證_2026-10-02.md`）。
  另一個我方獨有的觀察：2DGS 的射線-splat 是**投影**而非仿射 => 沿用 3DGS 的「半徑乘 3」不再精確也不保守（論文核對表 §12.3）。

### Gaussian-enhanced Surfels（GES，TOG 2025）`GMS.pdf`　💤
- 原文：雙尺度表示 —— **不透明**的 2D surfel（視角相依顏色）負責粗尺度幾何與外觀，少量 3D 高斯補細節；
  先用標準圖形管線光柵化 surfel 得到深度與顏色，再「有深度測試、與順序無關」地疊加高斯 => 免排序、極快。
  用一個 opacity 調變參數讓半透明 surfel 逐步變成不透明。
- 我方：未測。與我方「多層半透明殼」的病灶方向相反（它強迫表面不透明），可作為「少而準」路線的參考；但要換表示法，成本高。

### Deformable Beta Splatting（DBS）`DBS.pdf`　⛔
- 原文：高斯核換成可變形 Beta 核（有界支撐、可調頻率）；顏色也改用 Spherical Beta（SB）編碼，記憶體更省。
- 我方：只移植了 SB 顏色（`gaussian_2d_sb.py`，25 float/顆 vs SH3 59）。【舊⛔】SB-4 多 35% 顆數仍六項全輸、SB-16 OOM => 退役。
  原文 Table 3 沒有「高斯核＋SB 顏色」這一列（增益量在 Beta 核上），我方的負結果有原文根據（論文核對表 §2.2）。

### Ref-GS（2DGS 的方向分解）`ref-GS.pdf`　💤
- 原文：在 2DGS 上做方向光分解，用球面 Mip-grid 表示不同粗糙度，取代 SH 處理視角相依外觀，同時保住幾何。
- 我方：未測。與「顏色表示換更便宜的基底」相關（運算速度 Q4/Q8：SH 佔每顆參數 78%）；但它是為鏡面反射設計，空拍幾乎沒有高光。

### Scaffold-GS（CVPR 2024）`Scaffold-GS: ...pdf`　⛔
- 原文：用錨點分布局部高斯，屬性由 MLP 依視角與距離即時預測；錨點依神經高斯的重要度增長／剪除。
- 我方：【舊⛔】Scaffold／latent-MLP 線已關（與 2DGS 表面元表示衝突，研究總覽_v2 §8）。運算速度 Q6：這類「逐顆 latent＋共享解碼」省記憶體不省逐配對計算。

### SOGS（二階錨點）`SOGS: ...pdf`　⛔
- 原文：在錨點式 3DGS 上用錨點特徵的共變異（二階統計）擴增特徵，以更低的特徵維度換到更好的品質；加 selective gradient loss。
- 我方：屬錨點家族，隨 Scaffold 線一併關閉。

## B 密度控制、增生與初始化

### 3DGS as MCMC（NeurIPS 2024）`3dgs-mcmc.pdf`　✅
- 原文：把高斯集合視為 MCMC 樣本 —— 死粒子 relocation（不刪只搬）、位置加噪（`op_sigmoid(1-o)` 閘控）、opacity／scale L1、
  每次增生 `N_target = 1.05·N` 直到 cap。
- 我方：密度控制核心（`mcmc_2dgs_density_controller.py`），所有【新】跑次都用它。實作逐項核對正確；原文 Eq.8 印刷符號有誤
  （論文核對表 §1）。fast_noise 已用工具證等價（`tools/check_noise_opts.py`，相對差中位約 6e-8）；noise_gate ⏳ 60k 單變數已排（cnogate）。

### AbsGS（2024）`AbsGS_2404.10484.pdf`　✅⏳
- 原文：3DGS 的螢幕空間位置梯度在 splat 中心兩側互相抵消（梯度碰撞），過度重建的大高斯達不到分裂門檻
  => 改用**先取絕對值再加總**的梯度當 densify 判準。
- 我方：`absgrad_densify`（借用 `dL_dmean2D.z` 當累加器，渲染與梯度逐位元不變），MCMC 取樣權重 `o·(1+w·|g|/mean|g|)`，現行 w=2.0。
  【舊⛔】b12/b7 都顯著改善（那是現行配方的由來）。【新】**還沒有單變數測試** => ⏳ cag0／cag4（60k b6/b13）已排。

### Taming 3DGS（SIGGRAPH Asia 2024）`taming_3dgs.pdf`　🧪💤
- 原文：①在明確顆數預算下的建構式增生，分數含逐顆「覆蓋像素數」`c_g`（**符號為正**，大＝模糊＝該分裂，權重 0.1）；
  ②§4.1 per-splat 平行化 backward（數值等價，取代逐像素 atomicAdd）＋tile 遮擋尾巴略過＋StopThePop 的緊剔除；
  ③§4.2 SH 高階每 16 步才更新一次 Adam（不等價）、SH dc／高階不先 cat、可分離 SSIM 卷積。指出 backward 是瓶頸、其次 Adam。
- 我方：
  - ① 方向對照【新】b6 22k（同 N 1.85M）：`cs_costtaming`（偏好貴，w=-2.8）PSNR **29.141**／SSIM 0.8539／LPIPS 0.1679，
    基準 29.006／0.8519／0.1719，Load 中位 +10%、峰值 VRAM +0.13 GB；我方方向 `cs_costdir_cal`（w=+4.0）28.833（−0.17）、Load −15%。
    => 寬鬆預算下 Taming 的方向小勝（+0.14 dB，未過 22k 3sd=0.24）但更貴；我方方向省成本但輸品質。
  - ② ③ 💤 速度候選（運算速度紀錄 #9／#10／#11），等 kernel 拆解（⏳）決定。

### Gaussians on a Diet（2026）`Gaussians_on_a_Diet.pdf`　💤
- 原文：記憶體上限內訓練 —— 迭代地剪掉低影響高斯、帶補償地增生新的，峰值訓練記憶體近乎恆定。
  明確指出「訓練後剪枝解決不了訓練期峰值」，並批評 Taming 會留下位置不佳的高斯。
- 我方：最貼近命題的前作（論文核對表 §7）。它揭露的「共位 clone 梯度退化」解釋了 MCMC relocation 的死亡跑步機；
  建議的修法（沿累積位置梯度給小位移）💤 未實作。

### Mini-Splatting（ECCV 2024）`Mini-Splatting.pdf`　💤
- 原文：高斯在表面附近分布不均 => 增生用 blur split（按「主導像素數」分裂造成模糊的大高斯）與深度重新初始化，
  精簡用 intersection preserving 與取樣；在顆數受限下重組位置。
- 我方：blur split 已實作（`blur_score` 來自 trim pass 的 `T·α×覆蓋像素`），現行權重 0，【新】未測。

### FastGS（CVPR 2026）`FastGS.pdf`　🧪💤
- 原文：以**多視角一致性**決定每顆的重要性（足跡內高誤差像素數，跨視角累積）來增生與剪枝，不用顆數預算；
  另有 Compact Box（更緊的 tile 範圍）、沿用 Taming 的 per-splat backward 與 SH 加速；Tanks&Temples 一個場景 100 秒訓完。
- 我方：Compact Box 的同類 => 我方 `exact_conic_aabb`（2DGS 精確圓錐不對稱外接盒）。
  【新】離線 Σtile −41.2%、本機 forward −24.5%／fwd+bwd −15.1%；單變數品質（b6 22k、同 N 1.85M）：conic 開 vs 關
  PSNR 29.05 vs 29.05、精確 Load 中位 3.05M vs 5.09M（−40%）=> 同品質、成本少四成 ✅ 採用。
  （⚠ 60k 的 speed3 vs cs60_conic 不是單變數：speed3 是 depth-init；60k 單變數對照 cs60_base 的分數尚未彙整。）
  足跡內誤差當價值訊號 💤（論文核對表 §8.3）。

### Improving Densification in 3DGS（2025）`ImprovingDensification_2508.12313.pdf`　💤
- 原文：從「何時、如何增生、如何防過擬合」三面改：Edge-Aware Score 選分裂候選、Long-Axis Split（沿長軸分裂減少幾何扭曲）、

### RAIN-GS（2024）`2403.09413v2.pdf`　🧪

### 2DGS-R（2025）`2DGS-R_2510.16837.pdf`　💤（佐證）

## D 光柵化與訓練速度

### StopThePop（SIGGRAPH 2024）`StopThePop.pdf`　✅⏳
- 原文：主軸是階層式排序消除 popping；§3.4 **tile-based culling** —— 用 1/255 貢獻條件把每顆限制在真正有貢獻的 tile（每 tile −44%），
  渲染不變。
- 我方：整顆版（o ≤ 1/255 整顆不進 binning）＝`EXACT_SUPPORT`，**逐位元相同、峰值 render VRAM −20.3%** ✅ 預設開（程式事實，跨年代有效）。
  精確支撐半徑版逐位元不相同（真因未明）。**逐 tile 版**：⏳ `scripts/lab/task_tile_audit.sh` 先量 conic 盒內無貢獻配對的比例。

### HiGS（2026）`HiGS.pdf`　💤
- 原文：分區（binning、排序）與光柵化各用不同尺度 —— 粗的 macro-tile 做分區、細的 tile 做光柵化，工作依 macro-tile 內高斯數派發，
  密集區分散到多個平行單元；比原版 3DGS 快到約 15.8 倍，保留精確的前到後混合。
- 我方：推論期設計（沒有 backward），可借概念不可直接用；與「少數密集 tile 主宰時間」的現象相關。

### Proxy-GS（2026）`2509.24421v4.pdf`　💤
- 原文：用輕量代理幾何在 1 ms 內產生精確遮擋深度，用來剔除被遮擋的錨點／高斯（加速渲染）並導引增生；MatrixCity Street 有結果。
- 我方：未測。遮擋剔除與 kernel 層的「遮擋尾巴」（⏳ tile audit ②）是同一件事的不同層級。

### GS-Scale（ASPLOS 2026）`GS-Scale.pdf`　💤
- 原文：全部高斯存在主機記憶體，每次只把需要的子集送上 GPU；三個系統優化（幾何參數選擇性 offload 以快速視錐剔除、
  參數轉送讓 CPU 端 Adam 與 GPU 計算管線化、零梯度高斯延後更新）=> GPU 記憶體降 3.3–5.6 倍、速度接近不 offload。
- 我方：與「6GB 信封」直接相關（我方 VRAM 由 N 主導、每顆常駐 928 B）。未測；「零梯度延後更新」與 Sparse/Selective Adam 同類（速度候選）。

## G 最佳化與理論

### AdamW（ICLR 2019）`1711.05101v3.pdf`　📖
- 原文：權重衰減與梯度更新解耦（純 `λθ`，不經 `1/sqrt(v)`），理由是所有權重以相同速率衰減。
- 我方：解釋了「opacity_reg 調了沒用」（L1 在 loss 裡會被 Adam 的 sqrt(v) 正規化，論文核對表 §5）。

### AdamW-GS（ICLR 2026）`adamW.pdf`　🧪【舊⛔】💤
- 原文：重新分析 3DGS（含 MCMC）最佳化中 opacity／scale 正則與 Adam 的耦合，拆成三件：**Sparse Adam**、
  Re-State Regularization、**Decoupled Attribute Regularization（DAR）**；不需額外剪枝就能大幅降低冗餘、提升效率。
- 我方：DAR 已實作（`dar_lambda`，依成本加權），【舊⛔】結果作廢，現行 0。Sparse Adam 💤 是速度候選（optimizers.py 已有
  SelectiveAdam／SparseGaussianAdam 選項；與 GS-Scale 的零梯度延後更新同類）。

### 最佳化器狀態量化（2026）`2603.16731v1.pdf`　💤
- 原文：低精度（BF16 以下）的 EMA 狀態會因捨入讓許多更新「回到同一個存值」而停滯，適應變慢；狀態重設在低精度下才明顯有幫助。
- 我方：與「Adam 狀態佔 ckpt 2/3」（記憶 storage_structure）及程式裡的 `LowPrecMomentAdam`（bf16 動量）直接相關 ——
  若要用低精度動量省 VRAM，要注意停滯；未測。

### Flow Matching 的頻率平衡（2026）`2609.02748v1.pdf`　💤
- 原文：自然影像能量集中在低頻，像素空間 loss 讓低頻主導、細節學得晚；提出頻率平衡的 f-loss，先強調頻域、再轉像素 loss，收斂快到 40%。
- 我方：不同領域（生成模型）。與 `coarse_l1`（替 ≥32px 頻帶計價）及 FreGS 同一議題；未測。
