## 1. 顆數與排程

### 1.1 每塊顆數由塊內可靠 SfM 點數分配（10-31 → 11-10 規則）🟩
- 問題：每塊用同一個 cap，空曠塊（海、低樓）浪費、高樓塊不夠。
- 做法：`tools/sfm_cap_alloc.py`：每塊 cap ∝ 塊內可靠 SfM 點數（track ≥ 3、重投影誤差 < 1.5 px），總和＝平均 × 16（`configs/cap_alloc_sfm_g44.json`）。取代 10-31 要先跑一次 2.5M 探針的「價格分配」。
- 結果：平均 1M 全場景 27.822（探針分配 27.828、均勻 27.805、重跑雜訊 0.002）；與探針權重相關 0.69 => 零成本、免探針。使用者規則（11-10）：顆數由 SfM 分配決定，不准拿「盒內顆數一樣」當目標。

### 1.2 17k 步、增生到 70%（11-13～15）🟩
- 30k → 20k（增生 70%）兩塊打平、−31%；20k → 17k 再 −12～13%、換塊 +0.007／+0.001（代價地下 +0.5～0.6 層、F1 −.01～−.018，被 §3 的機制吃回）。
- 依據：時間約 1 分／千步；增生期佔 85～90% 的多出時間；增生期太短（15k）b1／b4 掉分 => 17k／70% 是甜蜜點。

## 2. 速度（全部不改或幾乎不改畫質）

### 2.1 V/C warp 先加總、零梯度像素略過（11-05）🟩（工程）
- 訓練 forward 順便累加 trim 要的 V（Σ T·α）／C（覆蓋像素）時，每個配對先在 warp 內加總再寫 shared：增生期 −8.5%，覆蓋數與渲染逐位元相同。
- backward 不處理上游梯度全 0 的像素（塊外遮罩 C 區）：−1.7%，梯度只差加總順序。

### 2.2 低解析度前段＋dist 每 8 步＋不記 log（11-13）🟩
- 單項兩塊一致才疊：低解析度前段（換塊 +0.015／+0.014、−15%）、dist 每 8 步（−5%）、train log 只記首尾（約 −6%）＋20k／70% => **純訓練 12.3／13.2 → 6.7／7.1 分（−46%）**，換塊 −0.004／+0.008、LPIPS 平。

### 2.3 demo 模式：啟動最佳化（11-14）🟩（工程）
- 拆出啟動 196 s 的組成：冷硬碟讀影像 102 s、純 Python 解析 SfM 檔兩次約 26 s、訓練中驗證 54 s。
- 做法（全部不改訓練結果、有逐值測試）：SfM 陣列化快速讀取＋快取、關訓練中驗證（評估一律離線）、讀預先縮好的影像（無損 PNG、逐位元相同）、不產生 log；每塊寫 `run_summary.json`（時間拆解、顆數、VRAM 峰值）。
- 結果：本機到第一步 38 s、訓練外只剩約 3.5%。

### 2.4 三段低解析度＋幾何步半解析度（11-17）🟨
- 三段低解析度 `lres3`：前 25／50／75% 的步數用 0.35／0.5／0.75 倍解析度（承 coarse-to-fine 解析度排程，如 DashGaussian；我方只用三段、不改步數）。
- 幾何步半解析度 `geo50`：每 8 步的完整路徑步（法向＋深度上限＋閘門＋dist，一步是一般步的 2～2.4 倍）用 0.5 倍解析度。
- 結果（b1／b4 對新底 6）：**純訓練 −12.0／−11.7%**、換塊 ±0.002、F1 +.008／+.005、陸地地下 −0.67／−0.27 層；代價 LPIPS +.0011／+.0023（全場景 LPIPS 落後的主因）。

### 2.5 光柵器逐 warp 盒外跳過、逐 warp 配對位元（11-16）🟨
- 量測：每像素迴圈 86～96 次、真正混合 24%；沒混合的 73～76% 在顆粒自己的精確支撐盒外。
- `skip_box`：warp（16x2 像素條）粒度，用精確圓錐盒在 α ≥ 1/255 的半徑 `R = sqrt(2 ln(255 o))` 判，盒外配對整個 warp 跳過 => **一般步 −7.8～−9.0%、渲染逐位元相同**（承 StopThePop §3.4 逐 tile 剔除、Speedy-Splat AccuTile；我方改 warp 粒度與精確圓錐盒）。
- `pair_bit_warp`：forward 記 8 個 warp 各自有沒有混合，backward 只走位元為 1 的配對 => 再 −3～4%（承 Taming 3DGS §4.1；順帶修正 backward 近平面判準與 forward 不一致）。

### 2.6 預讀下一塊（11-19）🟩（工程）
- 全場景啟動 17.1 分、其中快取影像 13.1 分（冷硬碟 35～120 ms／張、熱 17 ms）；訓練時硬碟閒著 => 本塊訓練時背景讀下一塊的檔案清單。
- 結果（新底 9 全場景）：**啟動 17.1 → 11.3 分（−34%）、整個訓練任務 −11%**；lab 容器記憶體滿時只讀一次的頁面會被擠掉 => 改讀兩次（待下一次全場景驗證，最多再省約 6 分）。

## 3. 畫質與幾何

### 3.1 點精靈下限 `px_floor`（11-07）🟩
- 病因：2DGS 走低通濾波分支時尺度拿不到光度梯度、scale 正則往下推 => 吸收態的約 1 px 不透明點（路燈帶 66%、車輛帶 72%、地面 59%；CityGS 0%）。
- 做法：每 1000 步重算每顆的像素長度，尺度不准低於約 1 px（新點繼承母點）。
- 結果：燈柱回來、地面覆蓋 0.55 → 0.77、**F1 +.017／+.034**（b3／b12）、畫質平、時間 +2%。

### 3.2 法向一致性每 8 步（11-04～07）⬜＋🟩
- 2DGS 的法向一致性（渲染法向對深度法向，⬜）；我方每 8 步算一次、權重 ×8（🟩）。牆面朝向 0.77 → 0.94、立面貼牆 0.96～0.97。

### 3.3 深度支撐閘門（投票、SfM 豁免）（10-31 → 11-07）🟩
- 顆粒中心投到每個視角、對先驗深度的殘差在 400 步視窗內多數票說「在前方」或從不貼面 => 不往 1 推熵、MCMC 抽母點 ×1e-3；離 SfM 點 8 倍近鄰間距內不判（不把塔頂壓成煙）。
- 結果：海上浮塊 −83～94%、PSNR 持平、時間 +0～4%（投票每 8 步版）。

### 3.4 L1 混 L2（11-07）🟨
- 光度 loss 加 2 x L2（L2 本身是標準 loss）：留住 b2 超高塔頂、b3 +0.05，**反而省 8% 時間**（收斂較快）。

### 3.5 合併後刪除（10-31 → 11-07）🟨
- 互為最佳、同平面、同色的鄰居做質量守恆的矩匹配合併（承 surfel fusion／NanoGS 的兩兩合併），被併的刪掉並扣名額；3k 到 90% 步數，每 1500 步、每次最多 2%。
- 結果：顆數 −16%、PSNR 平、浮塊 −24～41%、時間 −3～7%。

### 3.6 新基準：位置學習率回 ×1、拿掉視線一致性 v4（11-10）🟩（診斷）
- 11-09 全場景退步 −0.33 dB（掉在磚牆窗格的 b1／b4／b0）逐項拿掉：位置 lr ×2 補回 87%、v4 補回 49%。
- 結果：三塊畫質追平 A＋dist4（換塊 +0.092／+0.026 vs +0.080／+0.016）、F1 +.032／+.024、地下 −40／−38%、時間 −4／−2%。教訓：候選一律在 b1／b4 驗。

### 3.7 鄰域平面約束每 16 步（11-10）🟨
- 不渲染：Morton 近鄰 PCA 平面（每 400 步重算），把面元拉近平面、朝向對齊（同類：PGSR／GaussianPro 的平面先驗；我方不渲染、不需要深度圖）。
- 結果：朝向 0.91、浮塊 −22%、低角度不變差；換塊 +0.093／+0.034、F1 +.033／+.016。

### 3.8 SfM 三角形校正深度＋逐貢獻深度上限＋只罰躺平（11-11～12）🟩 ★主線
- 問題：路面大半在地底（A＋dist4 b3 地下 4.92 層、正確高度只 0.54 層；CityGS 1.08）——地下顆粒從表面層的縫補顏色，空拍 test 看不出來，低角度變成半透明。單目深度 ±10% 太粗看不出來。
- 校正深度：每張影像用 SfM 點的 Delaunay 三角形對單目深度做分片校正，附可靠度分級 => **深度誤差中位 2.15% → 0.15%**。
- 逐貢獻深度上限（光柵器內算）：`B(p) = Σ_i T_i α_i max(z_i / ((1+m) z_prior(p)) − 1, 0)`，每一份落在先驗表面後面超過 1% 的混合貢獻依權重罰（中位深度 loss 碰不到的「後面的層」也罰得到）。
- 只罰躺平：只在先驗表面 |n_z| > 0.8 的像素設上限（立面與樓頂突出物不誤罰）。
- 結果（b1／b4 對 A＋dist4）：換塊 −0.012／−0.023、**F1 +.11／+.11、地下 −73／−75%**、時間 −4%（b4）。

### 3.9 高塔遮罩（11-13）🟩
- 塊外遮罩（每像素 A 塊內／B 塊外要透明／C 不計分）原本用單目深度判，高樓頂單目壓扁 => 接縫旁 200 m 以上的監督只剩 87%；改用校正深度判 => 97%。
- 結果：**b2 +0.058、b6 +0.019**、b1 平、時間不變。

### 3.10 三角式稠密起點、深度上限只補前面（11-15）🟩
- 稠密起點：可靠像素沿校正深度反投影補到 0.9 cap（不撒空中隨機點）。b1／b4／b3／b2 換塊打平、**F1 四塊都升**、塔立面 +2.4／+3.1 pt、0～250 m 立面覆蓋 +1～4 pt、朝向 +3～7 pt。
- 只補前面（`capfc`）：深度上限的梯度只推「落在後面的那一份」往前，不拉其他層 => **地下 −21～−43%**、F1 −.002～−.018（取捨，使用者採用）。

### 3.11 海面：海面物件、錨定海面層、海面上限、浮塊收回（11-17～19）🟩
- 問題：全場景最大的落差——A＋dist4 海面上方不透明顆粒 77,669 vs CityGS 5,663；SfM 看得到海，是訓練把海面抬起來；平視有白色針狀霧、港口有煙團。
- 海面物件（v9）：各影像海面區平面擬合 => 多視角共識平面＋海面格投票；水面高度自動算（水體偵測，分開的水面各自處理）；只在有證據的地方鋪（不外推）、補齊交界。
- 錨定海面層：每個海面格一顆面元，每步位置還原、法向固定、尺度夾住，不搬家／不剪枝／不當母點、名額另算（延伸 11-05 的 SfM 錨點）。
- 海面上限：深度上限在海面寬遮罩上用共識平面深度。
- 浮塊收回：海面格上方 > 1 格、水面下 > 0.5 格、離「非水面」可靠 SfM > 1 格的自由顆粒，增生事件時交給 MCMC 搬家、增生後刪（11-19 發現原本水面上的 SfM 點把附近浮塊都保護住了 => 拿掉）。
- 結果：b1 海面上方 > 20 m 浮塊 **1,497 → 3**、可見面積 −99%（CityGS b1 307 顆）；b3 −81%；換塊 −0.005／−0.010、F1 +.016／+.007；港口煙團消失；**水面下針狀面元 b1／b3 −99%／−97%**；60k 長訓練的海面浮塊 237.8k → 1.8k m²；時間不變（海面層的同步讀檔改背景預讀後）。

### 3.12 正則只算畫面內（11-18）🟩
- 尺度、熵等正則原本對全部顆粒取平均 => 不在畫面內的顆粒（大多是別處的塔頂）每步被正則推、卻沒有光度梯度拉回；改成只對本步可見的顆粒取加權平均。
- 結果（對同底）：b2 換塊 +0.045、塔頂 GT 量尺明顯變好；b1／b3／b4 ±0.01；時間在雜訊內。

### 3.13 海面起點不去下方離群（11-19）🟩
- 拆解（新底 6 起點只改一項）：起點的「去下方離群」讓陸地地下層 +0.18～+0.41 層，PSNR 不變 => 拿掉。
- 結果（b1／b3／b4）：換塊打平、地下 −0.29／+0.11／−0.11（起點重產雜訊 ±0.06）、海面看不出差別；資料準備少一步。
