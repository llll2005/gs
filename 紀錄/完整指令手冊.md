### 0-1. 排程器（**鐵律：只用這一套，不准自己寫 watcher**）

單卡序列，所以一定要有東西持有佇列。那個東西已經存在：

```bash
setsid nohup bash scripts/runner.sh > /dev/null 2>&1 < /dev/null &   # 起（通常已經在跑）
```
```bash
$EDITOR scripts/queue.txt          # 一行一個任務；跑動中也可以改／加／重排
```
```bash
python tools/queue_status.py       # 現在在跑什麼、佇列裡還有什麼、最近完成
```
```bash
tail -f logs/runner.log            # 即時輸出
```
```bash
touch scripts/queue.stop           # 做完目前這個就停
```

規則：
- runner **每個任務開始前重讀 `queue.txt`** ⇒ **只有正在執行的那一行是固定的**，底下都可以改。
- 長指令放 `scripts/task_*.sh`，佇列行只呼叫它。**佇列行不可含 `$(...)` 或反斜線。**
- 任務行**正上方緊鄰的 `#` 註解區塊**會成為台帳標籤（含 ★ 的那行優先）。區塊錯位 =
  標籤掛錯跑次（發生過兩次）⇒ 用 `tools/queue_status.py` 確認「標籤 ↔ 指令」對得上。
- 不碰 GPU 的工作加 `[cpu]` 前綴，才不會排在訓練後面。
- GPU 是否空閒**由 `nvidia-smi` 的 VRAM 判定（<1500 MiB = 空）**。
  ⛔ **不准用 `pgrep`**：`conda run` 會改寫 cmdline、殭屍照樣匹配、檢查用的 shell 會匹配到自己
  —— 三種都害過這個專案空等（最久 2.5 小時）。
- `flock` 擋第二個 runner。

`results.txt` **不寫步數** ⇒ 半途 OOM 的跑次會留下看起來正常的分數（曾害我擬出一條假關係）。

### 0-4. 複製任務腳本之後

```bash
python tools/lint_task_scripts.py
```
`sed` 複製腳本會漏改 `rm -rf outputs/X`，曾經刪光一整組跑次。這支檢查

### 3-1. 單塊訓練
```bash
bash scripts/lab/task_cmp.sh --help                                                     # 臂清單（每臂的覆寫旗標）與環境變數
CITYGS_GRID=44 CITYGS_LEAN=1 STEPS=60000 CITYGS_FAMILY=g44_ bash scripts/lab/task_cmp.sh 6 best1      # 基底 best1

```
- 跑次名＝`<家族><臂>`，lab 上落在 `outputs/lab/<跑次>/blocks/block_<B>/`；`best1<X>`＝`best<X>` 的配方再加 best1 的組成（opacity_reg 0＋二元熵＋V/C＋兩個 backward 加速）。
- 佇列行慣例：尾巴加 `--model.renderer.init_args.record_reduce true --model.renderer.init_args.absgrad_gate true`（與單變數臂一致）。
- **環境變數**：`STEPS`（全長；增生期＝STEPS/2、LR 積分跟著縮）／`CITYGS_LEAN=1`（渲染逐位元相同、每步 −21%）／`CITYGS_CAP`（cap_max，預設 2.6M）／
  `CITYGS_DUP44`（覆寫 dup 份數）／`CITYGS_SAVE_ITERS`（中間存檔；**預設 `[]` 只存最終**，10-18 起）／`CITYGS_RUN_NAME`。
- ⛔ **需要幾何通道的臂不能開 lean**（`*dist*`、`*normal`、`*depth`、`*geo`；腳本會擋）=> 連帶不能用累加式 trim（`trim_running_vc` 要 lean）。

## 8. 執行台帳 `logs/quad_progress.log`（2026-07-28 改為程序自寫）

**格式（固定，不再由腳本拼字串）**：
```
MM-DD HH:MM | <run 名稱, 24 欄>   | START/DONE/DIED  <結構化欄位>
```
實例：
```
07-28 21:27 | b12_cap2m_reg000_exact   | START  max_steps=60,000 cap=2.00M opacity_reg=0.0 out=outputs/...
07-28 21:27 | b12_cap2m_reg000_exact   | DONE   step=60,000/60,000 N=1.93M 4.12it/s VRAM=4.83/6.1G PSNR=23.457@60,000
07-28 21:27 | b12_cap2m_reg000_exact   | DIED   OutOfMemoryError: CUDA out of memory... | step=12,345/60,000 N=1.93M ...
```

**由誰寫**：`internal/callbacks.py` 的 `TrainConsole._progress()`，掛在 `setup`(START) /
`on_train_end`(DONE) / `on_exception`(DIED)。數值直接取自 live footer 與 `state.vals`。

**為何改**：舊做法是**每個腳本各自 grep 訓練 log 再拼字串**，結果
(1) 把 tqdm 進度條與 ANSI 逃脫碼一起撈進台帳（`DONE rc=0 Epoch 5: 29%|██▊ |...[A[A`），
(2) 各腳本欄寬漂移（`%-22s` vs `%-24s`），
(3) 跑掛的時候常常什麼都沒寫（grep 不到 results.txt 就靜默）。

**規則**：
- **腳本不得再寫 START/DONE/DIED**——那三個由程序負責。
- 腳本的 `log()` 只寫**程序不可能知道的佇列層事件**（等 GPU、批次邊界），一律加 `QUEUE ` 前綴。
- 台帳寫入失敗**絕不影響訓練**（`_progress` 整段包在 try/except）。

#### 安插任務（在尾巴加）

⚠ 註解區塊與任務行之間**不可有空行**，否則台帳會把上一個任務的標題掛到這個跑次上。

#### 殺掉單一任務 / 全部任務

#### 暫停 / 恢復（不丟進度）

```bash
labrun "kill -STOP <python_pid>"      # 凍結：行程留著、**VRAM 不會釋放**
labrun "kill -CONT <python_pid>"      # 解凍
```
⚠ `SIGSTOP` **不釋放 VRAM** ⇒ 想騰出卡來跑別的，暫停沒用，只能殺掉或等它跑完。

#### 獨佔整張卡

佇列行前面加 `[solo]`：
```bash
labrun "cd /workspace/data/hdd/11213/gs; printf '\n# ★ 要獨佔整張卡的量測\n[solo] bash scripts/lab/task_allocfrag.sh\n' >> scripts/queue.txt"
```
runner 看到下一個是 `[solo]` 就**等現有任務全部跑完**才啟動它，而且它跑的時候**不開任何其他槽**。
用在「量時間/量 VRAM 碎片」這種會被鄰居干擾的任務上。

其他前綴：`[cpu]` = 這個任務不碰 GPU，**不必等卡**（分割、depth-init、分析類）。
⚠ `[cpu]` **仍然佔一個槽** —— 它省掉的是「等 VRAM 空出來」那道關卡，不是「額外多開一條」。
⚠ `[solo]` **不檢查 VRAM 餘量**（它靠「等到沒有別的任務」來保證獨佔）⇒ 如果有**不是 runner
  起的**行程佔著卡（見坑 ①），`[solo]` 還是會啟動，然後可能 OOM。

#### 啟動 / 重啟 runner

```bash
labrun "cd /workspace/data/hdd/11213/gs; ps -eo pid,cmd | grep 'runner.sh' | grep -v grep | cat"   # 先確認沒有在跑
labrun "cd /workspace/data/hdd/11213/gs; RUNNER_SLOTS=3 setsid nohup bash scripts/runner.sh > /dev/null 2>&1 < /dev/null &"
```
`flock` 會擋住第二個 runner（會印「另一個 runner 已在執行」），所以重複啟動是安全的。

可調的環境變數（啟動時給）：
```

RUNNER_GPU_RESERVE_MIB=6800 還要剩多少 MiB 才准再開一個（一個 6GB 信封的跑次）
RUNNER_STAGGER=90           兩次啟動間隔幾秒（避開同時配置的尖峰）
RUNNER_QUEUE=<檔>           指向別的佇列檔（乾跑測試用）
```
