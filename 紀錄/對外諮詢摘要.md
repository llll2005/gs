## 1. 專案目標與硬體條件

把 **CityGaussianV2**（ICLR 2025，大場景 3D 高斯潑濺重建）做出**低資源平替**：
在**單張 RTX 4050 Laptop（6 GB VRAM）**上訓練城市級 2D Gaussian Splatting，
品質要能與原方法競爭。

| | CityGaussianV2（論文） | 我方 |
|---|---|---|
| 硬體 | 8×A100，記憶體 14.2~31.5 GB | **單張 6 GB**（46 GB 系統 RAM） |
| 資料 | MatrixCity aerial | 同 |
| 論文分數 | **27.23 PSNR**（全場景合併） | 見下 |

**表徵**：2DGS（2D Gaussian Surfel）+ 球諧 sh_degree 3
**密度控制**：3DGS-MCMC（relocation 式），非原版的梯度門檻 ADC
**初始化**：Depth-Anything-V2 偽深度反投影（非官方的全域 coarse 模型）
**分塊**：5×5 grid，逐塊獨立訓練。b12 = 284 訓練相機 / 36 驗證；60,000 步、約 10 小時/塊

## 3. 當前最優解

**`sched30` + `absgrad_densify 2.0`**

```
                        PSNR(最後4點均)  PSNR(終點)  SSIM     LPIPS
block 12                   26.560         26.782    0.7755   0.3467
block  7                   25.136           —       0.8087   0.2425
顆數 2.34M ／ VRAM 5.6~5.7 GB（6.1 上限）／ 約 10 小時/塊
```

**組態**：cap_max 2.6M ／ densify_until_iter 30,000 ／ opacity_reg 0.002 ／ scale_reg 0.007
／ lambda_normal **0** ／ depth_loss **0** ／ screen_size_prune_px 300 ／ 60,000 步

**`absgrad_densify` 是什麼**：MCMC 用 `probs = opacity` 抽「父代」來安置回收的粒子，
完全沒有誤差項。我方把 **AbsGS 的絕對值位置梯度** `|g|` 接進去：
`probs = opacity × (1 + w·|g|/mean|g|)`。

- 為何是 `|g|` 而不是我方自製的誤差分數：先量**天花板** `ceiling(top5%)/mean` ——
  我方誤差分數只有 **1.22×**（完美取樣器也賺不到），`|g|` 是 **16.68×**。
- 2DGS 的 viewspace 梯度**不是** 3DGS 的對應物（只在次像素 fallback 分支被寫）；
  真正的對應物是 `dL_ds`，我方在 CUDA 裡把 `|dL_ds|` 累加進**從未被讀取的**
  `dL_dmean2D.z`（渲染與梯度逐位元不變）。
- 強度 `w` 是**倒 U**：w=1 → 26.38、**w=2 → 26.56**、w=3 → 26.39（w=3 三指標全輸 w=2）。

## 5. ⛔ 已排除的方向（**請避免重複建議**）

全部是**修正後**的實測，判準同 §2。

### 5.1 密度控制／族群組成 —— 八次介入，全部碰不到核心問題
| 介入 | 結果 |
|---|---|
| `cost_aware_densify`（往渲染成本低處增生） | **六項全平**；且實測它連渲染負載都沒移動（+1.9%，方向還錯） |
| `vpc_prune_frac`（剪掉低 value-per-cost） | **−2.34 dB**。走的是 relocation ⇒「破壞集合」；而「改變集合」才有效 |
| `err_guided_densify`（我方誤差分數導向） | 天花板只有 1.22× ⇒ 沒有空間；且該旗標當時是**死碼** |
| `densify_until` 30k→36k | PSNR −11.0sd、SSIM −35.6sd |
| `blur_split`（Mini-Splatting 式，按模糊分裂） | 只動到水面；疊到高 cap 上三項在噪音內、最差 10% 更差 |
| `scale_reg = 0` | −18sd。它做的「塵埃」是它壓住尺度上限的副產物 |
| 收割期移除 `opacity_reg` | 判死率 15.03%→7.82%、確信率 +15.59pp（**機制完全成功**），PSNR **−3.4sd** |
| 收割期回收死粒子（relocation 續跑） | 判死率 15.03%→**0.00%**（最徹底），PSNR **−3.6sd** |

> **⇒ 族群組成可以被大幅改造（死亡率 15%→0%、確信率 23%→39%），而 PSNR 與
> 「糊掉%」都不動。這是「剩下的差距不是密度問題」最強的證據。**

### 5.2 幾何正則項 —— 把 CityGSV2 有、我方關掉的加回來，兩個都更差
| 介入 | PSNR | SSIM | 「糊掉%」 |
|---|---|---|---|
| `depth_loss 0.5`（偽深度監督） | −19.0sd | −111.8sd | 46.08 → 48.52（更差） |
| `lambda_normal 0.0125`（法線一致性） | −22.3sd | −191.6sd | 46.08 → **49.45**（更差） |

判準是**事前指定**的（主看尾巴指標而非平均），**兩者在平均與尾巴上同時輸**。
機制量測：法線一致性讓判死率**多 48%**，代價幾乎全來自 `0.05~0.5` 的中高不透明度帶
（−8.40pp）——而好視角正是靠那批半透明粒子平滑混合做出來的。

⚠ 偽深度的誤差是**表面解析度的 174 倍**，粒子早已貼到它的極限 ⇒「深度監督已榨乾」。

### 5.3 表徵
- **SH0 高顆數**：4.96M 顆只有 24.16（遠輸現行 26.5）⇒ 「換低階 SH 換顆數」不是出路
- **Spherical Beta 色彩（SB）**：SB-4 帶 +35% 顆粒**六項指標全輸**；SB-16 OOM 且慢 2.2×

### 5.4 省時間
- `trim` 相機取樣 stride=4（省 8.7% wall time）：PSNR **−6.7sd** ⇒ 否決
- `fused_ssim`：宣稱省 4.9%，但 SSIM 是同組態重跑的離群值（−4.06sd）⇒ 已退回
- MCMC noise 的等價改寫（免 materialize N×3×3）：**實測省 44% 該項但只佔每步 4.2%**，
  低於跨跑次噪音底 ⇒ 已實作為旗標但預設關閉

## 6. ★ 核心未解問題：40~46% 的 tile「只剩低頻」

這是目前最大的缺口，而且**上面所有機制都碰不到它**。

### 6.1 現象（量測，非推測）
把畫面切成 48×48 px 的 tile，逐 tile 對 GT 線性迴歸 render：

```
只看**紋理最強的 15%** 的 tile（排除平坦區，避免相關係數在低變異下失去意義）：
                GT 紋理   render 紋理   render/GT   GT 亮度   render 亮度
持續糊掉        0.0789     0.0129      **0.16**     0.310     0.294
從不糊掉        0.1612     0.1508        0.94       0.333     0.324
                                    佔比 **39.8%**
```

**是雙峰的**：一半的 tile 紋理保留 94%，40% 只保留 16%，而**低頻（亮度）兩邊都正確**。
不是「整體有點糊」，是「要嘛幾乎完美、要嘛只剩低頻」。

### 6.2 位置高度持續
跨 5 個不同配方的「糊掉 tile」交集 / 聯集 = **68.2%**（隨機的話只有約 2%）。
兩兩比更高（78.7~82.6%）⇒ **位置主要由輸入決定，不由訓練動力學決定**，
這解釋了為何 §5.1 的八次介入全部無效。

### 6.3 已排除的三個解釋（都用 SfM 點雲投影量測，零 GPU）
| 假說 | 預測 | 實測 | 判定 |
|---|---|---|---|
| 遠場／內容超出塊的空間範圍 | 糊掉區深度明顯大 | 深度比 **1.09×**（幾乎相同） | ⛔ 推翻 |
| SfM 取樣不足 | 糊掉區點數明顯少 | 點數比 **1.43×（反而更多）**，零點 tile **0.0%** | ⛔ 推翻 |
| 深度不連續（2D 面片跨越邊緣被平均） | 糊掉區深度離散大 | 離散比 **0.83×（反而更平坦）** | ⛔ 推翻 |

### 6.4 目前對它的完整畫像
```
持續糊掉的 tile：
  幾何平坦（深度離散比從不糊掉的 0.83×）
  SfM 特徵密集（點數 1.43×）
  影像紋理中等（GT 0.0789 vs 0.1612）
  render 抹掉 84% 的紋理，但**亮度完全正確**
  空間上集中在畫面上半（縱向位置中位 0.294 vs 0.529）
```
⚠ 「畫面上半」在近垂直的空拍影像裡**不代表更遠**（深度已證相同），
它代表世界座標的某個方向 ⇒ **失效是空間上結構化的，但成因未知**。

## 7. 已量到的資源結構（可能對建議有幫助）

**VRAM 分項**（載入 60k ckpt 後用 CUDA 逐段量，N=2.34M）
```
逐顆參數            0.506 GB   （實測 58.0 floats/顆 = sh3）
+ 梯度              0.506 GB
+ Adam 兩個動量      1.011 GB
常駐小計            2.022 GB   <- 只隨顆數變化
渲染 forward 峰值    1.214 GB   <- 只隨渲染成本變化
                               => 儲存佔 62.5%，渲染佔 37.5%
```

**每步時間分項**（CUDA event，同 process，多次取中位數）
```
光柵化 forward         110.5 ms
forward+backward       259.4 ms（含 forward ⇒ backward 約 149 ms）
MCMC noise (cov3d+bmm)  59.4 ms
SSIM                    13.6 ms
L1                       0.5 ms
已量總和               443.3 ms；實際每步 602 ms ⇒ 約 269 ms（45%）是
                       optimizer step + 框架開銷（未細分）
```

**成本與顆數是解耦的**（沿同一條訓練軌跡量五個 ckpt）
```
step 14,999  N=1.31M  渲染負載 20.95M
step 29,999  N=2.60M  渲染負載 22.92M   <- 顆數 +98% 而成本只 +9.4%
step 60,000  N=2.34M  渲染負載 23.11M
```
⇒ 模型在 step 15k 就付掉了最終渲染成本的 91%，卻只用了最終顆數的 56%。
⇒ 「按顆數計價」（`cap_max`）是錯的貨幣。

**其他**
- cap 只交付 **90%**：cap 2.6M → 終點 2.34M
- 終點有 **15.03%** 的粒子 opacity ≤ 1/255（不進 binning、零貢獻、純佔儲存）
- 顆數槓桿實測 **+0.541 dB/加倍**（修正後）；補到論文的 27.23 需要不可行的顆數
