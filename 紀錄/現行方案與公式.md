## §1 需求側：對渲染成本計價

### 1.1 總式與拉格朗日
存在性指示函數不可微 → 用 opacity 當「軟存在指示」鬆弛：
```
min_θ  ℓ(θ)        s.t.   Σ_i c_i · o_i  ≤  B
L = ℓ(θ) + λ(Σ_i c_i o_i − B)
∂L/∂o_i = ∂ℓ/∂o_i + λ·c_i          ← 正則梯度 = 影子價格 × 該點成本
```
**前人皆為 `c_i ≡ 1` 的特例**（見 §4）→「顆數是錯的計價單位」從口號變成數學上的特例關係。
KKT 互補鬆弛 ⇒ **預算未緊時 `λ=0`（零懲罰）**，只有撞頂才收費。

### 1.2 更新式（DAR 解耦）
承 AdamW-GS（ICLR 2026, arXiv 2601.16736）兩點：正則梯度**不進** Adam 動量、用 `1/√v̂` 預條件。
實作為 `on_train_batch_end` hook（`optimizer.step()` 之後）→ Adam 動量保持純光度：
```
o_logit_i  −=  lr_o · min( λ · ĉ_i · u_i ,  C_t ),     u_i = √ε/√(v̂_i+ε) ∈ (0,1]
                       └成本┘ └敏感度┘   └速率上限┘     ε = dar_eps = 1e-8
```
**運籌學讀法**：壓力 = 資源價格 × 數量 / 邊際敏感度 = 市場定價。

**⚠ 兩件必須誠實寫進論文的事（2026-07-28 CPU 實測，用 b12@30k 自己的 Adam 狀態）**：

1. **`u_i` 在我方 regime 是惰性的，但這反而讓我方回到 AdamW 正典**（2026-07-28 讀 AdamW 原文後修正敘事）。
   實測 `v̂` 中位 **1.2e-17 ≪ ε** → `u_i ≈ 1` 對 99% 的點成立 ⇒ stride 實際上就是 `min(λ·ĉ_i, C_t)`。
   **AdamW Algorithm 2 第 12 行的解耦項本來就是純的 `λθ`，沒有 `1/√v̂`**，而且原文明講理由：
   「decoupled weight decay regularizes **all weights with the same rate λ**」。
   ⇒ **我方形式 ＝ AdamW 正典的解耦衰減，把「均一 rate λ」推廣成「rate `λ·ĉ_i` 依資源成本加權」。**
   AdamW-GS 的 `1/√v̂` 預條件是更強的推廣，**且與 AdamW 的核心論證相左**；本工作實測為惰性，
   故程式保留（零成本、他 regime 會生效）但**不宣稱其貢獻**。
2. **`v̂` 是平方梯度 EMA，量的是「光度損失對該點的絕對敏感度」，不是有號的效用**——
   「該變不透明」與「該消失」兩種點都給大 `√v̂`。「邊際效用」是敘事類比，論文須補這層數學定義。

**★ε 的位置是個真 bug（差 10000 倍）**：先前寫成 `1/(√v̂ + ε)`（ε 在外），`1/√v̂` 衝到 1e8，
`λ·ĉ·inv` **對 100% 的點都撞上 `C_t` 飽和**——連 λ 縮到 5e-4 都一樣——**把 `ĉ` 的 7× 差異
壓平成 1.00×，退化成本機制要取代的均勻衰減**。ε 必須在 `√` 裡（AdamW-GS Eq.8 原本就是），
再除以自身上界 `1/√ε` 正規化，`λ` 才有可讀刻度。

### 1.3 成本項 `ĉ_i`：兩層壓縮
```
ĉ_i = c_storage + log1p( min(r_i², H²+W²) / median(r²) )        c_storage = 0.1
```
- **物理上限截斷**：一顆 splat 的光柵化成本不可能超過整張畫面 → `r²` 夾在螢幕對角線²。
  必要性：**投影 Jacobian 在 z→0 是奇異點**，z~0.02 的 surfel 會報 `r²~1e16`（數學假象非成本）。
  實測 b12@30k：動態範圍 **5.8e11× → 52×**，19.4% 的點夾在滿格，怪物/正常鑑別力保住 **19.9×**。
- **log1p + 中位數正規化**：讓 `ĉ` 是 O(1)，`λ` 與場景無關。
- **`c_storage` 有物理意義** = 每點的 model-state 人頭稅（`F·4·M` bytes，與螢幕足跡無關）
  → 塵埃仍有緩慢衰減壓力，不會像 `opacity_reg=0` 那樣無限膨脹。

**壓力重分配（實測 b12，vs 現行 L1 的 1:1）**：塵埃 `ĉ=0.10`（×0.10）、大足跡 `ĉ=7.0`（×7.0）＝ **70:1**。

### 1.4 `C_t` 是速率上限，不是數值常數
```
t_death ≥ Δlogit / (lr_o · C_t)          Δlogit = 5.29  (o: 0.5 → min_opacity 0.005)
```
→ `C_t` 給出**保證最短存活時間**。這是我方對 DAR 的補強（原文只當數值安全常數）。

**但 `C_t` 有個上下夾擊，這是選它的真正約束**：
- **太大**（1.0 → 106 步）＝與死亡跑步機同速。
- **太小則 clip 綁住 → 把成本訊號壓平**：實測 `C_t=0.1` 有 **30% 的點飽和，壓力比從 6.98× 塌到 3.42×**。
- **`C_t` 必須高於最貴族群的 stride**。λ=0.05 下 stride 實測 0.015(正常)/0.029(塵埃)/0.204(大足跡)
  → **`C_t=0.25` 飽和 0%、壓力比 6.98× 完整保留、最短存活 423 步**。← 現行值

**真表面靠什麼活？不是 `ĉ`（它 2.47 > 1，壓力比塵埃還大），是 Adam 自己**：
有一致光度梯度的點，Adam 每步推回 ~`lr`；衰減只有 `lr·stride`。真表面 stride 0.123 → **回推力是衰減的 8×**。
這正是「Adam 尺度不變性」（曾使 `opacity_reg` 調整無效的同一個性質）**反過來為我方所用**：
**有梯度的點抗得住，沒梯度的點按 `ĉ` 排序沉下去。**

### 1.5 兩個預測（**CPU 已量化，訓練待驗**）
λ=0.05 / `C_t`=0.25，用 b12@30k 自己的 Adam 二階動量算出的實際 stride：

| 點型 | n | `ĉ_i` | stride | 死亡步數 | vs stock L1+Adam |
|---|---|---|---|---|---|
| 次像素塵埃 o<0.01 | 758,320 | 0.58 | 0.029 | **3621** | 64–106 步 → **慢 34–57× ⇒ 跑步機萎縮** ✓ |
| 霧 0.01<o<0.1（binning 82%）| 210,797 | 1.31 | 0.066 | 1614 | 逃過 L1 → **會死** ✓ |
| 大足跡 r>2000px | 188,239 | 4.08 | 0.204 | **519** | 永不死 → **3.5 個 densify 週期內死** ✓ |
| 正常 10–300px | 553,182 | 0.30 | 0.015 | 7051 | 受保護 ✓ |
| 真表面 o>0.7 | 1,058 | 2.47 | 0.123 | 858 | 靠 Adam 回推（8× 餘裕）|

**實際壓力比 6.98×**（＝`ĉ` 的 7× 完整傳遞到 stride，飽和 0%）。現行 L1 是 1:1。

且**每步連續作用**，解掉「怪物在 150 步事件間隙內長成」的時序問題。
若兩預測成立，它**取代**現行一堆補丁（清塵事件／relocation 閥門／v/c 事件／凝結退火）。

## §2 供給側：`K` 是同一條約束的對偶變數

### 2.1 峰值 VRAM 模型（標定得出）
```
peak(N, load, K) = [ model_state + A·N ]      ← K 砍不到
                 + [ B·N + γ·load ] / K        ← per-strip backward 分攤
```
- `model_state = N·F·4·M`：params+grad+2×Adam（`M=4`）。SB `F=25` → 1.45M 僅 0.54G。
- `B·N` = **backward activation，∝N**，是漸進 OOM 的主因（不是 binning）。
- `γ·load` = binning buffer。**`γ_trim ≈ 6.8 B/相交` vs gsplat 23–36 → trim 每相交省 3–5×**。
- 標定（b12 SB）：`A≈500`、`B≈1550` B/pt；驗證 K=1→2.63G / K=4→1.14G 吻合。

### 2.2 兩個方向的解
同一條不等式，對 `N` 解得上限、對 `K` 解得條帶數——**`N_max` 與 `K` 是對偶變數**：
```
N_max = (V_target − V_os) / (M·F·4 + γ·τ/K)
K     = clip( ceil( (B·N + γ·load) / room ), 1, K_max ),   room = safety·(V_t−V_os) − (model_state + A·N)
若 room ≤ 0 → K_max
```
現行值：`V_target=5.4G`、`V_os=0.358G`(trim)、`safety=0.6`、`τ_growth=1.65`（τ 訓練中會長，init 值偏樂觀）。
逐塊 cap 表在 `紀錄/block_caps.csv`（b12 SB→3.71M、乖塊上看 9–10M）；τ 病理地圖 `block_taus.csv`。
**傳統 3DGS 把 `N_max` 當靜態約束，我們證明它有個對偶供給桿 `K` 可即時求解。**

### 2.3 load 估計含 Jacobian 拉伸
```
stretch = sqrt(1 + (x_cam/z)² + (y_cam/z)²)
r       = 3·fx·s_max/z · stretch
```
近軸近似會低估離軸點 1.35×（極端 10×）。加拉伸後 est-vs-real 全部 `est ≥ real`
→ **估計器是安全上界，K 只偏大不偏小**。代價：偏保守可能多切條帶。

**★這不是「物理直覺」而是可證的（2026-07-28 推導，見 `論文核對表.md` §4.1）**：
`stretch` ＝ 投影 Jacobian `J Jᵗ` **最大特徵值的平方根**。以 `a=x/z, b=y/z, r²=a²+b²`：
`M=[[1+a²,ab],[ab,1+b²]]`、`tr=2+r²`、`det=1+r²`、`tr²−4det=r⁴` ⇒ `λ_max=1+r²`、**`λ_min=1`**。
各向同性下**精確**，各向異性下因取 `s_max` 而為上界。`λ_min=1` ⇒ **拉伸純沿徑向**，次軸不變
——這就是「離軸近點被拉成掃過畫面的長條」的機制。

### 2.4 ★壓低 `τ`：分母的第四條路（2026-07-28，未實作，估計最大）
`N_max = (V_t−V_os)/(M·F·4 + γ·τ/K)` 的 **`τ`（每點 tile 數）本身可以降**，且**無損**：
```
剔除條件   o·exp(−½d²) < 1/255  ⟺  d > sqrt(2·ln(255·o))     ← 精確支撐半徑
           o ≤ 1/255 = 0.0039   ⟹  全域到不了門檻 → 整顆從 binning 剔除
現行       truncated_R = sqrt(9 + ln o)   ← TIGHTBBOX 啟發式（原註解自承 "no use in the paper"）
```
**無損性已驗**：`forward.cu:408` 與 `backward.cu:322` 都已有 `if (alpha < 1/255) continue;`
⇒ 最大 alpha 低於門檻的 tile **前向反向都貢獻零** ⇒ binning 剔除**位元級相同**。
**實測估計（b12@30k，基準＝實際出貨的平 3σ，因 `#define TIGHTBBOX 0`）**：58.5% 的點 `o≤1/255` 可整顆剔；
**保守版 `min(sqrt(2ln(255o)), 3)` 省 8.71×（+矩形 AABB 10.17×）→ 分母 947→463 → `N_max ×2.05`
（K=1: 1.70M→3.48M）**。程式已寫入（`EXACT_SUPPORT=1`），**待 DAR 跑完重編驗位元級相同**。
⚠ **區分兩種機制**（先前混為一談已修正）：框**形狀**收緊（正方→矩形 AABB）只 **1.14×**；
按**貢獻**剔 tile 才是 **4.30×**——因為霧的足跡大但貢獻處處低，只有後者抓得到。
風險與驗收見 `論文核對表.md` §11。

### 2.5 條帶正確性
route-2 camera-crop（純 Python，不碰 CUDA）+ per-strip forward/backward + `h/H` 加權。
合成 MSE vs K=1：gsplat 1e-14、trim 1.4e-4（**需 `pp_shifty`**——trim 的 `intrins` 硬寫 `(W/2,H/2)`，
不修就是 MSE 9.5e-3）。相交緩衝實測乾淨 `÷K`。

## §4 相關工作差異化（＝論文的敘事切割點）

| 工作 | 怎麼罰 | **按什麼計價 `c_i`** | 供給側 |
|---|---|---|---|
| 3DGS-MCMC | L1 進 loss（與 Adam 耦合）| **`c_i ≡ 1`** 成本盲 | 無 |
| **Taming 3DGS** (SIGGRAPH Asia 2024) | **不罰**——分數只決定「誰被複製」（純建構式，不剪不 culling）| **預算＝顆數**（Eq.2 `B`=final count）；分數含面積但當**需求**（`c_g` 權重 0.1：大投影=模糊=該分裂）| 無（但 per-splat backward 降常數）|
| AdamW-GS (ICLR 2026) | **解耦 + `1/√v̂`**（修好「怎麼罰」）| **`c_i ≡ 1`** 仍成本盲 | 無 |
| Gaussians on a Diet (2604.20046) | 離散 prune/grow 排程 | 影響力（非對偶非連續）| 無 |
| Confident Splatting (2506.22973) | 學習式 Beta 信心度剪枝 | 學習的信心度 | 無 |
| Pocket-SLAM (2606.24796) | 按渲染面積**保留** top-B | 面積＝**價值** | tile 空間配額 |
| FastGS (CVPR 2026) | 多視角一致性重要度剪枝 | render-grounded**價值** | 無 |
| **本工作** | 解耦（承 AdamW-GS）| **`c_i` = 渲染成本（VRAM 預算的對偶）** | **動態 `K`** |

→ 前人在調「怎麼罰」與「罰多少」；**我方補的是「按什麼計價」與「約束的供給側另一半」**。
**殺手級對照＝近相機怪物**：Pocket-SLAM 面積大→判重要→**保留**；我方成本大→v/c 低→**判死**。
同一顆點兩框架相反決策＝ area-as-value vs area-as-cost 的本質分野。

`K` 的文獻定位：NeRF ray chunking 是靜態祖先（ray 獨立、手設超參）；我方是**動態反解 + 在 splat-coupled
2DGS 上做到無損**。Deferred per-tile backward 是更細粒度版本但要改 CUDA。HiGS 是 inference-only（無 backward）。

### 4.1 與 Taming 3DGS 的細部對帳（**最近前作，2026-07-28 讀完原文**）

`參考論文/taming_3dgs.pdf`（SIGGRAPH Asia 2024，CMU + TU Graz，含 3DGS 原作者 Kerbl）

**它做了什麼**：
- **預算＝顆數，鐵證**：Eq.2 `A(x)=((B−S−2N)/N²)x²+2x+B`，原文 `B is the final count (budget)`；
  Alg.1 L1 `T ← Target Gaussian count`、L19 `B = T − |G|`。拋物線排程讓顆數**精確**落在使用者給的 B。
- **純建構式**：訓練期不剪不 culling → `Peak #G ≈ Final #G`
  （Table 1：0.29/0.29，對照 Mini-Splatting 0.31/**4.32** ＝ 14× 落差）。
- **分數式 densify**（Eq.4，8 訊號手調加權，每 500 步一次＝3DGS 的 1/5）：
  `o_g`(100)、`∇_g`(50)、`D_g`(50)、**`B_g` blending 權重和(50)**、`s_g` 世界尺度(25)、
  `S_v` saliency(10)、`z_g` 深度(5)、**`c_g` 像素數(0.1)**。
- **工程**：per-splat backward（取代 per-pixel 原子加總，warp shuffle 交換 pixel state）、
  SH 分批 Adam（每 16 步）、1D 可分離 SSIM。自稱勝 gsplat 1.0 約 1.5–2×。碼：`github.com/nullptr81/3dgs-accel`。

**★VRAM 全篇只出現一次，且是事後觀察**（p.10 末）：
> "our first budgeted scenario allows training with consistently **less than 10 GB VRAM**—compact enough
> for a mid-range **NVIDIA RTX 3080**."

→ 他們的「limited resources」＝ **10GB / RTX 3080**，VRAM 是**顆數預算的副產品，不是被解的約束**。我方 6GB 且直接解 VRAM。

**⚠ 三個必須修正的我方說法（不修就是 overclaim）**：
1. ❌「沒人用螢幕面積」→ **他們用了 `c_g` 像素數**，但當**需求**（大投影=模糊=該分裂），權重 0.1。
   → **同一個量第三次方向相反**：Pocket-SLAM 當價值、Taming 當需求、**我方當成本**。
   三篇前作都把面積當「要更多」的理由，**只有我方當「要收費」** ← 這反而讓切割點更鋒利。
2. ❌「render-grounded 價值是 FastGS 的洞見」→ **Taming 的 `B_g`（權重 50）就是多視角 `T·α`**，2024 年就有。
   我方 v/c 的**價值那半非原創**；原創在**比值**與**成本側**。
3. ❌「churn 完全沒人處理」→ **他們用純建構式避開 prune/regrow 峰值**，精神上有前例（Table 1 `Peak #G` 欄即證據）。
   我方仍成立的是：**沒人把 churn 當成本量化**（他們只有 peak count，沒有 churn 指標）。

**修正後我方剩下的切割點（更鋒利）**：
- 他們 8 個權重**全是手調超參**，且只決定「**誰被複製**」；我方 `λ` 是**有物理單位的影子價格**，決定「**誰每步付租金**」。
- 他們預算是**顆數**（與記憶體無因果）；我方是 **bytes** 且 `N_max` 可算。
  **反例**：b12 **0.32M 顆 OOM** vs b8 **1.53M 顆存活** ＝ 同顆數 VRAM 差 3 倍 → 顆數預算在病理塊上失效。
- 他們**無供給側**（無 K）。
- **可疊加不衝突**：他們的 per-splat backward 打的正是我方量到的 OOM 主因（`B·N` backward activation ∝N），
  是「**降常數**」；我方 K 是「**除以 K**」。理論上可同時開（代價：改 CUDA、與 trim rasterizer 非同一 codebase）。

## §5 現行未驗與已知歧異（**別誤讀成已驗證**）

- ❌❌ **`dar_lambda` 全長臂＝崩潰（2026-07-28 開獎，60k）**：**PSNR 10.40 / SSIM 0.070 / LPIPS 0.858**
  vs reg000 **23.16**、A' 22.12。**現行 DAR 實作不可用。**
  - **崩因已定位＝尺度崩塌，不是 opacity**：`log-scale P50 = −20.94`（≈8e-10）、**100% 的點 `scale<1e-6`**；
    對照 reg000 `log-scale P50 = −6.74`、僅 38.8% 低於 1e-6。**opacity 完全正常**（P50 0.80、68.7% 在 0.5 以上）
    ⇒ **不是機制過猛，是「只動 opacity 的干預把 scale 弄死」的間接耦合**（未預料）。
  - **機制本身運作正常**：applied 59501/59501 零早退、`clipped 0%`、`u med 1.000`、churn 0%、`o<0.005` 僅 0.3%。
    → **不是實作 bug，是設計層的耦合問題。**
  - **時間點**：smoke 的 1700 步正常（loss 0.161 / ssim 0.474），但 step ~5k 起 loss 就固定在 0.3–0.5
    （reg000 同期 0.039–0.14）→ **壞在 1.7k–6k 之間，smoke 太短看不到**。
    📌 **護欄：smoke 只能證偽「機制沒觸發」，不能證實「機制無害」——長度要蓋過 densify 期的動力學。**
  - **🧪 兩個廉價後續**（未跑，用以分辨假說）：
    (a) `scale_reg=0` + `dar_lambda=0.05` → 測 scale L1 是否共犯；
    (b) `dar_lambda` 降一個數量級（0.005）→ 測是否只是壓力過大。
  - **假說（標明為假說）**：低通 `FilterSize` 使縮小尺度**不降低峰值 alpha 卻減少受影響像素**；
    在 opacity 被持續外力壓制、primitive 永遠「還沒擬合好」的狀態下，**縮小足跡是降低 loss 的捷徑**
    → 縮小→覆蓋少→梯度訊號少→更難改善→再縮小的正回饋。此假說預測 (a) 救不回來、(b) 會有效。
- ⚠ **`c_i` 用「解析投影足跡」而非 rasterizer 的 radii 窗口**：窗口每個 densify 事件被清 →
  事件後過半點 radii=0、`ĉ` 塌到人頭稅地板＝150 步鋸齒（實測）。解析投影每點都有值、
  與動態 K 共用 `strip_cameras.projected_radius`。**但它是「當前視角」的成本，不是 `Σ_v c_iv`**——
  跨步平均後才近似多視角；若要嚴格對齊 §1 的定義，下一步是對 `r²` 做 EMA（設計未實作）。
- 🟡 `v_i` 有兩套：現行 = `1/√v̂`（Adam 動量）；程式裡另有 **多視角 `T·α` 貢獻**版
  （`_value_per_cost_mask`，訊號來自 trim 的 `record_transmittance`）。後者理論更對稱
  （價值與成本都 render-grounded），但**事件式版本在 b12 densify 期方向錯**（往 63% 過載的系統加處決）
  → 待低 churn 環境或乖塊重測。
- ⚠ `λ` 現為靜態。動態對偶上升 `λ ← max(0, λ+η(V_pred/V_target−1))` 是設計，**故意還沒接**
  （在 SGD 上易震盪；先用靜態 λ 驗機制）。反應式 λ 的舊版已證實會抖 + 滯後 OOM。
- ⚠ **b12@2M 未解，但 2026-07-28 縮小到兩個可行動候選**（用程式自己的常數算，非猜）：
  ```
  N=1.5M load=424M → fixed 1.26G  room +1.50G  K=8  預測峰值 2.71G  (預算 2.76G) ✓
  N=1.7M load=424M → fixed 1.42G  room +1.34G  K=8  預測峰值 2.92G  > 預算       ✗ K_max 撐不住
  N=2.0M load=424M → fixed 1.68G  room +1.08G  K=8  預測峰值 3.22G  (需 K=12 才回到 2.71G)
  ```
  1. **`K_max=8` 飽和**（N≳1.7M 時估計器已無牌可打）→ 試 `K_max=12`，模型說 2M 就進預算內。
  2. **模型在 2M 低估**（預測 3.22G，但實際在 5.4G 以上 OOM）→ 有缺項，最可能是
     **MCMC densify 操作（2M 點的 relocate/add）自身的 O(N) 記憶體，K 碰不到**。
  **廉價分辨法**：在 N≈1.7–2M 實測峰值 vs 預測，差值就是缺項大小。
  ⚫ **已否決的解釋**：「`room ≤ 0` ＝ 6GB 物理極限」——算術不成立（1.5M 時 room=**+1.50G**）。
     這個解釋很誘人（把撞牆說成天命）但是錯的，記在這裡以免日後重新採信。
- ❌ **不要**借 2DGS 的 `min(s)/max(s)` 扁平率折扣：我方 surfel `scales` 是 `[N,2]`，第三軸恆為 0
  → 扁平度不是自由度。實測四族群全擠 0.79–0.85 且**方向反了**（怪物 0.852 比真表面 0.786 更圓
  → 會罰真表面更重）。這是「3DGS 的幾何直覺不能無腦搬到 2DGS」的具體案例，可寫進 discussion。

## §7 統一形式：密度控制 ＝ 一個背包問題（2026-07-28，讀完 9 篇後的綜合）

### 7.1 理型公式
所有讀過的方法都可寫成同一個約束最佳化：
```
maximize_{θ, S⊆P}   Q(θ_S)        s.t.   (1/K) · Σ_{i∈S} c_i  ≤  B(hardware)
                                            ↑        ↑              ↑
                                       供給側槓桿  每顆資源成本   硬體預算
```
`S`＝存活集合、`Q`＝渲染品質、`c_i`＝每顆的資源成本、`B`＝預算、`K`＝供給側槓桿。
**兩條解法路線，每篇論文各選一條**：
- **離散/貪婪（背包解）**：按**價值密度 `v_i/c_i`** 排序，取到預算綁住為止。
- **連續鬆弛**：用 opacity 當軟存在指示 ⇒ `∂L/∂o_i = ∂ℓ/∂o_i + λ·c_i`（拉格朗日）。
**這兩者是同一個背包的鬆弛解與精確解**——文獻的表面分歧（正則項 vs top-k 剪枝 vs 取樣排程）是**解法差異，不是問題差異**。

### 7.2 文獻＝這個式子的參數選擇表
| 方法 | 價值 `v_i` | **成本 `c_i`** | 預算 `B` | 解法 | 供給側 `K` |
|---|---|---|---|---|---|
| 3DGS ADC | 位置梯度 | **≡1** | 無（靠啟發式）| 門檻 clone/split/prune | 無 |
| 3DGS-MCMC | opacity | **≡1** | cap（顆數）| L1 鬆弛 + relocation | 無 |
| LightGaussian | `Σ(σ·T)·γ(vol)` | **≡1** | 顆數 | 全域 top-k | 無 |
| Taming 3DGS | 8 訊號手調加權 | **≡1** | 顆數（拋物線排程）| 取樣至排程 | 無 |
| Pocket-SLAM | **面積**（大＝重要）| **≡1** | 每 tile 顆數 | 逐 tile top-B | 無 |
| Mini-Splatting | `Σ w = Σ T·α·G²ᴰ` | **≡1** | 顆數 | 重要度取樣＋深度重初始化 | 無 |
| Diet | blending weight | **≡1** | **記憶體** | 高頻移除＋補回 | 無 |
| FastGS | −(足跡內誤差) | **≡1** | 顆數 | 雙門檻 | 無 |
| Confident Splatting | 學習的信心度 | **≡1** | 顆數 | 門檻 | 無 |
| **本工作** | render-grounded | **`c_i` ＝ 渲染成本** | **VRAM bytes（封閉式）** | 連續解耦衰減 | **動態 `K`** |

**⇒ 這張表就是論文的 contribution statement**：**九篇全部 `c_i ≡ 1`，差別只在 `v_i` 的選擇；
本工作是唯一給出非平凡 `c_i` 的，也是唯一有供給側變數的。**「顆數是錯的計價單位」從口號變成表格裡的一欄。

### 7.3 最精簡且最有效的實例化（可測試的主張）
四個選擇 `(v, c, B, K)` 之中，最小且能同時處理我方全部病理的組合：
```
v_i = S_i        擁有的像素數（我是最大貢獻者的像素數，Mini-Splatting Eq.2，forward pass 可得）
c_i = 足跡 tile 數                                   （forward pass 可得）
B   = (V_t − V_os) − 模型狀態                        （封閉式）
K   = 由同一條不等式反解                              （供給側）
```
單一比值 `S_i/c_i` ＝「**把多少光柵化成本轉換成實際擁有的像素**」＝產出率，四種病理一次分對：
霧（c 大 S≈0→殺）、近相機怪物（c 爆大 S≈0→殺）、塵埃（c≈1 S≈0→殺）、真表面（S≈c→保護）。
→ **這是本框架目前最強的候選判別式**，勝過現行 `1/√v̂`（實測惰性）與 opacity（抓不到怪物）。

### 7.4 ⚠ 統一到不了的地方（三個誠實的邊界，這些本身是結論）
1. **背包只涵蓋「留/殺」，涵蓋不了「長」**。`v_i` 需要「已存在的點的貢獻」，但 densify 要問的是
   **「一顆還不存在的點的邊際價值」**，任何 `v_i` 都測不到。→ 這解釋了為何**每篇論文的成長訊號都與剪枝訊號不同**
   （3DGS 位置梯度／Taming 8 訊號／FastGS 誤差圖／Mini-Splatting blur 面積）＝**成長是另一個問題，不是同一式的另一端**。
   **一條公式無法統一兩者，這是結構限制不是偷懶。**
2. **價值不可加**。殺掉一顆會改變其後所有點的 `T` ⇒ 集合價值 ≠ 個別價值之和（alpha-blending 是次模而非可加）。
   背包假設可加 ⇒ 貪婪 top-k 只是近似。**但這也解釋了為何「剪 10× 只掉 0.3 dB」**
   （Mini-Splatting 6.1M→0.6M 掉 0.3；我方 12.2× 掉 0.23）——冗餘極高時邊際損失近乎為零。
3. **預算不是靜態的**。`τ` 在訓練中成長（實測 73→~120），故 `B` 隨時間變 ⇒ 是**線上背包**不是背包。
   我方的 `τ_growth=1.65` 與動態 K 就是在處理這一項。

### 7.5 由統一形式導出的下一步
- 📐 **DAR 目前不含 `v`**（`u` 實測惰性）⇒ 自然的下一版是 `stride ∝ λ·c_i/v_i`，`v_i` 取 `S_i` 或 `Σ(T·α)`。
- 🧪 需要 rasterizer 逐像素 argmax 才能得 `S_i`（小幅 CUDA）；**免 CUDA 的代理＝現有 `record_transmittance` 的 `Σ(T·α)/c_i`**。
- 📌 成長側維持獨立訊號（不強行統一），候選＝FastGS 的足跡內誤差（forward pass 可得）。

## §8 組合最佳化定位：v/c 門檻是 LP 最優解，不是啟發式（2026-07-29）

> 使用者問「cost-aware 能否化約成背包、能否套近似演算法」。推完的結論是：**能化約，但化約之後會發現
> 組合那一半已經是最優的，誤差全在價值估計**。以下標明哪些是**可證的**、哪些是**假設**。

### 8.1 ✅【可證】留/殺那半＝分數背包，我方門檻即其最優解
固定候選集合 `P`（既有的高斯），選擇存活集合 `S ⊆ P`：
```
max  Σ_{i∈S} v_i      s.t.   Σ_{i∈S} c_i ≤ B
```
- **分數背包的最優解＝按價值密度 `v_i/c_i` 排序、取到預算用完**（Dantzig）。
- 我方判別式 `v_i/c_i ≥ λ` **就是這個規則**，`λ` 即 LP 對偶變數／影子價格。
- **整數最優與分數最優的差距至多一個物品**（經典結果）。我方 N ~ 1e6，故差距可忽略。

⇒ **`v/c` 門檻不是啟發式，是此問題的 LP 最優解。**
⇒ **推論（重要）：再進階的近似演算法也提升不了這一半。** 誤差全部在 `v_i` 估得準不準，
而**沒有任何近似演算法能修正錯誤的目標函數**。這與我方實測一致（opacity 抓不到怪物、
`1/√v̂` 惰性、真正對稱的多視角 `T·α` 版從未正確實作過）。

### 8.2 ✅【可證】我方的價值訊號正是一個次模覆蓋函數的邊際增益
定義每像素的「已解釋程度」：
```
f(S) = Σ_p [ 1 − Π_{j∈S} (1 − α_j(p)) ]
```
這是標準的**機率覆蓋函數（probabilistic coverage）**，**單調次模**（可證，經典）。其邊際增益：
```
f(S ∪ {i}) − f(S) = Σ_p α_i(p) · Π_{j∈S\{i}} (1 − α_j(p))
```
而 trim rasterizer 的 `record_transmittance` 累積的是 `Σ_p T_i(p)·α_i(p)`，其中
`T_i = Π_{j 在 i 前面} (1−α_j)`。

⚠ **兩者不完全相等**：`T_i` 只乘前方遮擋者，覆蓋函數的邊際乘**全部**其他點。
因 `T_front ≥ T_all`，故 **我方量到的 `Σ T·α` 是該次模邊際增益的上界**。
⇒ 可寫成：「我方價值訊號 ＝ 一個單調次模覆蓋函數之邊際增益的可計算上界」。這比「render-grounded
的啟發式」強得多，且**上界方向是安全的**（不會低估而誤殺）。

### 8.3 ⚠【假設，但 2026-07-29 已有實證支持】渲染品質 Q 本身的次模性

**實測（`tools/measure_diminishing_returns.py`，reg000 ckpt，b12）**：剪掉 k% 的點、以未剪模型自身
渲染為參考量失真，**兩種排序的失真曲線二階差分皆為正**（按貢獻 7/8、隨機 8/8）＝**凸＝邊際遞減**。
⇒ 可寫「empirically consistent with diminishing returns」，**仍不可寫成定理**。
**同時證實 `v_i` 有強鑑別力**（§8.1 的推論「誤差全在 `v_i`」因此是好消息而非壞消息）：
| 剪掉 | 按貢獻 | 隨機 |
|---|---|---|
| 20% | **90.76 dB** | 30.81 dB |
| 50% | 33.89 dB | 22.81 dB |
| 90% | 21.87 dB | 13.72 dB |
**★膝點在 20–30%**（剪 20% 近乎無損、剪 30% 斷崖），位置與「26 視角內貢獻為零的點佔 22.0%」吻合。
**對照 `cull_dust` 只找得出 0.7%**——它的判準（`o<0.05` 且次像素）抓不到「opacity 正常、尺寸正常，
只是從未被看見」的遮擋族群。**這正是 v/c 設計要抓的東西，也是它相對 cull_dust 的價值所在。**
**★★2026-07-30 修掉兩個缺陷後重測（B2：全 237 可排序視角 + 不相交 holdout 評測）——上表的「20% 近乎無損」被推翻**：
零貢獻比例 **9 視角 48.9% → 26 視角 22.0% → 237 視角 0.5%**（⇒ `cull_dust` 的 0.7% 才是對的；
我方一度拿 22% 去質疑它，方向是錯的）。
⚠ **但「零貢獻」與「低貢獻」是兩個問題，我方一度混淆**——真實取捨曲線（自我偏差 MSE 疊到既有誤差的保守上界）：
| 剪掉 | 5% | 10% | 20% | 30% | 50% |
|---|---|---|---|---|---|
| 對 GT-PSNR | −0.29 | −0.51 | **−0.85** | −1.22 | −2.27 dB |
| 效率（≈隨機剪 X%）| 1.2× | 2.3× | 4.3× | **6.1×（峰值）** | 4.2× |
⇒ **`v_i` 最擅長找出「最不重要的三成」，再往下優勢快速消失**（90% 時只剩 1.8×）。
次模性：二階差分 **contribution 8/8、random 7/8 全為正** ⇒ 比 B 更乾淨，**邊際遞減得到強支持**。
**★實務含意（重要）**：
- **部署側可用**：剪 20–30% 換 0.85–1.22 dB，遠優於 `cull_dust` 的 0.7%；但遠不如 A' 時代的 7.4×
  ——因為 **reg000 本來就不製造垃圾**。
- **訓練側淨負**：省 30% 預算能多塞 30% 點，而**2× 點只值 +0.23 dB** → 30% 約 **+0.1 dB**，
  比剪掉的 1.22 dB **少一個數量級**。⇒ **訓練中用 v/c 剪枝換更多點是賠的**，
  這才是 v/c 當初「方向錯」的**本質原因**（不只是 churn 過載）。

### 8.3b ⚠【原始假設陳述，保留】
`f(S)`（覆蓋）可證次模，但**品質**（對 GT 的負 L1）不等於覆蓋：加一顆顏色錯的高斯會讓畫面變差，
故 **`Q` 不單調**。非單調次模仍有常數因子保證，但**我方沒有證明 `Q` 次模，只有合理性論證**
（邊際遞減與實測相符：2× 顆數僅 +0.23 dB）。
**論文寫法：標為假設，或只宣稱 8.2 的覆蓋函數版本（那個是可證的）。不可寫成定理。**

### 8.4 能借的：CELF 惰性求值（可直接落地）
次模函數的邊際增益**只會隨 S 增大而遞減** ⇒ 貪婪選擇可用 **CELF/lazy evaluation**：
維護上界優先佇列，只在該項可能成為最大值時才重新求值。
**對我方是實質優化**：`v_i` 的量測需要渲染（現行 v/c 用 24 視角 transmittance pass，
曾使速度由 0.40 掉到 0.25 it/s）。惰性求值可把每事件的重新求值數從 O(N) 降到實務上的極少數。
⚠ 前提是 8.3 的次模性（或至少邊際遞減在實務上成立）→ **需先用實驗驗證遞減性**。

### 8.5 densify 那半不是背包（結構性，非能力問題）
背包假設**候選物品已存在**。densify 是在**創造**物品，而「一顆尚不存在的點的邊際價值」
沒有任何 `v_i` 測得到 ⇒ 那比較接近**最優實驗設計／主動學習**。
這解釋了為何每篇論文的成長訊號都與剪枝訊號不同（3DGS 位置梯度／FastGS 誤差圖／Mini-Splatting blur 面積）。
**一條公式無法統一兩者，這是結構限制。** ⚠ 對 b12 已無實務意義：densify 導引的天花板實測僅 **1.2×**。
