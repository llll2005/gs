## 2. 評測與判準

| 項目 | 狀態 | 驗法與證據 |
|---|---|---|
| 「糊掉%」指標非假影 | ✅ | 懷疑它只是在量「平坦區相關係數沒意義」。把對比門檻拉到只看**紋理最強 15%**（q=0.85）後**仍有 39.8% 糊掉**，且 render/GT 紋理比 **0.16 vs 0.94** ⇒ 真實失效 |
| 糊掉 ≠ 位移 | ✅ | 逐 tile 在 ±8px 搜尋最佳位移：清楚 tile 提升 **0.000**、糊掉 tile 提升僅 **+0.031** ⇒ 不是對齊問題。⚠ 別被「80% 有非零最佳位移」誤導，那是低訊號隨機峰值（清楚 tile 也有 33.5%）|
| `cmp_runs.py` 估計量 | ⚠ | 最後 4 個 val 點平均，噪音緊 2.9 倍。**⚠ 非無偏**：終點−平均 = +0.027~+0.222（因跑次而異）⇒ 比較機制用平均，報告成品用終點 |
| 噪音底 | ✅ | n=3 同組態重跑實測：PSNR sd 0.0277（平均）/ 0.0807（終點）。判準 \|sd\|<3 = 打平 |
| ❌ test 分數被丟棄 | ❌→✅ | `task_test.sh` 為保護訓練期 `results.txt` 而還原備份 ⇒ **test 分數被丟掉**。2026-09-03 改為先另存 `results_test.txt`。⚠ **既有 38 個跑次沒有 test 分數** |
| 台帳步數 | ⚠ | `results.txt` **不寫步數** ⇒ 半途 OOM 會留下看起來正常的分數。**比分前必跑 `tools/run_status.py` 或查 60k ckpt 是否存在** |

## 7.5 實作層稽核（2026-09-03，使用者要求「檢查代碼實現有沒有錯」）

**逐段讀過我方近期新增的實作，結果：**

| 項目 | 判定 | 說明 |
|---|---|---|
| `fast_noise` 的等價改寫 | ✅ **數學正確** | `R(S²(Rᵀv))` = `R S Sᵀ Rᵀ v` = `cov @ v`；兩條路徑的 `scales` 同源（都是激活後、補零到 3 維）|
| `relocate_gs` 不改變 N | ✅ | 只替換 `dead_indices` 的參數，無 cat/prune；實測 `agd2hr` 終點 N=2.34M 與對照相同 |
| ❌ `blur_persistence.py` 的半徑公式 | ❌→✅ | **第二項漏了 `** 2`** ⇒ 畫面上半 `ty<ny/2` 該項為負 ⇒ `sqrt(負)` = nan ⇒ 整欄中位數變 nan。已修，修正後 0.889/0.783 與獨立腳本**完全一致** |
| ⚠ `_absgrad_accum` 的累積視窗 | ⚠ **隱式，非設計** | 歸零只寫在 report 路徑；現行配方 `absgrad_report=0` ⇒ 該處不執行。它實際靠「N 改變時 shape 不符 ⇒ 重建為零」自癒 ⇒ **視窗 = 距上次 N 變動的步數**（densify 期約 150 步、撞 cap 後約 500 步）。**能用，但會在訓練中途從 150 悄悄變成 500** |
| ⚠ `_load_max` 在 report-only 模式 | ⚠ **標籤誤導** | 歸零只寫在 `add_new_gs` 且要 `cost_budget>0`。標定時只開 report ⇒ 印的是**全程最大值**而非「區間最壞視角」。**標定值本身有效**（200 視角的最大值正是要的預算），但標籤要改 |
| `tools/` 全體語法 | ✅ | 93 個檔案 `py_compile` 全過 |
| ⚠ `np.median` 未防 nan | ⚠ | **20 個工具**用 `np.median` 而未處理 nan。nan **會傳染整欄** ⇒ 已把 `blur_persistence` 改為 `nanmedian`；其餘工具若出現無法解釋的 nan，先查這裡 |

**★ 一個方法論教訓**：半徑那個 nan 我先前找不到，是因為除錯腳本**憑記憶重打公式**（而重打時打對了）
⇒ 重現不出來就以為 bug 在別處。**除錯時要逐字複製原始碼，不可重打。**
