## §9 參數冗餘稽核（2026-09-05，使用者要求「找出其實沒差的參數／無用的演算法」）

### 方法：三層，先零成本再花 GPU

```
第 0 層  零成本    讀 runner.log 的跑次區段數觸發次數／讀 ckpt 算量級   <- 已完成
第 1 層  ~3 分鐘   CUDA event 精確歸因該函式值多少 ms/step             <- 已排隊
第 2 層  9.6h/個   端到端消融（只給通過前兩層的候選）                   <- 待定
```
⚠ **不要一開始就排消融跑次**：現行最佳 config 有 density 48 + metric 20 = 68 個參數，
逐一消融 = 68 x 9.6h = 27 天。

### 第 0 層結果：`agd2_b12`（現行最佳）單次跑次的機制觸發統計

從 `logs/runner.log` 切出該跑次區段（365,229 行）後計數：
```
[screen-size prune]   **193 次**   每個 densify 事件都觸發
[densify-blind]       **193 次**   **只印字，不影響訓練**
[screen-prune EMERGENCY]  0
[vpc]                     0
[blur-split]              0
[harvest*]                0
[ac-shrink]               0
[cost-budget]             0
[transparent*]            0
```
⇒ 那 7 個 0 次的在 config 裡就是 0、且**有守衛擋著** ⇒ 不花錢，也不是冗餘（是關著的功能）。

**`screen_size_prune_px 300` 不是冗餘 —— 它在做實事**
```
193 次觸發，總回收 **189,433 顆 = cap 2.6M 的 7.29%**
單次中位 1,010 顆／最大 1,678 顆
觀測到的最大半徑：中位 1,245px／全場最大 **3,140px**
```
⚠ 但它的**品質貢獻從未被消融過** —— 它是從舊配方繼承下來的。
⚠ 而它是現行配方裡**唯一針對大足跡**的機制，與 §11.98 的耦合表述直接相關
   ⇒ 比起「刪掉」，更值得測的是**降低門檻**（300 -> 150）。

### 第 0 層結果：兩個真正的浪費候選

**候選 1：`_accumulate_error_score` —— `after_backward` 裡唯一沒有守衛、每步都跑的**
```
內容   全幅 avg_pool2d + N x 3 的投影矩陣乘（N = 2.34M）
消費者 err_unlock_frac / err_guided_densify / transparent_corrector  —— 現行配方**全是 0**
       `_report_densify_blindness`                                   —— **只印字**
⇒ 現行配方下，它每步執行只為了餵那 193 行 log。
```
⇒ 已加旗標 `densify_blind_report`（**預設 False**）並把累積納入守衛。
**關掉它訓練行為完全不變**（消費者全為 0）⇒ 這部分可直接採用，不需驗分數。
⚠ 守衛已含**全部三個**真消費者（`_err_triggered_unlock` / `_report_densify_blindness` /
  `_get_new_params` 的 transparent corrector）—— 這正是 §7 反覆踩到的坑。

**候選 2：MCMC 位置噪音可稀疏化 —— 實測可跳過 69%**
```
公式  noise = cov_3d @ (randn * op_sigmoid(1-o) * noise_lr * lr)
      gate = sigmoid(100*(0.005-o))  =>  o=0.005->0.500 / 0.03->0.076 / 0.05->0.011
成本  `_add_xyz_noise` = **59.4 ms/step**（總 602 ms 的 9.9%，tools/step_breakdown.py）
      來源：compute_cov_3d(N) + randn_like(N,3) + bmm(N,3,3) —— 全對整個族群做

可跳過比例（gate < eps）      14999      29999      60000
  eps = 1e-4                 40.2%      53.8%      62.6%
  eps = 1e-3                 47.6%      62.8%      **69.0%**
```
**安全性判準要用「相對自身尺寸」，不可用「相對 Adam 步長」**：
被跳過的多半梯度趨近 0，比值必然爆掉（實測 p99 到 1e6~1e17）——那是判準選錯，不是機制有問題。
正確的量：eps=1e-3 時每步位移 <= `scale^2*noise_lr*lr*eps` = 4.15e-8
⇒ 60,000 步隨機遊走累積 `sqrt(60000)*4.15e-8` = 1.0e-5 = **自身尺寸的 0.15%**。
⇒ 已加旗標 `noise_gate_eps`（**預設 0**）。⚠ 改變 RNG 串流 ⇒ **非位元等價，必須端到端驗四指標**。
