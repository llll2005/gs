## 1. 兩輪流程
**為什麼**：路面掉分的像素 78% 表面深度沒變、是顏色紋理變差（`37` §3.1）；補貨（A）與計價（B）都沒救回 => 單層不透明單色圓片畫不出細紋理，
以前是靠地下層從縫裡調色。現在給它一個合法的方式：貼著表面的半透明顆粒。以前一放鬆熵半透明就亂長（海面浮塊 ×3～10）；現在有深度上限守著「表面後面」，才有條件放鬆。

**行為規格**（S＝全長，預設 30k；比例都是對 S 或對 cap，沒有場景單位）
| | 第一輪：定形狀 | 第二輪：補外觀 |
|---|---|---|
| 步數 | 0 → S1（預設 0.6 S） | S1 → S |
| 增生期 | 到 0.6 x S1，之後收割到 S1 | S1 → S1＋0.5 x (S − S1)，之後精修 |
| 顆數上限 | **r1 x cap**（預設 0.7；cap＝SfM 分配，不變） | 長到 cap |
| 二元熵 | 加強：雙向段提早（從 S1 的 1/6 起）且權重 x2 | 只往 0 推（現行前 1/3 的設定），權重回原值；不往 1 推 |
| V/C 剪枝 | 照現行（到第一輪增生期結束） | **不剪**（半透明顆粒貢獻天生低，會被優先剪掉） |
| 新顆粒的母點 | 照現行 | **只能是「表面顆粒」**：第一輪結束（S1）時不透明（o > 0.5）且在上一個 V/C 累加窗口有出力的顆粒；第二輪生出來的顆粒也可以當母點 |
| 新顆粒的位置 | 照現行（輕度面內錯開） | 生在母點平面內（`inplane_offset` 嚴格）、**整個第二輪只准沿母點平面移動**（`inplane_hold` 套到第二輪結束） |
| 深度上限、鄰域平面、法向、dist | 照底 | 照底（上限要繼續開） |
| 合併、死顆粒回收 | 照現行 | 回收照常（第二輪的名額也從這裡來）；合併關掉（會把半透明細節併掉） |
- 位置學習率排程、SH 階數排程照全長走，不因為分輪而重來。
- 實作方式由實作者決定（一組 `round2_*` 設定或排程表都可以），**全部預設關，關的時候行為與現在逐位元相同**。
- 可觀測性（必做）：S1 時印——表面顆粒數／總數、此刻的不透明比例、名額剩多少；第二輪每 2000 步印——第二輪出生的顆粒數、其中半透明（0.05 < o < 0.5）比例、被面內限制擋下的位移比例。
- 測試：關閉時逐位元相同；非表面顆粒在第二輪抽不到；第二輪出生的顆粒位移的法向分量為 0；顆數不超過 cap。
- 調參元件（`task_tune25.sh`）：`r2`（上表預設）＋可調 `r2c<NN>`（第一輪顆數 %）、`r2s<NN>`（S1 佔全長 %）、`r2free`（拿掉母點與面內限制，拆因用）、`r2ent0`（第二輪熵全關）。

**臂**（b1、b4，[solo]，30k；都接在 `s30g50+np16+tricap0p5+` 後）
| 臂 | 元件 | 回答什麼 |
|---|---|---|
| R | `r2` | 主要假設 |
| Rc50／Rc85 | `r2+r2c50`、`r2+r2c85` | 第一輪該留多少名額 |
| Rs50 | `r2+r2s50` | 兩輪各佔多少步 |
| Rfree | `r2+r2free` | 拆因：不限制出身時，清掉的東西會不會長回來（預期會） |
| Rent0 | `r2+r2ent0` | 第二輪熵全關 vs 只往 0 推 |
評估：`TUNE_BASE=g44tn_s30g50np16tricap0p5_best1maskdistrfed10b4 TUNE_BASE_LBL=上限0.5 bash scripts/lab/task_tune25.sh eval <塊> round2 <各臂>`，
`TUNE_EXTRA` 帶 `鄰域平面30k=g44s30ksfm10nbnp16_best1maskdistrfed10b4`。另外要量（CPU，現成工具）：
- 路面像素的換塊誤差（`tools/probe/cap_error_split_1111.py` 的分類）；
- 建築內部的不透明＋半透明顆粒（`tools/probe/tower_interior_1108.py`）；
- 半透明顆粒佔覆蓋的比例、它們離最近表面顆粒平面的距離（以母點尺度為單位）。
**過關**（對 `tricap0p5` 底）：換塊 ΔPSNR 回升 >= +0.03 dB（目標追平 `nbnp16`）、LPIPS 不變差；地下覆蓋不回升超過 10%、建築內部不回填；
F1、貼地覆蓋不降；路燈帶／車輛帶缺口不變差；純訓練時間不增加。b1、b4 都過才補 b3；不自排全場景。

## 2. 海面：表面前面很遠的也罰（不改光柵器）
**想法**：深度上限只罰後面。加一條對稱的：在深度可靠的像素上，**渲染的期望深度**比校正深度淺很多（在表面前面超過 f）就罰。
浮塊在海面正上方時直接命中（若海面有可靠深度）；從斜角度看，背景是陸地或建築時也命中。路燈、車只在表面前面一點點，f 取寬就碰不到。
- 做法：仿 `see_through_loss`（`internal/metrics/mcmc_citygsv2_metrics.py`），方向相反：`relu(1／(1+f) − z_渲染／z_先驗)`，只在塊外遮罩 A、先驗有效、α > 0.5 的像素；
  用期望深度（半透明浮塊中位深度抓不到）。每 8 步、與法向同一步。設定 `depth_front_reg`、`depth_front_margin`（預設 0.05，相對深度、無因次）、`depth_front_interval 8`。元件 `trifr<W>`。
- **先做前提檢查（CPU）**：(1) 海面像素（定義沿用 `tools/probe/monodepth_sea_1102.py`，真深度只用來分類）裡校正深度「可靠」的比例、與它的誤差；
  (2) 對 b1 的 `tricap0p5` 模型離線算：海面上方浮塊所在像素有多少比例會被這條規則命中；(3) CityGS 同塊模型的路燈帶、車輛帶、塔頂細物（天線等）像素被命中的比例要 <= 約 3%。
  (1) 很低或 (3) 沒過 => 把數字貼給使用者，不要硬排。
- 臂（b1；b4 沒有海，換 **b3 或 b12**——要先補 `tricap0p5` 底）：`tricap0p5+trifr1`、`tricap0p5+trifr4`。
  評估看海面欄（上方浮塊數、Σo·面積、海面層覆蓋）、路燈與車缺口、換塊 PSNR。**過關**：海面上方可見量明顯下降、海面層不被剝掉、畫質與路燈／車不變差。
- 已知風險：SfM 沒抓到的細高物會被當成浮塊；岸邊那一大團若是貼著海面鼓起（不夠「遠」）這條抓不到——那要看兩輪流程的第一輪強熵會不會收掉，或回頭用「沒證據的不准往上」（`32` §4.6）。

## 3. 高塔：塊外遮罩改用校正深度判（現成，直接排）

- 遮罩已產生：`block_masks44_tri`（b1／b2／b6；檢查：盒內 SfM 點 → A 100.0／99.9%）。元件 `trimask`。
- 先量（CPU）：用 `tools/probe/mask_tall_seam_1109.py` 對新舊遮罩重量「盒內高樓表面被判 A／B／C 的比例」（依高度帶、離接縫距離）；⚠ 那支用 SfM 點當樣本，校正深度在 SfM 點上本來就準
  => 另外用真深度抽像素量一次（真深度只診斷）。
- 臂：b1、b2、b6 各跑 `tricap0p5`（底；b2／b6 沒有，要補）與 `tricap0p5+trimask`。評估加逐棟破洞（`tools/probe/tower_probe_1105.py` 那一類）與使用者指出的 b1 紅色高塔。
