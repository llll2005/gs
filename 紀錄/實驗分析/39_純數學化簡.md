# 39 純數學化簡（不訓練）

**起因（11-21 使用者）**：「讀現有的研究，用純數學的方式、完全不訓練，透過化簡／化繁／輸出項代換／運算式結合／相似算法整併，減少使用的算法量，甚至創新、可能還減少運算量。」
**做法**：只讀紀錄與程式碼推導；每個化簡先在 CPU 用真實 ckpt＋真實相機驗數值，再（要改光柵器的）在本機編一份獨立的 .so（PYTHONPATH 指過去，不動共用環境）做逐位元／噪音底比對與成對計時。
全程沒有任何參數更新（不訓練）。圖 `39_純數學化簡.png`。

**最重要的反面結論**：光柵器**不受算術限制**。#1 每配對少 3 次除法＋2 次外積（backward）、1 次除法＋外積（forward），時間只動 1.4%；
真正的成本是「迭代次數」（warp 走過多少個面元）以及記憶體／歸約。所以 #2（直接少走迭代）效果比 #1 大 4 倍。下一步的化簡應該找「少做多少次」，不是「每次少算幾個乘法」。

## 1. 反單應交點（#1）

**推導**。transMat 的三列 Tu, Tv, Tw 滿足 Tu·h = xZ、Tv·h = yZ、Tw·h = Z（h = (u, v, 1)），即 M h = Z (x, y, 1)，M = [Tu; Tv; Tw]。
2DGS 每配對算 k = −Tu + x Tw、l = −Tv + y Tw、p = k x l、s = p.xy/p.z、深度 = s·Tw.xy + Tw.z。因 Tw x Tw = 0：

```
k x l = Tu x Tv + x (Tv x Tw) + y (Tw x Tu) = det(M) · M^{-1}(x, y, 1)        （仿射；M^{-1} 的三欄就是這三個外積 / det）
Tw · (k x l) = det(M)（另兩項是三重積含兩個 Tw = 0）  =>  深度 = det(M)/p.z = 1/p'.z，p' = M^{-1}(x, y, 1)
```
=> 交點就是**反單應**：每顆一次算 Q = M⁻¹，每配對 p' = Q (x, y, 1)、深度 = 1/p'.z（本來就要的那個倒數），s = p'.xy·深度。

**數值（CPU，真實 b4 ckpt＋3 台相機，6 萬配對，float64 當真值）**

| 寫法（float32） | \|Δ(u,v)\| 中位 ↓ | p99 ↓ | \|Δz\|/z 最大 ↓ | \|Δalpha\| 最大 ↓ |
|---|---|---|---|---|
| 原寫法（外積） | 2.25e-5 | 1.02e-3 | 6.9e-3 | 1.6e-2 |
| Q 用 float32 伴隨矩陣 | 4.30e-5 | 2.14e-3 | 1.39e-1 | 1.0e-2 |
| Q 用幾何閉式（不錨定） | 4.71e-5 | 2.01e-3 | 9.5e-3 | 1.8e-2 |
| **Q 幾何閉式＋錨定在中心投影** | **2.29e-5** | **1.10e-3** | 9.7e-3 | 2.2e-2 |

- 誤差來源是逐像素求值 x q0 + y q1 + q2 的相消（像素座標約 1000、有意義的只是幾個像素的偏移），不是 Q 本身（幾何閉式的 Q 對真值相對誤差 8.7e-8）。
- **錨定**：Q (x_mu, y_mu, 1) = (0, 0, 1/Z_c) 恆成立（中心投影的射線打在 u = v = 0）=> p' = (0, 0, 1/Z_c) + (x − x_mu) q0 + (y − y_mu) q1。每顆存 q0、q1、x_mu、y_mu、1/Z_c 剛好 9 個 float（同 transMat）。
- **幾何閉式**（不從 T 反矩陣，避免 T 裡 cx·C_z 大項的相消）：M = K C、C = [s0 t0, s1 t1, mu]（相機座標）=>
  C⁻¹ 的三列 = (t1 x mu)/(s0 n·mu)、(mu x t0)/(s1 n·mu)、n/(n·mu)，n = t0 x t1 —— 就是教科書的射線-平面交點。

**梯度**。每配對只要 g = dL/dp'（與原本 dL_dp 同形式、1/p.z 換成 1/p'.z），累加 a0 = Σ dx·g、a1 = Σ dy·g、a2 = Σ g（9 個數，與原本 dL/dT 一樣多）；
每顆一次：dL/dM̃ = −Q̃ᵀ (a0 a1 a2) Q̃ᵀ（Q̃ = [q0, q1, (0,0,1/Z_c)]），dL/dM = A⁻ᵀ dL/dM̃（只改 Tw 那一列：D2 − x_mu D0 − y_mu D1）。

| dL/dT 的 float32 相對誤差（300 顆 x 48 像素，對 float64） | 中位 ↓ | p99 ↓ | 最大 ↓ |
|---|---|---|---|
| 原寫法（逐配對兩次外積） | 9.1e-6 | 1.5e-4 | 8.0e-4 |
| 反單應 v1（先還原未錨定的 Q、G 再相乘） | 1.4e-5 | 3.2e-4 | 1.6e-3 |
| **反單應 v2（錨定換算）** | **4.7e-6** | **7.2e-5** | **1.0e-4** |

**GPU 比對（b2、6 視角；`tools/check_lean_render.py`）**

| 比較 | 渲染最大差 ↓ | 位置梯度相對差 ↓ | 旋轉梯度 p99.9 ↓ |
|---|---|---|---|
| 舊 .so 跑兩次（atomic 噪音底） | 0 | 9.7e-8 | 1.2e-6 |
| 新 .so 旗標關 vs 舊 .so | **0（逐位元相同）** | 1.9e-7 | 1.3e-6 |
| 原寫法，位置擾動 1 ulp（浮點敏感度底） | 6.6e-2 | 3.2e-1 | 9.9e-2 |

- 反單應與原寫法的差 >> atomic 噪音底，但 << 「同一個演算法、位置只差 1 ulp」造成的差（約 1/70）——差的來源是 min(rho3d, rho2d) 與 alpha ≥ 1/255 這些不連續處的分支翻轉，任何捨入不同的實作都會有。=> 訓練上等價。

**計時**：見 §4。獨立 kernel 算 9 個數時 forward +1.2%；併進 preprocess（那裡位置／旋轉／尺度已在暫存器）後 +0.57%。

## 2. 幾何配對遮罩（#2）

**推導**。alpha ≥ 1/255 <=> min(rho3d, rho2d) ≤ tau，tau = 2 ln(255 o)。
- rho3d ≤ tau <=> F = p'x² + p'y² − tau·p'z² ≤ 0；p' 對像素仿射 => 像素中心那一列（y 固定）上 F(dx) = A dx² + B dx + C。
- 一個 warp 是 16x2 像素條 => 兩列、每列一個區間 [dx0, dx1]：區間上有 F ≤ 0 <=> 端點 ≤ 0，或（A > 0、頂點 −B/2A 在區間內、B² ≥ 4AC）。**不需要除法**（頂點條件改寫成 2A·dx0 ≤ −B ≤ 2A·dx1）。
- 低通圓盤：rho2d = |xy0 − pix|²/FilterSize² ≤ tau <=> 點到線段距離² ≤ 0.5·tau。
- F 對 p' 是齊二次 => p'z < 0 的另一葉只會多放行（安全）；tau 放寬 1%＋0.02（保守）。
- 實作成「幾何配對位元」：負責載入這顆面元的那條執行緒一次算本 tile 8 個 warp 的結果（8 bit），warp 只查自己那一位（比每個 warp 32 條 lane 重複算便宜 32 倍，也讓沒有配對位元的完整路徑能用）。

**離線上限（`tools/probe/conic_strip_cull_1121.py`；b2、3 台相機、各 8,000 顆）**

| 視角 | skip_box 不跳（＝現在實際走的 warp 迭代） | 精確測試不跳 | 離散真值（32 個像素中心有 alpha ≥ 1/255） |
|---|---|---|---|
| 0219 | 196,632 | 117,508（59.8%） | 117,383（59.7%） |
| 1417 | 95,269 | 57,536（60.4%） | 56,671（59.5%） |
| 1879 | 25,932 | 12,815（49.4%） | 12,695（49.0%） |
| **合計** | 317,833 | **187,859（59.1%）=> 再刪 40.9%** | 186,749（58.8%） |
- 沒有任何一個「真值有混合」的像素條被精確測試刪掉（腳本內建檢查）。
- 沒算 T 飽和：被刪的配對有一部分本來就在飽和點之後（像素已經被蓋滿、迴圈提早結束）=> 實際省的比 41% 少（同 10-03 `tile_cull` 的教訓：配對 −36%、backward 只 −3%）。
- lean backward 本來就有逐 warp 配對位元（pbw，只走 forward 真的混合過的配對）=> 遮罩只省 forward；完整路徑步的 backward 沒有配對位元，但實測也沒省（被刪的多在飽和點之後，反而多付遮罩計算）。

**GPU 驗證**：lean（只開遮罩、反單應＋遮罩）、完整路徑（MODE 0 forward＋GEOM backward）三種組合，渲染／radii／覆蓋數**全部逐位元相同**，梯度都在 atomic 噪音底內。

## 3. 其他推導（未實作）

- **#3 熵**：`_o.clamp(1e-6, 1−1e-6)` 再兩個 log 的寫法，換成 softplus(x) − x·σ(x)（σ(x) 本來就算好了），梯度 −x·σ(1−σ) 可直接寫成自訂 autograd。夾值外（|x| > 13.8）原寫法梯度 0、閉式 ≤ 1.4e-5，可忽略。
- **#4／#5 雜訊**：現行 `fast_noise` 算 R (s² ⊙ (Rᵀ v))；v 等向高斯 => Rᵀv 同分布 => 直接取兩個常態亂數 s₁²v₁t₁ + s₂²v₂t₂（t₁, t₂ = R 前兩欄）。
  閘門判準 gate > ε 是 opacity 的單調函數 => 改成比較原始參數（一次比較），不必對全部 N 算 sigmoid。另：`torch.nonzero` 每步一次 GPU→CPU 同步；若改成對全部 N 做遮罩運算（用 #4 的便宜寫法）就不用同步，但要實測。
- **#6～#8**：逐位元相同的刪減（權重 0 的 opacity L1、exp 之後的 abs、遮罩合成換 where）。都是每步幾個 N 長或影像大小的小 kernel，估各 0.5% 以內。
- **#9 齊次性**：lean 步深度不進 loss，L 只依賴 p' 的方向 => 對 Q 是 0 次齊次 => Euler 定理 Σ Q ⊙ dL/dQ = 0。逐配對也成立：q0·(dx g) + q1·(dy g) + iz·g.z = g·p' = 0。=> 可以不歸約 Σ g.z，每顆一次補回。backward 每配對 16 個歸約少 1 個。
- **#10**：2DGS 的 dist 用 m(z) = (F z − F N)/((F − N) z) = F/(F − N) − (F N/(F − N))·(1/z)，對逆深度仿射；反單應直接給逆深度 p'.z => 每配對少一次除法、backward 的 dm/dz 除法也消失。
  但完整路徑步實測不受算術限制（#1、#2 的教訓）=> 沒有實作。
