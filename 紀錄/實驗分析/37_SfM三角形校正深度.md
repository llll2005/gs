## §2 產生器與可靠度分級（`tools/make_tri_depths.py`）
```
inv(p) = 單目(p)·s + o ＋ 內插_三角形( 1/z_SfM − (單目·s + o) )(p)         凸包外：最近 SfM 點的殘差
可靠度（uint8）＝ 斜率級 + 8 x 大小級     斜率級 0／1／2／3／4 ＝ < 1／< 3／< 8／>= 8／凸包外     大小級 0／1／2／3 ＝ 最長邊 < 16／< 64／< 256／>= 256 px
```
- 輸出 `<dataset>/estimated_depths_tri/<名>.npy`（float32 逆深度、場景單位、960x540）、`estimated_depths_tri_rel/`、`estimated_depth_scales_tri.json`（全部 scale 1）。

### §3.1 逐貢獻的單側深度上限（11-11 使用者「可以改」光柵器；commit b615d6f，本機＋lab 已重編）
```
B(p) = Σ_i T_i·α_i·max(z_i·icap(p) − 1, 0)        icap(p) = 1／((1 + margin)·z_先驗(p))，0＝不設上限（不可靠的三角形、塊外、無效）
loss = 權重 x k x Σ_{設了上限的像素} B(p) ／ 像素數        每 k＝8 步（與法向同一步，完整路徑不多跑）、margin 0.01
```
- 這條光線上**每一份混合貢獻**落在校正深度後面超過 1% 就依它的混合權重罰——中位深度的 loss 碰不到的「躲在貼地層後面補顏色」的那幾層，這裡每一份都算得到。
- 光柵器：`out_others` 第 9 個通道（`CAP_OFFSET`）；forward 完整路徑多累加 B，backward 用與期望深度通道同一套回傳（dB/dα 走混合鏈、dB/dz_i＝T·α·icap）；
  lean 路徑一字未動。上限圖用裝置端全域指標，只在那一次 forward／backward 前後設定與清掉。
- 檢查（`tools/check_depth_cap.py`，本機 4050 與 lab 3090 都過）：沒設上限圖時渲染與前 8 個通道對舊版**逐位元相同**、梯度差在重跑雜訊內（1e-9）；
  有限差分 不透明度 6%、尺度 0.8%、全體沿 z 平移 0.4%（位置／旋轉的隨機方向會改排序，既有的 alpha／期望深度通道在同一個檢查下也差 25～53% => 只印）。
