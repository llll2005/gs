## 0. 一句話

兩個降成本機制各自只讓品質掉一點，合開卻崩潰（b6 val −5.1 dB）。原因是 **v/c 判準偏好「微小顆粒」**，而 **opacity 二元熵正則讓這些微小顆粒變成完全不透明、因此永遠不會被 MCMC 判死**；兩者合開時，六成的容量被「幾乎不畫任何東西的微小不透明顆粒」佔滿，塊內真正有用的顆粒只剩基底的 18%。

## 1. 兩個機制在做什麼

### 1.1 週期 trim 與 v/c × tile 名次判準（跑次 `g44_best0vt`）

週期 trim：增生期（≤ 30k 步）每 500 步，用全部訓練相機做一次「紀錄」渲染，給每顆顆粒打分數，**剪掉分數最低的 10%**（被剪掉的名額之後由 MCMC 增生補回）。

| 量 | 算式（程式碼） | 意思 |
|---|---|---|
| 價值 v_i | `max_{視角} [ Σ_{像素} T·α / 覆蓋像素數 ]` | 顆粒在「最看得清楚的那個視角」裡，**每個覆蓋像素**平均貢獻多少（已對大小正規化） |
| 成本 c_i | `Σ_{視角} 覆蓋像素數`（下限 1） | 顆粒在所有視角總共覆蓋多少像素（渲染工作量） |
| tile 名次 r_i | 顆粒在所有（視角, tile）裡，按該 tile 內貢獻排序的**最好名次** | 是否在某個 tile 是前幾名（保護每個 tile 的主角） |
| **判別式** | `s_i = (v_i / c_i) / (1 + r_i / 32)` | 分數低（價值低、成本高、在任何 tile 都排不上前面）就剪 |

預設（現行基底）只用 `s_i = v_i`。

### 1.2 opacity 二元熵正則（跑次 `g44_best0oe`）

在 loss 加一項 `λ · mean_i H(o_i)`，`H(o) = −o ln o − (1−o) ln(1−o)`，λ = 0.002，第 1,000 步起。
梯度 `dH/do = ln((1−o)/o)`：o < 0.5 的被推向 0，o > 0.5 的被推向 1 => **opacity 兩極化**。
推向 0 的顆粒，opacity ≤ 0.005 時被 MCMC 判死、搬到別處；**推向 1 的不會被任何機制判死**。

### 1.3 MCMC 的死亡判定（兩者共用）

`opacity ≤ 0.005` => 死亡，搬到 opacity 高的顆粒附近。**只看 opacity，不看大小或實際貢獻。**

## 3. 機制（從算式推，結構數據吻合）

1. **v/c 對大小懲罰了兩次**：v 已經是「每個覆蓋像素的平均貢獻」（大小中性），再除以 c（覆蓋像素總數）=> `s ∝ 1 / 大小`。
   一顆只蓋 1 個像素、opacity 接近 1 的微小顆粒，v ≈ 1、c ≈ 視角數 => **分數最高，永遠不會被 trim**；
   大顆粒（尤其靠近本塊相機、畫面上大的塊內顆粒）分數低 => 優先被剪。
   數據：v/c 單開時微小顆粒 10% → 40%，盒內比例 27% → 12%（遠處的塊外顆粒在畫面上小，c 低，也被保護）。
2. **opacity 二元熵讓微小顆粒免死**：單開時微小顆粒沒增加多少（12.9%），但它們幾乎全被推到 o ≈ 1（99.6%）。
   MCMC 只用 opacity ≤ 0.005 判死 => **不透明的微小顆粒永遠活著**。
3. **合開 = 選擇＋免死**：v/c 每 500 步把大顆粒剪掉、把名額留給微小顆粒；二元熵讓微小顆粒變不透明、MCMC 不收；
   被剪掉的名額由 MCMC 增生補回時，新顆粒又被 v/c 篩一次……到 60k 時 **64% 的容量是不畫任何東西的微小不透明顆粒**，
   盒內有效顆粒只剩基底的 18%（b6）=> 畫面缺顆粒、LPIPS .311。Load 最低（66 萬）也是這個原因：**不是變有效率，是畫得少**。

## 4. 能不能整合、避免副作用（提案，未實作）

可以，而且修法有原則，符合命題的成本模型 `t ≈ F + b·N + c·L`（每顆固定成本 b ＋ 每像素工作量 c）：

| # | 修正 | 算式 | 解決 |
|---|---|---|---|
| A | **價值改用總貢獻**（不要先除以大小） | `V_i = Σ_{視角} Σ_{像素} T·α`；判別式 `V_i / C_i` | 去掉「懲罰大小兩次」；比值變成大小中性的「每像素平均貢獻」 |
| B | **成本加每顆固定成本** | `C_i = β + Σ_{視角} 覆蓋像素數`，β ＝每顆顆粒的固定成本（常駐 VRAM／前處理／排序）換算成像素單位，可由時間模型的 b/c 估 | 微小顆粒不再「幾乎免費」：它佔 928 B VRAM 和一次前處理，卻幾乎沒畫東西 => 分數低 => 被剪 |
| C | **死亡判定加上「實際貢獻」** | MCMC 死亡：`o ≤ 0.005` **或** `V_i < ε`（在每次 trim 紀錄時一併判） | 不透明但不畫東西的顆粒也會被回收（對 opacity 二元熵特別重要） |

A＋B 一起改等於把 trim 判準改成「每單位成本換到的總貢獻」，這才是背包問題原本的意思；C 是保險，專門擋「opacity 二元熵讓微小顆粒免死」。
驗證方式：先用現成 ckpt 離線算新舊判別式會剪掉哪些顆粒（看微小顆粒是否落到底部），再跑 4x4 b6／b12（v/c 修正版、修正版＋二元熵），用換塊評測定案。

## 6. 離線判別式比賽（2026-10-12，§4 驗證第一步）

**做法**（`tools/discriminant_race.py`）：在已訓練模型上，只對**本塊盒內**顆粒做一次性剪枝（塊外顆粒合併時本來就丟，原樣保留），不重訓。
逐顆統計掃描本塊全部訓練相機（與訓練期 trim 同一套 record pass）；評分用**官方 test 集**（本機 10-12 照官方步驟重建，741 張 md5 全符）
中「本塊負責區域」佔畫面 >= 10% 的幀，區域＝完整模型深度反推回世界座標後落在本塊盒內的像素（幾何定義；
⚠ 起初用「盒內顆粒單獨渲染 alpha>0.5」會被靠近相機的巨大顆粒撐出假區域，隨機剪 30% 分數一位不差 => 已棄用）。
兩種預算：**顆數**（保留前 p 比例，＝訓練期 trim 的做法：每次剪 10% 顆數、MCMC 補回）與**成本**（依分數累加時間成本到 p）。

β（每顆每視角固定成本）由時間模型 `ms = 11.7 + 4.94·N(百萬) + 14.23·Σtiles(百萬/視角)`（lab outbox_cost 10 點，R² 0.954）換算：
β_T = 4.94/14.23 = 0.347 tile；換成像素單位（乘盒內「覆蓋像素／精確 tile」比）三個模型為 51.8／55.6／72.5 px。
對偶 `V − λ·成本 > 0 ⟺ V/成本 > λ`：在預算切斷下與比值排序是同一個集合，不另列。

與 b10（−0.01／−0.16／−0.74，v −0.02／−0.24／−0.97）都第一；β 版居中；壓力測試上 β 版在 70% 第一（−0.25 vs v −0.30）。

**讀法**
- **v/c 是唯一比隨機還差的判別式**（b12 −3.7 dB @90%）：它保護微小顆粒（壓力測試中被剪的只有 9% 是微小，隨機剪是 26%），
  優先剪畫面上大的塊內顆粒 —— 與 §3 從算式推的機制一致，這次是直接量到。
- **V/C 只改了一件事**：v 取「最好那個視角」的每像素貢獻，V/C 取各視角以覆蓋像素加權的平均。同成本下兩個正常模型都勝過 v。
- **β 的作用在壓力測試上最清楚**：被剪掉的顆粒 94.7% 是微小顆粒（V/C 82%、v 85%），保留 70% 顆數時只掉 0.01 dB。
  同顆數時兩個正常模型都是 β 版最好（壓力測試上不除成本的 V 略好，因為那裡要剪的幾乎全是零貢獻的微小顆粒）；
  但 β 版剪掉的成本較少（同顆數 Load 降幅小一些），在「品質對 Load」前緣上 V/C 不輸它（面板 b）=> 兩個都排訓練。
- 訓練期拿不到精確 tiles（要多一次正常渲染）；**覆蓋像素**與精確 tiles 的排序相關 0.84~0.99，用它算的 β 版與精確 tiles 版結果相同；
  radii 外接盒估的 tile 數反而較差（對稱盒與 conic 精確盒不一致）=> 訓練期用覆蓋像素，零額外成本（V 與 C 迴圈裡本來就在累加）。

**實作**：`renderer.init_args.trim_by_mean_contribution`（V/C）＋ `trim_cost_beta_px`（β，像素單位，每顆每視角）；
首次觸發印出「與現行 v 底部 10% 的重疊」與「被剪的微小顆粒比例」。臂 `best0trimVC`（β=0）、`best0trimVCb`（β=55）。
提案 C（死亡判定加「V 太小」）**暫不做**：trim 期間 V≈0 的顆粒已落在 V/(β+C) 的最底部；30k 後才需要它，而搬移低價值顆粒
（`vpc_prune_frac`）是 −2.34 dB 的舊線（研究總覽 §8）=> 等訓練結果顯示 30k 後微小顆粒仍累積再議。

## 5. 限制

- 品質數字都是單塊（val、塊內 held-out），有塊外偏差（`12` §7）；合開的損失合併後會縮小多少，等第一批換塊評測。
- 結構統計只看 60k 終點，沒看過程；「選擇＋免死」的時間順序是從算式推的。
- β 已估（§6，51.8~72.5 px）；ε 要避免誤殺「被遮擋但在其他視角重要」的顆粒（V 是跨視角總和，應可避免）。
- §6 是**單次剪枝不重訓**：訓練期 MCMC 會把名額重新分配（`06`：v/c 事後最差、訓練期曾有效），排序要以 lab 訓練＋換塊評測定案。
