## 結論

- **現行（10-09）★ 我方最佳解 4x4 全場景（合併 17.63M）在官方 741 幀 held-out 三項都贏兩條官方線**（同一支評分工具）：
  **27.739／0.879／0.129** vs release 27.261／0.867／0.154（24.48M）vs 論文設定 27.280／0.870／0.147（24.72M）；
  渲染 35.6 vs 21.9 FPS；訓練峰值實佔 **≤ 4.17 GB**（官方 release 7.65~14.56、論文設定 5.24~11.23）；乾淨的 block 0~9 訓練時間 0.48 倍。
- ✅ **評分工具落差 1.47 dB 已查明（面板 d）**：官方光柵器在 8~13% 的 test 視角把顏色算錯（畫面滿、顏色暗；0184 全黑），只換光柵器就恢復；
  正常幀上我方光柵器對官方模型反而低 0.35 dB => **官方 release 合理分數 ≈ 27.2~27.6**（論文報告 27.23），**我方領先 +0.1~+0.5 dB**；
  SSIM／LPIPS 的領先（.879 vs .867~.870、.129 vs .147~.154）與資源面（N -28%、FPS 1.6 倍、峰值 ≤4.17 GB、時間 0.48 倍）較穩。
- 同 N 附近每步：我方 121 ms（真實步；逐段同步和 157 ms，10-10 飽和跳過＋先加總後 126 ms，見 `01`(a)）vs 官方 release 214 ms（1.78 倍）。官方每步 **2 次 backward**（loss 與深度的 extra_loss 分開 backward，各約 69 ms）
  且 forward 帶幾何通道；我方 depth／normal 權重 0 => 1 次 backward＋lean。
- **合併模型按塊拆開（10-10，面板 c）：同一批塊視角上我方 16/16 塊都贏 release（+0.02~+0.76）**；b12 單塊 −3.84 → 合併 **+0.73**（95/116 幀贏）=> b12 的落差是單塊評法的假象（§0.2b）。
- 同塊 held-out（單塊模型、我方塊視角）：PSNR 平均 20.69／20.23／19.90、我方 9/16 塊勝 release；**LPIPS 官方 16 塊全較好**——
  但這個量尺偏向官方（官方單塊從全場景 coarse 起步、看得到塊外；合併後這個優勢消失，合併 LPIPS 反而我方好）。
- 官方兩條線之間：論文設定的 val 15/16 塊高於 release，但同塊 held-out 16/16 塊**低於** release；合併後幾乎平手（+0.02 dB、LPIPS 較好）。
- 官方原版用**官方工具**量的 held-out：PSNR 25.79／SSIM 0.833／LPIPS 0.176（⚠ 含光柵器暗幀，見 §0.1），N 24.48M、ckpt 41 GB、test 峰值實佔 11.9 GB、每幀 0.088 s。
- **官方 aerial release 的 trim 從未執行**：從 .ckpt 初始化時 renderer 被 coarse 的（`diable_trimming: true`）蓋掉，resolved config 卻仍記 false。
  一行修正後官方 b3：N 5.23M → 0.91M（-83%）、峰值 7.30 → 2.75 GB、val 31.69 → 30.87；我方程式碼跑同配方 0.93M／30.91 => 一致。
- **論文 §5.1 的設定（ω=0.9、prune_ratio 0.025）與 release 不同**：照論文設定，b3 3.05M／31.78、b6 5.31M／30.35 —— **顆數少 25~42%、val 反而高**。全場景已完成（§0）：合併 24.72M、我方工具 27.28。
- 官方的 **6GB 障礙在 coarse**（峰值配置 7.0 GB），逐塊微調每塊 7.3~13.9 GB => 一張 24GB 卡同時只跑得動 2 塊（一律 [solo]）。
- 官方模型依 opacity 剪 10% 逐位元不變、剪 25% 只 -0.03 => 約 610 萬顆幾乎白付。
- **v/c trim 在官方 vanilla 配方大輸**（b3 -2.62、b6 -3.77）：v/c 只在 MCMC 下有效。
- 與論文 27.23：官方工具的 25.79 被光柵器暗幀拉低；排除後官方 release ≈ 27.2~27.6，與論文相近（資料為重生版、評分環境不同，只能說相近）。
