## 結論
- **10-31 的自適應 cap 不通用**（§1）：要先把整個場景以每塊 2.5M 訓練一次當探針（約 5 h），再算 V/C、再正式訓練；換場景就要重來。權重只在 0.4 這個比例（約平均 1M）算過。
- **訓練前就有的「塊內可靠 SfM 點數」和探針權重相關 0.69**（Spearman 0.68；相機數 0.15、視野和 0.31）（§2）。b3／b12 的 SfM 權重 1.04／0.68，探針 1.02／0.69。
  => `tools/sfm_cap_alloc.py`＋`configs/cap_alloc_sfm_g44.json`，**lab 排了平均 1M 全場景**（`g44s30ksfm10fssh16di4_`，配方同 27.828 那次，只換權重）。
- **「需要多少點」是算法的性質**（§3）：CityGS b3 盒內 1.49M（40% 不透明、長軸約 0.95 m），我們 1M 臂 0.67M（92% 不透明、0.52 m）；劑量實驗 b3 在 1M 最好只代表現在的算法多給點用不好（`27`：容量花在地下層與離 SfM 遠處）。
  => cap 要由規則在訓練中決定，算法變好時才會自動給更多。
- **定價自決容量 v1 失敗**（§4）：b3 顆數 0.67M → **0.15M**、LPIPS +0.019、時間 −34%；b12 0.66M → 0.18M、LPIPS +0.017。
  原因：① V/C 在訓練早期本來就低（中位 3k 2.3e-3 → 30k 5.4e-3），用最終模型校的 λ 從 3k 就套；② 被這輪 trim 剪掉的 10% 不算合格 => cap 只降不升；③ 各時點容量變動 8～29%，「收斂就提早結束」的判準不成立。
- **採樣控制器（使用者的想法）已實作並在跑**（§5）：留出 1.5% 的「安全相機」（看到的點別人也看得到）當驗證視角、15k 後放回；6k 起每 1500 步看驗證視角的塊內誤差與透空率，cap ±10%。
  留出 16 台的觀測損失：隨機挑讓 1.5%（b3）／3.0%（b12）的 SfM 點從 ≥3 台掉到 <3 台，挑安全相機降到 0.63%／0.73%。
  **b3 第一跑**：減了三次、顆數 0.67M → **0.49M（−27%）**、held-out 與組合臂同級（PSNR +0.008、LPIPS +0.0017）、牆鐘 −9%；但「加點」的條件從沒成立（§5）。
- **SfM 點數分配 vs 採樣控制器（11-06，本機 b12）**（§6）：SfM 分配 cap 0.68M => 終點 0.45M、held-out 11.896／.8105（均勻 1M 11.883／.8078、控制器 11.900／.8084）、
  牆鐘 −17%（控制器 −1%）。訓練前就能決定、省得最多；代價 LPIPS +0.003（重跑差 0.0003 => 真的稍差）。全場景同總量比較等 lab。

## §1 現行（10-31）自適應 cap
```
探針：A＋dist4 全場景、每塊均勻 2.5M 跑完的 16 個單塊模型
每顆價值  v_i = sum_視角 sum_像素 T*alpha / sum_視角 覆蓋像素         （= 累加式 trim 的 V/C）
共同價格  λ：16 塊的顆粒放在一起，取 λ 使 #{v_i >= λ} = 0.4 x 總顆數  （λ = 0.00415）
每塊      cap_b = #{b 塊裡 v_i >= λ} / 0.9；權重 w_b = cap_b / 平均       （0.69 b12 ～ 1.34 b13）
```
- 理論＝`14` §3.3：總量固定時各塊「最後一顆的邊際價值」相等；用平均價值 V/C 近似邊際價值。
- 全場景平均 1M：27.828 vs 均勻 27.805（+0.023、LPIPS −2.6%；全場景重跑雜訊 0.002）。
- 弱點：探針成本一次全場景、權重只在一個預算點算、V/C 是平均不是邊際、和劑量實驗對不上（探針給 b12 最低 0.69，劑量實驗 b12 是加點還有收益的那塊，+0.04 接近雜訊）。

## §5 採樣控制器（使用者 11-05；`cap_ctrl_*`）
```
起訓：從本塊訓練相機挑 K = max(6, round(1.5% x 相機數)) 台當驗證視角——只從「它看到的可靠 SfM 點裡，觀測 <= 4 台的比例最低」的 8K 台裡抽；
      看到的可靠點 < 50 的不選（例：只拍到海）。它們在 densify_until（15k）前整步跳過（不做 optimizer step、步數不前進），之後放回訓練。
6k 起每 1500 步：渲染驗證視角（只算塊內 A 像素）=> L1、PSNR、透空率（alpha < 0.5）
  加 10%：透空 >= 2% 或 L1 這段進步 >= 2%，且 N >= 0.95 cap（cap 綁住）；上次加了、這次進步 < 0.5% => 不再加
  減 10%：透空 <= 0.5% 且進步 <= 0.5%   （cap 降了 MCMC 不補、trim 剪到新 cap；訓練中合併照常）
  範圍 [0.2M, 硬體上限]；cap_ctrl_adjust=false＝只留出與記錄（對照組）
```

- **要改的地方（11-05 審查）**：① 進步要用平滑趨勢（例如最近三次的斜率）並大於量到的重跑雜訊才算；② 檢查點避開訓練排程的切換（10k 熵切雙向、合併每 1500 步）；
