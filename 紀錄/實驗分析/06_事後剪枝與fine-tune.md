## 結論

- **現行（10-03）**：訓練期 trim 仍用 v（預設）；逐 tile 前 K 名做成訓練期判準（tilek）22k +0.08／+0.12、Load 待量；v/c×tile 名次（vpctilek）60k：val 平手（-0.03／-0.01）、Load 中位 -37／-38%、held-out -0.34／-0.12（`05` §0）。
- 剪完不重訓時，**現行 trim 判準 v 與逐 tile 前 K 名幾乎重疊、v 略佳**（同 PSNR 時 Load 更低）；前 K 名先前看起來最好，是因為對照組較弱。
- **v/c 在「剪完不重訓」時最差**（只留小而暗的顆粒、畫面出現大洞）；它在訓練期有效是因為 MCMC 會把名額重新分配（`05`）。
- 剪完再 fine-tune 5k 步：前 K 名與同 N 的 opacity 補回後**幾乎一樣（差 ≤0.04 dB）**；相對「不剪＋5k」，前 64 名 Load -30%／-0.35 dB、前 32 名 -47%／-0.84 dB —— **訓練期 v/c（-49%／-0.26）仍較好**。
- opacity 分布：中位 0.39、o>0.9 佔 21.7%、o<0.05 佔 5.8% => 大量卡在中間值，兩極化有空間；opacity 熵正則 `oent` 60k：val -0.62／-0.13 但 held-out +0.22／+0.42、Load -48／-52%（`05` §0）。

## §1 事後剪枝（不重訓，面板 a）

近似：kernel 只回傳每顆在一個視角的總貢獻 => 平均分到它覆蓋的 tile 再排名（邊緣 tile 會被高估）。

| K（保留比例） | 前 K 名 Load / PSNR | opacity 最高 | 總貢獻最大 | **現行 trim v** | v/c | 隨機 |
|---:|---|---|---|---|---|---|
| 8（25%） | 0.65M / 22.83 | 1.18M / 23.12 | 1.83M / 23.22 | **0.58M / 22.74** | 0.19M / 13.50 | 0.73M / 20.10 |
| 16（36%） | 0.92M / 24.95 | 1.35M / 25.22 | 2.05M / 25.19 | **0.85M / 25.03** | 0.31M / 15.04 | 1.05M / 22.00 |
| 32（50%） | 1.37M / 27.23 | 1.60M / 27.20 | 2.31M / 27.24 | **1.25M / 27.30** | 0.49M / 17.04 | 1.48M / 24.21 |
| 64（66%） | 1.92M / 29.17 | 1.93M / 28.83 | 2.56M / 28.97 | **1.78M / 29.17** | 0.76M / 19.81 | 1.94M / 26.54 |

- 「總貢獻最大」＝各視角（每像素平均 × 覆蓋像素）取最大，偏好又大又亮的顆粒 => 同顆數下 Load 最高。
- 「現行 trim v」＝各視角每像素平均貢獻取最大（renderer 週期 trim 的預設判準）。
- ⚠ 2026-10-01 更正：此圖初版把「總貢獻最大」誤標成「現行 trim 判準」。

## §2 剪完再 fine-tune（面板 b）

用 Lightning **接續** 60k → 65k（學習率停在最終值，增生與 trim 在 30k 後本來就停）。

| 臂 | N | 剪完未重訓 Load / PSNR | fine-tune 後 Load / PSNR / SSIM / LPIPS |
|---|---:|---|---|
| 不剪 | 2.34M | 2.94M / 30.48 | 2.93M / **30.68** / .892 / .122 |
| 前 32 名 | 1.16M | 1.37M / 27.23 | **1.55M** / 29.84 / .868 / .153 |
| opacity（同 N） | 1.16M | 1.60M / 27.20 | 1.77M / 29.87 / .869 / .149 |
| 前 64 名 | 1.55M | 1.92M / 29.17 | 2.05M / 30.34 / .882 / .135 |
| opacity（同 N） | 1.55M | 1.93M / 28.83 | 2.07M / 30.32 / .883 / .133 |

- fine-tune 時 Load 會回升（顆粒長大）；不剪多跑 5k 步本身也 +0.20 => 比較要對「不剪＋5k」。

## 延伸：逐 tile 前 K 名做成訓練期判準

`trim_by_tile_topk`（22k）：b6 29.13 vs 29.05、b13 29.31 vs 29.19（+0.08／+0.12，SSIM/LPIPS/紋理比同向）；首次觸發與貢獻判準的底部 10% 重疊只有 37~40%（真的剪不同的一批）；Load 待量。
v/c × tile 名次的合成判別式（`vpctilek`）與 opacity 熵正則（`oent`）的 60k 結果見 `05` §0。
