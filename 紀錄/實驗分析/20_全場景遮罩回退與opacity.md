## 結論
- **判準（使用者 10-23 糾正）**：目標是「維持高速、維持分數」。遮罩臂 2.5M 全場景 27.533（6.7 h、43.3 FPS）對舊最佳 27.739（30.7 h、35.6 FPS）
  是**快很多、分數低一點**，本身就可以留；漂浮層要**在快的配方裡修**，不是把省時間的元件退回去。修法的比較對象＝現行遮罩臂（品質與速度兩欄一起看），舊最佳只是參考線。
- 把 opacity 設定整組改回舊值（`opacity_reg 0.002`＋二元熵關，臂 `best1maskdistrfoe`）在 b0 換塊追平舊最佳（整張 **+0.004**，現行 −0.169），
  **但 [solo] 訓練每塊 +43%／+40%**（b0 1730 → 2471 s、b1 1740 → 2440 s）=> 不符方向，全場景重訓跑完 b0～b2 後撤下（§5）。
- **保留速度的修法（§6）**：二元熵**只往 0 推**（`opacity_entropy_side down`）在 b0 追平舊最佳（+0.017），10k 後切回雙向（ed10）品質不變（+0.008）、
  純訓練 +14%（oe +49%）=> 冗餘層是熵「往 1 推」那一半在前 10k 鎖出來的。剩下的 +14% 是 opacity 兩極化不完全的混合成本，正在試更早切回／切回後加大權重。
- 遮罩臂（遮罩＋dist100＋30k＋融合 Adam＋累加式 trim）4x4 全場景**輸舊最佳 full44_best**：2.5M 27.533 vs 27.739、1M 27.403。
  2.5M 的損失集中在 b0／b4／b1（−0.53／−0.30／−0.21），其他塊 −0.03～−0.14；1M 是每塊都小輸（−0.17～−0.59）。
- **2.5M 的病灶＝盒內多長一層 opacity≈1 的冗餘層**（水面／玻璃上方約 0.45），壞區 80% 像素是「本模型表面在舊最佳表面前方」。
  不是遮罩判錯、不是 init 帶來的；同配方重跑會穩定重現（換塊差 0.01）。
- 機制（推論，部分驗證）：best1 的 opacity 設定（L1 0 ＋ 二元熵往 0／1 推）在高 cap 下讓「光度上一致的多餘一層」以 opacity 1 存活；
  L1 或關熵任一項都去掉中層，但只有兩者一起才追平（§4）。
- **1M 的病灶主要是容量**：壞區只有 42.5% 在前方、48.8% 同深；漂浮顆粒 8k（2.5M 是 7.5 萬）。改回舊 opacity 在 b0 只拿回 +0.04。
- **量測盲點**：全因子消融只在 b6／b12 用「本塊幾何區域 Δ」判。b12 其實也有水面（使用者指出；10-23 前文件誤寫成「b6／b12 沒有水面」），
  全因子的遮罩 2.5M 臂在 b12 **也長了中層**（§3），但 b12 的漂浮層小（全場景漂浮顆粒 4.6k vs b0 41k），整張畫面只 −0.04；
  而 best1 家族每個臂在 b12 都輸舊最佳 −0.03～−0.07（連不加遮罩的 best1 也是），被當成基底的共同偏移，沒有回頭比 opacity 設定。
  而且 **10-14 使用者 viewer 目視就已記錄**「b12 海面是一層厚體積（水面格顆粒高度 p90−p10 0.367 vs 有 SfM 格 0.024）、我方 opacity 1.00 多而小＝二元熵所致」（`new_archived/研究總覽_v3_至2026-10-15.md`），當時評測無差 => 只寄望 dist 正則，沒追 opacity 設定。
  幾何區域又用基準模型的表面定義，漂到鄰塊內容前方的漂浮物不算進去 => 盲點疊在一起才漏掉（`方法論.md`）。

  - 多出的 211 s（ed10 相對現行）：第一段 61 s、第二段 88 s、第三段 52 s => 後段（切回之後）佔三分之二。
- 10-24 接著排（b0 [solo] 各約 30 分鐘＋換塊評測三）：

  - 判準：整張 Δ ≥ ed10 −0.02、純訓練最接近現行者勝；勝者 => 排 2.5M 全場景。

## 限制
- 機制的因果只在 b0 驗證（加 b0 1M）；b12 只量到冗餘層存在（§3），b1／b4／b12 的修復要看全場景。
- 「中層」用固定高度帶 0.25～0.7 與現行跑次的漂浮 xy 定義，換了位置的漂浮物不會被算到 => 判定以換塊與全場景 PSNR 為準。
- b0／b1 的三個 opacity 變體是 3 槽平行訓練，時間不可用；全場景重訓是 [solo]。
