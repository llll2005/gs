## 1. ADMM 的骨架（📚 標準形式）

📚 Boyd, Parikh, Chu, Peleato, Eckstein, *Distributed Optimization and Statistical Learning via the Alternating Direction
Method of Multipliers*, Foundations and Trends in ML 3(1), 2011。本文用到的是其中三種標準形式（章節待下載核對）：
全域共識（global consensus）、一般形式共識（general form consensus：每個子問題只對共享變數的一部分負責）、
共享問題（sharing：多個子問題共用一個資源約束）。另有原始／對偶殘差（primal/dual residual）與自適應 rho。

**縮放形式**（scaled form，u = y / rho）：

```
min_x,z  f(x) + g(z)   s.t.  A x + B z = c
L_rho(x, z, u) = f(x) + g(z) + rho/2 ||A x + B z - c + u||^2 - rho/2 ||u||^2

x^{k+1} = argmin_x  f(x) + rho/2 ||A x + B z^k - c + u^k||^2
z^{k+1} = argmin_z  g(z) + rho/2 ||A x^{k+1} + B z - c + u^k||^2
u^{k+1} = u^k + A x^{k+1} + B z^{k+1} - c
原始殘差 r = A x + B z - c；對偶殘差 s = rho A^T B (z^{k+1} - z^k)
```

⚠ **非凸**：3DGS／2DGS 的光度損失非凸，ADMM 沒有一般性的收斂保證（📚 同書有專章討論非凸情形，待核對）。
我們的使用方式是「把它當成有結構的交替啟發式，靠殘差曲線判斷有沒有在收斂」，不宣稱收斂定理。

## 2. 我方的問題寫成一個最佳化問題（🧮）

### 2.1 現行流程其實是「rho = 0 的共識＋合併時擁有者勝出」

記 K 塊，區塊 v 的全部顆粒 x_v（含塊外），訓練視角集合 I_v。現行每塊獨立最小化

```
f_v(x_v) = (1/|I_v|) sum_{k in I_v} L_photo(R(x_v, k), GT_k)         （R = 渲染）
```

合併（`utils/merge_citygs_ckpts.py`）時，每塊只留自己分區盒 Omega_v 裡的顆粒。寫成共識的語言：

```
z|_{Omega_v} := x_v|_{Omega_v}     （擁有者勝出），其他塊在 Omega_v 的顆粒丟掉
```

這等於 ADMM 在 rho = 0（各塊之間沒有任何耦合）下各自收斂，最後再做一次「投影到擁有者」。
被丟掉的那部分不是免費的，🔬 量測：
- 4x4 共 16 塊訓練了 37.4M 顆，合併只留 17.6M（47%）；best0 單塊 b6 只有 27.2% 在盒內、b12 34.7%
  （記憶 `out_of_block_eval_bias` 10-10；`logs/swap_b6_1014_0110.log`、`swap_b12_1014_0129.log` 的「塊內 x／2,340,000」）
- 訓練視角裡只有 43~57% 的畫面是本塊內容；只留盒內顆粒時 forward+backward −44~−59%、常駐 VRAM −57~−73%（10-11 `outbox_cost`）
- 🔬 同一張影像被多塊各自擬合：5,621 張訓練影像中 4,618 張（82%）出現在 >= 2 塊的訓練清單
  （2 塊 2,984、3 塊 1,207、4~7 塊 427；分區清單 `partition/partitions-dim_4_4_visibility_0.08/*.txt`，10-14 統計）

=> **同一個場景量被多塊重複估計、彼此不溝通，最後只取一份**。這正是共識問題的結構（📚 一般形式共識：每個子問題只對共享變數的一部分負責）。

### 2.2 統一的問題（本提案的核心式）

```
min_{x_1..x_K, z, theta}   sum_v f_v(x_v) + g(z, theta)
s.t.   A_v(x_v) = z|_{Omega_v'}          v = 1..K      （共識：區塊 v 對場景量 z 的看法要與 z 一致）
       S_k(x_v) = theta_k                k in I_v       （每視角深度尺度共識，§3.1）
       sum_v c(x_v) <= B                                （資源：6GB 峰值或時間，§3.3）
```

- Omega_v' 是區塊 v **看得到**的範圍（不只盒內；塊外的顆粒也必須和 z 一致 => 它們不能再用 floater 胡亂解釋鄰塊）。
- g(z, theta) 是**全域先驗**：SfM 點、單目深度。它只進入 z-更新一次，所有區塊共用，不再每塊各吃各的。

增廣拉格朗日（u_v、w_vk 為縮放對偶變數，lambda 為資源價格）：

```
L = sum_v [ f_v(x_v) + rho/2 ||A_v x_v - z + u_v||^2 + sum_{k in I_v} sigma/2 ||S_k x_v - theta_k + w_vk||^2 + lambda c(x_v) ]
    + g(z, theta) - lambda B
```

單卡交替（一輪 = 每塊各訓練 T 步；總步數維持 60k，例如 4 輪 x 15k）：

```
x_v     <- 訓練 T 步：f_v + rho/2 ||A_v x_v - z + u_v||^2 + sigma/2 sum_k ||S_k x_v - theta_k + w_vk||^2 + lambda c(x_v)
z       <- argmin_z g(z) + sum_v rho/2 ||A_v x_v - z + u_v||^2           （§3.2 有閉式）
theta_k <- argmin   g_k(theta_k) + sum_{v: k in I_v} sigma/2 ||S_k x_v - theta_k + w_vk||^2   （§3.1 有閉式）
u_v     <- u_v + A_v x_v - z ；  w_vk <- w_vk + S_k x_v - theta_k
lambda  <- max(0, lambda + eta (sum_v c(x_v) - B))
```

## 3. 各個要處理的問題（立論 → 推導 → 可證偽的預測 → 成本）

### 3.1 每視角深度尺度共識（「尺度共識」第一層，最便宜）

**立論**
- 💻 單目深度的尺度現在是**每張影像各自、只擬合一次、訓練中固定**：`utils/get_depth_scales.py` L70-129，對該影像看得到的 SfM 點，
  在逆深度上取 t = median、s = mean|x - t|，scale = s_sfm / s_mono、offset = t_sfm - scale * t_mono；
  parser 讀入時再把 scale 超出全體中位數 0.2~5 倍的影像整張丟掉（`internal/dataparsers/estimated_depth_colmap_dataparser.py` L53）。
- 📄 CityGSV2 §3.2（`2411.00771v2.pdf` p.5）：用 Depth-Anything-V2 估逆深度、依 Kerbl et al. (2024) 對齊到資料集尺度，
  `L_Depth = |D̂_k - D_k|`，權重指數衰減；並寫「GS algorithm necessitates iterative optimization to **disambiguate monocular cues
  from each view**」—— 官方承認各視角的單目線索彼此不一致，靠訓練慢慢消化。
- 🔬 現行配方 depth loss 權重 0；depth 0.5 在 22k 與 0 平手（`研究總覽.md` §8）=> **在目前的尺度下深度監督沒有用處**。
- ⚠ 舊年代量過「偽深度誤差是表面解析度的 174 倍」—— 作廢，P1-B 重量。

**推導（🧮）**
單目逆深度 m_k(p) 與真實逆深度只差一個仿射：1/D(p) ≈ a_k m_k(p) + b_k。區塊 v 在視角 k 的渲染逆深度 y_v(p) = 1/d_v(p)
給出它自己的估計 S_k x_v = (a_k^v, b_k^v)（用同一個 median／MAD 公式，或最小平方 a = cov(m, y)/var(m)，b = mean(y) - a mean(m)）。
共識：所有看到 k 的區塊必須同意同一組 theta_k = (a_k, b_k)。theta-更新取先驗 g_k = mu/2 ||theta_k - theta_k^SfM||^2 時有閉式：

```
theta_k = ( mu theta_k^SfM + sigma sum_{v: k in I_v} (S_k x_v + w_vk) ) / ( mu + sigma n_k )      n_k = 看到 k 的區塊數
```

**離群（10-14 Gemini 審查隱患 B）**：某塊只看到該視角邊緣少量像素時，S_k x_v 可能離群、污染線性平均。
以每塊的有效像素數 n_vk（或擬合殘差的倒數）當權重 omega_vk，共識仍有閉式解（加權最小平方）：

```
theta_k = ( mu theta_k^SfM + sigma sum_v omega_vk (S_k x_v + w_vk) ) / ( mu + sigma sum_v omega_vk )
```

若仍有離群，用 Huber 的 IRLS：每輪依上一輪的殘差重算 omega_vk 再套同一個閉式 => 不必退化成梯度下降。P1-B 報告離群比例與「加權 vs 不加權」的差。

x-更新裡的共識項把每塊的渲染深度往「所有塊＋SfM 共同認可的尺度」拉；深度監督改用 a_k m_k + b_k（共識尺度）
=> 尺度不再是一次性、單張、只看 SfM 的擬合，而是**全場景一致、隨幾何一起收斂**。

**可證偽的預測（❓ P1-B）**：若同一影像在不同塊擬合出的 a_k^v 幾乎相同（變異係數 << 仿射殘差），這層共識不活躍 => 不做。
若 a_k^v 之間差異大、或與 SfM 擬合差異大 => 有事可做。

**成本（🧮）**：每台相機 2 個 float（5,621 台 = 44 KiB）＋對偶同量；x-更新需要渲染深度（幾何通道，P1-C① 量）。

### 3.2 粗表面共識（「尺度共識」第二層：取代 coarse、約束塊外內容）

**立論**
- 📄 CityGS／CityGSV2 的流程是「先訓練一個全域 coarse 模型，再分塊平行微調」（`2411.00771v2.pdf` p.6 Fig.4：Pretrain → Parallel Tuning & Trimming）。
  coarse 是一個**固定的**全域先驗。
- 💻／🔬 我方不訓練 coarse：每塊從 SfM 點（dup init）出發（`研究總覽.md` §0；`實驗分析/08`）。代價是各塊對塊外內容沒有共同參考 => §2.1 的重複估計。
- 🔬 接縫：合併模型離接縫 0~0.05 格的 PSNR 與官方相同，但格子內部我方領先 +0.3~+0.5（`tools/seam_failure.py`，`研究總覽.md` §0 10-12）
  => 我方**相對官方的領先**在接縫處歸零、在內部是 +0.3~+0.5（🧮 推論：若接縫處能達到內部同樣的相對水準，約有 0.3~0.5 dB 空間；未證實）。
  ⚠ 絕對 PSNR 上接縫並不比內部差：10-14 換塊評測的接縫分組（`logs/swap_b6_1014_0110.log`、`swap_b12_1014_0129.log`）
  b6 接縫帶 25.69 vs 內部 0.1~0.2 格 25.74、b12 27.52 vs 27.11 => **接縫不是瓶頸**，這層共識的主要目的不是接縫。
- 🔬 單塊模型用塊外顆粒解釋鄰塊內容：單塊 held-out 只有 5~14% 像素是塊內內容，oreg0 的 val +1.41 其實是塊外 +2.34／塊內 −0.36（記憶 `out_of_block_eval_bias`）。

**推導（🧮）**
z 取一個場景量的粗表示。最簡單、可加權平均的選擇：分區座標系地面網格上每格 j 的表面高度 h_j、法向 n_j（以及顆粒尺寸 s_j，§3.2.1）。
A_v x_v = 區塊 v 從它的視角渲染出的表面點落到各格後的（加權）中位高度與平均法向。z-更新取先驗 g_j = mu/2 (h_j - h_j^SfM)^2（SfM 點在該格的高度）：

```
h_j = ( mu h_j^SfM + rho sum_{v sees j} (A_v x_v + u_v)_j ) / ( mu + rho n_j )
```

=> z 就是「學出來的 coarse」：初值來自 SfM（相當於 coarse 的角色），之後由所有區塊的觀測共同更新，而不是預訓練後固定。
x-更新的共識項：rho/2 sum_pixels (d_v(p) - d_z(p) + u)^2，d_z(p) 是視線與 z 表面的交點深度 => 對 x_v 可微（經由渲染深度 d_v）。
塊外顆粒也受這一項約束 => 用 floater 解釋鄰塊在幾何上要付代價。接縫一致是副產物（同一格 j 的所有區塊都對齊同一個 h_j）。

⛔ **2.5D 高度場被資料否決（10-14，P1-D 本機先跑，SfM 點不經 GT 影像配對 => 新年代有效）**：分區座標系地面網格上，
有 >= 5 個 SfM 點的格子裡，垂直分布 p90−p10 > 0.1 的格子 0.05 格 36.3%（點的 53.5%）、0.02 格 30.2%（點的 51.9%）
=> **一半以上的觀測落在不是單一表面的格子**（牆面、立面、樹；空拍是斜視角，立面看得到）。單一高度 h_j 會把它們壓扁（Gemini 審查隱患 C）。

**改用 z＝全場景 TSDF（🧮 推導）**：TSDF 融合（📄 官方抽網格用的 Open3D ScalableTSDFVolume，💻 `internal/utils/gs2d_mesh_utils.py` extract_mesh_bounded）
對每個 voxel j 存截斷符號距離的加權平均：

```
D_j = sum_i W_ij d_ij / sum_i W_ij        （i = 融合進來的深度圖，d_ij = voxel j 到該深度圖表面的截斷符號距離）
```

令 A_v x_v := 區塊 v 用自己的渲染深度（它的訓練視角）在 voxel j 算出的截斷符號距離（及權重 W_vj），
共識 z-更新在二次懲罰下是：

```
z_j = ( mu z_j^prior + rho sum_v W_vj (A_v x_v + u_v)_j ) / ( mu + rho sum_v W_vj )
```

=> **ADMM 的共識 z-更新就是一次（帶先驗與對偶修正的）TSDF 融合**：有閉式解、是 3D 的（牆與懸空都能表示），
融合權重 W_vj 天然就是逐 voxel 的信心 => 逐 voxel 的 rho_j = rho W_vj 解決「複雜區域該放鬆」（隱患 C）。
d_z(p) = 從視角 p 對 z 的 TSDF 做光線投射（raycast）求零交點；x-更新的共識項 rho/2 sum_p (d_v(p) − d_z(p) + u)^2 經由渲染深度 d_v 對 x_v 可微。
先驗 z^prior 可由 SfM 點與共識尺度後的單目深度（§3.1）融合而來 => 仍是「學出來的 coarse」，而且是 3D 的。
成本：每輪 z-更新 = 每塊全部訓練視角的深度渲染＋融合 => 與官方抽網格同一個流程，**已排的幾何 F1 任務會量到**它的時間與 RAM（`tools/mesh_tsdf_stream.py` 的 [成本] 行）。

#### 3.2.1 顆粒尺寸（LoD）共識 —— 只量、暫不約束
同一區域在擁有者區塊是細顆粒、在鄰塊是粗顆粒（塊外看得遠）。強迫一致可能反而增加成本 => P1 只報告差異，不列入 P2。

**可證偽的預測（❓ P1-A）**：相鄰兩塊在共同視角上，兩個單塊模型對同一像素的深度差：
「v 盒內」組（u 在這裡是塊外）若相對差與 >0.01（官方網格 voxel）比例都很小 => 塊外內容其實已經一致，這層共識不活躍；反之有事可做。

**成本（🧮＋❓）**：高度場版本的 z 只要 2~12 MiB，但已被否決；TSDF 版本的記憶體與時間由幾何 F1 任務量（稀疏 voxel，只存截斷帶）；
每輪 z-更新需要每塊把全部訓練視角渲染一次深度（P1-C②；本機 4050 上 b10 的 938 視角 69.8 s）加上融合。

### 3.3 全域資源預算：取代「每塊固定 cap」（共享問題）

**立論**
- 💻 現行每塊 `cap_max 2,600,000`，16 塊相同，與內容無關（`scripts/lab/task_cmp.sh` 共同旗標）。
- 🔬 區塊 10 的超高層大樓：屋頂 SfM 785 點、60k 只剩 177 顆；full44 時間線 1,651 → 222；換成 opacity 正則 0 後本塊幾何區域 +0.96 dB、
  大樓所在 +1.45 dB（`研究總覽.md` §0 10-12；`logs/swap_b10_1012_1432.log`）=> 不同區塊需要的容量本來就不同。
- 🔬 VRAM 與時間模型（lab outbox_cost 10 點，10-12 擬合）：時間 ms = 11.7 + 4.94 N(百萬) + 14.23 Σtiles(百萬/視角)（R² 0.954）；
  峰值增量 GB = 0.355 + 0.592 N + 0.057 Σtiles（R² 0.9995）；常駐 928 B／顆（記憶 `storage_structure`，09-17）。

**推導（🧮，📚 共享問題）**
```
min sum_v f_v(x_v)  s.t.  sum_v c(x_v) <= B
拉格朗日對偶：q(lambda) = sum_v min_{x_v} [ f_v(x_v) + lambda c(x_v) ] - lambda B
```
固定 lambda 時各塊**完全解耦**（各自訓練、各自以價格 lambda 計費）；lambda 只在輪與輪之間依總用量更新。
KKT（可微近似）：對所有使用容量的區塊，邊際價值相等 -df_v/dc_v = lambda
=> 固定 cap 等於強迫每塊用同樣的量，邊際價值不相等；共用價格讓容量**自動流向**像區塊 10 這種邊際價值高的地方。
c 可以是顆數（VRAM 常駐）、Σtiles（時間）或上面的峰值模型（6GB）。

⚠ 單卡逐塊訓練時「同時」只有一塊在卡上 => 6GB 是**每塊**的峰值上限，不是總和；總和預算的對象是**時間**與合併後模型的大小。
所以 B 要分兩種：每塊峰值（硬上限，仍由 cap 保證）與全場景時間／合併大小（由 lambda 分配）。

**可證偽的預測（❓ P2 之後）**：同總預算下，價格分配的容量 vs 固定 cap，合併模型 PSNR／F1 的差。

### 3.4 價值－價格剪枝：取代 trim 比例與 opacity 正則

**立論**
- 🔬 `實驗分析/13`：v/c 判準對大小懲罰兩次（§3），trim 判準 v、V/C、V/(β+C) 在訓練裡只是沿前緣移動的旋鈕（§7）；
  現行 trim 每 500 步固定剪 10%（💻 `sep_depth_trim_2dgs_renderer.py` 週期 trim），剪多少與預算無關。
- 🔬 opacity 二元熵正則換塊評測品質平手、Load −12%／−23%（`實驗分析/13` §2）—— 現有唯一「同品質省成本」的機制，但它是手寫的規則。

**推導（🧮）**
資源項 lambda c(x) 對單一顆粒 i 的邊際：移除 i 讓 f 增加約 ΔV_i、省下 c_i。增廣拉格朗日下降 <=> 移除條件

```
ΔV_i < lambda c_i
```

ΔV_i 的一階代理是 13 §4 的總貢獻 V_i；lambda 由 §3.3 的對偶更新給出 => **剪多少由預算決定**，不再是固定 10%；
判別式從比值 V/c（固定剪枝比例下的排序）變成差值 V − lambda c（價格下的門檻）。兩者在「剪掉固定比例」時給出同一個集合（13 §1），
差別在**數量**是否由預算決定 —— 這正是 13 §2 量到「只是沿前緣移動」的原因：比例是手調的，價格是被約束決定的。
opacity 正則（opacity_reg、二元熵）是「對所有顆粒收同一個價」的特例（c_i ≡ 1、價格固定）=> 被 lambda c_i 取代。

### 3.5 殘差驅動的增生：取代獨立的增生判準

**立論**
- 🔬 現行增生：MCMC 取樣權重 probs = opacity·(1 + w·|g|/mean|g|)，|g| 是 AbsGS 的絕對位置梯度（💻 `absgrad_densify`；📄 `AbsGS_2404.10484.pdf`）；
  ⚠ 舊年代「往誤差在的地方增生有效、往便宜／貴的地方無效」（記憶 `cost_aware_sampling_refuted`，分數作廢、機制可參考）。

**推導（🧮）**
|g| 是**總損失**對位置的梯度。x-更新的損失含共識項 rho/2 ||A_v x_v - z + u_v||^2，其梯度在「區塊與共識不一致」的地方大
=> 若 |g| 取自增廣拉格朗日的總損失，**共識殘差自動進入增生權重**：區塊解釋不了共識（原始殘差大）又在光度上有誤差的地方多長顆粒。
不需要新的增生機制，只要讓現有的 absgrad 看到增廣項的梯度。

### 3.6 接縫（副產物）

## 10. 待辦：共識背景取代盒外高斯（使用者 10-14 提議；**延後**：等 ADMM 相關數據（幾何 F1、P2）都出來，再看能否與共識結合後啟用）

**動機（🔬）**：單塊模型 73~81% 的顆粒在分區盒外（`g44_best0oeVC` b6 18.6%／b12 27.4% 在盒內），合併時全部丟掉；
它們存在是因為訓練影像有一半是鄰塊內容、光度 loss 要求被解釋。塊外池實驗（盒內顆粒 60 萬 -> 160 萬）品質不變 =>
盒外顆粒的代價是**時間與 VRAM**（只留盒內 fwd+bwd −44~−59%、常駐 −57~−73%，10-11），不是品質。

**想法**：讓模型「以為背景有東西」—— 由**鄰塊的盒內模型**（＝共識 z 的外觀部分）提供盒外像素，本塊只訓練盒內顆粒。
⚠ 只有幾何共識不夠，背景必須帶顏色；TSDF 的顏色（voxel ≈ 1 m、SH0）太粗，只能當第一輪的粗背景。

**討論過的做法**
| 做法 | 判定 |
|---|---|
| ① 鄰塊顆粒凍結、與本塊一起光柵化 | ✘ 本質同塊外池 B：渲染顆數不減，省不了時間 |
| ② 每輪預算背景圖（鄰塊渲染本塊訓練視角的 顏色＋深度＋alpha），訓練時兩層合成（依深度決定誰在前；背景在前的像素本塊不受監督） | ✔ 採用的方向 |
| 順序問題（先訓練的塊沒有鄰塊模型） | 用 **Jacobi 式**：第 k 輪一律用鄰塊第 k−1 輪的模型當背景，與訓練順序無關；第 1 輪照現行（含盒外顆粒） |
| 使用者的循環方案（每塊依序 0→10k、10k→20k…到 60k） | 可行；每次切換 ≈ 啟動 25 s（lab 實測 `g44_best0oeVC` b6：任務 05:12:50 -> 訓練開始 05:13:13）＋讀 ckpt 1~11 s ＋影像快取暖機 ~1 min ＋背景圖 1~2 min ≈ 3~4 min；6 輪 x 16 塊約 5~6 h（全場景約 30 h 的 +20%），可望被盒內化省下的時間抵掉 |
| **建議先做：在 30k（增生結束）切兩段** | 0→30k 照現行；30k→60k 拿掉盒外顆粒、cap 降到約 1M、背景＝鄰塊 30k 盒內；只有 16 次切換（約 1 h）；背景過時的話再在 45k 加一次更新（＝循環 3 輪） |

**最小驗證（不必從頭訓練）**：b6 起點＝`g44_best0oeVC`（或屆時的 `g44_best1`）b6 的 29999 ckpt；鄰塊背景＝`full44_best` 各塊 29999 ckpt 的盒內部分；
只跑 b6 的 30k→60k，換塊評測比品質，記每步時間與峰值 VRAM。實作：背景圖產生、兩層合成、30k 清盒外並調 cap、ckpt 接續（注意步數、LR、MCMC 狀態要接上）。約 1~2 天。

**與 ADMM 的結合點**：背景就是共識 z 的外觀部分；若 P2 的 TSDF 幾何共識成立，兩層合成的「背景深度」可直接取共識 TSDF 的 raycast，
背景顏色取鄰塊盒內模型 => 幾何與外觀共用同一個 z。

## 11. P2-a 自我共識（10-14 實作、本機功能測試通過、已排 lab）

**做法（🧮 縮放形式 ADMM，逆深度空間、逐視角逐像素）**
```
第 1 輪       x-更新 = best1 本身，0 -> T（T = 60k / R，R = 4 => 15k）
第 r 輪結束   A_v x   = 本塊全部訓練視角的渲染逆深度（alpha > 0.5）
              z-更新  = 把 (A_v x + u) 換回深度、融合成 TSDF（官方空拍參數 voxel 0.01／sdf_trunc 0.04／depth_trunc 5.0）
                        -> 抽網格 -> RaycastingScene 對每個視角 raycast => 共識逆深度 z（沒打到表面 = NaN）
              對偶    u <- u + (A_v x − z)（兩者都有效的像素）
第 r+1 輪     從上一輪 ckpt 接續（Lightning --ckpt_path：步數／Adam／LR 排程／MCMC 狀態都接上），
              深度 loss（現有 l1、逆深度）權重 rho = 0.2 固定、目標 = z − u；NaN => (depth, mask)、metric 只在遮罩內算
```
- 工具：`tools/admm_consensus.py`（z-更新＋對偶更新；`--neighbors` = P2-b）、`scripts/lab/task_admm_p2.sh <塊> [self|nb] [rho]`、
  `run_fit` 的 `CITYGS_RESUME=1`、dataparser `load_depth` 的 NaN 遮罩（單目深度檔沒有 NaN => 原路徑逐位元不變）。
- 與 §5.1 隱患 A 的處理不同：第一版 **rho 固定 0.2**，不做殘差平衡的自適應 rho；先看原始／對偶殘差與 PSNR 的軌跡再決定。
- 每輪 z-更新印出並存 `admm/round_<r>/consensus_stats.json`：原始殘差 |Ax − z|/z、對偶殘差 |z − z_prev|/z、raycast 命中率、有效目標像素比例。
