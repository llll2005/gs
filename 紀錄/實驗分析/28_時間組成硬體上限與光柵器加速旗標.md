## §3 不計分像素（塊外遮罩的 C 區）
**遮罩比例**（1600x900、16 px tile、各 150 張）
| 塊 | C 像素 | 整個 tile 都是 C | 整個 warp（2 列 x 16）都是 C | 整個 tile 都是 B 或 C |
|---|---|---|---|---|
| b3 | 12.4% | 10.9% | 12.7% | 40.8% |
| b12 | 14.3% | 12.9% | 14.7% | 48.5% |
- C 區是成片的 => 幾乎所有 C 像素都在整塊 C 的 tile 裡，可以整塊不跑。B 區不能略過（它負責把背景壓透明）。
- metric 把 C 像素的 render 換成 detach（`r*(1-c) + r.detach()*c`）=> 送進光柵器的顏色梯度在 C 區恰為 0；dist 步 C 區仍有 dist 梯度。

**本機檢查（ms，forward＋loss／backward／合計；相對 base）**

| base 重跑（噪音底） | ±0.0% | +0.2% | 梯度差 1e-7 級 |

## §4 V/C 累加先在 warp 內加總（`trim_running_warp`；forward.cu `WACC`）
- 原本：訓練 forward 每個被評估的（像素, 顆粒）做兩次 shared atomicAdd，同一 warp 32 條執行緒同時處理同一個 j => 32 路打同一位址、排隊。
- 改成：覆蓋數用 ballot＋popc（整數）、T·α 用 5 次 shuffle 加總，每個 j 每個 warp 只有 lane 0 寫 shared；混合的算式與順序一字不動。
| 設定（增生期：累加式 V/C 開） | forward＋loss | backward | 合計 | 正確性 |
|---|---|---|---|---|
| 累加（原本） | 34.91 | 36.45 | 71.36 | — |
| 累加（重跑） | 34.94 | 36.47 | 71.41 | 覆蓋數逐位元相同、Σ T·α 差 2.3e-7 |
| ★ warp 先加總 | **28.76（−17.6%）** | 36.50 | **65.26（−8.5%）** | 覆蓋數逐位元相同、Σ T·α 差 3.1e-7、渲染逐位元相同、梯度在噪音內 |
| ＋兩個 C 區旗標 | 28.25 | 35.36 | 63.61（−10.9%） | — |
- 只在增生期（累加式 trim 開著，≤ 15k）有作用 => 全程約 −4%；本機 30k 跑次合計 −10%（含 C 區）。
- ⚠ 第一次檢查沒量到東西：載入訓練到底的 ckpt 時，renderer 帶著「增生期結束、停止累加」（`_acc_stop`）的狀態 => 四種設定都沒在累加（`方法論.md`）。

## §6.1 每像素工作量與兩個新手段（11-08；使用者「減少 tile 就能減少時間」「都試試；VRS 判準多作幾個假設」）
`tools/probe/work_bench_1108.py`（b3 30k 預設 ckpt、N 0.72M、24 個訓練視角稽核＋10 個視角實測，GT 當目標；scratchpad `work_bench_b3_1108.log`）
- **每像素飽和前走過 80 顆（q50 59／q90 200／q99 354），其中真的混合 21 顆**（26.5%）=> 不是「一兩層就飽和」：
  一個像素平均疊 21 個 α >= 1/255 的貢獻（鄰近面元的高斯尾巴＋半透明層）才蓋滿。
- **飽和門檻 1e-4 -> 1e-3**（光柵器 lean bit 1024、renderer `t_sat_1e3`，預設不變）：n_proc ×0.843、n_blend ×0.800、整塊一起走的工作量 ×0.880；
  **實測 forward＋backward −6.3%**（66.22 -> 62.05 ms）。和 11-07 alpha 上限 0.999 的 < 0.3% 不同：0.999 只影響有 α > 0.99 實心層的像素，門檻影響所有像素的尾巴。
- **跳過 tile（VRS，metric `vrs_mode`）**，平均保留 0.6、下限 0.25，工作量＝256 × tile 內最大 n_proc：
  | 判準 | 期望略過工作量 | 分數最低 40% 的 tile 佔工作量 | 實測 forward＋backward |
  |---|---|---|---|
  | random（對照） | 40.0% | — | −15.6% |
  | error（上次逐 tile L1） | **47.5%** | **47.5%** | **−18.9%** |
  | texture（GT 梯度強度） | 31.0% | 28.0% | −11.9% |
  - **誤差低的 tile 反而是貴的**（佔 47.5% 工作量），平坦的 tile 才是便宜的（28%）=> error 判準省最多、texture 最少。
  - 略過 40% 工作量只省 16～19%：前處理、排序、SSIM、Adam 不隨 tile 數變。
- 訓練臂已排（b3 30k）：門檻 1e-3（`PF2DTS_`）、VRS random／error／texture／error 不補權重（`PF2DVRR_`／`VRE_`／`VRT_`／`VREN_`）。
