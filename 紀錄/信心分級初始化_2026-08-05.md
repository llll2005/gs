## 1. 立論：唯一沒被用過的資訊

我們試過**五個判準**去事後辨識 floater，全部失敗：

| 判準 | 結果 |
|---|---|
| 貢獻度剪枝（v/c） | 訓練側淨負（省 30% 只值 +0.1dB，剪掉的值 1.22dB） |
| `opacity_reg` | 劑量響應存在但只壓 opacity，不管位置 |
| 塵埃收割 | 剪 92% 顆粒紋理零損失 ⇒ 剪的是塵埃不是 floater |
| 多視角集中度 | 懸空/貼地分不開 |
| 深度一致度 | r=+0.253、五分位只差 1.3× |

**共同死因**：「這顆粒子在不在真實表面上」這個資訊，**訓練完的模型裡已經不存在了**。

但它在**訓練開始前**存在：**COLMAP 點的 track 長度 ＝ 這個 3D 位置被幾個獨立視角交叉驗證過**。
`internal/utils/colmap.py:52-57` 的 `Point3D` 一直帶著 `image_ids`，我們從來沒讀。

## 2. 實測前提（發車前驗完，全部成立）

### 2.1 track 長度有鑑別力

```
track 長度  p10/p50/p90/p99 = 2 / 4 / 17 / 60   max 338
  >=3: 75.0%   >=4: 53.5%   >=6: 34.2%   >=10: 19.5%   >=20: 8.0%
```

### 2.2 ⛔ 重投影誤差**不能**當信心指標（反相關）

```
track <= 2  誤差中位 0.142 px      ← 兩條射線精確可解，從沒被第三個觀測檢查過
track >= 6  誤差中位 0.549 px      ← 必須妥協於所有觀測
```

BA 可以自由移動 2-track 點去同時滿足兩條射線，殘差自然低。**用誤差加權會系統性偏好最沒被驗證的
點。** 這是本次差點踩進去的陷阱，記下來。

### 2.3 高信心子集的覆蓋沒有崩

```
只留 track>=3 (75.9%): 全體點到最近高信心點 p50=0.0x  p90=2.1x
只留 track>=4 (54.3%): p50=0.0x  p90=3.9x
只留 track>=6 (34.7%): p50=1.1x  p90=6.1x
```
（單位 = SfM 自身中位 NN 距離 0.00363）

## 3. 機制

**Tier A（錨點）**：`track >= k` 的 SfM 點，位置是公制的、**依定義離表面 0×**（對照 depth-init
實測 20.2×）。`w_i = 1`
**Tier B（填充）**：深度反投影點，**只放在沒有錨點的體素**。單目深度被降級成它唯一擅長的事——覆蓋
SfM 三角化不出東西的無紋理區（水面、空白牆）。`w_i = 0`

錨點的 **normal / scale / rotation 取自最近的 depth-init 點**，兩層 surfel 慣例完全一致 ⇒ 對照
depth-init 臂**唯一的變數是位置**。

`w_i` 的三個用途（**Stage 1**，本次未實作）：

| 位置 | 作用 | 對到 |
|---|---|---|
| `lr_i = lr·(1-w_i)` | 錨點幾乎不動 | 訓練把 20.2× 推到 29.2×（1.45×） |
| 剪枝豁免 | 錨點不受貢獻度剪枝 | 五個判準都剪錯人 |
| relocation 目標偏向高 `w` 鄰域 | | 死亡跑步機把點搬到空中 |

管路已存在：`rtg_stable_density_controller.py` 的 `eta` 就是逐顆屬性穿過 density control
（`dt_admm_density_controller.py:279` 註明 `_prune_points` 會一起過濾）。

## 4. 與主軸的一致性（含一個對自己的修正）

命題是 `max Q(θ_S) s.t. (1/K)·Σ_{i∈S} c_i ≤ B`，批評是「現有方法用 count 計價、盲於渲染成本」。

**我們自己的 init 也是 count-based。** 而且比我一開始以為的更徹底：

- `depth_init_blocks.py` 用世界座標固定體素下採樣決定**放幾顆** → 成本盲
- **尺寸也是成本盲**：實測 b12 的 PLY，`scale range = -3.5066 到 -3.5066`，**全部相同**，
  `exp(-3.5066)=0.02995 ≈ voxel_min 0.03`。走的是 `depth_init_blocks.py:444` 的**後備分支**
  （單一體素尺寸），不是 `:432` 的 `depth_i/focal`（每顆蓋一個像素足跡）。
  ⚠ 我一度寫成「尺寸是成本感知的」，**錯，已修正**。

⇒ 我們的 init 正是論文批評的 `c_i ≡ 1` 特例，只是套在初始化上。信心分級把同一個式子往前推一步：
init 決定候選集 `S_0`，track 長度給 `q_i` 的先驗、螢幕足跡給 `c_i`，**初始化本身就是同一個
knapsack，只是在訓練前解一次**。論文目前只把成本感知用在 densify，延伸到 init 是自然且沒人佔的。

## 5. 實作：`tools/make_graded_init.py`

```
conda run -n gspl python tools/make_graded_init.py --block 12 --track_min 4 \
  --out data/matrix_city/aerial/train/block_all/depth_init/graded_k4_block_12.ply
```

輸出 PLY（欄位與 depth-init 完全相同）＋ `<out>.w.npy`（Stage 1 用）＋ `<out>.track.npy`。

### 5.1 ⚠ 取點區域不能用 partition AABB（第一版的 bug）

第一版用 `load_partition_aabbs` 取區域，結果**錨點只有 30,476（2.5%）**。原因：

```
b12 官方 partition AABB 內的 SfM 點     196,631
depth-init 雲的足跡內的 SfM 點        1,160,384      ← 大約 6 倍
```

**depth-init 是把 284 張影像的每個像素反投影出來的，那些相機看得到的範圍遠超出 block 邊界。**
所以正確的區域判準是「離 depth-init 雲夠近」（預設 3× 格距），不是 AABB。這同時免費濾掉
COLMAP 的離群點（z 最低 -202）。

**副產物事實：我方 block 之間的內容重疊非常嚴重**（單塊的重建範圍約是其 AABB 的 6 倍面積）。
這對 merge 與「25 塊全場景」的成本估算有含意，待另外評估。

### 5.2 k=4 的實得組成

```
區域內 SfM        1,160,384
track >= 4          648,416  (55.9%)
體素降採樣 @0.02456 → 203,916 錨點   (track 中位 11, p90 42)
Tier B 填充       1,112,307  (91.8% of depth-init)
總計              1,316,223  = depth-init 1,211,537 的 1.09×   ✓ 顆數對齊
```

**⚠ 錨點只佔 15.5%。** 瓶頸是「有多少體素格裡有任何 SfM 點」——那是 SfM 覆蓋的性質，
**把 k 降到 2 也只會小幅增加**。所以 Stage 0 預期分數差異很小。

### 6.1 真正要量的不是 PSNR

15.5% 的錨點、沒有 lr 保護（那是 Stage 1），預期分數差異小。**Stage 0 的產出是兩個在 step 5,680
就能讀到、且決定 Stage 1 值不值得做的量測**（工具＝`tools/measure_anchor_drift.py`）：

1. **漂移**：錨點離自己初始（已驗證）位置跑多遠
   - 漂了 ⇒ 光度損失會把驗證過的點拉離表面，**Stage 1 的 lr 保護是必需品**，且知道要救多少倍
   - 沒漂 ⇒ init 線比假設的弱，該轉向 RAIN-GS 的觀點（問題在優化不在 init）
2. **存活率**：v1 是淨衰減（interval 350 > break-even 231.5，每 3500 步 −22%），貢獻度剪枝會大量
   處決。**錨點存活率若不高於填充點，就是第六個判準的獨立驗證**——貢獻度剪枝盲於幾何。

⚠ **粒子沒有持久 ID**（剪枝/relocation 每幾百步重寫陣列），所以兩個量測都定義在**初始體素格的
佔用率**上，不需要身分追蹤。

### 6.2 起步健康度（已確認）

`d_reg = 0.170 / 0.148`，與 v1 同期（0.169/0.148）同量級。對照失敗的純 SfM-init 臂是 **5.5e5**
——Tier B 保證覆蓋，中位深度退化沒有觸發。VRAM 1601 MiB。

## 7. 三個必須帶著的警告

1. **`surface_distance` 判不了勝負。** 它的定義就是「到最近 SfM 點的距離」，Tier A 起點必然 0×，
   循環論證。勝負只看 PSNR / SSIM / LPIPS / 紋理比。
2. **RAIN-GS 是直接的反證**（*Relaxing Accurate Initialization Requirement for 3DGS*）。它主張用
   對的優化策略，隨機初始化也能追平 SfM 初始化。若成立，整條 init 線打錯方向。
   使用者提供的辯護是「RAIN-GS 假設資源充足，6GB 下沒本錢讓優化器盲目探索」——**這個辯護尚未查證**。
   ⚠ arXiv ID 據稱 `2311.16043`，**離線無法核對，引用前必須確認**。
3. **⛔ 已知的幻覺文獻，不得寫入文獻探討**：使用者轉述的 Gemini 回覆中，「EDGS (CVPR 2026)」、
   「Photometric SLAM 密集初始化 (2026)」、「MDPI 動態場景誤差分離 (2026)」**經其本人確認為無對應
   arXiv ID 的幻覺**，全部作廢。只有 RAIN-GS 是真實存在的（仍待查證 ID）。
