# 提案：雙峰 opacity 正則化 MCMC（RTG 語義 × MCMC 引擎的融合）— 請 Gemini 評估

> 給 Gemini 的自足文件。數學用 ASCII。背景：6GB VRAM 城市級 2DGS 訓練，
> 底座 = CityGS trim rasterizer + 3DGS-MCMC 密度控制 + SB color（DBS 移植，F=25 floats/pt）。
> 單塊 b12 錨點：SH3@1.0M=22.45、SB@1.0M=21.99（60k 步）。

## 0. 一句話提案

把 MCMC 的 opacity L1 正則換成**雙峰勢阱**：讓 opacity 的統計分佈在 alpha=0.99 和
alpha=0.1 形成兩個峰、往 0 和 1 兩端急速遞減——即 RTG-SLAM 的「不透明面 / 透明細節」
二分語義，但**不用硬釘死 alpha**（硬釘死會殺掉 MCMC 的死亡-回收引擎），改用軟性
統計壓力實現。

## 1. 它一定會配到的機制（全景，這些交互決定成敗）

現行 pipeline 中 opacity 參與的所有機制：

| 機制 | 現行行為 | 與雙峰的交互 |
|---|---|---|
| (a) opacity L1 + 免疫護城河 | `R = 0.007 * sum |o_i| * 1(o_i < 0.9)`——**注意：alpha>0.9 已免疫**（保護 depth-init 的 alpha=0.99 先驗） | **現行系統已是「單邊高峰自由區 + 下方均勻衰減」**。雙峰的邊際增量只有 0.1 吸引子 + 中間勢壘 |
| (b) MCMC 死亡-回收 | o<0.005 判死 → relocation 搬到高 alpha 點旁 | 0.1 峰若太深會困住點掉不到 0.005 → **餓死 relocation 供給** |
| (c) relocation 重整化 | 搬家時 host 分裂成 N 份：`o' = 1-(1-o)^(1/N)`，保證搬家瞬間渲染不變 | **核心衝突點,見 §4-P1（棘輪效應）** |
| (d) 貢獻度 trim | 每 500 步渲染全視角，砍 transmittance 貢獻最低的 10% | 0.1 族=天然低貢獻族 → **trim 每次都優先處決 0.1 峰** → 「細節族」無法存續 |
| (e) xyz 噪聲注入 | 噪聲量 ∝ sigmoid(-k(o-t))：低 alpha 點多噪聲（探索）、高 alpha 穩定 | **天然協同**：雙峰後 0.99 族=穩定低噪、0.1 族=高噪探勘——MCMC 噪聲排程已經隱含 RTG 的 stable/unstable 二分 |
| (f) SB color（alpha-color 簡併） | 顏色振幅走 softplus 無上界，`alpha * c` 乘積可互相補償 | 雙峰塑形 alpha 後，外觀可能被顏色振幅重新吸收 → 雙峰可能只是「化妝」 |
| (g) min_opacity=0.005 死亡線 | 均勻 L1 下點自然滑落過線 | 0.1 峰到 0.005 之間要留通道 |

## 2. 數學表達式

### 現行（等效形式）
```
R_op = lambda_o * sum_i |o_i| * 1(o_i < 0.9)      lambda_o = 0.007
```
= 高段 [0.9, 1] 自由區（de facto 高峰）+ 低段均勻衰減（死亡通道）。

### 候選雙峰形式（三種，遞增原則性）

**形式 A：最近峰二次阱**
```
R_bi = lambda_bi * sum_i min( (o_i - 0.1)^2 , (o_i - 0.99)^2 )
```
簡單，但 0.1 阱雙邊對稱 → 困點（違反 (b)）。

**形式 B：非對稱阱 + 洩漏項（我方目前傾向）**
```
R_bi = lambda_hi * sum_i (o_i - 0.99)^2 * 1(o_i > t_split)          # 高段拉向 0.99
     + lambda_lo * sum_i (o_i - 0.1)^2  * 1(0.1 < o_i <= t_split)   # 中段只從上方拉向 0.1（單邊）
     + lambda_leak * sum_i o_i          * 1(o_i <= 0.1)             # 0.1 以下:微弱衰減=死亡通道
t_split ~ 0.5(勢壘位置), lambda_leak << lambda_lo
```
0.1 阱做成**單邊**（只從上方吸，不從下方托）→ 光度上無用的點仍可滑落死亡。

**形式 C：混合先驗 MAP（SGLD 觀點，理論最乾淨）**

3DGS-MCMC 原論文把訓練解讀為從 exp(-loss) 採樣（SGLD），正則項 = -log(prior)。
換先驗理論上完全合法：
```
R_bi = -lambda_bi * sum_i log( w1 * N(o_i; 0.1, s1) + w2 * N(o_i; 0.99, s2) )
```
「往 0/1 急速遞減」= s1, s2 取小。死亡通道問題同樣要靠 s1 或額外洩漏項處理。

## 3. 為什麼可能合理（四個論點）

1. **先驗匹配收斂統計**：訓練完的 3DGS/2DGS opacity 分佈本來就近似雙峰（一坨貼 1、
   一雲低值）。把先驗設成終態分佈 → 點更快「表態」，可能縮短我們實測 34k 步的
   庫存期 churn（Arm A 解剖：densify 期 val 平坦 34k 步，收割只需尾部 ~10k）。
2. **噪聲排程免費協同**（機制 e）：0.99 族自動低噪聲=穩定幾何、0.1 族自動高噪聲=
   探索者。RTG 的 stable/unstable 分類不用另外實作，MCMC 噪聲公式順手就給了。
3. **中段 opacity = 病理帶**：我們的 b12 近相機怪物 opacity≈0.028、floater 通常
   也是中低 opacity 半透明體。雙峰**抽乾中段**（要嘛表態成 0.99 真幾何、要嘛落
   0.1/死亡）→ 直接打擊半透明浮游物族群。這是我們自己的病理數據支持的論點。
4. **免疫護城河已是半成品**：現行 alpha>0.9 免疫 = 高峰自由區已存在且有效
   （它是 b12 存活配方的一部分）。提案只是把「另一半」補上，不是推倒重來。

## 4. 為什麼可能不合理（五個問題，P1 最致命）

**P1（核心）：relocation 重整化的「向上棘輪」**
現行重整化 `o' = 1-(1-o)^(1/N)` 保證分裂瞬間渲染不變。host o=0.99 分裂：
```
N=2: o' = 1-(0.01)^(1/2) = 0.900
N=3: o' = 1-(0.01)^(1/3) = 0.785
```
→ 分裂產物**落在兩峰之間**。接著：
- 現行 L1：把它們往下拉（與死亡供給方向一致，系統自洽）
- 雙峰：把它們往上拉回 0.99 → **每次 relocation 事件淨增 opacity 質量**（棘輪向上）
  → (i) 渲染系統性變亮/糊；(ii) 死亡供給隨時間萎縮 → MCMC 引擎自我熄火。
這是提案與 MCMC 核心數學的**結構性矛盾**，不是調參能繞的。

**P2：trim 處決 0.1 族**（機制 d）：0.1 族被設計成「合法低貢獻」，但貢獻度 trim
每 500 步砍貢獻墊底 10% → 0.1 族=旋轉門（正則塞人進去、trim 拖出去斃掉）。
RTG 的 0.1 是要**存活**的細節表達；不改 trim 的話這語義不成立。

**P3：勢壘阻斷晉升**：細節點該轉正（0.1→0.99）時必須逆著正則梯度翻越 t_split
勢壘 → 遲滯。RTG 靠顯式分類規則做晉升（非梯度）；純正則版缺分類器，
族籍變成初始化樂透。

**P4：alpha-color 簡併**（機制 f）：SB 振幅無上界，`alpha*c` 可補償——雙峰塑形了
alpha 的直方圖，外觀該表達的還是被顏色吸走 → 可能只改了統計美觀，沒改渲染品質。

**P5：超參曲面爆炸**：兩峰位置、兩阱深、勢壘位置、洩漏強度 ≈ 5-6 個新超參，
而我們的驗證成本是 24h/run（6GB 單卡）。搜尋負擔不可忽視。

## 5. 進行中的先導實驗（結果會餵給這個設計）

收割期三臂（從 SB@1.0M 的 42k ckpt 精確續訓，只重放 18k 收割段，~80min/臂）：
```
cprime: 原樣          -> resume 機制驗證,應 ~21.99
freeze: opacity 凍結   -> 收割期 alpha 壓力是純損耗?(Arm A 尾端 trim 折損 1.0M->0.90M)
noreg : opacity_reg=0 -> 只撤收縮壓,光度仍可動 alpha
```
判讀 → 雙峰設計：freeze/noreg 若 +X dB → 收割期壓力=損耗 → 高峰阱該深（保庫存）；
若 ≈ 平 → alpha 壓力無害 → 雙峰的預期效益下修。

## 6. 丟給 Gemini 的問題

1. **P1 棘輪有沒有數學解？** 能否推導一個「峰約束下的渲染保持重整化」——分裂時
   直接產出 {一個 0.99 + 其餘 0.1} 的組合且 alpha-blending 淨貢獻不變？閉式存在嗎？
   （約束：sum 渲染權重守恆,輸出限定落在兩峰上）
2. **0.1 峰值得存在嗎？** 還是航拍場景下正確答案其實是「單峰 0.99 + 死亡通道」
   （= 現行免疫護城河 + 更陡的中段衰減），RTG 的 0.1 透明細節族只在近景/室內有用？
3. **trim 相容性**：0.1 族該對貢獻度 trim 免疫嗎？還是干脆讓 trim 取代 min_opacity
   成為唯一死亡通道（0.1 阱做成雙邊、死亡全交給 trim）？
4. **晉升機制**：靠光度梯度翻勢壘（純正則）vs 在 densify 事件做顯式重分類
   （RTG 式規則）——哪個與 MCMC 的分佈保持哲學相容？
5. **形式選擇**：A/B/C 三式，若走 C（混合先驗），w1/w2/s1/s2 有沒有原則性設法
   （例如從收斂 run 的 opacity 直方圖擬合）？
6. **判準預註冊**：這條線的 kill criteria 該是什麼？我們傾向:中段(0.2-0.8) opacity
   質量占比、floater 密度、settle 收斂步數、最終 PSNR 四項，全平即關線。
   單次驗證 24h,預算最多 2-3 次全跑。

## 7. 我方傾向（供對撞）

形式 B（非對稱阱+洩漏）+ 晉升走 densify 事件顯式重分類 + 0.1 族對 trim 半免疫
（trim 配額按族分開）。但 P1 棘輪未解前不動工——若 Q1 無解，這條線可能該降級成
「只補中段衰減斜率」的小改（拉陡 0.1-0.9 區間的 L1，不做真雙峰）。
