# 現況摘要（給外部查證用）2026-08-01

專案：消費級 6GB GPU（RTX 4050 Laptop）上訓練城市級 2D Gaussian Splatting。
資料：MatrixCity small_city aerial，5621 張訓練影像，官方 741 幀 held-out 測試集。
基線：CityGaussianV2（ICLR 2025），論文用 8×A100。

---

## 一、今天（2026-08-01）確立的事實

**1. 姿態是精確的 GT。** `sparse/0` 存的是 MatrixCity GT 姿態 × 1/100（Umeyama Sim3 對齊
5621 台相機，殘差 0.0 px，尺度因子恰好 0.010000）。COLMAP 只做三角化。
官方 CityGaussian pipeline 本身就是這樣做的（`tools/convert_cam.py` 跑的是
`point_triangulator` 而非 `mapper`）。→ 我們先前「GT-free」的定位建立在誤解上。

**2. 全專案既有數字都不是 held-out。** `split_mode=reconstruction` 使 val ⊂ train
（每 8 張取 1 張，但那張也拿去訓練）。共 318 筆實驗、270 筆三指標齊全，全部如此。

**3. 逐塊評測官方 test 集無效。** 單塊模型只擁有 1/9（3×3）或 1/25（5×5）的城市，
而航拍視錐涵蓋範圍遠大於此 → 畫面大半渲染成空白，PSNR 卡在 ~15 dB，與該塊品質無關。
實測：b7 模型在官方測試視角上，畫面左半重建正常、右半空白拉絲。
→ 只有合併模型能對外比較。目前正在跑 3×3 全場景（9 塊，約 10.5 h/塊）。

**4. 我們用了兩週的指標在該區間沒有鑑別力。** b12 於 07-19~28 的跑次：

| | n | 平均 PSNR | 平均 LPIPS |
|---|---|---|---|
| 30~34k 就 OOM 死掉 | 4 | 19.39 | **0.729** |
| 完整跑完 60k | 9 | 21.97 | **0.737** |

半途死掉的殘廢模型 LPIPS 反而「較好」。原因之一：b12 約一半畫面是平坦水面，
水面視角 PSNR 32~40 dB 而渲染幾乎是均勻色塊，把建築區的失敗完全稀釋掉。
→ 該區間的實驗狀態是「**沒測過**」而非「測過無效」。

## 二、目前唯一穩固的量化結果

同一塊（b12）、resolved config 逐項相同（cap 1M / 1.2× / opacity_reg 0.007 / sh0 / 60k /
train_strips 1），**只有 rasterizer 二進位不同**：

| 步驟 | PSNR | SSIM | LPIPS |
|---|---|---|---|
| 基線（07-21） | 22.12 | 0.592 | 0.742 |
| **+ EXACT_SUPPORT** | 23.31 | 0.640 | 0.624 |
| + opacity_reg 0.007→0 | 23.11 | 0.652 | 0.525 |
| + cap 1M→2M（實得 1.80M） | 23.39 | 0.667 | 0.491 |

**EXACT_SUPPORT** = 在 binning 階段直接剔除 `o <= 1/255` 的 primitive，並把支撐半徑
收緊到 `d_max = sqrt(2*ln(255*o))`。對**固定模型**是位元級無損（實測 maxdiff = 0，
因為 blend loop 本來就丟棄 `alpha < 1/255`），省 20.3% 渲染峰值 VRAM，
訓練顆數天花板 2.0M → 2.5M（3×3 實測達 2.70M）。
但在**訓練時**被剔除的 primitive 拿不到梯度 → 它同時是一個隱式稀疏化機制，
這是我們量到過最大的單一品質槓桿。

⚠ 注意 `opacity_reg 0.007→0` 讓 PSNR 掉 0.20 卻讓 LPIPS 進步 0.099 —— 只看 PSNR 會做出相反決定。

## 三、當前的方法論方向（需要新穎性查證）

### 命題：把「內參 → 外參」的修正對稱地套用到資源分配問題的兩側

現有密度控制用**內參**（primitive 自身的屬性）當代理：

| | 內參（現行做法） | 外參（我們的修正） | 狀態 |
|---|---|---|---|
| 供給側：定價 | count / opacity L1 / scale L1 | 螢幕 tile 覆蓋 `c_i` | 已實作 |
| 需求側：誰該死 | `opacity < 門檻` | 多視角貢獻 `v_i = Σ_views Σ_px T·α` | 未測 |
| 需求側：往哪去 | `probs ∝ opacity` | 結構缺口（SSIM 梯度） | 未測 |

佐證：我們觀察到「殭屍」現象——高 opacity 但從不渲染的 primitive 一度佔 87%。
那正是 opacity 作為內參代理的失效模式（高不透明度、零貢獻）。
供給側已修掉的同一個瑕疵，需求側原封不動還在。

實測：MCMC 的取樣對誤差完全盲目，`err@opacity-sampled / mean = 1.000~1.005`。

### 相關的已知數字

品質 scaling law `PSNR ≈ a + 0.8*ln(N)`，我方截距 a≈12.1 vs CityGaussianV2 a≈16.7
（缺口約 4.5 dB）。純靠堆顆數補足需要 `e^(4.5/0.8) ≈ 277 倍`顆數 —— 6GB 上不可能。
→ 訊號（截距）是唯一能動的槓桿。CityGaussianV2 把該截距歸功於 DGD
（Decomposed-Gradient Densification，其 Eq.2）：

    grad_densify = max( w * |grad_L|_avg / |grad_L_SSIM|_avg , 1 ) * grad_L_SSIM

理由是 L1 對「糊」不敏感，SSIM 才是懲罰結構流失的項。

⚠ 但我方 2026-07-29 量測誤差導向 densify 的天花板僅 1.2×
（`mean(top5% 誤差) / mean(全部)`），據此擱置。該量測的兩個弱點正在重測中：
(a) 量的是光度誤差而非 SSIM 梯度；(b) 在 b12（一半是水）上量，水面會把集中度稀釋向 1.0。

## 四、想請外部（可聯網）查證的問題

**Q1（前案／新穎性・最重要）** 「在 binning 階段直接丟棄 `o <= 1/255` 的 primitive，
並用 `sqrt(2*ln(255*o))` 當精確支撐半徑」——這個具體做法是否已有論文發表？

我們的差異點宣稱是：**對固定模型位元級無損**（非近似），且**訓練時它同時是隱式稀疏化器**。

換成 `∝ 外參的結構缺口或多視角貢獻`，是否已有工作做過？

**Q3（現況數字）** MatrixCity aerial（small_city）目前 SOTA 的 PSNR/SSIM/LPIPS 是多少？
用的是哪個測試協定（官方 741 幀 held-out？還是自訂 val）？多少 GPU、多少 primitive？

**Q5（風險）** 是否有工作report過「合併多個獨立訓練的 block 之後，各塊的 floater 疊加
導致新視角品質崩壞」？有沒有標準的緩解手段（我們目前打算用 contribution-based
的無損剪枝）？
