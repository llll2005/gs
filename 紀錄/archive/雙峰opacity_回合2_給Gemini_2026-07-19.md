## 0. 炸彈：收斂態 opacity 直方圖（兩個 kernel 都量了）

b12 60k 收斂 ckpt（N=900k，final trim 後），sigmoid 後：

```
             SB@1.0M(21.99)   SH3@1.0M(22.45)
o < 0.05        96.6%            97.1%

mid(0.2-0.8)     0.8%             0.7%
o > 0.90         1.4%             1.3%   (~12k 顆)
```

**兩個 kernel 幾乎同分佈 → 這是配方收斂常態，非 SB 病理**（也順帶排除了
「SB 的 -0.46dB 來自 alpha-color 簡併霧化漂移」假說——SH3 一樣霧）。

**渲染 22 dB 的實體影像的，是一團 97% 近透明的「霧」**：靠 b12 的高 overdraw
（tau_mean~40）讓幾十片 o~0.02 的 splat 沿射線疊出表面。另兩個附帶事實：
- depth-init 出生時 1.21M 顆全是 alpha=0.99；60k 後只剩 ~12k 顆還在高峰
  → **免疫護城河(>0.9 免 L1)會漏**：光度梯度自己把點拖過 0.9 線，然後 L1 接手。
- b12 近相機怪物 o=0.028 = **這個分佈裡的中位數公民**——opacity 對病理零訊號
  （我方 cost-aware 論文命題的又一實證）。

## 1. 這個事實如何重排雙峰討論

1. **回合 1 我方論點 3.1（「先驗匹配收斂統計」）錯了**：收斂分佈不是
   「一坨貼 1 + 一雲低值」的教科書雙峰——是「97% 貼 0 + 1.3% 貼 1、低峰在
   ~0.02 而非 0.1」的極端簡併雙峰。
2. **中段早就是空的（0.7%）**——「抽乾中段打擊 floater/怪物」這個論點沒東西可抽。
3. **0.1 阱對現有族群近乎惰性**：97% 的點在 0.1 以下；單邊阱（只從上方吸）對
   它們無力；雙邊阱反而把 0.02 的霧「抬」到 0.1 = 增加 opacity 質量 = 反向棘輪。
4. **你的「0.1 = transient probes」歪打正著、但號碼寫錯**：系統已經是
   probe-dominated——只是 probe 峰在 0.02，且是 97% 的主體不是少數派。
5. **真正的設計空間反轉了**：問題從「要不要造 0.1 族」變成
   **「要不要把霧凝結成面」**——即擴大那 1.3% 的 0.99 錨定族
   （opacification 壓力），方向與我們原先擔心的完全相反。
6. **霧 ↔ VRAM 經濟耦合（接上我們的 cost-aware 主線）**：不透明面表達下每像素
   只需 ~1-2 片 splat；霧表達需要幾十片疊加 → **霧直接推高每像素相交數
   → tau×N → rasterizer 緩衝 → 我們的 6GB 瓶頸本身**。opacification 不只是
   品質假說，是**成本槓桿**：若能凝結，N_max 公式的 tau 項下降。
   （反面：霧可能就是光度最優——薄結構/抗鋸齒天然愛半透明。未測。）

## 2. 閉式解對帳（你的 P1 解）

**數學驗證：通過。** 穿透率守恆與顏色守恆推導我們獨立驗算無誤
（同位置同色下 C = c_host * o_host 嚴格成立）。三個補充：

- **有效域缺口**：o_main >= 0 要求 `o_host >= 1 - (1-o_low)^(N-1)`。
  MCMC 的 host 按 opacity 抽樣、單 host 可分到多個死點，我們 N_max=51：
  N=23 需 o_host>=0.90、N=51 需 o_host>=0.995 → **必須加 per-host ghost 配額**
  `G_max = floor( log(1-o_host) / log(1-o_low) )`，溢出的死點改派其他 host
  或回退古典重整化。
- **附帶紅利（你沒提）**：此方案下 ghost 必須完整複製 host 的
  scale/rotation/位置 才能維持守恆 → **原 compute_relocation 的 binomial
  scale 調整可以整段跳過**（那套是為等分 split 推的）——實作反而更簡單。
- 守恆只在分裂瞬間成立、之後被噪聲打破——與現行 MCMC 同等待遇，可接受。

## 3. 回答你的反問（ghost 的 SB 振幅初始化）

**全量繼承 host 的 SB 參數（含 DC 與 lobes），不重置。** 三個理由：
1. **守恆要求**：你的顏色守恆證明假設所有分裂產物同色——ghost 若重置 lobes，
   分裂瞬間渲染就變了。
2. **churn 稅教訓**（我方 beta 線實測）：可學 kernel 參數在 churn 中反覆重置
   = 淨負。ghost 九成會被 trim 收割，繼承是零成本；重置是白繳學費。
3. **晉升暖啟動**：僥倖轉正的 ghost 出生在 host 位置，host 的局部視角依賴
   就是它最好的先驗。

## 4. 給你的新問題（按優先序）

1. **霧 vs 面，怎麼判**：97% 霧態是「光度最優的合法表達」還是「L1 常數下拉
   造成的人工均衡」（點停在光度梯度 ~= lambda_o=0.007 的懸崖邊）？有沒有
   理論工具或便宜實驗能區分？（我們正在跑的 noreg 臂——收割期撤掉 opacity L1
   ——似乎正好測這個：撤壓後若霧自發凝結+PSNR 升 → 人工均衡實錘。你怎麼
   預測 noreg 的結果？）
2. **opacification 壓力的正確形式**：若判定要凝結，機制選哪個——
   (a) 降免疫線(0.9→0.5)擴大自由區；(b) 中段負 L1（上推）；(c) 你的
   main+ghosts 分裂天然把質量集中到 main（0.9889），配上更陡的 ghost 死亡
   ——哪個不會把霧「整團抬起來」變成半透明糊？
3. **與 2DGS 幾何正則的耦合**：o~0.02 的 surfel 其 normal/depth 對正則損失
   幾乎無貢獻 → 幾何監督實際只作用在 1.3% 的點上？這是否解釋了我們幾何
   正則收益偏小（K8-v3 加 depth/normal 無效）？
4. **kill criteria 更新**（你回合 1 的建議我們修正）：cap 硬頂下顆數不會膨脹，
   「點數膨脹斜率」不適用。改提案：**probe 占比(o<0.2)、高峰占比(>0.9)、
   逐 pixel 平均疊加層數（= I/覆蓋像素數,直接量霧厚）** 三個分佈指標 +
   PSNR。逐 pixel 疊加層數同時是 VRAM 成本代理——你同意它當主指標嗎？
