# Session 1 紀錄（2026-05-07 ~ 2026-05-08）

## 概覽

**目標**：讓 CityGSV2 能在 RTX 4050（6GB VRAM）上跑起來。
主障礙是 CityGSV2 原版需要先做全局粗訓練（coarse training，需 24GB VRAM），
本 session 的工程目標是**完全取代 coarse training**，改用 Depth-Anything-V2 深度圖反投影做 per-block 初始化。

**參考論文**：RTG-SLAM (SIGGRAPH 2024, `參考論文/3641519.3657455.pdf`) §3.1-3.2 — depth-prior 初始化策略

**最終結果**：Block 0 以 depth-init PLY 成功訓練 500 步（PSNR 21.20），可擴展至全 25 blocks。

---

## 1. 整體流程變更

### 原版 CityGSV2 流程

```
全場景 coarse 訓練（30k steps, 24GB VRAM）
  → checkpoint (aerial_train_block_all_3x/.../epoch=6-step=30000_sh2_padded.ckpt)
  → partition_citygs.py（Gaussian 投影算可見度）
  → train_citygs_partitions.py（per-block fine-tune）
  → merge_citygs_ckpts.py
```

### 新流程（本 session 實作）

```
Depth-Anything-V2 depth maps (.npy)  +  COLMAP camera poses
                  ↓
         depth_init_blocks.py          ← 新增
                  ↓
        depth_init/block_*.ply（per-block 點雲）
                  ↓
         partition_from_colmap.py      ← 新增（取代 partition_citygs.py）
                  ↓
   train_citygs_partitions.py --depth_init_dir ...  ← 修改
                  ↓
         merge_citygs_ckpts.py（不變）
```

## 2. 新增/修改的檔案與理由

### 2.1 `utils/depth_init_blocks.py`（新增，2026-05-08 升級為 RTG-SLAM 策略）

**做什麼**：從 DA2 depth maps + COLMAP pose，為每個 block 生成 2DGS 相容的 PLY 初始化點雲。

**對應論文**：RTG-SLAM §3.1-3.2（`參考論文/3641519.3657455.pdf`）
- Point 1：Opaque Gaussian 表示（alpha=0.99）
- Point 2：Depth 計算法向量 → surfel 旋轉四元數
- Point 3：M_s mask（valid depth + grazing angle < 60°）+ 5% 隨機採樣
- Point 6：Voxel 去重（offline 版本取代 online fusion）

**核心步驟（RTG-SLAM 升級版）**：

1. **深度對齊**（`estimated_depth_scales.json` 的 per-image scale/offset）：
   ```python
   inv_aligned = scale * inv_depth + offset
   depth = 1.0 / inv_aligned  # DA2 逆深度 → 公尺深度
   ```

2. **法向量估計**（RTG-SLAM §3.1，Point 2）：
   ```python
   # vertex map V = [Xc, Yc, depth] in camera space
   V = stack([(u-cx)/fx * d, (v-cy)/fy * d, d])
   n = cross(dVdu, dVdv); n /= |n|
   n[n_z > 0] *= -1   # flip to point toward camera
   ```

3. **M_s mask + 5% 採樣**（RTG-SLAM §3.2，Point 3）：
   ```python
   # grazing angle filter: |n · r_hat| >= cos(60°) = 0.5
   cos_ang = |einsum('hwc,hwc->hw', normals_cam, ray_hat)|
   ms_mask = valid_depth & valid_n & depth_in_range & (cos_ang >= 0.5)
   # 5% 隨機採樣（取代 stride-4 grid）
   chosen = rng.choice(len(ms_idx), size=int(len(ms_idx)*0.05))
   ```

4. **反投影（COLMAP T_cw 慣例）**：
   ```python
   pts_world = (pts_cam - t_cw) @ R_cw   # = R_cw.T @ (p_cam - t)
   ```

5. **法向量 cam → world**：
   ```python
   n_world = n_cam @ R_cw   # 等同 R_cw.T @ n_cam（列向量批次）
   ```

6. **Voxel 去重**（Point 6，帶 normal 平均）：
   ```python
   pcd.points = xyz; pcd.normals = normals
   pcd_down = pcd.voxel_down_sample(voxel_size)
   # voxel_size = max(voxel_alpha * scene_scale, voxel_min)
   # 平均後 re-normalize normals
   ```

7. **旋轉四元數（Point 2，vectorized）**：
   ```python
   # cross([0,0,1], n) = [-ny, nx, 0]
   angle = arctan2(sqrt(nx^2+ny^2), nz)
   q = [cos(a/2), (-ny/|cross|)*sin(a/2), (nx/|cross|)*sin(a/2), 0]
   ```

8. **儲存 2DGS PLY（Point 1）**：
   ```python
   opacity = logit(0.99) ≈ 4.595   # opaque surface Gaussian（舊版 0.1）
   scale_0 = scale_1 = log(voxel_size)  # 舊版 KNN distance
   rot_0..3 = normals_to_quats(nrm_d)  # 舊版 identity [1,0,0,0]
   nx, ny, nz = normals                 # 寫入 PLY 作元資料（load_from_ply 不讀，無害）
   ```

**與 Session 1 初始版的差異**：

| 項目 | 初始版（Session 1） | RTG-SLAM 升級版（本次） |
|---|---|---|
| 採樣 | stride=4 grid | M_s mask + 5% random |
| 旋轉 | identity | 法向量對齊四元數 |
| Scale | KNN distance | voxel_size（≈ depth-based） |
| Opacity | logit(0.1) | logit(0.99)（opaque） |
| 法向量 | 全為 0 | 真實 cam→world 法向量 |
| 掠射角過濾 | 無 | cos≥0.5（< 60° 才保留）|

**輸出**：`data/matrix_city/aerial/train/block_all/depth_init/block_{id}.ply`

### 2.2 `utils/partition_from_colmap.py`（新增）

**做什麼**：完全不依賴 Gaussian model，只用 COLMAP track 可見度做場景分塊，取代原本的 `partition_citygs.py`。

**為何需要**：`partition_citygs.py` 需要已訓練好的 checkpoint（做 Gaussian 投影計算可見度），而 coarse checkpoint 對應的資料已不存在。

**核心機制**（取代 `projection_based_partition_assignment`）：

```python
# 對每個 camera，計算其 COLMAP tracks 落在各 block 的比例
for cam_idx, indices in enumerate(cam_track_indices):
    track_in_block = is_in_block[:, indices]       # [N_blocks, n_tracks]
    frac = track_in_block.float().mean(dim=-1)      # [N_blocks]
    vis = frac > args.content_threshold             # 預設 0.08
    not_already = ~is_cam_in_partition[:, cam_idx]
    is_partitions_visible[:, cam_idx] = vis & not_already
```

**結果**：25/25 blocks 成功生成分塊清單（原本的 `partition_citygs.py` 完全無法啟動）。

### 2.3 `internal/gaussian_splatting.py`（修改）

**問題**：從 PLY 初始化時，原始程式碼會嘗試 `from internal.renderers.vanilla_2dgs_renderer import Vanilla2DGSRenderer`，但該 renderer 依賴 `diff_surfel_rasterization`（vanilla 2DGS 版本），在本環境未安裝（只有 CityGSV2 用的 `diff_trim_surfel_rasterization`）。

**修法**：改寫 PLY loading path，根據 PLY 的 scale 維度自動選擇模型類別，完全不 import vanilla renderer：

```python
if load_from.endswith(".ply") is True:
    from internal.utils.gaussian_utils import GaussianPlyUtils
    ply_data = GaussianPlyUtils.load_from_ply(load_from).to_parameter_structure()
    n = ply_data.xyz.shape[0]
    if ply_data.scales.shape[-1] == 2:          # 2DGS: scale_0, scale_1
        from internal.models.gaussian_2d import Gaussian2D
        gaussian_model = Gaussian2D(sh_degree=ply_data.sh_degrees).instantiate()
    else:                                        # 3DGS: scale_0, scale_1, scale_2
        from internal.models.vanilla_gaussian import VanillaGaussian
        gaussian_model = VanillaGaussian(sh_degree=ply_data.sh_degrees).instantiate()
    gaussian_model.setup_from_number(n)
    gaussian_model.to(self.device)
    # ... load_state_dict
    renderer = self.renderer   # 保留 config 指定的 renderer（SepDepthTrim2DGSRenderer）
```

### 2.4 `internal/dataparsers/colmap_block_dataparser.py`（修改）

**問題**：COLMAP 的 images.bin 記錄的影像名稱是 4-digit padding（如 `0014.png`），但實際磁碟上的檔案是 6-digit padding（`000014.png`）。

**修法**：加零補位 fallback（保留原始 COLMAP 名稱作為識別符，只改 file I/O 的路徑）：

```python
img_path = os.path.join(image_dir, extrinsics.name)
if not os.path.exists(img_path):
    base_n, ext_n = extrinsics.name.rsplit('.', 1)
    padded_path = os.path.join(image_dir, f"{base_n.zfill(6)}.{ext_n}")
    if os.path.exists(padded_path):
        img_path = padded_path
image_name_list.append(extrinsics.name)   # 識別符用原始名稱
image_path_list.append(img_path)           # I/O 用 padded 路徑
```

同樣修法也施加於 `colmap_dataparser.py`（全場景非分塊版本）。

### 2.5 `internal/dataparsers/estimated_depth_colmap_block_dataparser.py`（修改）

**問題**：depth 檔案命名是 `000014.png.npy`（6-digit），但 COLMAP 識別符是 `0014.png`，導致深度圖查找失敗，`assert loaded_depth_count > 0` 直接 crash。

**修法**：同樣加零補位 fallback：

```python
depth_file_path = os.path.join(self.path, self.params.depth_dir, f"{image_name}.npy")
if not os.path.exists(depth_file_path):
    base, ext = image_name.rsplit('.', 1)
    padded_path = os.path.join(self.path, self.params.depth_dir,
                                f"{base.zfill(6)}.{ext}.npy")
    if os.path.exists(padded_path):
        depth_file_path = padded_path
    else:
        print(f"[WARNING] {image_name} does not have a depth file")
        continue
```

### 2.6 `internal/dataset.py`（修改）

**問題**：`down_sample_factor: 1.2` 會把 camera intrinsics scale 到 1600×900（配合 DA2 depth map 解析度），但 `dataset.py` 的 `# TODO: resize` 從未實作，PIL 直接讀原始 1920×1080 影像，導致：

```
RuntimeError: size of tensor a (1600) must match tensor b (1920) at non-singleton dimension 2
```

**修法**：實作 TODO，用 PIL LANCZOS resize 到 camera 尺寸：

```python
# 原本是：
# TODO: resize
pil_image = Image.open(self.image_set.image_paths[index])
numpy_image = np.array(pil_image, dtype=np.uint8)

# 改為：
pil_image = Image.open(self.image_set.image_paths[index])
cam_w = int(self.image_cameras[index].width)
cam_h = int(self.image_cameras[index].height)
if pil_image.size != (cam_w, cam_h):
    pil_image = pil_image.resize((cam_w, cam_h), Image.LANCZOS)
numpy_image = np.array(pil_image, dtype=np.uint8)
```

**為何用 LANCZOS**：高品質縮放，適合訓練用 GT 影像（避免 aliasing 影響 photometric loss）。
