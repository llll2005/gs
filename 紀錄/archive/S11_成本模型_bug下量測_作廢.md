## 11.2 成本模型

前向混合在像素 p 由前往後累積，`T_k(p) = prod_{j<k} (1 - a_j(p))`，在 `T < tau = 1/255` 停止。
定義實際執行的求值次數

    n(p) = #{ (i,p) : i 在 T(p) 掉到 tau 之前被求值 }
    W    = sum_p n(p) = sum_i c_i ,   c_i = #{ p : i 在 p 被求值 }

（`c_i` ＝ `num_covered_pixels`，語意已於 `forward.cu:406/452/455/459` 核對。）

    VRAM ≈ V_fix + 4*F*N + b * W / K
            └固定┘  └模型狀態,精確算術┘ └可被 K 切┘

**F1 說 `4*F*N` 以外的部分不隨 N 走；F2/F3/F4 說它隨 W 走。**

### 透射率定律

視線上各層有效 alpha 相近時

    (1-a)^(n-1) < tau   =>   n ≈ ln(1/tau) / a = 5.545 / a

**⇒ 每像素成本反比於 alpha。** 這條式子同時預測 F2（reg 壓低 a ⇒ W 上升）、
起始 trim 在 o=0.99 砍 73% 而 o=0.05 只砍 20%（n ≈ 5.6 vs 111 層）、
以及體積雲 50 萬顆 ≈ 表面雲 360 萬顆的 VRAM。**三個獨立現象、一條式子。**

## 11.3 最佳化問題與 `c_i` 的集合相依性

    max_{S,theta} Q(S,theta)   s.t.   4*F*|S| + b*W(S)/K <= B - V_fix

`c_i` 依賴整個 S（移走遮擋者，i 的成本上升）：

    W(S + j) - W(S) = c_j(S) - D_j(S)     D_j = j 遮住別人所減少的可見足跡

S 越大能遮的越多 ⇒ 邊際成本遞減 ⇒ **W 次模**。所以這不是背包，是
次模目標 + 次模約束（submodular cost submodular knapsack）。

## 11.4 ⛔ 為什麼「成本感知選擇」不成立（今天的主要負結果）

**退化定理。** 若 `v_i = kappa * c_i`（kappa 為常數），則對固定預算，任何可行子集給出相同的 Q：

    Q(S) = sum_{i in S} v_i = kappa * sum c_i = kappa * W(S)

而約束正是把 W(S) 頂死，故 Q 只是預算的函數，**選擇無自由度**。∎

**幾何理由**：半徑 r 的粒子，`c_i ~ pi*r^2*(可見比例)`、`v_i ~ pi*r^2*(它解釋掉的像素量)`
⇒ `v_i/c_i ~ a_i*T_i`，在存活粒子間近乎均勻。

**實測驗證**：
- F5：按貢獻度剪掉後 50%，只移除 24.4% 的成本 ⇒ 被剪的那半**比平均便宜 2 倍** ⇒ 成本跟著價值走。
  擬合 `成本 ≈ 顆數^beta` 得 **beta ≈ 0.40**（溫和剪枝）、0.75（激進剪枝）。
- F6：`corr(密度, 誤差) > 0` 且高紋理格已多 41% 粒子 ⇒ **粒子已經在誤差所在處**。

**⇒ 定向投放／誤差導引 densify／子集重選，在本場景都沒有可利用的自由度。**
與先前量到的「error-guided densify 天花板 1.2×」與四條 net-zero 重分配路線一致。

### 連帶：成本感知的「替換」也不划算

用 F2 的乾淨對照做替換試算（同 VRAM 預算下，用低 reg 換更多顆粒）：

    oreg_0p0   900k  W/P 258  VRAM 3.57G  PSNR 23.107
    oreg_0p002 900k  W/P 694  VRAM 5.38G  PSNR 23.848
    同樣 5.38G 下，reg=0 可負擔 694/258 = 2.69x 顆數 = 2.42M
    2.69x = 1.43 次加倍 x 0.23 dB = +0.33  =>  23.107 + 0.33 = 23.44  <  23.848

**⇒ `opacity_reg` 貴，但它買到的品質是顆數買不到的。成本感知的帳算對了，
但照它的建議去換，會輸 0.4 dB。** 這一點必須寫進論文，否則命題站不住。

## 11.5 真正的約束是最佳化速率，不是 VRAM

F7：密度 4.1× ⇒ 高紋理區誤差只降 6.2%，`d(誤差)/d(ln 密度) ≈ -0.0010`。
F8：邊際 PSNR 增率**正比於位置學習率**（比值 0.16 vs 0.18）。

⇒ **精修期的平台不是收斂，是排程把 LR 關掉了。** 於是應該把預算寫成兩個而非一個：

    B_mem = V_fix + 4*F*N + b*W/K            （VRAM，已頂死在 N ≈ 4.06M）
    B_opt = integral_0^T eta(t) dt           （最佳化預算）

指數排程 `eta(t) = eta_0 * f^(t/T)`：

    integral_0^T eta dt = eta_0 * T * (f - 1) / ln f

    f = 0.01（現行）: 0.215 * eta_0 * T
    f = 0.10       : 0.391 * eta_0 * T   = 1.8x，**不花額外時間**
    T -> 2T        : 2x，花兩倍時間

**可辯護的主張**：在 6GB / 2DGS-SB / MatrixCity aerial 上，**`B_mem` 在 3.6M 顆時已經不是
綁定約束，`B_opt` 才是**。三項證據：(i) F8；(ii) F7；(iii) 顆數標度只有 0.23 dB/加倍。

## 11.6 演算法（修正後）

不再是「按 `c_i` 定價做選擇」——那條被 11.4 否證。改成：

    min_theta  L_photo + L_depth + L_normal + lambda * R(theta)/|P|
    R(theta) = sum_p sum_k T_k(p) = sum_i c_i^soft ,  c_i^soft = sum_p T_i(p)

`R` 是 `n(p)` 的可微代理（`T_k` 即視線存活到第 k 層的機率，其和為期望層數），
而且**渲染器已經在算**（`record_transmittance` 累積的就是它）。

`lambda` 不是調參，是對偶變數：

    R* = (B_mem - V_fix - 4*F*N) * K / b
    lambda <- max(0, lambda + eta_d * (R_measured - R*))      對偶上升

**符號檢查（論文的爆點）**：`dR/do_j < 0`（提高 o_j 壓低後續 T_k）⇒ **這個成本項把
opacity 往高推，與 MCMC 的 opacity L1 方向相反**。而 11.4 末的試算說明：兩者的取捨
必須用實測定，不能只靠成本論證。

**`B_opt` 這一側**（今天才確立，實驗進行中）：`lr_final` 從 0.01×init 提到 0.1×init，
在不增加時間的前提下把 `integral eta dt` 提高 1.8 倍。

## §11.9 Mini-Splatting 對照：退化定理的出口在「改變集合」不在「選子集」

`參考論文/Mini-Splatting.pdf`（arXiv 2403.14166v3）。Fig 1：**0.6M 顆 25.2 dB vs 3DGS 6.1M 顆 25.24**。

**它不推翻 §11.4 的退化定理，它證實前提再繞過去。** 論文自述
"direct pruning... tends to yield **suboptimal** simplification outcomes" ⇒ 與我方實測一致
（剪 50% 只省 24.4% 成本、`corr(密度,誤差)` 為正）。它的自由度來自**改變集合**：

**① Blur Split（式 2）** — `S_i = sum_x delta(i(x)==i_max(x))` 是「i 在多少像素上是最大權重貢獻者」，
`S_i > theta_blur*H*W`（`theta_blur=2e-4`，1600x900 下 = 288 px）就強制分裂。
**S_i 大 = 一顆高斯獨自糊住一大片 = under-reconstruction**，正是我方 08-07 診斷出的高紋理區失敗
（密度 0.176~0.722 顆/px、誤差與密度無關）。
⇒ **近似實作免改 CUDA**：`transmittance_sum_i = sum_p T_i*alpha_i` 已在累積
（`sep_depth_trim_2dgs_renderer.py:141` 目前除以 `num_covered_pixels` 取平均，改用原始和即可）。

**② Depth Reinitialization** — 用**模型自己渲染的深度**（取最大貢獻高斯的 mid-point，
論文 Fig 4 證明 alpha-blend 深度充滿假影）反投影成點雲，**訓練中反覆重新初始化**。
對我方特別重要：來源自洽（不像 DA2 的 284 張互相錯開成殼）、**零單目深度網路依賴**、
且直接打擊 "overlapping" ＝我方量到的 overdraw/W。

**⚠ 三個但書**：①它的基準是原版 3DGS 梯度 densify，我方用 MCMC ⇒ 10× 增益有多少是
MCMC 已經給的未知（前例：DGD 曾被高估為「高分引擎」，實際只值 +1.0）；②物件級 Mip-NeRF360
vs 城市級；③它取樣 350 萬點重初始化，而**我方天花板就是 406 萬**，沒有餘裕。

**⇒ 下一條主線**：blur-split 的代理實作（免改 CUDA，可先在既有 ckpt 上量 `S_i` 分佈驗前提）。

### 11.9.1 blur-split 前提實測（`tools/measure_blur_split_candidates.py`，免訓練）

代理量 `raw_i = sum_p T_i*alpha_i`（軟版 `S_i`；因 `sum_i raw_i ≈ sum_i S_i ≈ P`，論文門檻可直接套用）：

```
run              N        超標顆數   佔比    佔總權重   最大 raw
cap4m         3.6M         303    0.01%     12.6%      5,593
oreg_0p002    900k         390    0.04%     15.8%      8,059
uniform_60k   900k         382    0.04%     15.9%      4,068
v1clean        77k         756    0.98%     46.7%     21,882
```
**極端重尾成立**：0.01~0.04% 的高斯扛 12.6~15.9% 的混合權重，單顆最多獨佔 5,593 像素份（門檻 19 倍）。
**大團佔比隨顆數單調下降 46.7%→15.8%→12.6%** ⇒ 證實「少數大團＝糊」，densify 本就在消滅它們。

**⚠ 混淆（Mini-Splatting 不會遇到）**：b12 半面是平坦水面，**水面本來就該用一顆大高斯**——
那是正確且高效的。論文判準假設「大面積主宰＝under-reconstruction」，在 Mip-NeRF360 成立，
在有大片平坦區的城市航拍**不成立**。直接套用會切碎水面的高效大高斯 ⇒ 增加成本不增加品質，
正是 §11.4 證明會失敗的操作。

**修正版判準（我方場景特性帶出的真實改動）**：
```
G^blur = { G_i | S_i > theta*H*W  AND  局部 GT 梯度 > tau_tex }
```
訓練影像梯度是合法輸入（光度損失每步都在用），非被禁的 GT。
**待驗**：超標高斯落在水面還是建築區——決定這個閘門是必要還是多餘。

### 11.9.2 Depth reinit：我方已有比論文更好的深度來源（免新機制）

Mini-Splatting 的 Fig 4 證明 **alpha-blend 深度充滿假影**（depth collapse / object misalignment /
blending boundary），所以他們自造「最大貢獻高斯的 mid-point 深度」。

**我方不需要造**：`configs/mcmc_2dgs_sb_60k_aggr17_aerial.yaml` 的 `depth_ratio: 1.0`
⇒ `sep_depth_trim_2dgs_renderer.py:194` 的 `surf_depth` 是**純中位深度**（累積 alpha 跨 0.5 的點），
本來就是單一表面而非混合結果 —— 正是他們要的量，且已在 `outputs["surf_depth"]` 裡。

**結構性論證（比實測更強的理由）**：
| | 來源 | 會不會產生殼 |
|---|---|---|
| `depth_init_blocks.py` | DA2 對 284 張各自估計 | 284 個互相錯開的估計，體素 0.03 合併不了 0.0795 的層 ⇒ **殼**（[[start_trim_shell]]） |
| 自渲染深度 reinit | **同一個模型**的 284 視角 | 幾何只有一份，投影必然自洽 ⇒ **結構上不可能有殼** |

**⇒ 實作路徑（無新 CUDA、無新渲染）**：訓練中週期性地 ①對每個訓練視角渲染 `surf_depth`
②反投影到世界座標（`depths_to_points` 已存在於同檔）③取樣後重新初始化。
一次解掉：殼、overlapping/overdraw、以及對單目深度網路的依賴（GT-free 敘事更乾淨）。

**⚠ 未實作、未驗證。** 且我方天花板 406 萬顆，沒有論文那種「取樣 350 萬點後還能長」的餘裕，
重初始化的目標顆數要另外定。

### 11.9.3 ImprovingDensification (arXiv 2508.12313, Zhejiang) —— 三個機制，兩條軸

**⚠ 先記最重要的一條：§11.9.1 我提的「用局部影像梯度當 blur-split 的閘門」不是新的。**
該文的 **Edge-Aware Score (EAS)** ＝「edge information + pixel-level loss」，同樣診斷
（"view-averaged coordinate gradients **fails to identify certain large Gaussians that contribute
to blurred reconstructions**"）、同樣解方。**投稿前必須引用，不可當自己的貢獻。**

| 軸 | Mini-Splatting | ImprovingDensification | 我方 2026-08-07 |
|---|---|---|---|
| densify 誰 | blur split（最大貢獻面積） | **EAS**（邊緣＋逐像素損失） | `sum_p T*alpha` ✅已實作 + 實測驗證候選落點 |
| 怎麼放子代 | — | **LAS**（Long-Axis Split，最小化分裂前後幾何差） | ⚠MCMC relocation 的 Eq.9 修正**可能已部分涵蓋，先查再說** |
| 最佳化側 | depth reinit | **MU**（每 N 步才更新參數）+ **GC**（平滑曲線控制成長率） | `B_opt` 綁定（§11.5）；`surf_depth` 中位深度已是更好的 reinit 來源（§11.9.2） |

**三篇在同一診斷上收斂**：造成模糊的是「獨自主宰大片區域的大高斯」，梯度判準看不見它們。
**我方作法的實務優勢**：`sum_p T*alpha` 由 trim pass 順便算出（本來就走訪全部相機）＝零額外成本；
EAS 要另外算邊緣圖與逐像素損失。

**MU 值得優先試**：減少更新次數卻改善品質，機制應是**累積多視角梯度＝有效批次變大＝噪音變小**，
而它落在我方已證明會綁定的 `B_opt` 軸上，且**不花額外時間**。

**LAS vs MCMC Eq.9 的核對結果（已查 `mcmc_density_controller.py:148-157`）**：
`compute_relocation` 修正 **opacity 與 scale**（N 份副本總貢獻＝原本那顆），**但不動位置**——
副本全留在宿主原點，靠 SGLD 噪音分開。LAS 明說它設計的是
"the **relative positions**, shapes, and opacities of child Gaussians"。
⇒ **位置那部分 MCMC 沒有，是真缺口**，且**直接與已實作的 blur-split 互補**：
挑出大團後把副本疊在原點等噪音推開是弱的，沿長軸鋪開才能立刻覆蓋那片區域。
**這是 blur-split 之後最自然的下一步。**

### 11.9.4 ⛔ 長軸散開（LAS）在 MCMC 框架下無效 — 已實測證偽

`blurlas_b12`（blur 預算 0.3 + `long_axis_spread` 0.5）vs `blurbudget_b12`（僅 blur 0.3）：

| | PSNR | SSIM | LPIPS | 紋理比 |
|---|---|---|---|---|
| blurbudget | **24.353** | 0.6931 | **0.4674** | **0.3783** |
| blurlas | 24.224 | 0.6914 | 0.4678 | 0.3762 |
| Δ | **−0.129（2.4× 噪音）** | −0.0017 | +0.0004（噪音內） | −0.0021（噪音內） |

**淨負面。** 兩個成因，事後看都很清楚：
1. **前提本身失效**：我論證「子代疊在原點只能靠 SGLD 分開，而噪音在 opacity>0.03 時≈0」——
   前半對，但實測**只有 0.01% 的粒子位置位元級重合**，它們本來就會分開
   （多半來自 rasterizer `atomicAdd` 的非確定性順序，被混沌放大）。
2. **它破壞 MCMC 的 Eq. 9**：`compute_relocation` 推導修正後的 opacity/scale 時，
   **前提是 N 份副本共位**——那才使合成貢獻等於原本那一顆。把它們推開，修正就不成立，
   於是每次 densify 都注入一次微小影像擾動。

⇒ **通則：MCMC 的 relocation 是自洽的整體，動位置就得重推 Eq. 9，不能只加位移項。**
程式保留（`long_axis_spread`，預設 0）當作相關工作的實測反例：LAS 是文獻真實機制
（ImprovingDensification arXiv 2508.12313），而我方是唯一有噪音底線能判定它不轉移到 MCMC 的。

**⚠ 流程教訓**：0.01% 那個量測在 blurlas 排隊時就做完了，我也說了「這下修了預期」，
**但沒有把它從佇列移除** ⇒ 白跑 13 小時。**量到否定前提的證據時，要當場重排佇列。**
