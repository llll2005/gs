### 0.2 報告怎麼寫：可以宣稱的原創／必須引用前例的
**可以宣稱原創的（未查到前例）**
1. **用 SfM 三角形校正的深度當幾何先驗**，以及下游的三個用法：
   - 校正深度本身：誤差中位 2.15% → 0.15%。
   - 可靠度分級。
   - 逐貢獻深度上限，加上「只罰躺平」「只補前面」：地下層 A＋dist4 7.3 → 1.4 層。
2. **塊外遮罩的 B（要求透明）與 C（不計分）三分類**：b2 +0.058。
3. **海面物件整套**：水體偵測、海面格、錨定層、浮塊收回。b1 海面上方浮塊 1,497 → 3。
4. **SH 可觀測子空間**：由相機幾何決定，理論預測 10 維與量測一致。訓練峰值 −25%。尚未進預設。
5. **評測方法**：換塊評測、特定問題量尺。
6. 實作層級的原創，可以寫但不是主貢獻：
   - lean 路徑。
   - 配對位元在 backward 重用。
   - m39 的伴隨矩陣閉式與 16x2 條遮罩。
   - regvis。
   - 面內增生。
   - 幾何步半解析度。

#### 2.2' 單目逆深度（Depth Anything V2）＋每張影像的縮放與位移
- **我們怎麼做**：Depth Anything V2 ViT-L 逐張預測逆深度 d；每張用自己觀測到的 SfM 點擬合 `inv = s·d + o`：
  ```
  t = median(inv_SfM)、t' = median(d)；s_SfM = mean|inv_SfM − t|、s_mono = mean|d − t'|
  s = s_SfM / s_mono，o = t − t'·s
  ```
  （`utils/get_depth_scales.py`，檔頭註明抄自 hierarchical-3d-gaussians 的 `make_depth_scale.py`）。**我方不把它當深度 loss**（權重 0），只當 2.3 的輸入。
- **來源**：
  - CityGaussianV2 §3.2「Optimization Mechanism」p5：照 Kerbl 等 2024 的做法用 Depth-Anything-V2 估逆深度並對齊到資料集尺度，再做 L_Depth = |D̂ − D|（權重指數衰減）。已讀原文 p5。
  - Hierarchical 3DGS（Kerbl 等，ACM TOG 2024）App. C.1：逐影像用該影像 SfM 點的逆深度，位移取中位數、尺度取對中位數的平均絕對偏差；原文用的網路是 DPT。已讀 arXiv HTML App. C.1。
  - Depth Anything V2（Yang 等，NeurIPS 2024）p6：輸出是仿射不變的逆深度 => 用 `s·d + o` 對齊是合理的。已讀原文 p1、p6。
- **關係**：⬜ 完全沿用（對齊程式也是原樣）。
- **差在哪**：對齊方式相同；用途不同——CityGS 把它當訓練 loss，我方只用來做校正深度（2.3）的底。
- **動機**：CityGS 的資料準備本來就有這一步；我方後來發現單目約 ±10% 太粗（`new_archived/實驗分析_過程/37_…_至1113.md` 起因段），所以沒有直接拿來監督，改做 2.3。
- **成效**：單獨當深度 loss 時，新年代 22k 重測權重 0.5 對 0 平手（`論文總覽.md` RaDe-GS 列）=> 維持 0。當初始化時 depth-init 27.19／26.84 輸 SfM 起點 28.52／28.02（20k，`論文總覽.md` 驗過總表）。

#### 2.3 SfM 三角形校正深度＋可靠度分級（`tools/make_tri_depths.py`）
- **我們怎麼做**：每張影像用它自己觀測到的可靠 SfM 點做 Delaunay 三角形：
  ```
  inv(p) = (s·d(p) + o) + interp_tri( 1/z_SfM − (s·d + o) )(p)      三角形內線性內插「SfM 與單目的殘差」；凸包外用最近點
  可靠度 = 斜率級 + 8·大小級；斜率 = |grad log z|·fx（無因次），大小 = 三角形最長邊（px）；訓練只用斜率級 ≤ 1 且大小級 ≤ 3
  ```
- **來源**：
  - ACMP（Xu & Tao，"Planar Prior Assisted PatchMatch Multi-View Stereo"，AAAI 2020）：把可信的稀疏對應點三角化，同一三角形內的像素共用三個頂點決定的平面，當作 PatchMatch 機率模型裡的平面先驗（Eq.6–7）。已讀 ar5iv 全文（頁面沒有章節編號；原文沒說三角化是否為影像平面上的 Delaunay）。
  - HI-SLAM2（arXiv 2411.17982，2024；網頁未標會議）§III-A：每張深度先驗估一個 2D 尺度網格、逐像素雙線性內插；Replica 上單一尺度 AbsRel 6.70% → 網格 3.41%（Table VI）。已讀 arXiv HTML §III-A 與 Table VI。
  - Hierarchical 3DGS App. C.1（見 2.2'）：只有全域的一個尺度＋位移。
- **關係**：🟨＋🟩。分片平面先驗（ACMP）與空間變化的單目校正（HI-SLAM2）都有前例；「內插殘差而不是取代單目」「每張只用自己的觀測」「斜率／大小的可靠度分級」未查到前例（`文獻查證_論文用_1119.md` #1，信心中）。
- **差在哪**：
  - ACMP：三角形內**取代**成平面、用在 MVS 的匹配成本；我方內插的是**殘差**，三角形內保留單目的起伏，頂點上恰好等於 SfM，產出的是給 3DGS 用的稠密深度與可靠度。
  - HI-SLAM2：尺度網格（乘法、規則格子、和位姿聯合最佳化）；我方是三角形分片線性的加法殘差，頂點就是 SfM 點，前處理一次算完、不參與訓練。
  - Hierarchical 3DGS：每張一組全域 (s, o)；我方在那之上再做分片校正。

#### 3.1 2DGS 面元表示＋SH 3 階
- **我們怎麼做**：面元＝中心、兩個面內尺度、旋轉、opacity、SH 3 階顏色；值在射線與面元平面的交點上算 `G = exp(−(u²+v²)/2)`，前到後 alpha 混合；側對時用物件空間低通濾波（取兩者較大）。每顆 3＋2＋4＋1＋48 ＝ **58 個 float＝232 B**（SH 高階 45／58 ≈ 78%）。
- **來源**：2DGS（Huang 等，SIGGRAPH 2024 Conference Papers）§4.1 Eq.4–6（面元定義）、§4.2 Eq.8–10（射線-面元交點）、Eq.11（低通濾波）、Eq.12（混合），p4–5。SH 階數與逐 1000 步加一階：3DGS（Kerbl 等，SIGGRAPH 2023）§7.1 p8。已讀兩篇原文上述頁。
- **關係**：⬜ 完全沿用。
- **差在哪**：表示相同。和 CityGaussianV2 的差別：V2 §3.3 p6 從頭就用 SH 2 階（為了省掉蒸餾），我方用 3 階。
- **動機**：CityGaussianV2 選 2DGS 的理由是幾何（V2 p2）；本專案以 V2 為底沿用。SH 3 階：11-20 敏感度測過 2 階，使用者看 viewer 不採用（`現行方法.md` §10.1）。
- **成效**：表示本身沒有和 3DGS 的對照，**無量測**。SH 2 階對 3 階：每顆參數 −36%、b1 純訓練 −9%，本塊區域 +.013／+.010／−.066（b1／b4／b2），b4 海面上空出現大霧團 => 不採用（`現行方法.md` §10.1）。

#### 3.2 塊外遮罩 A／B／C，用校正深度判（元件 `trimask`）
- **我們怎麼做**：每塊每張影像一張三值圖。像素沿**校正深度**反投影成 3D 點 X(p)：A＝X 在本塊盒內 => 照常算光度 loss；B＝X 在盒外、且射線之後不再進盒 => 目標＝本步隨機背景色（本塊在這裡必須透明）；C＝第一表面在塊外但射線之後會進本塊、無效深度、交界帶 => 權重 0。
- **來源**：
  - Mega-NeRF（Turki 等，CVPR 2022）§3.2「Spatial Data Parallelism」：像素加入射線穿過的每個格子的訓練集；訓練 10 萬步後用粗不透明度結構把被遮住的像素從不貢獻的格子移除。沒有「要求透明」的監督。已讀 ar5iv §3.1–3.2。
  - HUG（arXiv 2504.16606v2；紀錄寫 ICCV 2025，arXiv 頁未標，待確認）§3.2「Visibility Mask Generation」Eq.5：本塊 SfM 點重投影後用非線性分類（SVM）切出可見區；沒有寫遮罩外的像素在 loss 裡怎麼處理。已讀 arXiv HTML §3.2。
  - Sun 等（CGF 44(7) 2025，doi 10.1111/cgf.70265）：據搜尋片段是用深度比較產生遮罩。**全文取不到**（出版商 403）。
- **關係**：🟨（A 類：每塊只用自己的像素）＋🟩（B 類要求透明、B／C 用射線路徑三分類、用校正深度判）。因為 Sun 等全文沒讀到，B／C 只能寫「未查到前例」。
- **差在哪**：
  - Mega-NeRF：射線穿過格子就分給它（體積式 NeRF，靠射線取樣）、後期用學到的不透明度剔除；我方用前處理的深度直接判每個像素的第一表面在不在盒內。
  - HUG：SfM 點投影＋SVM 的二值可見遮罩；我方三值，且 B 類不是排除而是監督成透明。
  - 隨機背景學透明是 NeRF／3DGS 常見技巧（舊出處表的說法，本次未查原文）；我方只用在 B 類像素。
- **動機**：
  - 遮罩本身（10-17）：單塊模型 73～81% 的顆粒在分區盒外、合併時全丟——訓練影像約一半是鄰塊內容，光度 loss 會要求本塊去解釋它（`new_archived/實驗分析_定案/17_塊外遮罩訓練.md`「為什麼」）。

#### 3.3a 精確圓錐外接盒＋o ≤ 1/255 整顆不進 binning（`exact_conic_aabb`、編譯旗標 `EXACT_SUPPORT`）
- **我們怎麼做**：面元在螢幕上的支撐 u²+v² ≤ R²（R＝3）在透視下是圓錐曲線；用對偶圓錐 S＝diag(R², R², −1) 求封閉解：
  ```
  c_x = (aᵀSw)/(wᵀSw)，e_x = sqrt(c_x² − (aᵀSa)/(wᵀSw))（y 同理）；盒 = [c−e, c+e] ∪ 低通圓盤（半徑 0.7071·R）
  ```
  盒心可以偏離投影中心（不對稱盒）。另外 o ≤ 1/255 的顆粒整顆不進 binning（逐位元相同）。
- **來源**：
  - Speedy-Splat（Hanson 等；`reference_papers.md` 記 CVPR 2025，PDF 為 arXiv 版）§4.1.1 SnugBox p4：3DGS 投影橢圓在 alpha ≥ 1/255 的截斷 t＝2 ln(255σ)（Eq.9）下的軸對齊緊外接盒，盒心＝投影中心；§4.1.2 AccuTile 逐列列舉相交 tile。已讀原文 p4–5。
  - StopThePop（Radl 等，ACM TOG 43(4) 2024）§3.4 p5：每條射線本來就丟掉貢獻 < 1/255 的高斯，是精確的剔除條件；並指出 3DGS 用最大特徵值的外接矩形對細長高斯很鬆。已讀原文 p5–7。
  - Fast-SegSim（arXiv 2604.10951，2026-04）§3.2 p3：把 SnugBox／AccuTile 搬到 2DGS，面元投影用局部線性化近似成橢圓。已讀原文 p3。
  - 2DGS 上游程式的外接盒：在 r＝1 求對偶圓錐、再乘截斷半徑線性外推、以投影中心為準的正方形（2DGS 論文 p5 只說「先算螢幕外接盒」，細節在程式）。
- **關係**：🟨 借用改造。
- **差在哪**：Speedy-Splat 是 3DGS 的仿射橢圓、對稱盒；Fast-SegSim 對 2DGS 做線性化近似；我方是 2DGS 透視下的**精確**圓錐（不線性化），盒子與投影中心解耦（不對稱）。正交極限下退化成 SnugBox。**不能宣稱「2DGS 第一個緊外接盒」**（Fast-SegSim 在前）。AccuTile 式逐 tile 列舉我方沒做（量過 binning 只佔一步 1%，`加速論文對照.md` A3）。
- **動機**：09-21：上游的線性化盒在 88.7% 的（顆粒, 相機）上高估、11.3% 低估（`加速論文對照.md` A1）；當時的成本計價命題需要精確的逐顆 binning 成本 `tiles_touched`（`04_外接盒與binning成本.md` 結論）。
- **成效**：
  - 精確外接盒：離線 Σtiles −41.2%；60k 同 N 實測 forward −16.0／−25.2%、forward＋backward −13.7／−17.0%（b6／b13）；峰值 VRAM 只 −5～−7%；品質 4／4 組比較沒有負的（22k b6 29.05 vs 29.05）（`new_archived/實驗分析_定案/04_外接盒與binning成本.md` 結論、§0.1）。
  - o ≤ 1/255 不進 binning：渲染位元級相同、渲染峰值 VRAM −20.3%（`論文總覽.md` StopThePop 列；`程式碼稽核清單.md`；程式事實，跨年代有效）。
- **⚠ 要修**：`論文總覽.md` 驗過總表把這一項的對應論文寫成「FastGS／Compact Box 類」——FastGS 的 Compact Box 是用 β 再縮支撐（有損，`加速論文對照.md` A2），最接近的前人應寫 Speedy-Splat SnugBox（與 Fast-SegSim）。

#### 3.3c 逐 warp 盒外跳過（光柵器 `skip_box`，元件 `sbox`）

#### 3.3i 反單應交點（光柵器 `inv_homog`，`m39` 五項之一）
- **我們怎麼做**：射線-面元交點寫成反單應 `p' = M⁻¹(x, y, 1)`、深度 = 1/p'.z。M⁻¹ 不從 3x3 矩陣求反，而用幾何閉式（列＝(t1 x mu)/(s0 n·mu)、(mu x t0)/(s1 n·mu)、n/(n·mu)），並**錨定在中心投影**：`p' = (0, 0, 1/Z_c) + (x − x_mu) q0 + (y − y_mu) q1`，每顆存 9 個數；backward 每顆一次把 dL/dp' 的加總換回 dL/dT。側對（n·mu → 0）時夾 1e-30、交給低通分支（`forward.cu` `aihFromGeom`）。
- **來源**：
  - 2DGS §4.2 p4：Zwicker 等（Perspective Accurate Splatting，Graphics Interface 2004，pp.247–254）用 M＝(WH)⁻¹ 的隱式方法把面元的圓錐投影到螢幕；2DGS 指出這個反矩陣在面元側對、退化成線段時數值不穩，前人只能用門檻丟掉，可微訓練下不好用，所以 2DGS 改用三個平面相交的顯式交點（Eq.8–10，靈感來自 Sigg 等 2006、Weyrich 等 2007）。已讀 2DGS 原文 p4 與參考文獻 p8；**Zwicker 2004 原文未讀**（只透過 2DGS 轉述）。
  - `39_純數學化簡.md` §6 自己也寫「射線-平面交點的反矩陣寫法是教科書內容」。
- **關係**：🟨＋🟩。反單應寫法是 Zwicker 2004 的（🟨）；未查到前例、可算我方的：幾何閉式的 M⁻¹（避開 T 裡 cx·C_z 大項的相消）、錨定在中心投影以避免逐像素相消、對應的梯度換算（39 §6，未系統查證）。

- **差在哪**：Zwicker 2004 用反矩陣、側對時靠門檻丟掉；2DGS 用兩平面外積（數學上就是 det(M)·M⁻¹(x,y,1)，39 §1 推導）避免除法；我方回到反單應，但用閉式與錨定控制誤差，側對時夾值並交給低通分支（與原寫法一樣）。
- **動機**：使用者 11-21「用純數學方式、完全不訓練，透過化簡／代換／結合減少算法量」（`39_純數學化簡.md` 起因）。
- **成效**：

#### 3.3j 幾何配對遮罩（光柵器 `exact_strip_cull`，`m39` 五項之一）
- **我們怎麼做**：alpha ≥ 1/255 ⇔ min(rho3d, rho2d) ≤ tau，tau＝2 ln(255 o)。rho3d ≤ tau 寫成 `F = p'x² + p'y² − tau·p'z² ≤ 0`；p' 對像素仿射，所以每一列像素上 F 是一元二次式，16x2 像素條（兩列）上「有沒有 F ≤ 0」用端點與頂點條件判斷、不需除法；再聯集低通圓盤（點到線段距離）。負責載入這顆面元的執行緒一次算出本 tile 8 個 warp 的結果（8 bit），warp 只查自己那一位；tau 放寬 1%＋0.02 保守。

- **關係**：🟨＋🟩。「精確的 1/255 子 tile 剔除」有前例（StopThePop；Warp-Level Culling）；未查到前例的是：2DGS 透視圓錐的逐列二次式無除法判斷、∪ 低通圓盤、16x2 warp 條的 8-bit 幾何遮罩、用在訓練 forward。
- **⚠ 要修**：`現行方法.md` §3.3 標 🟩，應改 🟨（StopThePop §3.4 的精確剔除與 4x4／2x2 子 tile 階層、Warp-Level Culling 都在前）。
- **差在哪**：StopThePop 是 3DGS 仿射橢圓、tile 與 4x4／2x2 子 tile、為了排序；Speedy-Splat 逐列但只到 tile 粒度；我方是 2DGS 精確透視二次式、16x2 條、和 3.3c 的外接盒疊用（遮罩是齊二次式，p'z < 0 的另一葉會多放行，外接盒剛好擋掉，39 §7.3）。
- **動機**：同 3.3i（11-21 使用者要求純數學化簡）；離線上限顯示 skip_box 不跳的 warp 迭代還有 41% 可刪（39 §2）。

### A. 損失（`現行方法.md` §4）

#### A1. 光度損失 L1＋D-SSIM（`lambda_dssim 0.2`；SSIM 用融合 kernel `fused_ssim`）
- **我們怎麼做**：`L_rgb = 0.8·L1 + 0.2·(1 − SSIM)`。像素目標依塊外遮罩分三類：A＝GT；B＝本步隨機背景色；C＝渲染值本身（梯度 0）。遮罩屬於 §3.2，不在本部分。
- **來源**：3DGS，Kerbl et al., "3D Gaussian Splatting for Real-Time Radiance Field Rendering", ACM TOG（SIGGRAPH 2023），§5.1 Eq. 7，p.5，λ = 0.2。**已讀原文 p.5。**2DGS（SIGGRAPH 2024）§5 Eq. 16 的 L_c 也是同一個組合，已讀 p.5。
- **關係**：⬜ 完全沿用。融合 SSIM 只是實作加速，屬於第 1 部分 §3.3。
- **動機**：基底框架（2DGS／CityGS）的預設。紀錄沒有另外的選擇理由。
- **成效**：無單獨量測。這是基底，沒有拿掉它的臂。

#### A2. L1 之外加 L2（`metric.rgb_l2_weight 2.0`；臂名 `nol2` 為拿掉）
- **我們怎麼做**：`loss += (1 − λ_dssim)·w2·mean((render − gt)²)`，其中 w2 = 2。**實際係數是 0.8×2 = 1.6**（程式約第 1252–1259 行）。
  - ⚠ `現行方法.md` §4 寫成「+2·L2」，與程式不符。
  - C 類像素兩邊都是 detach 的渲染，差為 0，不受影響。
- **來源**：
  - L1：3DGS Eq. 7（已讀 p.5）。
  - L2（平方誤差）：NeRF，Mildenhall et al., ECCV 2020，Eq. 6，p.9，總平方誤差。**已讀原文。**
  - 「L1＋L2 混用」本身：**未查到前例**（沒有做系統搜尋）。
- **關係**：🟨 借用改造。兩種損失都是既有的，組合方式與權重是我方定的。
- **差在哪**：3DGS 只用 L1；NeRF 只用 L2。我方兩者相加，L2 讓大誤差像素的權重變大。
- **動機**（`new_archived/實驗分析_定案/33`；進展 §3.3）：
  - L1 對每個像素的梯度只有 ±1。少數視角裡的強證據（b2 超高塔頂）會被多數視角稀釋，塔頂在訓練中被移除。

#### A3. 幾何項每 k 步算一次、權重乘 k（`lambda_dist_interval 8`、`lambda_normal_interval 8`、`depth_cap_interval 8`；臂名 `geo8`）

#### A10. 鄰域平面 L_surf（`surf_reg 0.01`、`surf_orient 1.0`、`surf_interval 16`、`surf_every 400`；臂名 `np16`）

  - §3.3 Eq. 3：L_PCA ＝ λ1 ＋ γ|λ3 − λ2|，γ = 0.001。
  - Eq. 4：法向對齊 `1 − |<v1, n_i>|`。
  - 附錄 A：7k 步後開，作用於全部高斯；論文沒給 K。
  - PGSR／GaussianPro 的平面先驗**未讀原文**（只在舊紀錄被提及）。
- **關係**：🟨 借用改造。同期前例，非常接近。
- **差在哪**：

  | 項目 | PCAsplat | 我方 |

  | 共變異 | 不加權 | opacity 加權 |
  | 作用範圍 | 全部高斯 | 只對平坦、鄰居夠的顆粒 |
  | 位置項 | λ1（法向方向的變異數） | 截斷的「到平面距離 ÷ 面內尺度」，上限 2，超過當真結構、梯度 0 |
  | 計算時機 | 程式清單看起來每步算 | 每 400 步重算平面、每 16 步算 loss、每次抽 10% 顆粒 |
  | 鄰居搜尋 | — | Morton 序近鄰 |

- **動機**：

- **成效**：

#### A11. 不透明度二元熵 L_H（`opacity_entropy_reg 0.002`、`opacity_entropy_side down`、`opacity_entropy_both_from_iter STEPS/3`、`opacity_entropy_both_reg 0.008`；臂名尾碼 `ed10b4`）

#### B1. MCMC 密度控制：死亡、搬家、增生到上限（`MCMC2DGSDensityController`；`densification_interval 150`、`min_opacity 0.005`、`add_ratio 1.05`）
- **我們怎麼做**：每 150 步一個事件，從 1k 步到 70% 步數（17k 時為 11,900）。
  - 死亡：`o <= 0.005`。
  - 搬家：每個死顆粒按 opacity 抽一個活顆粒當母點，用 Eq. 9 平分 opacity、縮尺度。母點的 Adam 歸零，搬家的那顆保留動量。
  - 增生：`N ← min(cap, 1.05 N)`。
  - 10-24 修過 Eq. 9 的 NaN：母點 o 恰好等於 1.0 時 float32 相消，現在夾到 1−eps。
- **來源**：3DGS-MCMC（NeurIPS 2024）。**已讀原文。**
  - §3.4 Eq. 9（p.6）：搬家公式。
  - p.6 實作段：每 100 步做一次；按 opacity 多項分布抽；目標的 Adam 動量重設，來源的保留。
  - p.5 註 2：死亡線是 o < 0.005。
  - §3.6（p.7）：每次增加 5% 直到上限；500 步暖身。
- **關係**：⬜ 沿用，排程數值改了。
- **差在哪**：

  | 項目 | 3DGS-MCMC | 我方 |
  |---|---|---|
  | 事件間隔 | 每 100 步 | 每 150 步 |
  | 起訖 | 500 步後開始 | 1k 步開始，70% 結束 |
  | 死亡判準 | o < 0.005 | o <= 0.005 |
  | 增生抽樣 | 按 opacity | 乘上 |g| 權重（B2） |
  | 新點位置 | 和母點同一點 | 在母點平面內錯開（B4） |
  | 上限 | 一個全域值 | 每塊由 SfM 點數分配（E） |

- **動機**：
  - 舊年代（09-13 之前）就換成 MCMC，當時是為了精確控制顆數上限，配合 6 GB VRAM（CLAUDE.md 的研究方向）。
  - 間隔從 200 改 150：config 註解寫「加密 add 事件」，紀錄沒有更多理由。
- **成效**：
  - 新年代沒有「MCMC 對 3DGS 原版密度控制」的同底對照，**無量測**。
  - 數值敏感度：事件間隔改 300 步時，顆數只長到 0.51M／1.5M，本塊區域 −.523／−.666／−.548、b1 純訓練 −37%（`現行方法.md` §10.1）。

#### B2. |g| 導引增生抽樣（`absgrad_densify 2.0`；需要光柵器 `ABSGRAD 1`）
- **我們怎麼做**：增生（`add_new_gs`）抽母點的機率為 `o_j·(1 + 2·|g_j| / mean|g|)`。
  - |g| 是「逐像素子梯度先取絕對值再加總」的位置梯度，累加在光柵器原本沒用的 `dL_dmean2D.z`，渲染與梯度逐位元不變。
  - ⚠ **搬家不用 |g|**：搬家的機率只有 opacity。`relocate_absgrad` 預設 0，現行配方沒開，只出現在舊臂 `besttrim3`（`mcmc_density_controller.py` 第 286、318、412–431 行；`mcmc_2dgs_density_controller.py` 第 3862 行）。
  - `現行方法.md` §6.2 寫「搬家：機率 ∝ o_j·(1 + 2|g_j|/mean|g|)」，與實作不符；舊的 `完整Pipeline數學詳解_v2` §7 也是這樣寫。
- **來源**：AbsGS，Ye et al., "AbsGS: Recovering Fine Details for 3D Gaussian Splatting", arXiv 2404.10484（PDF 未載明會議），§3.3 Eq. 12–13（p.5）。**已讀原文。**
  - 先對每個像素的子梯度取絕對值再加總，避免方向相反的梯度互相抵消（gradient collision）。
  - 只用在 split 判準（門檻 τ_p），clone 仍照 3DGS 原版。
- **關係**：🟨 借用改造。
- **差在哪**：

  | 項目 | AbsGS | 我方 |
  |---|---|---|
  | 訊號用途 | 和固定門檻比較，決定要不要 split | 乘進 MCMC 抽樣機率，是加法式權重 `1 + w·ĝ`，不是門檻 |
  | 作用於 | split | 增生 |
  | 會不會改變顆數 | 會 | 不改顆數，只改長在哪裡 |

- **動機**：
  - 「往誤差在的地方增生」這個家族曾以「天花板只有 1.2 倍」被關掉。後來量到，1.2 倍是我方自製誤差分數的天花板；同一統計換成 AbsGS 的 |g| 是 16.68 倍（CLAUDE.md；`mcmc_2dgs_density_controller.py` 第 3730 行附近的註解）。
  - 對比：`vpc_prune_frac` 把粒子搬走掉了 2.34 dB。結論是「決定往哪裡增生」有效，「搬走既有粒子」無效（程式 docstring 第 824 行起）。
- **成效**：
  - 舊年代的數字已作廢（09-13 年代分界）。
  - 新年代數值敏感度（`現行方法.md` §10.1）：
    - 權重 0：本塊區域 **−.091／−.098／−.124**。
    - 權重 1：+.003／+.016／−.008。
    - 權重 4：+.004／+.007／−.003。
    - 結論：一定要開，1～4 之間打平。

#### B3. 位置雜訊與雜訊閘門（`noise_lr 5e5`、`fast_noise true`、`noise_gate_eps 1e-3`）
- **我們怎麼做**：
  - 每步 `dmu = lr_mu · 5e5 · sigmoid(100(0.005 − o)) · Sigma · eps`，其中 `Sigma = R diag(s1², s2², 0) Rᵀ`。2DGS 法向那一軸是 0，所以雜訊自然只在面元平面內。
  - 只算閘門值大於 1e-3 的顆粒。舊量測可跳過 47.6～69.0%（docstring）。
  - `fast_noise` 改成不 materialize N×3×3 矩陣的寫法：`R(s² ⊙ Rᵀv)`。
- **來源**：3DGS-MCMC §3.3 Eq. 7–8（p.5）。**已讀原文。**
  - 雜訊只加在位置上，量 = λ_lr · sigmoid · Σ · η。
  - k = 100、t = 0.005、λ_noise = 5×10⁵（p.7）。
  - p.9：拿掉共變異項或 opacity 項都會變差。
- **關係**：⬜ 沿用形式，加上🟨工程改寫（閘門跳過、代數改寫）。
- **差在哪**：
  - ⚠ 論文 Eq. 8 印的是 `σ(−k(t − o))`，代進去會變成「不透明的雜訊大」，和正文說的相反。我方用 `σ(k(t − o))`，和正文一致（論文總覽已記為「Eq. 8 印刷錯」）。
  - 2DGS 的共變異法向軸是 0，所以「只在平面內」是 2DGS 表示帶來的結果，不是另外加的設計。
  - 閘門跳過不是逐位元等價（亂數串流不同）。按估算，被跳過的顆粒 60k 步累積的位移約為自身尺寸的 0.15%（docstring）。
- **動機**：加速。舊量測時雜訊佔一步的 9.9%；`fast_noise` 57.47 → 31.98 ms（舊年代 N = 2.34M；只牽涉時間，不受年代分界影響）。
- **成效**：
  - 新年代沒有「雜訊開或關」的品質量測，**無量測**。
  - noise_gate 的單變數測試在 10-11 被使用者取消（`已關閉的線.md` A 移出列）。

#### B4. 面內增生（`inplane_offset 1.0`、`inplane_hold 1000`）
- **我們怎麼做**：
  - 增生或搬家產生的新點，不再疊在母點同一位置，而是在母點的面元平面內往隨機方向錯開 `1 × 長軸 × 漸增係數`。
  - 出生後 1000 步內，位置梯度去掉法向分量，只能在自己的平面內移動。
  - 漸增係數在 1k 步前為 0，10k 步後為 1。
- **來源**：無直接前例。最接近的兩個：
  1. 3DGS §5.2（p.5）split：新位置以原高斯為機率分布取樣，尺度除以 1.6。**已讀原文。**
  2. 3DGS-MCMC Eq. 9（p.6）：新點和母點同位置，並靠調整 opacity／尺度讓渲染幾乎不變。**已讀原文。**
- **關係**：🟩 原創，使用者 11-02 構想：在牆面上複製，新點只能長在牆面上（程式 docstring）。
- **差在哪**：
  - 3DGS split 在 3D 高斯內部取樣，沒有平面限制，也沒有出生後的移動限制。
  - MCMC 新點和母點同一點。我方錯開以後，Eq. 9「渲染幾乎不變」的前提不再成立（兩顆並排而不是疊在一起）。這是推論，未量測。
- **動機**：使用者 11-02「排 2」。目標是讓牆面上的複製留在牆面，減少低角度看過去的透空。
- **成效**：
  - 11-02～03（lab，b3／b12，`實驗分析_過程/25` §1）：換塊 −0.05／−0.02、F1 +0.024／+0.034、b12 低角度透空 2.1%（當時最好）、時間 −2～−3%。
  - 反面：兩次拿掉它，海面浮塊都大減，高於 20 m 的少 −65／−79% 與 −54%（`研究總覽_v6` §5.4）。
  - 但 11-15 在新底 3 拿掉：b2 換塊 −0.031、F1 −.011／−.016、> 250 m 沒有顆粒 +1.0／+1.2 pt（§5.5），所以不拿掉。海面浮塊之後改由海面機制處理。
  - 現行配方上無拿掉臂。

#### B5. 點精靈下限（`px_floor 1.0`、`px_floor_interval 1000`）
- **我們怎麼做**：
  - 每步把長軸小於 `px_floor × 最近可見訓練相機的深度 / fx`（即在那台相機裡不到 1 px）的顆粒，兩個尺度都拉回這個下限。
  - 「最近可見深度」每 1000 步全量重算一次；新增和搬家的顆粒繼承母點的值。
  - 單位是像素，沒有用公尺常數。
- **來源**：
  - Mip-Splatting，Yu et al., "Mip-Splatting: Alias-free 3D Gaussian Splatting", CVPR 2024，§5.1 Eq. 7、Eq. 9，§6.1。**已讀 arXiv HTML 前 10 萬字元，涵蓋 §5.1 與 §6.1。**
    - 每顆的最大取樣率 ν̂ ＝ 所有可見相機中最大的 f/d。
    - 共變異加上 (s/ν̂)·I 做 3D 平滑。
    - §6.1：3D 濾波變異數 0.2，每 100 步重算取樣率。
  - 病因（點精靈從哪來）：2DGS §4.2 Eq. 11（p.5）的物件空間低通濾波，取 max(G(u), G((x−c)/σ))、σ = √2/2。**已讀原文。**
- **關係**：🟨 借用改造。
- **差在哪**：

  | 項目 | Mip-Splatting | 我方 |
  |---|---|---|
  | 作用方式 | 卷積，改變渲染出的形狀，是平滑的下限 | 硬性夾住長軸，不改渲染器 |
  | 用在 | 3DGS | 2DGS 面元 |
  | 重算頻率 | 每 100 步 | 每 1000 步 |
  | 看哪一軸 | — | 只看長軸：細長筆觸沿長軸仍拿得到尺度梯度 |

  取樣率的定義相同，都是「可見相機中最近的 d/f」。
- **動機**（`定案/35`；`研究總覽_v6` §5.2）：
  - 從 10-09 起每一代都沒有路燈，車也糊。
  - 病因是 2DGS 走低通分支時，尺度與旋轉拿不到光度梯度，尺度正則又一直往下推，於是卡成約 1 px 的不透明點。這是吸收態，MCMC 不會把它判死。
  - 比例：路燈帶 66%、車輛帶 72%、地面 59%，CityGS 0%。
  - 這個吸收態的機制分析未查到前例（1119 文獻查證 #8）。
- **成效**：
  - 本機採用時，b3／b12、30k（進展 §3.1；`定案/35` §5）：
    - held-out −0.005／−0.005、F1 **+.017／+.034**、貼地覆蓋 +0.22／+0.13。
    - 點精靈佔不透明顆粒比例 26.3／21.6% → 0.0／0.1%，燈柱回來。
    - 時間 +2／0%；副作用 b12 地下 +13%。
  - 11-09 拆解：屬於「有在幫忙」的項。
  - 現行配方上無拿掉臂（lab 換塊補量排過，紀錄未見結果）。

#### B6. 增生後刪死顆粒（`harvest_prune_dead true`、`harvest_prune_dead_interval 500`）
- **我們怎麼做**：增生期結束後（70% 步數以後），每 500 步刪掉 `o <= 0.005` 的顆粒。
- **來源**：
  - 3DGS §5.2（p.5）：每 100 步做一次增生並刪掉 α < ε_α 的透明高斯。**已讀原文。**
  - 2DGS §6.1（p.5）：每 3000 步刪掉 opacity < 0.05 的面元。**已讀原文。**
  - 3DGS-MCMC §3.4 把這些剪枝改寫成「搬家」，增生期結束後就沒有回收路徑了。
- **關係**：🟨 借用改造。⚠ `現行方法.md` §6.2 標 🟩，應改為 🟨。這是把 3DGS 原有的透明剪枝接回 MCMC 的收割期。
- **差在哪**：只在 MCMC 增生結束後才做；門檻用 MCMC 的死亡線 0.005（不是 2DGS 的 0.05）；每 500 步一次。
- **動機**（docstring）：
  - 增生停了以後 MCMC 不再回收，熵切回雙向後又把 o < 0.5 的一路推向 0，這些顆粒一直躺到訓練結束。b3 30k 有 5.5 萬顆，佔 7.6%。
  - 離線刪掉 V = 0 的那批，held-out 與 F1 一位不差。
- **成效**：
  - 1.5M 不開閘門的三項拿掉確認（`現行方法.md` §10）：本塊區域 −.018／+.016／−.040、顆數 +2.0／+2.8／+1.5%、純訓練 −1～−3%。

  - 使用者 11-21 決定保留。

#### B9. 逐顆正則融合（`metric.fused_reg`；屬於 `m39`）
- **我們怎麼做**：一個自訂 autograd 一次算完熵與尺度正則。
  - 二元熵用閉式 `H(σ(x)) = softplus(x) − x·σ(x)`，梯度為 `−x·σ(1−σ)`。
  - 尺度不再取 abs，因為 exp 本來就大於 0。
  - 權重 0 的 opacity L1 不算。
  - 塊外遮罩的合成改用 `where`。
  - 推導見 `實驗分析/39` §0 #3、#6–#8 與 §3。
- **來源**：sigmoid／softplus 的代數恆等式與 autograd 實作，不是方法貢獻，沒有論文出處。
- **關係**：🟩 原創（工程化簡）。
- **差在哪**：與 A11／A12 的數學相同。
  - float32 下閉式反而更準。
  - 原寫法把 o 夾在 1−1e-6，完全不透明的顆粒會被算成約 1.5e-5 的熵（沒有梯度）。閉式算的是真熵，只影響 log 裡的數字（39 §3）。
- **動機**：使用者 11-21 要求「純數學化簡、不訓練」。正則每步都對全部 N 顆跑好幾個小 kernel。
- **成效**：
  - 本機微基準（150 萬顆）：forward＋backward 5.67 → 3.61 ms／步（−36%）；影像梯度逐位元相同、opacity 梯度差 5.3e-7（39 §3）。
  - 五項合計（`m39`，含第 1 部分的兩項光柵器化簡）：
    - lab b2 純訓練 −10.4%、換塊 +0.003（39 §4.6）。
    - 全場景純訓練 −9.0%（1.45 → 1.32 h）、PSNR −0.003（雜訊內，39 §4.7）。
  - ⚠ 五項的時間沒有逐項拆開，所以本項單獨的 lab 省時是**無量測**。

#### B10. 雜訊同分布化簡（`density.noise_math`；屬於 `m39`）
- **我們怎麼做**：
  1. 閘門 `sigmoid(100(0.005 − σ(x))) > 1e-3` 改寫成直接比較原始參數 `x < −2.526`。
  2. 雜訊改成 `s1²·v1·t1 + s2²·v2·t2`：只取兩個常態亂數，t1、t2 是 R 的前兩欄。因為 v 是等向高斯，`Rᵀv` 和 v 同分布，所以和原式同分布。
  - 推導見 39 §0 #4、#5 與 §3。
- **來源**：等向高斯的旋轉不變性、sigmoid 的單調性，都是數學事實，沒有論文出處。
- **關係**：🟩 原創（工程化簡）。
- **差在哪**：和 B3 同分布，但不是逐樣本相同（亂數串流不同，約等於換種子）。閘門邊界在 1.48 萬顆裡差 3～4 顆。
- **動機**：同 B9。
- **成效**：
  - 本機 b2：0.84 → 0.31 ms／步（39 §5）。
  - 整合檢查：逐顆 E|Δ|² 比值中位數 1.000。
  - lab 單項省時**無量測**（併在 `m39` 的 −9.0% 裡）。

#### B11. px_floor 下限線性化（`density.pxf_linear`；屬於 `m39`）
- **我們怎麼做**：
  - 可見性 `0 ≤ u < W`、`0 ≤ v < H`、`z > 0` 乘上 z 之後，都是 (X, 1) 的線性函數，值 z/fx 也是。
  - 所以每顆 × 每台相機的投影加除法，可以換成一次 `[n,4] @ [4,5K]` 的矩陣乘加比較。
  - 解析度改變時，`fl += log(res_old) − log(res_new)`，不必重算。
  - 推導見 39 §0 #11 與 §3.5。
- **來源**：齊次座標的線性性，屬於數學事實。
- **關係**：🟩 原創（工程化簡）。
- **差在哪**：和 B5 結果相同。可見與否 0 顆不同，值差 ≤ 1.4e-6（log 空間）。
- **動機**：同 B9。B5 一次全量重算要掃 143 萬顆 × 1009 台相機。
- **成效**：
  - 本機 b2：每次重算 1650 → 595 ms。
  - 三段低解析度期間再省 3 次全量重算。
  - lab 估計每塊省 5～6 秒，約 1.4%（39 §3.5）。
  - lab 單項**無量測**。

### C. 累加式 V/C trim（`現行方法.md` §6.3；`renderer.trim_running_vc true`、`trim_running_warp true`、`prune_ratio 0.1`、每 500 步）

- **我們怎麼做**：
  - 每個 lean forward 順便逐顆累加 `V_i += sum_p T_i alpha_i` 與 `C_i +=` 覆蓋像素數。
  - 每 500 步（到 70% 步數為止）：`score_i = V_i / max(C_i, 1)`。
  - 剪掉分數最低的 10%（以 N 計，只在有被看到的顆粒中選；C = 0 的這一輪不剪），然後累加器歸零。
  - 對應程式：`_running_trim`，renderer 第 962–1010 行。
- **來源**：三篇，**都已讀原文**。
  1. TrimGS，Fan et al., "Trim 3D Gaussian Splatting for Accurate Geometry Representation", arXiv 2406.07499（頁面未載會議；已讀 arXiv HTML）。
     - §4.1 Eq. 4–6：單一視角的貢獻除以投影區像素數，權重形式為 `alpha^γ · T^(1−γ)`。
     - Eq. 6：取貢獻最高的前 5 個視角平均。
     - §5.1：每 1000 步剪最低的 10%。
  2. CityGaussianV2（ICLR 2025）§3.3 Eq. 3–4（p.6）。
     - 單一視角的貢獻同樣 ×1/|P_k|（P_k ＝ 投影區像素），γ = 0.5。
     - 對該塊的所有視角取平均，用百分位門檻剪；實作設剪枝比例 0.025（p.7），消融時用 0.1（p.10）。
  3. LightGaussian（NeurIPS 2024）Eq. 3–4（p.4–5）。
     - 全域重要度 ＝ 所有像素上的 `1(相交) · σ · T · γ(體積)` 總和，**不除以像素數**，另乘一個正規化後的體積項。
- **關係**：🟨 借用改造。
- **差在哪**：

  | 項目 | TrimGS | CityGaussianV2 | LightGaussian | 我方 |
  |---|---|---|---|---|
  | 每份貢獻 | `alpha^0.5 T^0.5` | `alpha^0.5 T^0.5` | `σ·T·體積` | `T·alpha`（實際混合量） |
  | 跨視角聚合 | 前 5 名視角各自比值的平均 | 塊內所有視角各自比值的平均 | 全像素總和 | 所有被看到的視角「總和 ÷ 總和」 |
  | 何時算 | 另掃相機 | 另掃相機 | 訓練後一次 | 在訓練 forward 中順便累加，不另掃相機 |
  | 剪多少 | 每 1000 步 10% | 百分位，0.025 | 一次性 | 每 500 步 10%，與 MCMC 搭配（剪掉的名額之後由增生補回） |
  | 解讀 | — | — | — | 背包對偶：`V − λC > 0 <=> V/C > λ` |

- ⚠ **舊出處表要修正**：`機制出處_至2026-11-19.md` 寫「除以覆蓋像素 C＝我方命題」。
  - 實際上 CityGaussianV2 自己的 Eq. 3 就已經除以 |P_k|，TrimGS Eq. 5 也是。
  - `現行方法.md` §11 只列 TrimGS，應補上 CityGaussianV2 Eq. 3。
  - 我方可以主張的只剩：總和比總和、訓練中累加、背包對偶解讀、成本端的量測。
- **動機**（`定案/13`；`研究總覽_v6` §1）：
  - 成本感知命題：以「每單位渲染成本的價值」決定保留哪些顆粒，覆蓋像素是精確 tile 成本的代理，排序相關 0.84～0.99。

  - 改成「累加」：不再每 500 步掃全部相機，以省時間。
- **成效**：

### D. 合併後刪除（`現行方法.md` §6.4；`merge_interval 1500`、`merge_color_tol 0.1`、`merge_prune true`、`merge_from_iter 3000`、`merge_until_iter` ＝ 90% 步數、`merge_max_frac 0.02`）

- **我們怎麼做**（`merge_ops.py` 檔頭）：
  - 候選條件：Morton 近鄰 PCA 平面夠平；兩顆的鄰域平面同向（`|n_i·n_j| > 0.9`）；彼此離對方平面近；面內距離 < 1.5 × 長軸和；顏色 L1 差 < 0.1；兩顆互為最佳配對。
  - 合併方式：以 o × 面積為權重做矩匹配。中心取加權平均；法向取兩個鄰域平面法向的平均；面內共變異＝兩片投影共變異加上中心離散的二階矩；`o = 1 − (1−o_i)(1−o_j)`；SH 取加權平均。
  - 被併掉的那顆直接刪除，並從上限 cap 扣掉同樣顆數。
  - 3k 步到 90% 步數之間，每 1500 步做一次，每次最多 2%。
- **來源**：
  1. NanoGS，"NanoGS: Training-Free Gaussian Splat Simplification", arXiv 2603.16103（v3 頁面日期 2026-09；**已讀 HTML**）。
     - §3.1 k 近鄰圖；§3.2 Eq. 1、5–6：代價＝I-divergence 加外觀 L2。
     - §3.3 Eq. 7–11：以質量 `w = (2π)^{3/2}·α·prod(s)` 做加權矩匹配；opacity 用 over 規則 `α_i + α_j − α_i α_j`。
     - 每輪貪婪挑出互不重疊的配對；不需要訓練，作用在 3D 體積高斯上。
  2. surfel fusion 的判準：ElasticFusion，Whelan et al., "ElasticFusion: Dense SLAM Without A Pose Graph", RSS 2015。**已讀原文 §III（p.2）。**
     - ⚠ 原文只說 surfel 的初始化與深度融合沿用 Keller et al. 的規則，本身沒有列判準。
     - 真正的判準在 Keller et al., "Real-time 3D Reconstruction in Dynamic Scenes using Point-based Fusion", 3DV 2013。**找不到原文、未讀。**
- **關係**：🟨 借用改造。
- **差在哪**：

  | 項目 | NanoGS | 我方 |
  |---|---|---|
  | 時機 | 訓練後一次性、不重訓 | 訓練中，合併後繼續訓練 |
  | 表示 | 3D 體積高斯 | 2DGS 面元：用鄰域 PCA 判平坦，合併後的平面取鄰域法向 |
  | 合併代價 | I-divergence＋外觀 | 判準式（同平面、相鄰、同色、互為最佳） |
  | 名額 | — | 扣 cap，讓 N 真的減少 |
  | opacity | over 規則 | 同一個式子（union） |

  與 surfel fusion 的差別：SLAM 的融合是「新量測併進既有 surfel」，我方是「兩個已學好的面元兩兩合併」。
- **動機**：
  - 使用者 10-30 提出合併機制，理由是 MCMC 只有「搬」與「增」，沒有「併」。
  - 第一版（被併的交給 relocation 搬走）N 不變、沒有輕量化效果，11-02 關閉（`已關閉的線.md` E 移出列）。
  - 使用者 11-02「合併完就減少點數」，改成刪除並扣名額。
- **成效**：
  - 採用時（10-31～11-04，lab，A＋dist4 2.5M，b3／b12，進展 §3.4）：換塊 −0.003／−0.003、F1 −.012／−.007、終點顆數 **−24／−21%**、海上浮塊 −50／−35%、時間 −4／−2%。
  - 11-09 拆解：與那次全場景退步無關。
  - 加強合併當加速（mgr75、mq6）：N −20～−24%，但純訓練只 −2.5～−4.2%，換塊 −0.03，不採用（`已關閉的線.md` K）。
  - 現行配方上無拿掉臂。

  | 塊外內容 | 靠 coarse 先驗把點導向幾何正確的位置（V1 p.6；Tab.4：Rubble 有全域先驗 25.01、基準 23.98） | 塊外遮罩 A／B／C（在另一部分，現行方法 §3.2） |
  | 細修 | 每塊 30k（V1 論文）；我們跑的 V2 release 是 60k；8×A100 平行（V2 p.7） | 17k，1×RTX 3090 依序 |
  | 合併後處理 | V1：LightGaussian 的剪枝、蒸餾、VQ（V2 p.4 的描述）；V2：VQ 加 float16（p.6） | 只做半精度（§E2） |

- **動機**：
  1. 6 GB 目標：同一張 3090 上，CityGS 光 coarse 階段的峰值配置就有 7,116 MiB，花 3.5 h（`參考_CityGS參考線.md` §2）。
  2. 時間：同硬體上 CityGS 要 coarse 3.4 h 加 16 塊細修 66.0 h（`現行方法.md` §9.2）。
  3. 4x4 是使用者 10-10 定的，理由是方便跟 CityGS 比較：每一塊都能直接對 CityGS 的逐塊模型（記憶 `project_grid44_best0.md`）。
  4. 依序訓練是因為專題目標是單張消費級卡。同卡同時跑多塊只快 6%，已關線（`new_archived/研究總覽_v6_至2026-11-19.md` l.46）。
- **成效**：
  - 全場景 741 幀：27.940／.8721／.1425。同一支工具評 CityGS release 是 27.261／.8671／.1540。
  - 純訓練 1.49 h，CityGS 約 69.4 h。訓練峰值 3.90 GB，CityGS 每塊 12～21 GB。（`現行方法.md` §0、§9.2）
  - 接縫：10-12 用 full44 舊配方量過，接縫帶（離邊界 < 0.05 格）的失敗 tile 比例和 PSNR 都與 CityGS 相同（`參考_CityGS參考線.md` §0.5）。這是舊配方，現行配方沒有重量。

#### A2. 不做全域 coarse 預訓練（設計選擇）
- **我們怎麼做**：完全不訓練全域模型。分區只用 SfM（`utils/partition_from_colmap.py` 的 docstring 寫明不需要 coarse checkpoint）。每塊從 SfM 點加校正深度反投影開訓。
- **來源**（我們拿掉的東西）：
  - CityGaussian V1 §3.2 p.6～7：coarse 先驗的作用是減少塊外浮塊、讓分塊融合可靠。已讀原文。
  - CityGaussianV2 Tab.2 p.10（GauU-Scene Residence）：改用 7k 步預訓練時，總時間 3 h → 2 h，PSNR 23.57 → 23.17。已讀原文。
  - Hierarchical 3DGS（Kerbl et al., TOG 43(4) 2024）§6.1：先訓一個關掉增生、位置固定的 coarse 支架，只用來提供 chunk 外的背景。已讀 arXiv HTML §6.1（網頁擷取）。
- **關係**：刻意拿掉上游元件（我方的設計選擇）。同樣不用 coarse 的有：
  - VastGaussian（CVPR 2024）§4.1：每格直接從裁過的 SfM 點起訓。已讀 arXiv HTML §4（網頁擷取）。
  - DOGS（NeurIPS 2024）p.2、p.4：用 ADMM 共識加 master 上的全域模型，取代 coarse。已讀原文。
- **差在哪**：
  - VastGaussian 處理塊外內容的方式：用含空域的能見度挑相機、整張影像訓練、合併前刪掉格外顆粒。
  - DOGS 靠多節點的 ADMM 共識。
  - 我方用校正深度做逐像素的塊外遮罩（B 類要求透明、C 類不計分），單卡、不通訊。
- **動機**：
  - coarse 階段本身就超過 6 GB（7,116 MiB，`參考_CityGS參考線.md` §2）。
  - 11-16～17 實測過 coarse 路線，代價太大（見成效），已關線（`new_archived/已關閉的線.md` 的 coarse5 列）。
- **成效**：
  - coarse5（全域 10k、1/4 解析度、SH0、cap 2M）加每塊 7k 細修：全場景 26.728／.8255／.2060，新底 5 是 27.775 => **−1.05 dB**，時間 −48%。
  - coarse 越長越差：細修 13k 時，coarse 30k −0.25／−0.24、10k −0.10／−0.07（b1／b4）。
  - coarse 不增生：N 只剩 0.29～0.67M，−0.35～−0.83 dB，F1 −.20。（以上 `已關閉的線.md` l.146）
  - 起點類型的對照（5x5、20k、機制全關、val）：SfM 起點比單目深度起點 +1.33／+1.18 dB，隨機起點崩到約 22 dB（`new_archived/實驗分析_定案/08_初始化.md` 結論）。

#### A3. 分區與相機分配（`utils/partition_from_colmap.py --block_dim 4 4 --content_threshold 0.08`）
- **我們怎麼做**：相機中心落在塊的 xy 盒內就分給該塊。不在盒內的相機，若它觀測到的 SfM 點（COLMAP track）有超過 8% 落在該塊的 xy 盒內，也分給該塊。不渲染、不需要 coarse。
- **來源**：
  - CityGaussian V1 Eq.3～5，p.7～8：遮掉本塊高斯前後渲染的 SSIM 損失 > ε，或相機在塊內，就分配。已讀原文。
  - 上游程式 `internal/utils/citygs_partitioning_utils.py` 的 `projection_based_partition_assignment`（把本塊不透明度設 0、比較 1−SSIM 與 `content_threshold`）。已讀程式。
  - 上游 `utils/partition_citygs.py` 的 `content_threshold` 預設是 0.08。已讀程式。
  - VastGaussian §4.1：把格子連同空域的包圍盒投影到相機，看可見面積比例，門檻 T_h＝25%。已讀 arXiv HTML（網頁擷取）。
  - Hierarchical 3DGS §6.1：相機在 chunk 內，或在 2 倍範圍內且看到 chunk 內超過 50 個 SfM 點。已讀 arXiv HTML（網頁擷取）。
- **關係**：借用改造。
- **差在哪**：
  - V1 量的是渲染差異，需要 coarse 模型；我方量的是 SfM 觀測點的比例。
  - **0.08 這個數字沿用自 CityGS 上游工具的預設，但上游的 0.08 是「SSIM 損失」的門檻，我方用在「SfM 觀測比例」上**：同一個數字，量的東西不同。紀錄沒有寫為什麼沿用 0.08。
  - 與 VastGaussian 比：它投影的是盒子（含空域），我方數的是 SfM 點，所以空中沒有 SfM 點的部分不會讓相機被分進來。
  - 與 H3DGS 比：它用點數門檻（50），我方用比例。
- **動機**：不需要 coarse 就能分區（工具 docstring）。紀錄沒有寫為什麼選比例而不是點數。
- **成效**：**無量測**。紀錄裡沒有本分配法與 SSIM 分配法在同一個底上的對照。
  - 參考數字：與 CityGS 同格，但兩邊的訓練相機只重疊 52～70%（`參考_CityGS參考線.md` §0.2）。
  - 每塊相機數：b1／b2／b4 是 811／1009／799（`實驗分析/40` §1.5）。

#### A4. 每塊顆數 ∝ 塊內可靠 SfM 點數（`tools/sfm_cap_alloc.py`；詳細在另一部分 §6.5）
- **我們怎麼做**：每塊的 cap＝平均 cap × 該塊可靠 SfM 點數的占比權重，總量固定。
- **來源**：沿用 1119 查證 #11。
  - Taming 3DGS 依場景把預算設成 SfM 點數的倍數，是單一場景層級的做法。
  - BlockGaussian 用 SfM 密度決定切塊，沒有每塊預算。
- **關係**：借用改造。「在同一場景內、總量固定，按 SfM 點數比例分給各塊」這一點沒查到前例。
- **動機**：舊的探針分配要先跑一次全場景 2.5M 的探針（GPU 約 5 h），而且使用者認為那不通用（`現行方法.md` §2.8）。
- **成效**：均勻 cap 27.805、探針分配 27.828、SfM 分配 27.822（零 GPU 成本）（`現行方法.md` §6.5）。

### B. 幾何先驗（現行方法 §2.2'、§2.3）

#### B1. 單目逆深度加逐張 SfM 尺度（Depth Anything V2；`utils/get_depth_scales.py`）
- **我們怎麼做**：
  - 用 Depth Anything V2 ViT-L 算每張影像的逆深度。
  - 每張用自己觀測到、重投影誤差 < 1.5 px 的 SfM 點擬合一組尺度與位移：
    `scale = mean|inv_SfM − median(inv_SfM)| / mean|inv_mono − median(inv_mono)|`
    `offset = median(inv_SfM) − scale·median(inv_mono)`
  - 程式註明是複製自 hierarchical-3d-gaussians 的 `make_depth_scale.py`。
- **來源**：
  - Hierarchical 3DGS App.C：用中位數做位移、**平均絕對偏差**做尺度，把單目逆深度對齊到 SfM 逆深度。論文用的單目模型是 DPT，不是 Depth Anything。已讀 arXiv HTML App.C（網頁擷取）。
  - CityGaussianV2 §3.2，p.5：照 Kerbl et al. 2024 的做法，用 Depth-Anything-V2 估逆深度並對齊尺度，當成 L_Depth，權重從 0.5 指數衰減到 0.0025（p.8）。已讀原文。
- **關係**：完全沿用（程式碼也是複製來的）。
- **差在哪**：
  - 與 V2 相同。差別在用途：V2 直接拿它當 depth loss；我方不直接當 loss，只當 B2 校正的底。
  - 現行方法 §2.2' 寫的「中位數／MAD」要寫清楚：MAD 在這裡是平均絕對偏差（mean），不是中位絕對偏差。
- **動機**：CityGaussianV2 就是這樣做，H3DGS 的程式可以直接用。
- **成效**（也是 B2 的動機）：對 MatrixCity GT 深度（350 張）：
  - 誤差中位 2.15%，|e| > 5% 的像素 24.6%，比真表面近 5% 以上（「判在前方」）15.7%。
  - 超高塔頂（z ≥ 3）中位 18.35%，判在前方 77.2%。
  - （`new_archived/實驗分析_過程/37_SfM三角形校正深度_至1113.md` §1）

#### B2. SfM 三角形校正單目深度（`tools/make_tri_depths.py` → `estimated_depths_tri/`）
- **我們怎麼做**：
  - 每張影像只用它**自己觀測到**的可靠 SfM 點（track ≥ 3、誤差 < 1.5 px，相近的點去重），在影像平面做 Delaunay 三角化。
  - 三角形內用重心座標線性內插「逆深度殘差」，再加回單目：
    `inv(p) = (s·d(p) + o) + interp_tri( 1/z_SfM − (s·d + o) )(p)`
  - 凸包外用最近 SfM 點的殘差。SfM 觀測少於 50 個的影像直接給單目，並全部標成不可靠。輸出解析度 960x540。
  - 為什麼三角形內線性內插合理：平面的逆深度在影像座標上是仿射的，所以對平面是精確的；而且三角形頂點（SfM 點）上完全吻合。
- **來源（最接近的前例）**：
  1. **Depth Anything with Any Prior**（Wang et al., arXiv 2505.10565，ICLR 2026 的 poster 頁可查到）§3.2「pixel-level metric alignment」Eq.1～4。做法：每個缺值像素取最近的 K＝5 個先驗點，用距離加權最小平方擬合局部的尺度和位移，填入 s·D_pred + t；之後再交給一個條件化的單目深度網路細修。已讀 arXiv HTML §3.2（網頁擷取）。**這篇 1119 查證沒有收，現行方法 §11 也沒有列，是這次新找到、最接近的前例。**
  2. ACMP（Xu & Tao，AAAI 2020，會議依紀錄）§3「Planar Model Construction」：把可信的稀疏對應點三角化，每個三角形的三個頂點定一個平面，當作 PatchMatch 多視角比對成本裡的平面先驗。已讀 ar5iv §3（網頁擷取）。⚠ 擷取到的正文沒有明寫「Delaunay」，紀錄裡的「ACMP 用 Delaunay」待確認。
  3. HI-SLAM2（arXiv 2411.17982）：每張的深度先驗估一個 2D 尺度網格，逐像素雙線性內插。沿用 1119 查證。
  4. B1 的全域尺度加位移（H3DGS App.C、CityGaussianV2 §3.2）。
- **關係**：原創（是一個組合；各成分都有相近做法）。
- **差在哪**：
  - vs Prior Depth Anything：
    - 他們每個像素做 KNN 最小平方，擬合「局部尺度＋位移」；我們只內插「位移殘差」（在逆深度空間），而且用三角形重心座標。
    - 我們的做法在 SfM 點上精確、對平面精確，完全不需要網路。
    - 他們後面接學習式的細修網路；我們沒有，但另外輸出可靠度等級（B3）。
  - vs ACMP：
    - ACMP 用三角形平面「取代」深度，當多視角光度比對的先驗；我們不做多視角比對。
    - 我們內插的是殘差，所以三角形內保留了單目的起伏。
  - vs HI-SLAM2：它是規則網格上的尺度場；我們是跟著 SfM 點位置走的三角形位移場。
- **動機**：
  - 37 線開線時（11-11）讀紀錄發現，好幾條關掉的線的重開條件都是同一句：有比單目（約 ±10%）更準的稠密深度。這幾條是：單目看穿判準、塊外遮罩在高樓接縫誤判、深度支撐閘門把塔頂壓成煙、補洞沿視線放點（`37_至1113` 開頭）。
  - 地下層大約在視線距離的 1.5～3% 處，單目（中位誤差 2%）看不到（`37_至1113` §1）。
  - 選三角形內插是因為平面的逆深度在影像上是仿射的（工具 docstring）。
- **成效**：
  - 350 張對 GT 深度，單目 → 校正後：
    - 誤差中位 2.15% → **0.15%**；|e| > 2% 53.2% → 11.5%；判在前方 15.7% → **2.2%**。
    - 超高塔頂 18.35% → 0.45%，判在前方 77.2% → 15.9%。
    - （`37_至1113` §1）
  - 純 SfM 三角形（不用單目）的中位也是 0.15%，但 |e| > 2% 是 19.0%（校正單目 11.5%），而且只有 90% 像素有值 => 三角形內的單目起伏有貢獻（同上表）。
  - **單獨把深度換成校正版、其他機制不動（`tri`）時，分數不變**：b1 換塊 −0.001、F1 −.002（`37_至1113` §3）。它的價值在下游：
    - 用校正深度判的塊外遮罩：b2 +0.058、b6 +0.019（`現行方法.md` §3.2）。
    - 校正深度加逐貢獻深度上限：對鄰域平面基準，F1 +.101／+.112、地下覆蓋 −69／−71%（`研究總覽_v6` l.59；這是兩項一起的結果）。
  - 成本：全場景 5,621 張，lab CPU 11.6 分（6 行程，`37_至1113` 開頭）；一鍵流程實測 10 分（`現行方法.md` §9.2）。
  - 救不了的：畫面裡完全沒有 SfM 點的東西（重複窗格的高樓立面、玻璃塔）。三角形會直接跨過去，那些像素被標成不可靠（`37_至1113` 開頭）。

#### B3. 校正深度的可靠度分級（斜率級＋大小級；`make_tri_depths.py`、dataparser `depth_rel_*`）
- **我們怎麼做**：
  - 每個三角形的無因次斜率：`slope = |grad(1/z)| / mean(1/z_頂點) · fx = |grad log z|·fx`，物理意義是表面對視線的 cot。
  - 斜率級：< 1／< 3／< 8／≥ 8／凸包外。大小級：三角形最長邊 < 16／< 64／< 256／≥ 256 px。可靠度 = 斜率級 + 8·大小級。
  - 訓練只用斜率 < 3 的像素。起點用斜率 < 3 而且最長邊 < 256 px 的像素。
- **來源**：未查到前例（1119 #1 的 (c)；這次沒有另外搜尋）。最接近的兩個：
  - Prior Depth Anything 用距離加權最小平方，但不輸出可靠度（§3.2，網頁擷取）。
  - ACMP 用比對成本 < 0.1 篩「可信的頂點」，判的是頂點，不是三角形內部（ar5iv §3，網頁擷取）。
- **關係**：原創。
- **差在哪**：用三角形自己的幾何（斜率、像素大小）判斷「這個三角形是不是跨過高低落差的橡皮膜」，門檻全是無因次量或像素，沒有場景單位。
- **動機**：跨過高低落差的三角形斜率大，內插不可信（`37_至1113` §1）。使用者的規則是不准用場景單位的門檻（記憶 `feedback_no_scene_unit_thresholds.md`）。
- **成效**（校正後的深度在各等級，`37_至1113` §1）：
  - 斜率 < 1（佔 34.1% 像素）：中位 0.05%。斜率 1～3（36.1%）：0.15%。斜率 3～8：0.85%。斜率 > 8：1.95%。凸包外：0.75%。
  - 訓練規則「斜率 < 3」涵蓋 70.2% 像素：中位 0.05%，|e| > 2% 3.1%，比真表面近 2% 以上 1.6%。
  - **已知失效**：b1 海岸外那團浮塊在斜視角裡落在 SfM 凸包外。那些像素的校正深度其實準（與遠方海面差 −0.3%），卻被判成不可靠，結果那裡沒有任何深度約束（`研究總覽_v6` §5.4，11-15 深夜）。

### C. 起點（現行方法 §6.1；`tools/make_tri_dense_init.py ... --drop_fill --plane_dir estimated_depths_plane --plane_sep --sea_object sea_object_v9 --seed_per_block`，不加 `--drop_outliers`）

#### C1. 校正深度的稠密起點（臂元件 `dense`，11-15 起進底）
- **我們怎麼做**：
  - 本塊訓練影像每 2 張取 1、像素步長 3，把可靠像素沿校正深度反投影成世界點，丟進體素。
  - 至少有 2 個不同視角的點落在同一格才收（多視角一致），每格取質心和平均色；已經有 SfM 點的格不再加。
  - 體素邊長用二分搜尋，讓總顆數 = 0.9 × 本塊 cap。最後裁到塊盒外擴 0.15 × 內側塊短邊。
  - 之後照常增生。
- **來源（相近）**：
  - EDGS（Kotovenko et al., arXiv 2504.13204）：把稠密對應點三角化成起點，並且完全拿掉增生。只讀摘要。
  - Mini-Splatting（Fang & Wang）p.7～8「Depth Reinitialization」：把渲染深度點重投影到世界、取 GT 顏色，約 350 萬點，訓練中反覆重新初始化。已讀原文（本機 `Mini-Splatting.pdf`；會議待確認，PDF 內沒看到）。
  - RTG-SLAM（SIGGRAPH 2024）：從 RGB-D 像素直接放高斯，深度來自感測器。已讀原文 p.2、p.5 的相關段落。
- **關係**：借用改造。
- **差在哪**：
  - 深度來源是「SfM 三角形校正過的單目」，不是稠密比對、渲染深度或感測器。
  - 加了體素層級的多視角一致過濾。
  - 起點顆數跟著 SfM 分配的 cap 走（體素邊長是解出來的，不是固定常數）。
  - **增生保留**：EDGS 式「稠密起點加拿掉增生」在我方測過，不採用（見成效）。
- **動機**：
  - 舊起點是把 SfM 點複製 K 份，沒有新資訊；無紋理的路面、素牆沒有 SfM 點，只能等增生慢慢長過去，所以增生期不能短。
  - 路面那層沒蓋滿，是地下層的來源（工具 docstring）。
  - 11-11 第一次試時被增生期洗掉、沒採用；11-15 在新底 3 上改成照常增生後採用（`38_至1119` §10）。
- **成效**：
  - lab 11-15，新底 3，b1／b4：換塊 +0.008／−0.002，F1 **+.007／+.012**，海面 Σo·面積 −2%／−24%，地下 −0.03／−0.06 層，時間 +0.1 分（`new_archived/實驗分析_過程/38_時間拆解與配方瘦身_至1119.md` §10）。
  - b3／b2：換塊 −0.009／+0.003，F1 +.009／+.017，立面 +2.4／+3.1 pt，朝向對齊 +3～7 pt（`研究總覽_v6` l.194）。
  - 對照組，EDGS 式（稠密起點、拿掉增生）：省 17～19% 時間，但換塊 −0.033／−0.066、LPIPS +.0088／+.0138、立面減半、b4 地下 +1.23 層 => 不採用（`38_至1119` §8）。

#### C2. 起點不撒空中隨機點（`--drop_fill`，臂元件 `densenf`）
- **我們怎麼做**：拿掉舊起點（`make_sfm_fill_init.py`）裡在空處用 SfM 平均色撒的隨機補點，少掉的名額改由校正深度反投影的點補滿。
- **來源**：這是修正我方自己的舊起點（09-13 的 sfmfill）。外部沒有直接對應，沒有做文獻搜尋。
- **關係**：原創（修正自身流程）。
- **差在哪**：不適用。
- **動機**：b1 海面上方 > 5 m 的起點 6,833 顆全是空中補點。協作 AI Fable 的判斷是：海面沒有紋理，顆粒生在哪就留在哪（`研究總覽_v6` §5.4 l.188）。
- **成效**：`densenf`（同時開 `sbox`）b1／b4：換塊 −0.013／−0.002、F1 +.017／+.007、地下 +0.19／−0.05；**b1 海面浮塊 Σo·面積 818k → 471k m²（−42%）**（記憶 `fable_premise_1116.md`；`new_archived/圖/流程與決策.html`）。

#### C3. 立面平面外推點，另算名額（`make_plane_depth.py` kind 1＋`--plane_sep`）
- **我們怎麼做**：
  - 找立面區：單目法向不躺平、依方位角分 12 格（每格 15°）的連通區。
  - 用區內可靠的校正深度擬合平面。自我檢查：留出最高的 20% 可靠像素，看外推誤差，通過才用。再外推到區內不可靠的像素（例如塔頂）。
  - 反投影進起點，用自己的名額，名額 = max(拿掉的空中補點數, 3% × 目標)，也用自己的體素邊長。
- **來源**：沒有做系統文獻搜尋。概念上接近平面先驗類方法（ACMP；PGSR、GaussianPro 本輪沒讀）。提案者是協作 AI Fable（11-17 第三輪），程式由我方寫。
- **關係**：原創（標 ⚠：沒做文獻搜尋）。
- **差在哪**：只用在起點，不進任何 loss；只外推到校正深度不可靠的像素；帶自我檢查。
- **動機**：
  - 塔頂沒有 SfM、校正深度不可靠。
  - v1 把平面點和陸地點放在一起解體素邊長，平面點吃掉陸地名額（陸地體素粗了 3～41%），陸地地下 +0.2～0.5 層，所以 v2 改成分開解（工具註解）。
- **成效**：
  - 前提：立面塔頂（> 250 m）外推誤差中位 0.8～1.5%，自我檢查 0.2%（`make_plane_depth.py` docstring）。
  - 平面另算名額（不去離群）b1／b3／b4：地下 −0.12／+0.13／+0.08 層，換塊 −0.001／+0.004／+0.001（`37_至1119` §4），可視為打平。

- **來源**：修正我方 11-17 加的 `--drop_outliers`。外部沒有對應。
- **關係**：原創（修正自身流程）。

- **成效**：b1／b3／b4 地下覆蓋 1.69 → 1.40、2.37 → 2.48、1.45 → 1.34；換塊打平（+0.001／−0.008／−0.000）；F1 在雜訊內（`37_至1119` §4）。

### D. 海面物件（現行方法 §6.6；資料準備 stage 7～11，合計 99 分，是資料準備最大的一項，`現行方法.md` §9.2）

整套海面機制的提案者是協作 AI Fable（11-16～17 第三、四輪；規格 6 由 Fable 寫），我方實作，使用者看 viewer 後決定採用。紀錄把它標成我方原創 🟩。1119 查證 #5 的判定是「整套未查到前例」，信心中低。

#### D1. 每張影像的海面區與外圈平面（`tools/make_plane_depth.py` kind 2）
- **我們怎麼做**：
  - 海面區的條件：校正深度無效或在凸包外、5x5 內 RGB 標準差小（顏色均勻）、連通、面積夠大。
  - 用海面區外圈帶上的可靠校正深度擬合平面（殘差 MAD 相對中位深度要夠小），外推到整個區。
  - 視線與平面法向夾角 > 80° 的像素不放（擋掠射）。
- **來源**：
  - 折射感知 GS（ISPRS Annals 2026）把水面當平面折射界面，是前提假設。沿用 1119 查證 [E2]。
  - Through the Water（AAAI 2026）⚠：1119 只看到片段。
  - 攝影測量 DSM 的 hydro-flattening：沒查。
- **關係**：原創。
- **差在哪**：上面兩篇是假設水面是平面，再處理折射；我方是在空拍大場景裡，從影像和稀疏深度**自動找出**水面區、擬合平面，不做折射。
- **動機**：海面沒有 SfM、校正深度無效，那裡的顆粒只受光度約束（規格 6 §0）。
- **成效**：
  - 前提：海面外推誤差中位 0.6～1.8%，區內幾乎全是海（`make_plane_depth.py` docstring；規格 6 §0 說誤罰約 0%）。
  - 但單張影像的海面區只涵蓋 GT 海面像素的 42～56%（規格 6 P3），所以需要 D2、D3。

#### D2. 多視角共識平面與水體自動偵測（`tools/make_sea_object.py`、`tools/water_bodies.py`）
- **我們怎麼做**：
  - 各影像的海面平面轉到世界座標（n_w = Rᵀn、c_w = c − n·t），依區的像素數加權：法向取加權中位，丟掉偏離超過 3 倍加權 MAD 的區，再重擬，得到共識平面。夾角 > 10° 的整塊判為不是海。
  - **水體偵測**：把各塊（v2）的海面格畫進全場景格網，膨脹 1 格後取 8 連通區，每個連通區是一個水體（小於 200 格丟掉）。
  - 水體高度：落在該水體格上、離共識平面 ≤ 2 格的可靠 SfM 點，取 z 中位；去掉超過 3 × 1.4826 MAD 的離群點後再取一次中位。
  - **現行（v9）的海面是「該水體高度的水平面」**。共識平面只用在傾斜檢查和 v2 投票（v2 投票的結果再拿來定水體）。
- **來源**：未查到前例（1119 #5）。穩健平面估計本身是標準做法。
- **關係**：原創。
- **差在哪**：同 D1。另外沒查到「多塊各自估平面，再在全場景把同一水面合併成單一高度」的做法。
- **動機**：
  - v3（11-18）發現：海面格上可靠 SfM 水面的傾斜只有 0.05～0.3°、高度 −2.3～−2.8 m；但我們的共識平面歪 0.4～2.1°，各塊高度從 −2.2 到 −6.6 m 不等，合併後接縫會出現台階（`研究總覽_v6` l.49～50）。
  - 使用者 11-18：海平面高度改成自動算；判定為同一個面的（湖、海）分開各自處理（`water_bodies.py` docstring）。
- **成效**：
  - MatrixCity 偵測到一個水體，高度 −2.565 m，有 30.8k 個 SfM 水面點（`現行方法.md` §6.6；原始 log 本機沒找到）。
  - **無單獨量測**：「水平水面 vs 共識平面」沒有單獨的分數對照，只有整包（v9）的結果，見 D3。

#### D3. 海面格投票與補齊（abstain 規則、`--grow`、`--gap`、`--gap2`、`--gap3`、`--far_levels 6`）
- **我們怎麼做**：
  - 在水面上鋪規則格子，邊長 = 16 px × 海面格最近可見深度的中位 / fx（用像素定義）。
  - 每張影像對每格投一票：射線打到該張的海面區算贊成；可靠深度在平面「後面」超過 1% 算反對；其他棄權。贊成 ≥ 3 且贊成 > 反對的格算海面格。
  - `--grow`：從海面格往 8 連通的鄰格長。條件是「像海」票夠（顏色均勻、和同張海面顏色接近），而且格內沒有高出平面的 SfM 結構。
  - `--gap2`：交界帶長格時不看顏色。
  - `--gap3`：在海面上，「可靠深度在平面後面」不算反證；條件改成：像海 ≥ max(1, 2 × 前面有東西)、不像海 ≤ 0.2 × 像海。
  - `--far_levels 6`：遠處的像素依它在平面上的足跡，投到 2^L 倍的粗格。
  - 不外推到沒有訓練影像看到的地方（使用者同意）。
- **來源**：原創。
- **關係**：原創。
- **差在哪**：不適用（沒有找到可比的前例）。
- **動機**（各規則的由來，見工具註解與 `研究總覽_v6`）：
  - **abstain 規則**：規格原本的反對規則會把 SfM 看得到的海也算成反對（b12 有贊成票的格只有 25% 成為海面格）；改成「在後面才反對」又會把岸邊陸地算成海。
  - **grow**：碼頭之間的水沒有拿到票。
  - **far_levels**：新底 7 候選全場景，b3 本塊區域 −0.81 dB，原因是往外海看時地平線一條全黑（0226 幀 26.50 → 18.80；`30_至1119` l.57～60）。
  - **gap3**：港口有一團煙狀浮塊，那幾格的「可靠深度」其實是錯的，所以「在平面後面」不能當反證。
- **成效**：
  - v2（grow）加浮塊收回，對 S1：b1 可見面積再 −94%、> 20 m 歸零；b3 −58%、> 20 m −70%；換塊 +0.003／+0.006、F1 ±.006（`研究總覽_v6` l.43、l.49）。
  - 新底 8（海面 v9）全場景，對新底 5，按相機中心所在的塊分：b3 −0.053（`30_至1119` l.15）。新底 7 候選（v2）是 b3 本塊區域 −0.81。⚠ 兩者量法不同（一個按相機中心分塊、一個是本塊區域），只能說遠海變黑大致解決，不能直接相減。

#### D4. 錨定的海面層與海面鋪磚起點（`sea3dt`；density controller 的 `sea_layer_file`／`sea_layer_obj`）
- **我們怎麼做**：
  - 每個海面格放一顆鋪磚（顏色取贊成票影像的中位），接在起點最後。
  - 每步結束時：位置還原到格心；法向固定為平面法向（面內轉角照學）；兩個尺度夾在 [0.5, 2] × 格距。不透明度和顏色照學。
  - 鋪磚不參與搬家、補洞、trim、合併、刪死顆粒，也不當母點。名額另外算，不佔 SfM 分配的 cap。
  - （以上已對照程式 `mcmc_2dgs_density_controller.py` 的 config 說明。）
- **來源（相近）**：
  - RoGs（arXiv 2405.14342，只讀摘要，加上 1119 查證 [E1] 讀過的 HTML）：在路面均勻方格的頂點放 2D 面元，用來重建路面。
  - Hierarchical 3DGS §6.2：一層 10 萬顆、放在 10 倍場景直徑球面上的天空殼，各 chunk 共用。已讀 arXiv HTML §6.2（網頁擷取）。
  - 我方 11-05 的 SfM 錨點（`sfm_lock`）。
- **關係**：原創（延伸我方 SfM 錨點；結構上類似 RoGs 的網格面元層和 H3DGS 的固定天空殼）。
- **差在哪**：
  - vs RoGs：RoGs 是用網格面元表示整個路面（任務是路面重建）；我們只鋪在自動偵測到的水面上，位置和法向每步硬性還原、尺度被夾住，而且和自由高斯並存，被排除在 MCMC 之外。
  - vs H3DGS 天空殼：天空殼是遠場的球面殼，用來表示天空；我們是場景內、水面高度的一層平面。
- **動機**：
  - 規格 6 §0：四輪清浮塊下來的共同形狀是「清掉一層，另一層接手畫」（上方浮塊少了 40～92% 之後，露出 2.5 km 深的巨大面元）。缺的是「一層保證鋪滿、動不了、不會長大的顆粒」，其他顆粒才能退場。
  - 使用者的判準（11-15）：viewer 裡海面浮塊要**完全不見**才算有用。
- **成效**（S1＝錨定層加寬遮罩上限一起量）：
  - b1 海面上方 > 20 m 的浮塊 1,497 → 3，可見面積 −99%（CityGS b1 是 307 顆、477k m²）；b3 −81%。
  - 換塊 −0.005／−0.010，F1 +.016／+.007，時間 ±7% 以內（`研究總覽_v6` l.42）。
  - LPIPS 歸因：海面機制 −.0004～−.0019（`現行方法.md` §9.3）。

#### D5. 海面寬遮罩上的深度上限（`seabackt`）
- **我們怎麼做**：逐貢獻深度上限 L_cap（另一部分 §4）在海面物件的寬遮罩上，把 z_prior 換成水面平面的深度。落在水面後面超過 1% 的混合貢獻會被罰，梯度只補前面（`capfc`）。
- **來源**：沿用我方的深度上限。相近前例（URF、SplatAD、DS-NeRF）見 1119 #2，歸另一部分。
- **關係**：原創（上限的先驗來源換成水面平面）。
- **差在哪**：同深度上限那節（另一部分）。
- **動機**：海面的校正深度無效，上限在那裡原本沒有先驗可用。
- **成效**：**無單獨量測**，和 D4 一起量（S1，見 D4）。
  - 反方向的「海面前方上限」前提沒過，已關（`研究總覽_v6` §5.4；`已關閉的線.md` I）。

#### D6. 海面浮塊收回（`seafl`＋`seafl2`＋`seafl3`＋`seaflb`）
- **我們怎麼做**：符合下列條件的自由顆粒（不是鋪磚）會被收回：
  - 中心投到平面時落在海面格上；
  - 高出水面 > 1 格，或低於水面 > 0.5 格；
  - 離最近的「非水面」可靠 SfM 點 > 1 格（水面 1 格內的 SfM 點不算保護）。
  - 增生期在每次增生事件時把它們併進死亡，交給 MCMC 搬家；增生期之後每 500 步直接刪。
  - 門檻用格距（像素定義），沒有公尺常數。
- **來源**：沒有系統文獻搜尋。紀錄提到的同類（TIDI-GS、FastGS 的多視角浮塊判定）只看過搜尋摘要（`機制出處_至2026-11-19.md` 11-15 那一節）。
- **關係**：原創（⚠ 沒做文獻搜尋）。
- **差在哪**：判定只用三樣東西：水面物件、可靠 SfM 距離、格距。不用渲染統計。
- **動機**：
  - S1 之後還剩一顆 123 m 高、9x6 m、離 SfM 173 m 的面元；海面上限只罰平面後面，上方沒有東西推它（程式註解）。
  - 港口浮塊都在 10 格以下，原門檻收不到（`seafl2`）。
  - 60k 時一顆都收不到，因為水面上的 SfM 點把它們全保護了（`seafl3`）。
  - 水面下的暗色楔形（`seaflb`）。
- **成效**（`37_至1119` §5）：
  - b1（17k）：水面上方 5.3k → 1.6k m²，水面下 13.6k → **0.1k** m²。
  - b3：上方 20.3k → 1.2k，水面下 28.1k → 0.8k。
  - 換塊 −0.001／+0.002，F1 +.004／+.005。
  - 60k b1：上方 237.8k → 1.8k，時間不變（32.3 vs 32.5 分）。
  - 已知副作用：60k 長訓練的海面直條紋還在（貼在水面 1 格內，不是浮塊）。

### E. 合併、部署、儲存（現行方法 §7）

#### E1. 盒內合併（`utils/merge_citygs_ckpts.py`）
- **我們怎麼做**：每塊只保留中心落在自己分區盒內的顆粒，連同 Adam 的狀態一起把 16 塊串接。現行配方的分區不收縮，`contract` 分支用不到。
- **來源**：
  - CityGaussian V1 §3.2 p.8：每塊濾出在自己空間邊界內的細修高斯，直接串接。已讀原文。
  - 合併程式本身來自 Gaussian Lightning 的 CityGS 實作。git 紀錄裡我方只改過一處：bug 修正 `40f0e29`，讓逐顆的 density controller 緩衝也套上區塊遮罩。
  - VastGaussian §4.3 也一樣，合併前刪掉格外高斯（已讀 arXiv HTML，網頁擷取）。
  - H3DGS §6.3 的規則不同：在 chunk 外、而且離另一個 chunk 更近的才刪（已讀 arXiv HTML，網頁擷取）。
- **關係**：完全沿用。
- **差在哪**：沒有實質差別。
- **動機**：CityGS 的標準做法，而且合併後的模型可以直接跟 CityGS 的 release 比。
- **成效**：
  - 合併讓單塊評測的偏差消失：b12 單塊 held-out −3.84 dB，合併後 +0.73（`參考_CityGS參考線.md` §0.2b）。
  - 接縫沒有問題（見 §A1，舊配方）。

#### E2. 半精度部署（`tools/half_ckpt.py`）
- **我們怎麼做**：位置維持 float32（座標到幾十個場景單位，float16 的間距太粗），其他參數（SH、不透明度、尺度、旋轉）存成 float16，並丟掉 Adam 狀態。載入時轉回 float32。不剪枝、不做 VQ。
- **來源**：
  - LightGaussian（NeurIPS 2024）p.6：沒做 VQ 的屬性存 float16。已讀原文。
  - CityGaussianV2 §3.3 p.6：重要的 SH 和其他屬性存 float16，其餘 SH 做 VQ。已讀原文。
- **關係**：借用改造（簡化版：只做半精度，而且位置不轉）。
- **差在哪**：
  - V2 有 VQ，Tab.4 的模型 0.56 GB；我們沒有 VQ。
  - 我們刻意把位置留在 float32。
  - §H 的低維 SH 存檔（`40` §1.7：本機 b2 檔案 374 → 257 MiB）是另一條路：它減的是維數，半精度減的是每個數的位元，兩者可以疊加。但「疊加後的大小」紀錄裡沒有量過。
- **動機**：使用者 10-24 問能不能換儲存形式減少存儲（工具 docstring；`加速論文對照.md` C8）。
- **成效**：
  - 本機 b6：每顆 232 → 122 B（−47%），PSNR −0.0008 dB（C8、工具 docstring）。
  - 配方 A：部署 18.0 → 3.2 GiB，PSNR 不變（`研究總覽_v6` l.117）。
  - 反例：事後把高階 SH 能量最低的 25%／50%／100% 顆粒歸零，PSNR −0.55／−1.58／−4.90 dB，所以「事後裁 SH」不行（C8）。§H 的子空間投影是另一回事。
  - ⚠ `現行方法.md` §7 寫「全場景約 1.3 GiB」，這與 1M 版的 10.7M 顆相符；現行 1.5M 版是 16.0M 顆，按 122 B／顆推算約 1.8 GiB（這是推算，沒有量過，要改成實測值）。

#### E3. 儲存組成（量測，不是機制）
- 每顆 58 個 float（232 B），其中高階 SH 佔 78%；ckpt 有 2/3 是 Adam；訓練常駐約 928 B／顆（`現行方法.md` §3.1、§7；`實驗分析/40` §0；記憶 `storage_structure.md`）。
- 這是 §H 能省多少的基準。

### F. 評測協定（現行方法 §8、§9.5～9.6）

#### F1. 全場景 741 幀，兩邊用同一支工具（`tools/eval_official_test.py`）
- **我們怎麼做**：
  - 合併模型渲染 MatrixCity test 741 幀，用同一個光柵器、同一份 test 目錄（照 CityGS 的資料轉換步驟重建，逐張驗 md5）。
  - 算 PSNR／SSIM／LPIPS（torchmetrics AlexNet），另外量 FPS 和顯存。我方與 CityGS release 都用這支評。不做色彩校正。
- **來源**：
  - 指標是標準指標。
  - 測試集張數：V1 p.2 寫 740 張、DOGS 寫 741（`大場景對手` 注意事項 3）、V2 p.7 只寫 450 張以上。已讀原文。
- **關係**：指標與測試集沿用；「用我們的工具重評對手的 release 模型」是我方的評測設計。
- **差在哪**：
  - CityGS 用自己的工具量 release 模型得 25.79；我們的工具得 27.261。
  - 原因已查明：CityGS 的光柵器在 8～13% 的 test 視角把顏色算錯（暗幀），只換光柵器就恢復（`參考_CityGS參考線.md` §0.1）。
- **動機**：要和 CityGS 在同一個評分環境下比；論文數字的測試集和解析度描述不完整。
- **成效**：
  - CityGS release 用我方工具 27.261，論文 27.23。
  - ⚠ **注意**：`參考_CityGS參考線.md` §0.1 也量到，在正常幀上我方光柵器讀 CityGS 模型平均低 0.35 dB，所以 CityGS release 的合理分數區間是 27.2～27.6。`現行方法.md` §0 只寫「評測設定對得上」，沒有這個附註；PSNR 領先 +0.68 應加註「上限可能高估約 0.35 dB」。SSIM／LPIPS 的領先比較穩。

#### F2. 換塊評測（`tools/swap_block_eval.py`）
- **我們怎麼做**：把一個參考合併模型的第 B 塊盒內顆粒，換成候選 ckpt 的盒內顆粒，歸屬規則和合併相同。報兩組分數：第 B 塊的視角，以及全部 741 幀。
- **來源**：沒做文獻搜尋。CityGS 系列只報合併後的整體分數。
- **關係**：原創（評測方法）。
- **差在哪**：單塊 held-out 混了「單塊模型帶了多少塊外內容」；換塊評測量的是「其他 15 塊不變、只換這一塊」的真實合併結果。
- **動機**：10-10 發現單塊 held-out 的畫面只有 11～15% 是塊內內容；b12 單塊 −3.84，合併後 +0.73（工具 docstring；`參考_CityGS參考線.md` §0.2b）。
- **成效**：雜訊約 ±0.01～0.03 dB（`現行方法.md` §8）。現行配方的單變數判定全部用它。

#### F3. 幾何 F1（全場景用 TnT 協定；區塊用 `tools/block_f1.py`）
- **我們怎麼做**：
  - 全場景：照 CityGS 的參數做 TSDF 融合（voxel 0.01／sdf_trunc 0.04／depth_trunc 5.0），用 `tools/eval_tnt/run.py`（含 ICP 配準）對 MatrixCity GT 點雲，τ＝0.006。同時報不配準的版本。
  - 區塊：只換第 B 塊、只用本塊相機融合；GT 與網格都裁到 crop ∩ 分區盒；不做 ICP。
- **來源**：CityGaussianV2 §4，p.6～7：TnT 式流程，用能見頻率估 crop volume、在表面均勻取樣、τ 依最近鄰距離定（0.3～0.6 m）；p.8：用 median depth 做 TSDF，MatrixCity 深度截斷 500 m。已讀原文。
- **關係**：全場景是完全沿用；區塊 F1 是借用改造。
- **差在哪**：區塊版只用本塊相機、裁到分區盒、不配準。不配準的理由：10-15 量到 eval_tnt 的配準把我方模型移歪了 0.07（full44：配準 0.356 vs 不配準 0.425；CityGS release：0.597 vs 0.590，`參考_CityGS參考線.md` §6.1）。
- **動機**：使用者要求每個單變數臂都要有幾何分數（工具 docstring）。
- **成效**：全場景我方 .711（P .611／R .850；不配準 .703），CityGS release .597（不配準 .590），論文自報 .556（`現行方法.md` §0）。

#### F4. 對 GT 深度的渲染深度誤差（`現行方法.md` §9.6）
- **我們怎麼做**：訓練視角每 20 張取 1（282 台）。算 AbsRel＝|渲染 − GT|／GT 的中位和平均、δ1.01／δ1.05（誤差在 1%／5% 以內的像素比例），以及「在後面／在前面 > 2%」的比例。GT 深度只用來診斷。
- **來源**：AbsRel 與 δ 門檻是單目深度估計的慣用指標（Eigen et al., 2014；⚠ 原文沒重讀）。1.01／1.05 與 ±2% 是我方選的。
- **關係**：借用改造（指標沿用，門檻改得比慣用的 δ<1.25 嚴很多）。
- **差在哪**：門檻收緊到 1%／5%，另外分前後兩側。
- **動機**：要量 test PSNR 看不到的「半透明霧、浮塊」造成的深度尾巴。
- **成效**：全部 4.06 億像素：δ1.01 我方 95.7%、CityGS 81.1%（95.7 − 14.6）；在前面 > 2% 我方 1.50%、CityGS 10.29%（1.50 + 8.79）（`現行方法.md` §9.6）。

#### F5. 色彩校正版評測（`tools/eval_color_correct.py`）
- **我們怎麼做**：每張渲染圖用該張 GT 擬合 multinerf 的 `color_correct`（逐色版的二次轉換，5 輪、排除飽和像素），套上後再算指標。
- **來源**：multinerf（Mip-NeRF 360）的 `color_correct` 程式。工具註明逐行對照過，論文沒讀。DOGS 的程式和 Momentum-GS 的 camera-ready 用的是同一種校正（`大場景對手` 注意事項 1）。
- **關係**：完全沿用。
- **差在哪**：沒有差別。只是為了和做 CC 的那一群並列。
- **動機**：使用者 11-20 問我們能不能也做色彩校正（工具 docstring）。
- **成效**：我方 27.94 → 28.93，CityGS release 27.29 → 28.48（`現行方法.md` §9.5）。

#### F6. 特定問題量尺與自檢渲染（`eval_arms_lab.sh` ground／sea／smallobj／facade／orient、`tools/probe/tower_gt_1113.py`、`recess_1118.py`、`tools/render_views.py`）

### H. SH 可觀測子空間（`實驗分析/40_高斯內參化簡.md` §1.1～1.7；renderer `sh_proj_k`／`sh_basis_k`／`sh_basis_file`，臂 `shp<k>`／`shb<k>`；**還沒進預設**，`shb10` 的 741 幀 test 還在跑）

- **我們怎麼做**（分四步，越後面越完整）：
  1. **可觀測性分析（§1.1～1.3）**：
     - 對每顆累加 `M_i = sum_v w_iv·Y(d_iv)·Y(d_iv)^T`（16x16，Y＝16 個 SH 基底在視線方向的值）。M_i 的零空間就是訓練完全看不到的 SH 組合。
     - 全域平均的 M̄ 只用相機幾何就能算（訓練前、零成本），按渲染貢獻加權算出的形狀幾乎相同。
     - 空拍相機的仰角集中在一個窄帶，所以每個方位階 m 最多只有 2 維可觀測，合計 **10／16 維**（每個色版），和量測一致（b2：逐顆有效維度中位 10）。
  2. **保留 DC 的投影（§1.4）**：
     - 高階 15 維用 Schur 補數 `S = M_rr − M_r0·M_00^-1·M_0r` 的前 k−1 個特徵向量 U 做投影：`rest' = U·U^T·rest`。
     - DC 依帶內最小平方補償：`Δdc = M_0r·(rest − rest') / M_00`。這個投影是冪等的。
  3. **訓練時限制在子空間**：
     - §1.5 `sh_proj_k`：SH 升到 3 階後，每步 optimizer 更新完就投影一次。只為驗證畫質，參數個數不變。
     - §1.6 `sh_basis_k`：**真正的低維參數化**。高階 SH 每色版只存 K＝k−1 個係數 a，`rest = U·a`。
       光柵器在前處理把 a 展開成 15 個係數；backward 照原式算出 15 個係數的梯度，再乘 U^T 縮回 K 維。
       SH 的 Adam 與每 16 步的累加都直接在 K 維上做，所以參數、Adam 兩份、梯度都只有 K 維，沒有 N x 45 的暫存。
  4. **全場景共用基底與低維存檔（§1.7）**：
     - `tools/sh_basis_global.py` 把 16 塊（每塊 3 萬個可靠 SfM 點 x 該塊訓練相機）的 M̄ 平均成一個全域基底（`configs/sh_basis_matrixcity_aerial.npz`）。
     - ckpt 直接存 [N,K,3] 加 `checkpoint["sh_basis"]`（Adam 也是 K 維，可以接著訓練）。讀檔與 web viewer 轉 PLY 時才展開成 15 維；合併時檢查各塊用的是同一組基底。
- **來源（最接近的同類，都是 SH 壓縮或降維）**：

  | 方法 | 怎麼減 SH | 怎麼決定 | 看不看相機分布 | 讀到的程度 |
  |---|---|---|---|---|
  | LightGaussian（NeurIPS 2024） | 3 階截成 2 階，用偽視角（在訓練相機位置加高斯擾動）蒸餾；重要度低的 SH 做 VQ | 固定截階 | 否（偽視角只用來補監督） | 已讀原文 p.5 §3.3～3.4、p.7 |
  | CityGaussianV2（ICLR 2025） | 從頭就用 SH 2 階（每顆 48 → 27 個係數）；合併後重要度低的 SH 做 VQ | 固定截階 | 否 | 已讀原文 p.6 §3.3、p.10 Tab.2（GauU-Scene Residence：PSNR 23.57 → 23.49） |

  | C3DGS（Niedermayr et al., CVPR 2024） | 對方向顏色和高斯參數做敏感度感知的向量分群，加量化感知訓練 | 資料驅動 | 摘要沒提 | 只讀摘要 |

- **關係**：原創。沒查到「依相機分布決定可觀測 SH 子空間」的前例：搜了兩次，第一次只找到「SH 只在訓練視角附近擬合、離開會過擬合」這類一般性描述；第二次找到 LowRankSH 這類資料驅動的低秩方法。
- **差在哪**：
  1. **基底從哪來**：
     - 我們用相機幾何（M̄），訓練前就能算，不看係數。
     - LowRankSH、C3DGS、CompGS 是對訓練後的係數做 PCA 或 VQ。
     - LightGaussian、V2 是固定截階。
     - Reduced3DGS 是逐顆看顏色變化。
     - 訓練時就降維的只有 LowRankSH 的 SHAC-LST（低秩分解在訓練中學）與 V2 的 SH 2 階。我們的基底在訓練前就固定，訓練中不學。
  2. **存法（§1.6～1.7）**：
     - 我們是一組全場景共用的固定線性基底，加上每顆 K 個係數。解碼只要一次矩陣乘法，沒有碼本和索引；梯度可以直接回傳；Adam 狀態也是 K 維。
     - VQ 類（C3DGS、CompGS、LightGaussian 的 SH VQ、V2 的 VQ）要存碼本加每顆的索引，而且是量化、有損。
     - Reduced3DGS 每顆保留的階數不一樣，存法是變長的。
     - 我們每顆一樣長，16 塊共用一組基底，所以合併不必改格式。
  3. **子空間的形狀**：不是「截掉高階」。10 維子空間保留部分 3 階成分（例如 |m|＝3 的那兩個各保留 1 維），丟掉的是「同一個 m、不同 l」的組合（`40` §1.2）。
     V2 的 SH 2 階剛好是 9 維，但選的是另一個子空間。我方在 MatrixCity 試過 SH 2 階：b2 本塊區域 −0.066，viewer 裡出現巨型霧團，使用者不採用（`現行方法.md` §10.1）。
  4. **有理論預測維數**：窄仰角帶使每個 m 最多 2 維 => 10。量測與理論一致。
  5. **DC 分開處理**：16 維正交投影會把 DC 搬到 Y10／Y20，帶外（viewer 低角度）顏色會偏；Schur 補數版把 DC 的變化中位從 0.27 降到 0.002～0.005（`40` §1.4）。
  6. **只對空拍這類「視角分布窄」的資料有意義**。前人的方法不分資料類型。
- **動機**：使用者 11-21 要研究高斯參數裡有沒有沒用的、或能用數學合併的部分（`40` 開頭）；SH 佔每顆 58 個 float 裡的 48 個。

  - 事後投影（看向該塊的 test 幀）：

  - **訓練時就限制維數**（lab b1／b2／b4，對新預設）：

  - 投影版（`shp`）的參數個數沒變，而且每步投影讓純訓練 +16～21%（kernel 發射成本；`40` §1.5）。
  - **低維參數化（§1.6）的本機驗證**（b2、k＝10）：
